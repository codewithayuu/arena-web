<LessonCard>

The model is simple. Every member a class can have (field, method, constructor) has a matching reflection object (`Field`, `Method`, `Constructor`) that describes it. Asking a `Class` for these objects is the way to walk the structure. This lesson builds a small `describe()` utility that takes any class and prints what it contains, using a small e-commerce class hierarchy (`Product`, `Order`, `Cart`, `Customer`) as the running example.

<h1 id="the-inspection-vocabulary">The Inspection Vocabulary</h1>

The `Class` object is the entry point. From there, three families of accessors expose members.

The diagram shows the four kinds of question a `Class` answers. Fields, methods, and constructors each come in two flavors: a "public, including inherited" version and a "declared, including private but only on this class" version. The next two sections unpack that distinction. The metadata family covers modifiers, parent class, interfaces, and category questions like "is this an enum?"

The `Product` class used for most of the lesson:

```java
public class Product {

    public static final double TAX_RATE = 0.08;

    private long id;
    private String name;
    private double price;
    int stockQty;

    public Product() {
        this(0L, "", 0.0, 0);
    }

    public Product(long id, String name, double price, int stockQty) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stockQty = stockQty;
    }

    public long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public double getPrice() {
        return price;
    }

    public int getStockQty() {
        return stockQty;
    }

    public boolean isInStock() {
        return stockQty > 0;
    }

    @Override
    public String toString() {
        return name + " ($" + price + ")";
    }
}
```

This is the test subject. It has one public static field, three private fields, one package-private field, two constructors, four getters, one boolean method, and an overridden `toString`. Reflection should be able to surface every one of these.

<h1 id="getfields-vs-getdeclaredfields">getFields() vs getDeclaredFields()</h1>

One source of confusion in the reflection API is the difference between `getX()` and `getDeclaredX()`. The naming makes them sound like minor variants. They are not.

| Method                | What it returns                                                                     |
| --------------------- | ----------------------------------------------------------------------------------- |
| `getFields()`         | Public fields only, but including those inherited from superclasses and interfaces  |
| `getDeclaredFields()` | All fields declared on this class, regardless of visibility, but NOT inherited ones |

The same pattern holds for methods and constructors. Both axes matter: visibility (public vs all) and origin (this class vs the whole hierarchy).

```java
import java.lang.reflect.Field;

public class FieldsExample {

    public static void main(String[] args) {
        Class<Product> productClass = Product.class;

        System.out.println("getFields() returns " + productClass.getFields().length);
        for (Field f : productClass.getFields()) {
            System.out.println("  " + f.getName());
        }

        System.out.println("getDeclaredFields() returns " + productClass.getDeclaredFields().length);
        for (Field f : productClass.getDeclaredFields()) {
            System.out.println("  " + f.getName());
        }
    }
}
```

`getFields()` returns only `TAX_RATE` because it is the only `public` field on the class. The three private fields and the package-private one are hidden from it. `getDeclaredFields()` returns all five fields that the `Product` source file declares.

Adding a subclass shows the inherited-vs-declared dimension.

```java
public class DigitalProduct extends Product {

    public static final double DOWNLOAD_FEE = 0.99;

    private String licenseKey;

    public DigitalProduct(long id, String name, double price, String licenseKey) {
        super(id, name, price, Integer.MAX_VALUE);
        this.licenseKey = licenseKey;
    }

    public String getLicenseKey() {
        return licenseKey;
    }
}
```

```java
import java.lang.reflect.Field;

public class FieldsOnSubclass {

    public static void main(String[] args) {
        Class<DigitalProduct> dpClass = DigitalProduct.class;

        System.out.println("Public fields (including inherited):");
        for (Field f : dpClass.getFields()) {
            System.out.println("  " + f.getName());
        }

        System.out.println("Declared fields (this class only):");
        for (Field f : dpClass.getDeclaredFields()) {
            System.out.println("  " + f.getName());
        }
    }
}
```

`getFields()` picked up both `DOWNLOAD_FEE` (declared here) and `TAX_RATE` (inherited from `Product`), because both are public. It did not pick up `licenseKey` because it is private. `getDeclaredFields()` listed `DOWNLOAD_FEE` and `licenseKey` because those are the two fields declared on `DigitalProduct`, but it did not list `TAX_RATE` because that field belongs to `Product`.

The cross product as a table:

| Question                                                                   | Method to call                                                  |
| -------------------------------------------------------------------------- | --------------------------------------------------------------- |
| "Everything accessible through this class, regardless of declaration site" | `getFields()`                                                   |
| "Everything declared right here, including private members"                | `getDeclaredFields()`                                           |
| "All fields, public and private, from anywhere in the hierarchy"           | Walk `getDeclaredFields()` up the chain using `getSuperclass()` |
| "All public fields declared here, ignoring inheritance"                    | Filter `getDeclaredFields()` by `Modifier.isPublic`             |

There is no single built-in method for the third row. The loop has to be written by hand, as covered later in the lesson.

<h1 id="methods-and-constructors-follow-the-same-rule">
  Methods and Constructors Follow the Same Rule
</h1>

The same pair of accessors applies to methods and constructors. The naming and meaning match the field case.

```java
import java.lang.reflect.Method;

public class MethodsExample {

    public static void main(String[] args) {
        Class<Product> productClass = Product.class;

        System.out.println("Public methods on Product (including inherited from Object):");
        for (Method m : productClass.getMethods()) {
            System.out.println("  " + m.getName());
        }

        System.out.println();
        System.out.println("Declared methods on Product:");
        for (Method m : productClass.getDeclaredMethods()) {
            System.out.println("  " + m.getName());
        }
    }
}
```

The exact order of `getMethods()` is not guaranteed, so runs may show methods in a slightly different order. The contents are guaranteed: `getMethods()` lists every public method visible through `Product`, including the ones inherited from `Object` (`wait`, `equals`, `hashCode`, `getClass`, `notify`, `notifyAll`, and the three overloads of `wait`). `getDeclaredMethods()` returns only the six methods the `Product` source file declares.

`getMethods()` and `getDeclaredMethods()` walk the class structure on each call and allocate a fresh array. When inspecting the same class repeatedly in a hot path, hold a reference to the `Method` instead of looking it up every iteration.

Constructors work the same way. `Product` has two public constructors, so both come back from either call.

```java
import java.lang.reflect.Constructor;

public class ConstructorsExample {

    public static void main(String[] args) {
        Class<Product> productClass = Product.class;

        System.out.println("Public constructors:");
        for (Constructor<?> c : productClass.getConstructors()) {
            System.out.println("  " + c);
        }

        System.out.println("Declared constructors:");
        for (Constructor<?> c : productClass.getDeclaredConstructors()) {
            System.out.println("  " + c);
        }
    }
}
```

Constructors do not get inherited in Java, so the two methods return the same list as long as every constructor is public. Adding a private constructor (for a singleton or a factory) makes `getConstructors()` hide it while `getDeclaredConstructors()` still shows it.

<h1 id="looking-up-a-specific-member-by-name">
  Looking Up a Specific Member by Name
</h1>

Sometimes only one field or method is needed, not all of them. The lookup methods take the name (and for methods and constructors, the parameter types) and return the matching reflection object.

| Method                                   | Returns                                               | If not found            |
| ---------------------------------------- | ----------------------------------------------------- | ----------------------- |
| `getField(String)`                       | The public field with that name (including inherited) | `NoSuchFieldException`  |
| `getDeclaredField(String)`               | The declared field with that name on this class       | `NoSuchFieldException`  |
| `getMethod(String, Class<?>...)`         | The public method with that name and parameter types  | `NoSuchMethodException` |
| `getDeclaredMethod(String, Class<?>...)` | The declared method on this class                     | `NoSuchMethodException` |
| `getConstructor(Class<?>...)`            | The public constructor matching the parameter types   | `NoSuchMethodException` |
| `getDeclaredConstructor(Class<?>...)`    | The declared constructor on this class                | `NoSuchMethodException` |

The parameter-types argument is a varargs of `Class<?>`. For `getMethod("setPrice", double.class)`, pass `double.class`, not `Double.class`, because the method's parameter is the primitive. Mixing those up is a frequent cause of `NoSuchMethodException`.

```java
import java.lang.reflect.Field;
import java.lang.reflect.Method;
import java.lang.reflect.Constructor;

public class LookupExample {

    public static void main(String[] args) throws Exception {
        Field priceField = Product.class.getDeclaredField("price");
        System.out.println("Found field: " + priceField.getName());

        Method getPrice = Product.class.getMethod("getPrice");
        System.out.println("Found method: " + getPrice.getName());

        Constructor<Product> fullCtor = Product.class.getConstructor(
                long.class, String.class, double.class, int.class);
        System.out.println("Found constructor with " + fullCtor.getParameterCount() + " params");
    }
}
```

If the name does not exist or the parameter types do not match, a checked exception is thrown. The exception is descriptive: it names exactly what was being looked up.

```java
public class MissingMemberExample {

    public static void main(String[] args) {
        try {
            Product.class.getDeclaredField("discount");
        } catch (NoSuchFieldException e) {
            System.out.println("NoSuchFieldException: " + e.getMessage());
        }

        try {
            Product.class.getMethod("setPrice", double.class);
        } catch (NoSuchMethodException e) {
            System.out.println("NoSuchMethodException: " + e.getMessage());
        }
    }
}
```

Both `NoSuchFieldException` and `NoSuchMethodException` are checked, so call sites must declare them or catch them. This is one of the reasons reflection code looks heavier than direct code: every lookup forces an exception decision.

One common mistake to flag early: `getMethod("getPrice", double.class)` will throw `NoSuchMethodException` even though `getPrice` exists, because that method takes zero arguments and the lookup asks for one of type `double`. The lookup matches on signature, not just on name. To find a no-arg method, pass no parameter types at all: `getMethod("getPrice")`.

<h1 id="reading-field-metadata">Reading Field Metadata</h1>

A `Field` object exposes everything the source file declared about that field: its name, its type, its generic type, and its modifiers. This section is read-only.

```java
import java.lang.reflect.Field;
import java.lang.reflect.Modifier;

public class FieldMetadataExample {

    public static void main(String[] args) {
        for (Field f : Product.class.getDeclaredFields()) {
            String modifiers = Modifier.toString(f.getModifiers());
            String type = f.getType().getSimpleName();
            System.out.println(modifiers + " " + type + " " + f.getName());
        }
    }
}
```

`Modifier.toString(int)` converts the raw modifier bits into a readable string in the order the Java Language Specification prefers (visibility first, then `static`, then `final`, and so on). The `getType()` call returns the field's declared type as a `Class`. Calling `getSimpleName()` strips the package, so the result is `String` instead of `java.lang.String`.

For generic fields, `getType()` returns the erased type. `getGenericType()` returns the full generic type, which can be a `ParameterizedType`. Here is the difference.

```java
import java.lang.reflect.Field;
import java.util.List;
import java.util.Map;

public class GenericFieldExample {

    static class Cart {
        List<Product> items;
        Map<String, Integer> stockLevels;
    }

    public static void main(String[] args) throws Exception {
        Field items = Cart.class.getDeclaredField("items");
        Field stock = Cart.class.getDeclaredField("stockLevels");

        System.out.println("items.getType()        = " + items.getType().getSimpleName());
        System.out.println("items.getGenericType() = " + items.getGenericType());
        System.out.println("stock.getType()        = " + stock.getType().getSimpleName());
        System.out.println("stock.getGenericType() = " + stock.getGenericType());
    }
}
```

`getType()` is appropriate when only the raw class of the field is needed. `getGenericType()` is appropriate when the type parameter matters: for example, a serializer that needs to know "is this a `List<Product>` or a `List<Order>`?" Both methods are cheap and read-only.

The `Modifier` class also exposes static predicates: `Modifier.isPublic(int)`, `Modifier.isPrivate(int)`, `Modifier.isStatic(int)`, `Modifier.isFinal(int)`, `Modifier.isVolatile(int)`, `Modifier.isTransient(int)`, and so on. Use them for a single yes/no answer instead of parsing a string.

```java
import java.lang.reflect.Field;
import java.lang.reflect.Modifier;

public class ModifierPredicatesExample {

    public static void main(String[] args) {
        for (Field f : Product.class.getDeclaredFields()) {
            int mods = f.getModifiers();
            System.out.printf("%-10s static=%-5s final=%-5s private=%-5s%n",
                    f.getName(),
                    Modifier.isStatic(mods),
                    Modifier.isFinal(mods),
                    Modifier.isPrivate(mods));
        }
    }
}
```

This pattern is the basis of any inspector that needs to filter by visibility or by "is this a constant?" (`static` plus `final`). The `describe()` utility at the end of the lesson uses it.

<h1 id="reading-method-metadata">Reading Method Metadata</h1>

A `Method` object exposes a richer set of properties than a `Field` because methods have parameters, a return type, and a declared list of thrown exceptions.

| Accessor                 | What it returns                                                |
| ------------------------ | -------------------------------------------------------------- |
| `getName()`              | The method name, like `"getPrice"`                             |
| `getReturnType()`        | The erased return type as `Class<?>`                           |
| `getGenericReturnType()` | The full generic return type, including type parameters        |
| `getParameterTypes()`    | An array of `Class<?>` describing the parameter types          |
| `getParameterCount()`    | The number of parameters                                       |
| `getParameters()`        | An array of `Parameter` objects with name and type information |
| `getExceptionTypes()`    | The declared checked exception types                           |
| `getModifiers()`         | The raw modifier bits, same as for fields                      |

The next program walks every declared method on `Product` and prints a one-line summary.

```java
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;

public class MethodMetadataExample {

    public static void main(String[] args) {
        for (Method m : Product.class.getDeclaredMethods()) {
            StringBuilder line = new StringBuilder();
            line.append(Modifier.toString(m.getModifiers())).append(" ");
            line.append(m.getReturnType().getSimpleName()).append(" ");
            line.append(m.getName()).append("(");

            Class<?>[] params = m.getParameterTypes();
            for (int i = 0; i < params.length; i++) {
                if (i > 0) line.append(", ");
                line.append(params[i].getSimpleName());
            }
            line.append(")");

            System.out.println(line);
        }
    }
}
```

Each method is printed in the order it appears in the class file, though the JVM does not guarantee source order. The same logic works for any class, which is the property the `describe()` utility exploits.

When a method has parameters, `getParameters()` returns a `Parameter[]`. Each `Parameter` carries a name and a type. By default, the JVM does not store parameter names in the class file, so the names come back as `arg0`, `arg1`, and so on. Compiling with the `-parameters` flag (`javac -parameters` or the Maven compiler plugin's `parameters` option) preserves the real names and `getName()` returns them. Frameworks like Spring rely on this for binding request parameters.

```java
public class MethodWithParams {

    static class Cart {
        public double calculateTotal(double subtotal, double discountRate, double taxRate) {
            return (subtotal * (1 - discountRate)) * (1 + taxRate);
        }
    }

    public static void main(String[] args) throws Exception {
        java.lang.reflect.Method m = Cart.class.getDeclaredMethod(
                "calculateTotal", double.class, double.class, double.class);

        System.out.println("Parameter count: " + m.getParameterCount());
        for (java.lang.reflect.Parameter p : m.getParameters()) {
            System.out.println("  " + p.getType().getSimpleName() + " " + p.getName());
        }
    }
}
```

**Output (compiled without -parameters):**

```text
Parameter count: 3
  double arg0
  double arg1
  double arg2
```

**Output (compiled with -parameters):**

```text
Parameter count: 3
  double subtotal
  double discountRate
  double taxRate
```

Parameter name reflection is a build-time switch. When code or a framework needs real parameter names, the whole module must be compiled with `-parameters`, not just the calling code.

Generic return types follow the same pattern as generic field types.

```java
import java.lang.reflect.Method;
import java.util.List;

public class GenericReturnExample {

    static class OrderHistory {
        public List<Product> recentPurchases() { return null; }
    }

    public static void main(String[] args) throws Exception {
        Method m = OrderHistory.class.getDeclaredMethod("recentPurchases");
        System.out.println("getReturnType()        = " + m.getReturnType().getSimpleName());
        System.out.println("getGenericReturnType() = " + m.getGenericReturnType());
    }
}
```

For methods that declare checked exceptions in their `throws` clause, `getExceptionTypes()` returns the list. The common use is a serializer or RPC framework that needs to know which exceptions can flow out of a method.

```java
import java.lang.reflect.Method;

public class ExceptionTypesExample {

    static class CheckoutService {
        public void placeOrder(long customerId) throws IllegalStateException, java.io.IOException {
            // body omitted
        }
    }

    public static void main(String[] args) throws Exception {
        Method m = CheckoutService.class.getDeclaredMethod("placeOrder", long.class);
        for (Class<?> ex : m.getExceptionTypes()) {
            System.out.println("throws " + ex.getSimpleName());
        }
    }
}
```

<h1 id="reading-constructor-metadata">Reading Constructor Metadata</h1>

`Constructor` is the third reflection object and behaves like `Method` minus the return type. It exposes parameter types, parameter count, exception types, modifiers, and so on. A more realistic `Order` class illustrates it.

```java
public class Order {

    private final long id;
    private final long customerId;
    private final double total;

    public Order(long id, long customerId, double total) {
        this.id = id;
        this.customerId = customerId;
        this.total = total;
    }

    public Order(long id, long customerId) {
        this(id, customerId, 0.0);
    }

    private Order() {
        this(0L, 0L, 0.0);
    }

    public long getId() { return id; }
    public long getCustomerId() { return customerId; }
    public double getTotal() { return total; }
}
```

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.Modifier;

public class ConstructorMetadataExample {

    public static void main(String[] args) {
        System.out.println("getConstructors() (public only):");
        for (Constructor<?> c : Order.class.getConstructors()) {
            describe(c);
        }

        System.out.println("getDeclaredConstructors() (all):");
        for (Constructor<?> c : Order.class.getDeclaredConstructors()) {
            describe(c);
        }
    }

    static void describe(Constructor<?> c) {
        StringBuilder line = new StringBuilder("  ");
        line.append(Modifier.toString(c.getModifiers())).append(" Order(");
        Class<?>[] params = c.getParameterTypes();
        for (int i = 0; i < params.length; i++) {
            if (i > 0) line.append(", ");
            line.append(params[i].getSimpleName());
        }
        line.append(")");
        System.out.println(line);
    }
}
```

`getConstructors()` returns only the two public constructors. `getDeclaredConstructors()` adds the private one. This is a common pattern in factory-method classes: a public set of constructors for callers, a private one for internal use, and only the declared accessor sees both.

<h1 id="class-level-metadata">Class-Level Metadata</h1>

The `Class` object also describes itself: its modifiers, its parent class, its interfaces, its package, and whether it is something special like an interface, enum, annotation, or record.

```java
import java.lang.reflect.Modifier;

public class ClassMetadataExample {

    public static void main(String[] args) {
        Class<?> cls = Product.class;

        System.out.println("name        = " + cls.getName());
        System.out.println("simpleName  = " + cls.getSimpleName());
        System.out.println("package     = " + cls.getPackageName());
        System.out.println("modifiers   = " + Modifier.toString(cls.getModifiers()));
        System.out.println("superclass  = " + cls.getSuperclass().getName());

        System.out.println("interfaces  :");
        for (Class<?> i : cls.getInterfaces()) {
            System.out.println("  " + i.getName());
        }

        System.out.println("isInterface  = " + cls.isInterface());
        System.out.println("isEnum       = " + cls.isEnum());
        System.out.println("isAnnotation = " + cls.isAnnotation());
        System.out.println("isRecord     = " + cls.isRecord());
    }
}
```

**Output (assuming `Product` is in the default package):**

```text
name        = Product
simpleName  = Product
package     =
modifiers   = public
superclass  = java.lang.Object
interfaces  :
isInterface  = false
isEnum       = false
isAnnotation = false
isRecord     = false
```

Three details about this list:

`getSuperclass()` returns `Object` for any class that does not extend something else. For interfaces, it returns `null`. For arrays, it returns `Object`. A loop over it climbs the full inheritance chain.

`getInterfaces()` returns only the interfaces directly named in the `implements` clause. It does not include interfaces inherited transitively through a superclass or through another interface. The full set requires walking both `getInterfaces()` and `getSuperclass().getInterfaces()` recursively.

The `is*` family is the cheap way to ask category questions. `isInterface()` is `true` for an interface declaration. `isEnum()` is `true` for an enum (and the enum's class shows `extends java.lang.Enum<...>` as its superclass). `isAnnotation()` is `true` for an annotation declaration. `isRecord()` was added in Java 16 and is `true` for record types.

Records get their own dedicated accessor as well. A record's components are not the same as its fields from the JVM's point of view: the language guarantees that a record component is a one-to-one match with a private final field of the same name and type, but the reflection API has a separate `RecordComponent` type for them.

```java
import java.lang.reflect.RecordComponent;

public class RecordExample {

    record CartItem(long productId, int quantity, double unitPrice) { }

    public static void main(String[] args) {
        Class<?> cls = CartItem.class;
        System.out.println("isRecord = " + cls.isRecord());
        for (RecordComponent rc : cls.getRecordComponents()) {
            System.out.println("  " + rc.getType().getSimpleName() + " " + rc.getName());
        }
    }
}
```

`getRecordComponents()` returns `null` on non-record classes, not an empty array, so always check `isRecord()` first when calling it on arbitrary classes.

<h1 id="reading-annotations-on-classes-fields-methods-and-parameters">
  Reading Annotations on Classes, Fields, Methods, and Parameters
</h1>

The reflection side of annotations is small: every annotated element exposes the same four-method vocabulary.

| Method                                                  | Returns                                                                  |
| ------------------------------------------------------- | ------------------------------------------------------------------------ |
| `getAnnotation(Class<A> type)`                          | The annotation of that type, or `null` if not present                    |
| `isAnnotationPresent(Class<? extends Annotation> type)` | `true` if the annotation is present                                      |
| `getAnnotations()`                                      | All annotations present, including those inherited via `@Inherited`      |
| `getDeclaredAnnotations()`                              | All annotations declared directly on this element, ignoring `@Inherited` |

The methods exist on `Class`, `Field`, `Method`, `Constructor`, and `Parameter`. They behave the same way everywhere. Only annotations whose retention is `RUNTIME` are visible to reflection; the others were dropped before the class reached the JVM.

A small example using `@Deprecated`, which has runtime retention, on each of those elements:

```java
import java.lang.annotation.Annotation;

public class AnnotationReadingExample {

    @Deprecated
    static class LegacyOrder {

        @Deprecated
        public long oldOrderNumber;

        @Deprecated
        public LegacyOrder() { }

        @Deprecated
        public void cancel(@Deprecated String reason) { }
    }

    public static void main(String[] args) throws Exception {
        Class<?> cls = LegacyOrder.class;

        System.out.println("class annotations:");
        for (Annotation a : cls.getAnnotations()) {
            System.out.println("  " + a.annotationType().getSimpleName());
        }

        System.out.println("field annotations on oldOrderNumber:");
        for (Annotation a : cls.getDeclaredField("oldOrderNumber").getAnnotations()) {
            System.out.println("  " + a.annotationType().getSimpleName());
        }

        System.out.println("method annotations on cancel:");
        java.lang.reflect.Method cancel = cls.getDeclaredMethod("cancel", String.class);
        for (Annotation a : cancel.getAnnotations()) {
            System.out.println("  " + a.annotationType().getSimpleName());
        }

        System.out.println("parameter annotations on cancel:");
        for (java.lang.reflect.Parameter p : cancel.getParameters()) {
            for (Annotation a : p.getAnnotations()) {
                System.out.println("  " + p.getName() + " has " + a.annotationType().getSimpleName());
            }
        }
    }
}
```

The parameter loop printed `arg0` instead of `reason` because this example was compiled without `-parameters`. The parameter name reflection rule from earlier applies here too.

`isAnnotationPresent` is a convenience method for checking presence without reading the data inside the annotation.

```java
public class AnnotationPresenceExample {

    @Deprecated
    static class OldDiscount { }

    static class NewDiscount { }

    public static void main(String[] args) {
        System.out.println("OldDiscount deprecated? " + OldDiscount.class.isAnnotationPresent(Deprecated.class));
        System.out.println("NewDiscount deprecated? " + NewDiscount.class.isAnnotationPresent(Deprecated.class));
    }
}
```

To read the data inside the annotation, use `getAnnotation` and call the element accessors on the returned annotation object. `Deprecated` has two elements added in Java 9: `since` and `forRemoval`.

```java
public class AnnotationDataExample {

    @Deprecated(since = "2.0", forRemoval = true)
    static class LegacyCheckout { }

    public static void main(String[] args) {
        Deprecated d = LegacyCheckout.class.getAnnotation(Deprecated.class);
        if (d != null) {
            System.out.println("since        = " + d.since());
            System.out.println("forRemoval   = " + d.forRemoval());
        }
    }
}
```

The `since` and `forRemoval` calls are real methods on the `Deprecated` interface. The annotation reflection returns an object that implements the annotation's interface, and element methods are called on it directly.

The difference between `getAnnotations()` and `getDeclaredAnnotations()` only shows up for classes, and only for annotations that are themselves marked `@Inherited`. By default annotations are not inherited, so the two methods return the same array. `@Inherited` is a meta-annotation that opts in to inheritance; the takeaway is that for fields, methods, constructors, and parameters, both calls return the same set, because annotations on those elements are never inherited regardless of the meta-annotation.

<h1 id="putting-it-together-a-describe-utility">
  Putting It Together: A describe() Utility
</h1>

The function below combines the pieces. It takes any class and prints a structured summary: class metadata, all declared fields with their modifiers and types, all declared methods with parameters and return type, and all declared constructors. It only reads; it does not invoke anything or change anything.

```java
import java.lang.annotation.Annotation;
import java.lang.reflect.Constructor;
import java.lang.reflect.Field;
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;

public class Describer {

    public static void describe(Class<?> cls) {
        System.out.println("=== " + cls.getName() + " ===");
        System.out.println("modifiers : " + Modifier.toString(cls.getModifiers()));

        Class<?> superCls = cls.getSuperclass();
        System.out.println("superclass: " + (superCls == null ? "(none)" : superCls.getName()));

        Class<?>[] interfaces = cls.getInterfaces();
        if (interfaces.length > 0) {
            StringBuilder sb = new StringBuilder("implements: ");
            for (int i = 0; i < interfaces.length; i++) {
                if (i > 0) sb.append(", ");
                sb.append(interfaces[i].getSimpleName());
            }
            System.out.println(sb);
        }

        printAnnotations("class", cls.getDeclaredAnnotations(), 0);

        System.out.println();
        System.out.println("fields:");
        for (Field f : cls.getDeclaredFields()) {
            String mods = Modifier.toString(f.getModifiers());
            System.out.println("  " + mods + " " + f.getType().getSimpleName() + " " + f.getName());
            printAnnotations("field", f.getDeclaredAnnotations(), 4);
        }

        System.out.println();
        System.out.println("constructors:");
        for (Constructor<?> c : cls.getDeclaredConstructors()) {
            System.out.println("  " + Modifier.toString(c.getModifiers()) + " "
                    + cls.getSimpleName() + "(" + paramList(c.getParameterTypes()) + ")");
        }

        System.out.println();
        System.out.println("methods:");
        for (Method m : cls.getDeclaredMethods()) {
            String mods = Modifier.toString(m.getModifiers());
            System.out.println("  " + mods + " " + m.getReturnType().getSimpleName() + " "
                    + m.getName() + "(" + paramList(m.getParameterTypes()) + ")");
            printAnnotations("method", m.getDeclaredAnnotations(), 4);
        }
    }

    private static String paramList(Class<?>[] params) {
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < params.length; i++) {
            if (i > 0) sb.append(", ");
            sb.append(params[i].getSimpleName());
        }
        return sb.toString();
    }

    private static void printAnnotations(String label, Annotation[] annotations, int indent) {
        for (Annotation a : annotations) {
            for (int i = 0; i < indent; i++) System.out.print(' ');
            System.out.println("@" + a.annotationType().getSimpleName());
        }
    }

    public static void main(String[] args) {
        describe(Product.class);
    }
}
```

Every line came from a reflection call covered earlier: `getModifiers`, `getSuperclass`, `getInterfaces`, `getDeclaredFields`, `getDeclaredConstructors`, `getDeclaredMethods`, `getType`, `getParameterTypes`, `getReturnType`, and `getDeclaredAnnotations`. The describer is a small program built from the eight or nine accessors that make up the read-only reflection surface.

Two practical extensions: walk the superclass chain so that inherited fields and methods also show up, and filter by visibility to print "the public surface only." The inheritance walk:

```java
import java.lang.reflect.Field;

public class DescribeWithInheritance {

    public static void main(String[] args) {
        Class<?> cls = DigitalProduct.class;
        while (cls != null) {
            System.out.println("--- " + cls.getSimpleName() + " ---");
            for (Field f : cls.getDeclaredFields()) {
                System.out.println("  " + f.getName());
            }
            cls = cls.getSuperclass();
        }
    }
}
```

The loop stops because `Object.getSuperclass()` returns `null`. The `Object` class has zero declared fields, so the section under it is empty.

Every reflection lookup costs more than a direct call. `Class.getDeclaredMethod(name, types)` does a linear scan of the methods array, allocates a defensive copy, and may trigger access checks. In hot code, cache the `Method` once at startup and reuse it; do not look it up on every invocation.

The final piece is filtering. To inspect only the public surface of a class, ignoring private helpers, `Modifier.isPublic` makes this a one-liner.

```java
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;

public class PublicSurfaceOnly {

    public static void main(String[] args) {
        for (Method m : Product.class.getDeclaredMethods()) {
            if (Modifier.isPublic(m.getModifiers())) {
                System.out.println(m.getName());
            }
        }
    }
}
```

The same predicate pattern applies to constructors and fields. Predicates can also be combined: `Modifier.isStatic` and `Modifier.isFinal` together identify constants; `Modifier.isAbstract` on a class indicates that the class cannot be instantiated; `Modifier.isInterface` checks the interface bit on a class's modifiers.
