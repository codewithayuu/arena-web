Many systems work perfectly well in a single cloud region. But as they grow, some need to run across multiple regions to serve users closer to where they are, reduce latency, and keep the system available even if an entire region goes down.

This lesson covers why large systems run in multiple geographic regions, the main ways to set up a multi-region architecture, and how to handle the hardest part, which is keeping data correct across regions that are far apart.

It also covers how to approach multi-region design in a system design interview, since it often comes up when a problem involves global users or very high availability.
