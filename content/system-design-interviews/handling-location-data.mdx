Ride-hailing apps, food delivery platforms, and local search all need to answer the same basic question: which drivers, restaurants, or places are closest to a given location? At first, this sounds like a simple database query. But a regular database index is designed for one-dimensional values, not geographic distance, so it cannot answer nearby-location queries efficiently on its own.

This lesson covers how systems store and search location data, why a query like "find everything near me" is harder than it looks, and the main techniques used to answer it quickly, like geohashes and quadtrees.

It also covers how to approach location data in a system design interview, since several common interview problems are built around it.
