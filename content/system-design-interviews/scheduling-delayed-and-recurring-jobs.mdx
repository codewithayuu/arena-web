Many systems need to run work at a specific time in the future, such as sending a reminder or cancelling an unpaid order. Others need to run tasks repeatedly, such as generating a report every night or cleaning up expired data every hour.

This lesson covers how systems run jobs at a specific time in the future, or on a repeating schedule, how to do this reliably across many servers, and how to handle problems like duplicate runs, missed runs, and time zones.

It also covers how to approach job scheduling in a system design interview, since it's a common standalone problem and also shows up inside many other designs.
