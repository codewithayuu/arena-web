<h1 id="quiz-questions">Quiz Questions</h1>

**Question 1: Which principle aims to avoid the duplication of logic or knowledge across a system?**

- [x] DRY Principle
- [ ] Separation of Concerns
- [ ] KISS Principle
- [ ] Composing Objects

**Question 2: When should you build additional flexibility into your software design according to the YAGNI principle?**

- [x] Only when the need is clear and present
- [ ] As early as possible in the project
- [ ] In every component of the system
- [ ] Whenever you foresee future changes

**Question 3: A module that performs unrelated operations such as user authentication, data parsing, and logging suffers from what design issue?**

- [x] Low Cohesion
- [ ] High Coupling
- [ ] High Cohesion
- [ ] Low Coupling

**Question 4: What does the KISS principle primarily encourage in software design?**

- [x] Simplicity and avoiding unnecessary complexity
- [ ] Focusing on future features
- [ ] Duplicating useful code
- [ ] Maximizing performance at all costs

**Question 5: Which scenario best demonstrates a violation of the Law of Demeter?**

- [x] Accessing chained objects and their properties in a single statement
- [ ] Invoking a method on your own class
- [ ] Calling a method on a direct collaborator
- [ ] Using interfaces to abstract dependencies

**Question 6: Why is high coupling between modules a maintenance problem?**

- [x] A change to one module can require changes to others
- [ ] Modules become too specialized
- [ ] Testing becomes completely isolated
- [ ] Documentation automatically improves

**Question 7: According to Separation of Concerns, what should a data access layer NOT be responsible for?**

- [x] Rendering user interface elements
- [ ] Fetching records from a database
- [ ] Saving objects to storage
- [ ] Providing query methods

**Question 8: When refactoring code to follow the DRY principle, which approach is best?**

- [x] Extract the repeated logic into one authoritative module
- [ ] Copy working code to all relevant classes
- [ ] Write custom logic for each use case
- [ ] Document where the code exists in each location

**Question 9: Which is the most direct benefit of composing objects rather than inheriting from them?**

- [x] Flexibility to replace or extend behaviors at runtime
- [ ] Deeper inheritance hierarchy
- [ ] Tighter coupling of classes
- [ ] Ability to access protected methods

**Question 10: A module that sends notifications, processes payments, and calculates taxes best demonstrates what?**

- [x] Poor Separation of Concerns
- [ ] High Cohesion
- [ ] Appropriate Interface Segregation
- [ ] Effective Polymorphism

**Question 11: Choosing to use a highly generic, flexible architecture before understanding all project requirements most directly violates which principle?**

- [x] YAGNI Principle
- [ ] KISS Principle
- [ ] DRY Principle
- [ ] Law of Demeter

**Question 12: What is a key risk of violating the DRY principle across documentation, business rules, and tests?**

- [x] Increased risk of inconsistencies and defects
- [ ] Reduced system performance
- [ ] Limited code reuse
- [ ] Stronger encapsulation
