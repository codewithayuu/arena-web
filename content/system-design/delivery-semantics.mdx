This is the core problem behind **delivery semantics**.

<h1 id="1-the-three-guarantees">1. The Three Guarantees</h1>

There are three common delivery guarantees:

- **At-most-once:** A message is delivered once or not at all. It may be lost, but it is never duplicated.
- **At-least-once:** A message is never lost, but it may be delivered more than once.
- **Exactly-once:** Every message affects the system one time, with no loss and no duplicates.

| Guarantee         | Retry?                  | When the consumer acknowledges       | Main Risk       |
| ----------------- | ----------------------- | ------------------------------------ | --------------- |
| **At-most-once**  | No                      | Before processing                    | Message loss    |
| **At-least-once** | Yes, until acknowledged | After processing                     | Duplicates      |
| **Exactly-once**  | Yes                     | After processing, plus deduplication | More complexity |

Each guarantee comes from a specific choice about when to retry and when to acknowledge. Let's look at each one in detail.
