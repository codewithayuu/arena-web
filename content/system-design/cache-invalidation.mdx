Later, the product price changes to $90. The database now contains the new price, but the cache still contains $100.

If the application continues reading from the cache, users will see the wrong value.

This is the core cache invalidation problem. We now have multiple copies of the same data, and when the source changes, we need some way to make sure the cached copy does not remain stale forever.

There are three basic things you can do with a cached value once the source changes:

1. **Expire** it after a fixed time, using a TTL.
2. **Delete** it, so the next read reloads it.
3. **Update** it with the new value.

The challenge is deciding when and how that cached value should be removed or refreshed. Most production systems combine these, for example deleting on write and keeping a TTL as a safety net.
