<LessonCard>

Given a 2D matrix `matrix`, handle multiple queries of the following types:

- **Update** the value of a cell in `matrix`.
- Calculate the **sum** of the elements of `matrix` inside the rectangle defined by its upper left corner `(row1, col1)` and lower right corner `(row2, col2)`.

Implement the `NumMatrix` class:

- `NumMatrix(int[][] matrix)` Initializes the object with the integer matrix `matrix`.
- `void update(int row, int col, int val)` Updates the value of `matrix[row][col]` to be `val`.
- `int sumRegion(int row1, int col1, int row2, int col2)` Returns the sum of the elements of `matrix` inside the rectangle defined by its upper left corner `(row1, col1)` and lower right corner `(row2, col2)`.

**Example 1:**

**Input:** `operations = ["NumMatrix", "sumRegion", "update", "sumRegion"]`, `arguments = [[[[3,0,1,4,2],[5,6,3,2,1],[1,2,0,1,5],[4,1,0,1,7],[1,0,3,0,5]]],[2,1,4,3],[3,2,2],[2,1,4,3]]`

**Output:** `[null, 8, null, 10]`

- `NumMatrix numMatrix = new NumMatrix([[3,0,1,4,2],[5,6,3,2,1],[1,2,0,1,5],[4,1,0,1,7],[1,0,3,0,5]]);`
- `numMatrix.sumRegion(2, 1, 4, 3);` // return 8
- `numMatrix.update(3, 2, 2);` // matrix[3][2] changes from 0 to 2
- `numMatrix.sumRegion(2, 1, 4, 3);` // return 10

**Constraints:**

- `m == matrix.length`
- `n == matrix[i].length`
- `1 <= m, n <= 200`
- `-10^4 <= matrix[i][j] <= 10^4`
- `0 <= row1 <= row2 < m`
- `0 <= col1 <= col2 < n`
- At most `5000` calls will be made to `sumRegion` and `update`.
- `-10^5 <= val <= 10^5`

This is the mutable version of Range Sum Query 2D - Immutable (LeetCode 304). When the matrix never changes, a 2D prefix sum gives O(1) queries after O(m \* n) preprocessing.

Here the matrix can change. A call to `update(row, col, val)` makes the precomputed 2D prefix sum stale, because a single cell affects every prefix-sum entry below and to the right of it. Rebuilding the entire table after each update costs O(m _ n). With up to 5000 operations on a 200x200 matrix, that is up to 5000 _ 40000 = 200 million additions for updates alone.

The question is what data structure handles both a cell update and a rectangle-sum query efficiently, instead of recomputing everything from scratch on each operation or precomputing everything upfront and paying for every update.

- `1 <= m, n <= 200` -> The matrix is at most 200x200 = 40,000 cells. An O(m \* n) cost per operation is 40,000 work units, which over 5000 operations reaches 200 million. That rules out rebuilding a full prefix table on every update.
- At most `5000` calls to `update` and `sumRegion` -> The workload mixes updates and queries, so both operations have to be fast, not just one.
- `-10^5 <= val <= 10^5` -> Values can be negative, so no approach can assume positivity. The `sumRegion` return type is a 32-bit `int`, so the problem guarantees every region sum fits in 32 bits. A 32-bit accumulator is therefore safe.

<h1 id="approach-1-brute-force-recompute-on-query">
  Approach 1: Brute Force (Recompute on Query)
</h1>

<h3 id="intuition">Intuition</h3>

Store the matrix as-is, write updates directly into it, and answer each sum query by iterating over every cell in the rectangle and adding them.

There is no preprocessing. An update is a single array write, so it costs O(1). A query traverses the whole sub-rectangle every time, so its cost scales with the rectangle's area.

<h3 id="algorithm">Algorithm</h3>

1. Store the matrix directly.
2. On `update(row, col, val)`, set `matrix[row][col] = val`.
3. On `sumRegion(row1, col1, row2, col2)`, iterate through every row from `row1` to `row2` and every column from `col1` to `col2`, accumulating the sum.
4. Return the accumulated sum.

<h3 id="example-walkthrough">Example Walkthrough</h3>

**Input:**

For `sumRegion(2, 1, 4, 3)`, iterate over every cell in rows 2 through 4, columns 1 through 3, and sum them:

- Row 2, columns 1-3: `matrix[2][1..3]` = 2 + 0 + 1 = 3
- Row 3, columns 1-3: `matrix[3][1..3]` = 1 + 0 + 1 = 2
- Row 4, columns 1-3: `matrix[4][1..3]` = 0 + 3 + 0 = 3
- Total: 3 + 2 + 3 = 8

For `update(3, 2, 2)`, set `matrix[3][2] = 2`. The cell at row 3, column 2 changes from 0 to 2. Nothing else is touched.

For `sumRegion(2, 1, 4, 3)` again, the same scan now sees the updated cell in row 3:

- Row 2, columns 1-3: 2 + 0 + 1 = 3
- Row 3, columns 1-3: 1 + 2 + 1 = 4 (the middle cell is now 2)
- Row 4, columns 1-3: 0 + 3 + 0 = 3
- Total: 3 + 4 + 3 = 10

```java
class NumMatrix {
    private int[][] matrix;

    public NumMatrix(int[][] matrix) {
        this.matrix = matrix;
    }

    public void update(int row, int col, int val) {
        matrix[row][col] = val;
    }

    public int sumRegion(int row1, int col1, int row2, int col2) {
        int sum = 0;
        for (int r = row1; r <= row2; r++) {
            for (int c = col1; c <= col2; c++) {
                sum += matrix[r][c];
            }
        }
        return sum;
    }
}
```

> - **Time Complexity:** O(1) for `update`, O(m \* n) for `sumRegion`. An update is a single array write. A query scans up to the entire matrix in the worst case.
> - **Space Complexity:** O(1) extra space. The original matrix is stored with no auxiliary data structures.

Each `sumRegion` call recomputes the same sums from scratch over the whole rectangle. The next approach precomputes partial sums along one dimension so a query reads each row's contribution in constant time.

<h1 id="approach-2-row-prefix-sums">Approach 2: Row Prefix Sums</h1>

<h3 id="intuition">Intuition</h3>

Precompute a prefix sum for each row independently. A full 2D prefix sum is too expensive to maintain because one cell change invalidates the entire table. Per-row prefix sums localize the damage: a cell at `matrix[row][col]` affects only row `row`'s prefix sums, so an update rebuilds a single row in O(n).

A query iterates over each row in the range and reads that row's contribution in O(1) from its prefix sum, so the query costs O(m), the number of rows in the rectangle.

Define `rowPrefix[r][c]` as the sum of `matrix[r][0..c-1]`. The sum of columns `col1` through `col2` in row `r` is then `rowPrefix[r][col2 + 1] - rowPrefix[r][col1]`. Loop over rows `row1` to `row2` and accumulate these differences.

<h3 id="algorithm">Algorithm</h3>

1. Build a prefix sum array for each row: `rowPrefix[r][c] = matrix[r][0] + matrix[r][1] + ... + matrix[r][c-1]`.
2. On `update(row, col, val)`, update `matrix[row][col] = val`, then rebuild the prefix sum for row `row` in O(n).
3. On `sumRegion(row1, col1, row2, col2)`, for each row `r` from `row1` to `row2`, add `rowPrefix[r][col2 + 1] - rowPrefix[r][col1]` to the total.
4. Return the total.

```java
class NumMatrix {
    private int[][] matrix;
    private int[][] rowPrefix;

    public NumMatrix(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        this.matrix = matrix;
        rowPrefix = new int[m][n + 1];
        // Build prefix sum for each row
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                rowPrefix[r][c + 1] = rowPrefix[r][c] + matrix[r][c];
            }
        }
    }

    public void update(int row, int col, int val) {
        matrix[row][col] = val;
        // Rebuild prefix sum for the affected row
        int n = matrix[0].length;
        for (int c = 0; c < n; c++) {
            rowPrefix[row][c + 1] = rowPrefix[row][c] + matrix[row][c];
        }
    }

        int sum = 0;
        for (int r = row1; r <= row2; r++) {
            // Use prefix sum to get column range in O(1)
```

> - **Time Complexity:** O(n) for `update`, O(m) for `sumRegion`. Update rebuilds one row's prefix sum by scanning all n columns. Query sums across at most m rows, each contributing O(1) via the prefix sum.
> - **Space Complexity:** O(m \* n). The row prefix sum table has the same dimensions as the matrix plus one extra column per row.

The query still scales linearly with the number of rows in the rectangle, and the update scales linearly with the number of columns. A Binary Indexed Tree brings both point updates and prefix-sum queries down to logarithmic time, and it extends to two dimensions.

<h1 id="approach-3-2d-binary-indexed-tree-fenwick-tree">
  Approach 3: 2D Binary Indexed Tree (Fenwick Tree)
</h1>

<h3 id="intuition">Intuition</h3>

A Binary Indexed Tree (BIT), also called a Fenwick Tree, supports point updates and prefix sum queries in O(log n) each in one dimension, and the same structure extends to two dimensions.

Maintain a 2D array `tree` of size `(m+1) x (n+1)` where each position holds a partial sum over a range of cells. To update `matrix[row][col]`, compute the delta and propagate it through the tree using `i += i & (-i)` in both dimensions. To read a prefix sum, traverse in the reverse direction using `i -= i & (-i)`, accumulating values. The expression `i & (-i)` isolates the lowest set bit of `i`, which is the width of the range that index is responsible for.

To get the sum of an arbitrary rectangle, combine four prefix sum queries by inclusion-exclusion:

`sumRegion(r1, c1, r2, c2) = prefix(r2, c2) - prefix(r1-1, c2) - prefix(r2, c1-1) + prefix(r1-1, c1-1)`

Here `prefix(r, c)` is the sum of all cells from `(0,0)` to `(r,c)`. Subtracting the strip above the rectangle and the strip to its left removes the top-left corner block twice, so the final term adds it back once. When `r1` or `c1` is 0, the corresponding `prefix(-1, ...)` term is 0, which the BIT traversal produces because the loop index `i = row + 1` becomes 0 and the loop never runs.

> A BIT decomposes any prefix sum into a logarithmic number of partial sums by walking the binary representation of the index. Node `tree[i][j]` covers a range of cells whose width in each dimension is the lowest set bit of that index. Updating a cell touches only the O(log m _ log n) nodes whose ranges include it, and reading a prefix sum combines O(log m _ log n) partial sums.
>
> The 2D version nests two independent BITs: the outer loop walks the row index, and for each row position the inner loop walks the column index. Every cell `(r, c)` contributes to exactly the set of nodes reached by both walks, so each prefix-sum query sums each contributing cell exactly once.

<h3 id="algorithm">Algorithm</h3>

1. Create a 2D BIT array `tree` of size `(m+1) x (n+1)`, initialized to zero. Also keep a copy of the matrix for computing deltas on update.
2. Build the tree by calling the BIT update for each cell in the original matrix.
3. On `update(row, col, val)`, compute `delta = val - matrix[row][col]`, update `matrix[row][col] = val`, then propagate `delta` through the BIT.
4. On `sumRegion(row1, col1, row2, col2)`, compute four prefix sums and combine with inclusion-exclusion.

<h3 id="example-walkthrough">Example Walkthrough</h3>

Take the matrix `[[1,2,3],[4,5,6],[7,8,9]]` and the query `sumRegion(1, 1, 2, 2)`, which sums the bottom-right 2x2 block: 5 + 6 + 8 + 9 = 28. The four prefix sums are `prefix(2,2)` = 45 (the whole matrix), `prefix(0,2)` = 6 (top row), `prefix(2,0)` = 12 (left column), and `prefix(0,0)` = 1. Inclusion-exclusion gives 45 - 6 - 12 + 1 = 28.

After `update(1, 1, 10)`, the center cell changes from 5 to 10, a delta of +5. The BIT propagates that delta to the nodes covering `(1,1)`. Re-running the query, `prefix(2,2)` rises to 50 while the other three terms stay the same (they do not cover the changed cell), so the new sum is 50 - 6 - 12 + 1 = 33, exactly 5 more than before.

```java
class NumMatrix {
    private int[][] matrix;
    private int[][] tree;
    private int m, n;

    public NumMatrix(int[][] matrix) {
        m = matrix.length;
        n = matrix[0].length;
        this.matrix = new int[m][n];
        tree = new int[m + 1][n + 1];
        // Build BIT by updating each cell
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                update(r, c, matrix[r][c]);
            }
        }
    }

    public void update(int row, int col, int val) {
        int delta = val - matrix[row][col];
        matrix[row][col] = val;
        // Propagate delta through the 2D BIT
        for (int i = row + 1; i <= m; i += i & (-i)) {
            for (int j = col + 1; j <= n; j += j & (-j)) {
                tree[i][j] += delta;
            }
        }
    }

    private int prefixSum(int row, int col) {
        int sum = 0;
        // Traverse BIT in reverse to accumulate prefix sum
        for (int i = row + 1; i > 0; i -= i & (-i)) {
            for (int j = col + 1; j > 0; j -= j & (-j)) {
                sum += tree[i][j];
            }
        }
        return sum;
    }

    public int sumRegion(int row1, int col1, int row2, int col2) {
        // Inclusion-exclusion on four prefix sums
        return prefixSum(row2, col2)
             - prefixSum(row1 - 1, col2)
             - prefixSum(row2, col1 - 1)
             + prefixSum(row1 - 1, col1 - 1);
    }
}
```

```python
class NumMatrix:
    def __init__(self, matrix: list[list[int]]):
        self.m, self.n = len(matrix), len(matrix[0])
        self.matrix = [[0] * self.n for _ in range(self.m)]
        self.tree = [[0] * (self.n + 1) for _ in range(self.m + 1)]
        # Build BIT by updating each cell
        for r in range(self.m):
            for c in range(self.n):
                self.update(r, c, matrix[r][c])

    def update(self, row: int, col: int, val: int) -> None:
        delta = val - self.matrix[row][col]
        self.matrix[row][col] = val
        # Propagate delta through the 2D BIT
        i = row + 1
        while i <= self.m:
            j = col + 1
            while j <= self.n:
                self.tree[i][j] += delta
                j += j & (-j)
            i += i & (-i)

    def _prefix_sum(self, row: int, col: int) -> int:
        total = 0
        # Traverse BIT in reverse to accumulate prefix sum
        i = row + 1
        while i > 0:
            j = col + 1
            while j > 0:
                total += self.tree[i][j]
                j -= j & (-j)
            i -= i & (-i)
        return total

    def sumRegion(self, row1: int, col1: int, row2: int, col2: int) -> int:
        # Inclusion-exclusion on four prefix sums
        return (self._prefix_sum(row2, col2)
              - self._prefix_sum(row1 - 1, col2)
              - self._prefix_sum(row2, col1 - 1)
              + self._prefix_sum(row1 - 1, col1 - 1))
```

```rust
struct NumMatrix {
    matrix: Vec<Vec<i32>>,
    tree: Vec<Vec<i32>>,
    m: usize,
    n: usize,
}

impl NumMatrix {
    pub fn new(matrix: Vec<Vec<i32>>) -> Self {
        let m = matrix.len();
        let n = matrix[0].len();
        let mut nm = Self {
            matrix: vec![vec![0; n]; m],
            tree: vec![vec![0; n + 1]; m + 1],
            m,
            n,
        };
        // Build BIT by updating each cell
        for r in 0..m {
            for c in 0..n {
                nm.update(r as i32, c as i32, matrix[r][c]);
            }
        }
        nm
    }

    pub fn update(&mut self, row: i32, col: i32, val: i32) {
        let row = row as usize;
        let col = col as usize;
        let delta = val - self.matrix[row][col];
        self.matrix[row][col] = val;
        // Propagate delta through the 2D BIT
        let mut i = row + 1;
        while i <= self.m {
            let mut j = col + 1;
            while j <= self.n {
                self.tree[i][j] += delta;
                j += j & (!j + 1);
            }
            i += i & (!i + 1);
        }
    }

    fn prefix_sum(&self, row: i32, col: i32) -> i32 {
        if row < 0 || col < 0 {
            return 0;
        }
        let row = row as usize;
        let col = col as usize;
        let mut sum = 0;
        // Traverse BIT in reverse to accumulate prefix sum
        let mut i = row + 1;
        while i > 0 {
            let mut j = col + 1;
            while j > 0 {
                sum += self.tree[i][j];
                j -= j & (!j + 1);
            }
            i -= i & (!i + 1);
        }
        sum
    }

    pub fn sum_region(&self, row1: i32, col1: i32, row2: i32, col2: i32) -> i32 {
        // Inclusion-exclusion on four prefix sums
        self.prefix_sum(row2, col2)
            - self.prefix_sum(row1 - 1, col2)
            - self.prefix_sum(row2, col1 - 1)
            + self.prefix_sum(row1 - 1, col1 - 1)
    }
}
```

```typescript
  update(row: number, col: number, val: number): void {

        this.tree[i][j] += delta;

    for (let i = row + 1; i > 0; i -= i & -i) {
      for (let j = col + 1; j > 0; j -= j & -j) {
        sum += this.tree[i][j];
      }

    return sum;

    return (

```

> - **Time Complexity:** O(log m _ log n) for both _`update`_ and _`sumRegion`_. Construction is O(m _ n _ log m _ log n). Each update propagates through O(log m) row positions, and for each, O(log n) column positions. Each query calls prefixSum four times, each costing O(log m \* log n).
> - **Space Complexity:** O(m _ n). The BIT array has (m+1) _ (n+1) entries plus a copy of the original matrix.
