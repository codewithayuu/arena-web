<LessonCard>

Given an `m x n` integer matrix `grid`, return the maximum score of a path starting at `(0, 0)` and ending at `(m - 1, n - 1)` going through every cell at most once.

The score of a path is the minimum value in that path.

For example, the score of the path `8 -> 4 -> 5 -> 9` is `4`.

A path can move in 4 directions: up, down, left, and right.

**Example 1:**

- **Input:** `grid = [[5,4,5],[1,2,6],[7,4,6]]`

- **Output:** `4`

**Example 2:**

- **Input:** `grid = [[2,2,1,2,2,2],[1,2,2,2,1,2]]`

- **Output:** `2`

**Example 3:**

- **Input:** `grid = [[3,4,6,3,4],[0,2,1,1,7],[8,8,3,2,7],[3,2,4,9,8],[4,1,2,0,0],[4,6,5,4,3]]`

- **Output:** `3`

**Constraints:**

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 100`
- `0 <= grid[i][j] <= 10^9`

Fix a candidate answer X, meaning we claim there is a path on which every cell has value at least X. Verifying that claim is straightforward: delete every cell with value below X, then check whether (0,0) and (m-1,n-1) are still connected with a BFS or DFS.

We need to find a path from the top-left corner to the bottom-right corner of a grid. The path can move in all four directions (not just right and down), and can visit each cell at most once. The "score" of a path is the smallest cell value along that path, and we want to maximize this score.

One way to picture the structure: treat each cell value as the width of a corridor. The bottleneck on any route is its narrowest corridor, and the goal is the route whose narrowest corridor is as wide as possible. This is a maximin path problem.

The distinguishing feature is that we are not minimizing or maximizing a sum. We care about the minimum value along the path, and we want the path that makes that minimum as large as possible. That reframes the problem around thresholds rather than shortest paths: "Is there a path where every cell is at least X?"

- `1 <= m, n <= 100` → Up to 10,000 cells, so an O(m _ n _ log(m \* n)) solution is comfortably within limits.
- `0 <= grid[i][j] <= 10^9` → Values fit in a 32-bit signed integer (max ~2.1 \* 10^9), so `int` is safe everywhere and no overflow handling is needed. The large range only affects the binary search bounds.

Fix a candidate answer X, meaning we claim there is a path on which every cell has value at least X. Verifying that claim is straightforward: delete every cell with value below X, then check whether (0,0) and (m-1,n-1) are still connected with a BFS or DFS.

The problem then reduces to finding the largest X for which a path of cells with value >= X connects start to end. This is a binary search on the answer, with the search space being the range of cell values. The feasibility test is monotonic: if a path exists for threshold X, it also exists for every threshold Y < X, because lowering the threshold only adds cells and never removes one. That monotonicity is what lets binary search converge on the boundary.

<h3 id="algorithm">Algorithm</h3>

1. Find the minimum and maximum values in the grid. These define the binary search range. Note: the answer cannot exceed `min(grid[0][0], grid[m-1][n-1])` since the path must include both endpoints.
2. Binary search on the threshold value `mid`.
3. For each `mid`, run BFS from (0,0) using only cells with value >= `mid`.
4. If BFS reaches (m-1,n-1), then `mid` is feasible. Try a larger threshold (search right half).
5. If BFS does not reach (m-1,n-1), then `mid` is too large. Search left half.
6. Return the largest feasible threshold.

```java
class Solution {
    public int maximumMinimumPath(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int lo = 0, hi = Math.min(grid[0][0], grid[m - 1][n - 1]);
        int[] dx = {0, 0, 1, -1};
        int[] dy = {1, -1, 0, 0};

        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            // BFS to check if a path exists using only cells >= mid
            boolean[][] visited = new boolean[m][n];
            Queue<int[]> queue = new LinkedList<>();
            if (grid[0][0] >= mid) {
                queue.offer(new int[]{0, 0});
                visited[0][0] = true;
            }
            boolean found = false;
            while (!queue.isEmpty()) {
                int[] cell = queue.poll();
                if (cell[0] == m - 1 && cell[1] == n - 1) {
                    found = true;
                    break;
                }
                for (int d = 0; d < 4; d++) {
                    int nr = cell[0] + dx[d], nc = cell[1] + dy[d];
                    if (nr >= 0 && nr < m && nc >= 0 && nc < n
                            && !visited[nr][nc] && grid[nr][nc] >= mid) {
                        visited[nr][nc] = true;
                        queue.offer(new int[]{nr, nc});
                    }
                }
            }
            if (found) {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return hi;
    }
}
```

> - **Time Complexity:** O(m _ n _ log(V)). We binary search over the value range V (up to 10^9), so log(V) is at most 30 iterations. Each iteration does a BFS over the entire grid in O(m \* n).
> - **Space Complexity:** O(m _ n). The BFS visited array uses O(m _ n) space. The queue can hold at most O(m \* n) cells.

This runs a full BFS up to 30 times. The next approach finds the optimal path in a single traversal by processing cells in order of value.

<h1 id="approach-2-max-heap-bfs-modified-dijkstras">
  Approach 2: Max-Heap BFS (Modified Dijkstra's)
</h1>

<h3 id="intuition">Intuition</h3>

Grow the explored region outward from (0,0), and whenever there is a choice of which cell to expand into next, expand into the unvisited neighbor with the largest value. Reaching a high-valued cell cannot lower the path's minimum, while a low-valued cell might become the bottleneck, so postponing the low values keeps the running minimum as high as possible.

This is a modified Dijkstra's algorithm. Standard Dijkstra's uses a min-heap to always process the closest node next; here a max-heap always processes the highest-value cell next. Instead of tracking shortest distances, we track the maximum achievable minimum value on the path to each cell. The first time the destination (m-1,n-1) is popped, the running minimum on the path that reached it is the answer.

> When a cell is popped from the max-heap, every cell still in the heap or not yet discovered has value no greater than the popped cell, by the heap ordering. So the path that reached the popped cell used only cells with value >= that cell's value, and no alternative route to it could have a higher minimum. Applying this to the destination pop gives the maximum possible minimum, which mirrors why Dijkstra's min-heap pop yields a finalized shortest distance.

<h3 id="algorithm">Algorithm</h3>

1. Initialize a max-heap with the starting cell (0,0) and its value.
2. Create a visited array to track processed cells. Mark (0,0) as visited.
3. Initialize `score` to `grid[0][0]` (the running minimum along the current best path).
4. Pop the cell with the largest value from the heap.
5. Update `score = min(score, value of popped cell)`.
6. If the popped cell is (m-1,n-1), return `score`.
7. For each unvisited neighbor, add it to the heap and mark it as visited.
8. Repeat from step 4.

```java
class Solution {
    public int maximumMinimumPath(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int[] dx = {0, 0, 1, -1};
        int[] dy = {1, -1, 0, 0};

        // Max-heap ordered by cell value (descending)
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
        heap.offer(new int[]{grid[0][0], 0, 0});
        boolean[][] visited = new boolean[m][n];
        visited[0][0] = true;
        int score = grid[0][0];

        while (!heap.isEmpty()) {
            int[] cell = heap.poll();
            int val = cell[0], row = cell[1], col = cell[2];
            score = Math.min(score, val);

            // Reached the destination
            if (row == m - 1 && col == n - 1) return score;

            for (int d = 0; d < 4; d++) {
                int nr = row + dx[d], nc = col + dy[d];
                if (nr >= 0 && nr < m && nc >= 0 && nc < n && !visited[nr][nc]) {
                    visited[nr][nc] = true;
                    heap.offer(new int[]{grid[nr][nc], nr, nc});
                }
            }
        }
        return score;
    }
}
```

```go
    dx := []int{0, 0, 1, -1}

    h := &MaxHeap{{grid[0][0], 0, 0}}

type MaxHeap [][3]int
func (h MaxHeap) Len() int            { return len(h) }
func (h MaxHeap) Less(i, j int) bool  { return h[i][0] > h[j][0] }
func (h MaxHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *MaxHeap) Push(x interface{}) { *h = append(*h, x.([3]int)) }
func (h *MaxHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}
```

> - **Time Complexity:** O(m _ n _ log(m _ n)). Each cell is pushed and popped from the heap at most once. Each heap operation takes O(log(m _ n)).
> - **Space Complexity:** O(m _ n). The heap can hold at most O(m _ n) cells. The visited array is also O(m \* n).

The log factor here comes from the heap operations. The next approach replaces the heap with a one-time sort and a Union-Find structure that tracks connectivity as cells are added.

<h1 id="approach-3-sort-union-find-optimal">
  Approach 3: Sort + Union-Find (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

This approach builds the grid up instead of searching it. Add cells one at a time in decreasing order of value, starting with the highest. At some point an added cell connects (0,0) to (m-1,n-1) for the first time, and the value of that cell is the answer.

The reason that value is the answer: when cells are added in decreasing order, every cell added so far has value >= the current one. So the moment start and end become connected, the connecting path consists entirely of cells with value >= the current cell's value, and the current cell is the smallest among them. No path could have a higher minimum, since any earlier connection would have been detected at a higher value.

Union-Find (Disjoint Set Union) tracks the connectivity as cells are added. Each added cell is unioned with its already-added neighbors, and after each step we check whether (0,0) and (m-1,n-1) share a component. The first step where they do gives the answer.

<h3 id="algorithm">Algorithm</h3>

1. Collect all cells as (value, row, col) tuples and sort them in decreasing order of value.
2. Initialize a Union-Find structure with m \* n elements.
3. Create a boolean grid `added` to track which cells have been added so far.
4. Iterate through the sorted cells. For each cell:
5. Return 0 (fallback, should not be reached for valid inputs).

```java
class Solution {
    private int[] parent, rank;

    public int maximumMinimumPath(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int totalCells = m * n;
        parent = new int[totalCells];
        rank = new int[totalCells];
        for (int i = 0; i < totalCells; i++) parent[i] = i;

        // Collect and sort all cells by value in decreasing order
        int[][] cells = new int[totalCells][3];
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                int idx = i * n + j;
                cells[idx] = new int[]{grid[i][j], i, j};
            }
        }
        Arrays.sort(cells, (a, b) -> b[0] - a[0]);

        boolean[][] added = new boolean[m][n];
        int[] dx = {0, 0, 1, -1};
        int[] dy = {1, -1, 0, 0};

        for (int[] cell : cells) {
            int val = cell[0], row = cell[1], col = cell[2];
            added[row][col] = true;

            // Union with already-added neighbors
            for (int d = 0; d < 4; d++) {
                int nr = row + dx[d], nc = col + dy[d];
                if (nr >= 0 && nr < m && nc >= 0 && nc < n && added[nr][nc]) {
                    union(row * n + col, nr * n + nc);
                }
            }

            // Check if start and end are connected
            if (added[0][0] && added[m - 1][n - 1] && find(0) == find(totalCells - 1)) {
                return val;
            }
        }
        return 0;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private void union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return;
        if (rank[px] < rank[py]) { int tmp = px; px = py; py = tmp; }
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
    }
```

```rust
use std::cmp::Reverse;

pub struct Solution;

impl Solution {
    pub fn maximum_minimum_path(grid: Vec<Vec<i32>>) -> i32 {
        let m = grid.len();
        let n = grid[0].len();
        let total_cells = m * n;
        let mut parent: Vec<usize> = (0..total_cells).collect();
        let mut rank = vec![0usize; total_cells];

        fn find(parent: &mut [usize], x: usize) -> usize {
            if parent[x] != x {
                let root = find(parent, parent[x]);
                parent[x] = root;
            }
            parent[x]
        }

        fn union(parent: &mut [usize], rank: &mut [usize], x: usize, y: usize) {
            let mut px = find(parent, x);
            let mut py = find(parent, y);
            if px == py {
                return;
            }
            if rank[px] < rank[py] {
                std::mem::swap(&mut px, &mut py);
            }
            parent[py] = px;
            if rank[px] == rank[py] {
                rank[px] += 1;
            }
        }

        // Collect and sort all cells by value in decreasing order
        let mut cells: Vec<(i32, usize, usize)> = Vec::with_capacity(total_cells);
        for i in 0..m {
            for j in 0..n {
                cells.push((grid[i][j], i, j));
            }
        }
        cells.sort_by_key(|&(val, _, _)| Reverse(val));

        let mut added = vec![vec![false; n]; m];
        let dx = [0, 0, 1, -1];
        let dy = [1, -1, 0, 0];

        for (val, row, col) in cells {
            added[row][col] = true;

            // Union with already-added neighbors
            for d in 0..4 {
                let nr = row as i32 + dx[d];
                let nc = col as i32 + dy[d];
                if nr >= 0
                    && nr < m as i32
                    && nc >= 0
                    && nc < n as i32
                    && added[nr as usize][nc as usize]
                {
                    union(
                        &mut parent,
                        &mut rank,
                        row * n + col,
                        nr as usize * n + nc as usize,
                    );
                }
            }

            // Check if start and end are connected
            if added[0][0]
                && added[m - 1][n - 1]
                && find(&mut parent, 0) == find(&mut parent, total_cells - 1)
            {
                return val;
            }
        }
        0
    }
```
