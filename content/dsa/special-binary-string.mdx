<LessonCard>

Special binary strings are binary strings with the following two properties:

- The number of `0`s is equal to the number of `1`s.
- Every prefix of the binary string has at least as many `1`s as `0`s.

You are given a special binary string `s`.

A move consists of choosing two consecutive, non-empty, special substrings of `s`, and swapping them. Two strings are consecutive if the last character of the first string is exactly one index before the first character of the second string.

Return the lexicographically largest resulting string possible after applying the mentioned operations any number of times.

\***\*Example 1:\*\***

- **Input:** `s = 11011000`

- **Output:** `11100100`

_Explanation: The strings "10" and "1100" are swapped. This is the lexicographically largest string possible after some number of swaps._

\***\*Example 2:\*\***

- **Input:** `s = 10`

- **Output:** `10`

\***\*Constraints:\*\***

- `1 <= s.length <= 50`
- `s[i]` is either `'0'` or `'1'`.
- `s` is a special binary string.

A special binary string has two properties: equal counts of 1s and 0s, and every prefix has at least as many 1s as 0s. This maps directly onto balanced parentheses. Replace every `1` with `(` and every `0` with `)`, and a special binary string becomes a valid balanced parentheses string. The prefix constraint is what prevents an unmatched closing bracket from appearing before its opener.

So `"11011000"` maps to `"(()(()))"`. Like balanced parentheses, special binary strings have a recursive structure: the string decomposes into top-level groups, and the interior of each group is itself a special binary string. The problem asks us to rearrange these groups through adjacent swaps to produce the lexicographically largest result. Since `1 > 0`, we want the 1s as early as possible.

This leaves two questions: what is the optimal arrangement of the top-level groups, and how do we handle the nested structure inside each group?

- `1 <= s.length <= 50` → The string is small, so even an exponential arrangement search over the top-level groups runs in time. A polynomial solution leaves a wide margin.
- `s` is guaranteed to be a special binary string → The input needs no validation, and the recursive decomposition always produces valid sub-problems.

<h1 id="approach-1-brute-force-try-all-permutations">
  Approach 1: Brute Force (Try All Permutations)
</h1>

<h3 id="intuition">Intuition</h3>

Identify all the top-level special substrings and try every possible ordering. Swapping adjacent special substrings any number of times lets us produce any permutation of those substrings, since any permutation can be reached through a sequence of adjacent transpositions. So we generate all permutations, concatenate each one, and keep the lexicographically largest.

Each top-level special substring can contain nested special substrings inside it. A complete brute force has to recursively try rearranging the nested substrings at every level too. The number of arrangements grows factorially, but with n up to 50 the number of top-level substrings at any single level stays small enough to enumerate.

<h3 id="algorithm">Algorithm</h3>

1. Scan through the string, tracking a running balance (add 1 for each '1', subtract 1 for each '0'). Each time the balance returns to 0, mark the boundary of a top-level special substring.
2. For each top-level special substring, strip the outer '1' and '0', and recursively apply the same process to the interior.
3. At each recursion level, generate all permutations of the top-level pieces.
4. For each permutation, concatenate the pieces and track the lexicographically largest result.
5. Return the largest result found.

```java
class Solution {
    public String makeLargestSpecial(String s) {
        // Base case: empty or minimal string
        if (s.length() <= 2) return s;

        // Find top-level special substrings
        List<String> parts = new ArrayList<>();
        int balance = 0, start = 0;
        for (int i = 0; i < s.length(); i++) {
            balance += s.charAt(i) == '1' ? 1 : -1;
            if (balance == 0) {
                // Strip outer 1...0, recurse on interior, wrap back
                String interior = s.substring(start + 1, i);
                parts.add("1" + makeLargestSpecial(interior) + "0");
                start = i + 1;
            }
        }

        // Try all permutations and pick the largest
        List<String> permutations = new ArrayList<>();
        permute(parts, 0, permutations);

        String best = "";
        for (String p : permutations) {
            if (p.compareTo(best) > 0) best = p;
        }
        return best;
    }

    private void permute(List<String> parts, int idx, List<String> results) {
        if (idx == parts.size()) {
            StringBuilder sb = new StringBuilder();
            for (String p : parts) sb.append(p);
            results.add(sb.toString());
            return;
        }
        for (int i = idx; i < parts.size(); i++) {
            Collections.swap(parts, i, idx);
            permute(parts, idx + 1, results);
            Collections.swap(parts, i, idx);
        }
    }
}
```

```rust
pub struct Solution;

impl Solution {
    pub fn make_largest_special(s: String) -> String {
        // Base case: empty or minimal string
        if s.len() <= 2 {
            return s;
        }

        // Find top-level special substrings
        let bytes = s.as_bytes();
        let mut parts: Vec<String> = Vec::new();
        let mut balance = 0;
        let mut start = 0usize;

        for i in 0..bytes.len() {
            balance += if bytes[i] == b'1' { 1 } else { -1 };
            if balance == 0 {
                // Strip outer 1...0, recurse on interior, wrap back
                let interior = s[start + 1..i].to_string();
                parts.push(format!("1{}0", Solution::make_largest_special(interior)));
                start = i + 1;
            }
        }

        // Try all permutations and pick the largest
        let mut best = String::new();
        let mut permutations: Vec<Vec<String>> = Vec::new();
        Self::permute(&mut parts, 0, &mut permutations);

        for p in permutations {
            let candidate = p.concat();
            if candidate > best {
                best = candidate;
            }
        }
        best
    }

    fn permute(parts: &mut Vec<String>, idx: usize, results: &mut Vec<Vec<String>>) {
        if idx == parts.len() {
            results.push(parts.clone());
            return;
        }
        for i in idx..parts.len() {
            parts.swap(i, idx);
            Self::permute(parts, idx + 1, results);
            parts.swap(i, idx);
        }
    }
}
```

> - **Time Complexity:** O(n \* k!), where k is the number of top-level groups at a level. We generate all k! permutations, and concatenating each one touches strings of total length up to n. With n at most 50, k stays small in practice.
> - **Space Complexity:** O(n \* k!). We materialize all k! permutation strings of total length n. The recursion can nest up to n/2 levels deep, adding O(n) stack space.

Generating every permutation is wasteful when we only need the largest one. The next approach replaces the permutation search with a single sort.

<h1 id="approach-2-recursive-decomposition-with-sorting-optimal">
  Approach 2: Recursive Decomposition with Sorting (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

A special binary string decomposes into top-level groups, the same way balanced parentheses do. Each top-level group starts with a `1`, ends with a `0`, and everything in between is itself a special binary string.

For `"11011000"`, scanning and tracking the balance (increment for `1`, decrement for `0`) brings the balance back to 0 only at the last character, so the entire string is one top-level group. Strip the outer `1` and `0` and the interior is `"101100"`, which decomposes into two top-level groups: `"10"` and `"1100"`.

Because adjacent special substrings can be swapped any number of times, the top-level groups can be reordered into any arrangement. Sorting them in descending order produces the largest concatenation. Before sorting, we recursively optimize the interior of each group, so the comparison ranks groups that are already in their best internal form.

The ordering matters: a group's interior must be optimized first, because rearranging the outer groups cannot fix a sub-optimal interior. The outer `1` and `0` of a group never move relative to each other, so each group's internal layout is fixed by its own recursion, and only the sequence of whole groups is free to change.

> One detail needs justification: why does sorting the groups in descending order maximize the concatenation? Every top-level group has equal numbers of 1s and 0s and starts with a 1, so no group is a prefix of another. When neither of two strings is a prefix of the other, their first differing character decides both the lexicographic comparison of the strings themselves and the comparison of the two concatenation orders. So putting the lexicographically larger group first is always at least as good, and a comparison sort that places each pair in that order yields the global maximum.
>
> The swap operation is what makes any ordering reachable: adjacent transpositions can compose into any permutation of the groups, so no arrangement is off-limits.

<h3 id="algorithm">Algorithm</h3>

1. If the string is empty or has length 2, return it as-is (base case).
2. Initialize a balance counter to 0 and a start pointer to 0.
3. Scan through the string character by character. Add 1 to balance for each '1', subtract 1 for each '0'.
4. Each time balance returns to 0, extract the top-level special substring from start to the current position.
5. Strip the outer '1' and '0', recursively call the function on the interior.
6. Store the result as "1" + recursive result + "0".
7. After scanning the entire string, sort all collected pieces in descending lexicographic order.
8. Concatenate and return.
