<LessonCard>

A **path** in a binary tree is a sequence of nodes where each pair of adjacent nodes in the sequence has an edge connecting them. A node can only appear in the sequence **at most once**. Note that the path does not need to pass through the root.

The **path sum** of a path is the sum of the node's values in the path.

Given the `root` of a binary tree, return the maximum **path sum** of any **non-empty** path.

**Example 1:**

- **Input:** `root = [1,2,3]`

- **Output:** `6`

**Explanation:** The optimal path is 2 -> 1 -> 3 with a path sum of 2 + 1 + 3 = 6.

**Example 2:**

- **Input:** `root = [-10,9,20,null,null,15,7]`

- **Output:** `42`

**Explanation:** The optimal path is 15 -> 20 -> 7 with a path sum of 15 + 20 + 7 = 42.

**Constraints:**

- `The number of nodes in the tree is in the range [1, 3 * 10^4].`
- `-1000 <= Node.val <= 1000`

Treat every pair of nodes as the endpoints of a path, compute the sum of the path between them, and track the maximum. In a tree, there is exactly one path between any two nodes, so finding it is well-defined.

We need to find a path in a binary tree that gives the maximum sum. The path can start and end at any node, it does not have to go through the root, and it does not have to go from a leaf to another leaf. The only rule is that the path must follow parent-child edges and cannot visit a node more than once.

A valid path has a specific shape. In a tree, any path looks like an inverted "V" (or a straight line, which is a degenerate case). It goes up from some node to an ancestor, then possibly back down through the other child. So at any node, the path either passes through it as a "bend point" (using both left and right subtrees), or it continues upward through one side only.

Each node therefore involves two separate computations. First, what is the best path that bends at this node (left + node + right)? That is a candidate for the global answer. Second, what is the best path we can report upward to the parent? That can only include one side, because a path cannot fork.

- `1 <= number of nodes <= 3 * 10^4` - An O(n^2) algorithm performs around 9 \* 10^8 pair computations, too slow for typical limits. We need O(n) or O(n log n).
- `-1000 <= Node.val <= 1000` - Node values can be negative, so including a subtree can reduce the sum. The solution must handle the case where the best choice is to skip a subtree entirely.

Treat every pair of nodes as the endpoints of a path, compute the sum of the path between them, and track the maximum. In a tree, there is exactly one path between any two nodes, so finding it is well-defined.

For each pair of nodes (u, v), the path goes from u up to their lowest common ancestor (LCA), then down to v. We can find the LCA and compute the path sum for each pair.

A path can also be a single node, so every individual node counts as a candidate too.

<h3 id="algorithm">Algorithm</h3>

1. Collect all nodes in the tree.
2. For every pair of nodes (u, v), find their lowest common ancestor.
3. Compute the path sum from u to LCA to v.
4. Track the maximum path sum across all pairs.
5. Return the maximum.

```java
class Solution {
    int maxSum;

    public int maxPathSum(TreeNode root) {
        List<TreeNode> nodes = new ArrayList<>();
        collectNodes(root, nodes);
        maxSum = Integer.MIN_VALUE;

        // Consider every node as a potential single-node path
        for (TreeNode node : nodes) {
            maxSum = Math.max(maxSum, node.val);
        }

        // Consider every pair of nodes
        for (int i = 0; i < nodes.size(); i++) {
            for (int j = i + 1; j < nodes.size(); j++) {
                int pathSum = getPathSum(root, nodes.get(i), nodes.get(j));
                maxSum = Math.max(maxSum, pathSum);
            }
        }
        return maxSum;
    }

    private void collectNodes(TreeNode node, List<TreeNode> list) {
        if (node == null) return;
        list.add(node);
        collectNodes(node.left, list);
        collectNodes(node.right, list);
    }

    private int getPathSum(TreeNode root, TreeNode p, TreeNode q) {
        TreeNode lca = findLCA(root, p, q);
        return pathToAncestor(lca, p, 0) + pathToAncestor(lca, q, 0) - lca.val;
    }

    private TreeNode findLCA(TreeNode root, TreeNode p, TreeNode q) {
        if (root == null || root == p || root == q) return root;
        TreeNode left = findLCA(root.left, p, q);
        TreeNode right = findLCA(root.right, p, q);
        if (left != null && right != null) return root;
        return left != null ? left : right;
    }

    // Returns sum from ancestor down to target, or Integer.MIN_VALUE if not found
    private int pathToAncestor(TreeNode node, TreeNode target, int currentSum) {
        if (node == null) return Integer.MIN_VALUE;
        currentSum += node.val;
        if (node == target) return currentSum;
        int left = pathToAncestor(node.left, target, currentSum);
        if (left != Integer.MIN_VALUE) return left;
        return pathToAncestor(node.right, target, currentSum);
    }
}
```

```rust
use std::cmp::max;

pub struct Solution;

impl Solution {
    pub fn max_path_sum(root: Option<Box<TreeNode>>) -> i32 {
        let root_ref = root.as_deref();
        let mut nodes: Vec<&TreeNode> = Vec::new();
        Self::collect_nodes(root_ref, &mut nodes);
        let mut max_sum = i32::MIN;

        // Consider every node as a single-node path
        for node in &nodes {
            max_sum = max(max_sum, node.val);
        }

        // Consider every pair of nodes
        for i in 0..nodes.len() {
            for j in i + 1..nodes.len() {
                let path_sum = Self::get_path_sum(root_ref, nodes[i], nodes[j]);
                max_sum = max(max_sum, path_sum);
            }
        }
        max_sum
    }

    fn collect_nodes<'a>(node: Option<&'a TreeNode>, list: &mut Vec<&'a TreeNode>) {
        if let Some(n) = node {
            list.push(n);
            Self::collect_nodes(n.left.as_deref(), list);
            Self::collect_nodes(n.right.as_deref(), list);
        }
    }

    fn get_path_sum(root: Option<&TreeNode>, p: &TreeNode, q: &TreeNode) -> i32 {
        let lca = Self::find_lca(root, p, q).unwrap();
        Self::path_to_ancestor(Some(lca), p, 0) + Self::path_to_ancestor(Some(lca), q, 0) - lca.val
    }

    fn find_lca<'a>(root: Option<&'a TreeNode>, p: &TreeNode, q: &TreeNode) -> Option<&'a TreeNode> {
        if let Some(node) = root {
            if std::ptr::eq(node, p) || std::ptr::eq(node, q) {
                return Some(node);
            }
            let left = Self::find_lca(node.left.as_deref(), p, q);
            let right = Self::find_lca(node.right.as_deref(), p, q);
            if left.is_some() && right.is_some() {
                return Some(node);
            }
            return if left.is_some() { left } else { right };
        }
        None
    }

    // Returns sum from ancestor down to target, or i32::MIN if not found
    fn path_to_ancestor(node: Option<&TreeNode>, target: &TreeNode, current_sum: i32) -> i32 {
        if let Some(n) = node {
            let current_sum = current_sum + n.val;
            if std::ptr::eq(n, target) {
                return current_sum;
            }
            let left = Self::path_to_ancestor(n.left.as_deref(), target, current_sum);
            if left != i32::MIN {
                return left;
            }
            return Self::path_to_ancestor(n.right.as_deref(), target, current_sum);
        }
        i32::MIN
    }
}
```

> - **Time Complexity:** O(n^3). We have O(n^2) pairs of nodes, and for each pair, finding the LCA and computing the path sum each take O(n). So the total is O(n^2) \* O(n) = O(n^3).
> - **Space Complexity:** O(n). We store all n nodes in a list, and the recursion stack can go up to O(n) deep for a skewed tree.

At O(n^3), this cannot handle 3 \* 10^4 nodes. The optimal solution drops the endpoint-pair view entirely: it treats each node as a potential bend point of the path and computes everything in a single DFS.

<h1 id="approach-2-dfs-with-global-maximum-optimal">
  Approach 2: DFS with Global Maximum (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

Instead of working with path endpoints, work with the "top" of the path, the node where the path bends. Every path in a tree has exactly one highest node. At that node, the path either goes down into the left subtree, the right subtree, or both.

At each node, compute the best path that has this node as its highest point: best gain from the left child + node's value + best gain from the right child. Compare that "fork" sum against the global maximum. Because every path has exactly one highest node, checking the fork sum at every node considers every path exactly once, at the node where it reaches its highest point.

When reporting a value upward to the parent, we can only go in one direction. A path cannot fork, so we report: node's value + max(left gain, right gain). The parent can then extend this single-branch path further.

One post-order DFS computes both quantities. At each node, we compute the "gain" (the maximum sum achievable going downward from this node along a single branch), update the global answer with the fork sum, and return the single-branch gain to the parent.

One more detail: if a subtree's gain is negative, we clamp it to zero. Extending a path into a subtree that reduces the total sum never helps, so we skip it.

<h3 id="algorithm">Algorithm</h3>

1. Initialize a global variable `maxSum` to negative infinity.
2. Define a recursive function `maxGain(node)` that returns the maximum gain achievable by going downward from `node` along a single branch.
3. For a null node, return 0 (no gain).
4. Recursively compute `leftGain = max(maxGain(node.left), 0)` and `rightGain = max(maxGain(node.right), 0)`. Clamping to 0 means we skip negative subtrees.
5. Compute the "fork path" sum: `node.val + leftGain + rightGain`. Update `maxSum` if this is larger.
6. Return `node.val + max(leftGain, rightGain)` to the parent, since we can only extend the path in one direction.
7. After the DFS completes, return `maxSum`.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n). We visit each node exactly once during the DFS. At each node, we do O(1) work (comparisons and additions). So the total is O(n).
> - **Space Complexity:** O(h) where h is the height of the tree. The recursion stack holds at most h frames. For a balanced tree, h = O(log n). For a skewed tree, h = O(n) in the worst case.

The DFS in Approach 2 recurses once per level of the tree, so its stack depth equals the tree height. The constraints allow a skewed tree with 3 \* 10^4 nodes, which overflows Python's default recursion limit of 1000 frames and can exhaust thread stacks in other runtimes. An explicit stack removes that risk.

<h1 id="approach-3-iterative-post-order-explicit-stack">
  Approach 3: Iterative Post-Order (Explicit Stack)
</h1>

<h3 id="intuition">Intuition</h3>

The algorithm is unchanged from Approach 2: every node needs the single-branch gains of its children before it can compute its own fork sum and gain. The recursion produced that children-before-parents ordering implicitly. We can produce the same ordering explicitly in two passes.

Pass 1 builds a list of nodes in which every parent appears before its children. Pop nodes from a stack one at a time, append each popped node to the list, and push its children. A node's children enter the stack only after the node itself has been appended, so they always appear later in the list.

Pass 2 walks that list in reverse, which yields a children-before-parents order. Each node's gain goes into a hash map keyed by node, the fork sum is computed exactly as before, and the global maximum is tracked across all nodes.

This gain-and-fork structure is the general tree DP shape: compute a value per node from its children's values, combine the children's values at each node into a candidate for the global answer, and pass only the restricted single-branch value upward. The same structure solves Diameter of Binary Tree, Longest ZigZag Path in a Binary Tree, and Longest Univalue Path.

<h3 id="algorithm">Algorithm</h3>

1. Push the root onto a stack and create an empty list `order`.
2. While the stack is not empty: pop a node, append it to `order`, and push its non-null children. After the loop, every parent in `order` precedes its children.
3. Create an empty map `gain` and initialize `maxSum` to negative infinity.
4. Iterate `order` from the last element to the first. For each node, look up `leftGain` and `rightGain` in the map (0 for a missing child), clamping each to at least 0.
5. Update `maxSum` with the fork sum `node.val + leftGain + rightGain`.
6. Store `gain[node] = node.val + max(leftGain, rightGain)`.
7. After the loop, return `maxSum`.

```java
class Solution {
    public int maxPathSum(TreeNode root) {
        // Pass 1: collect nodes so that every parent precedes its children
        Deque<TreeNode> stack = new ArrayDeque<>();
        List<TreeNode> order = new ArrayList<>();
        stack.push(root);
        while (!stack.isEmpty()) {
            TreeNode node = stack.pop();
            order.add(node);
            if (node.left != null) stack.push(node.left);
            if (node.right != null) stack.push(node.right);
        }

        // Pass 2: process children before parents
        Map<TreeNode, Integer> gain = new HashMap<>();
        int maxSum = Integer.MIN_VALUE;
        for (int i = order.size() - 1; i >= 0; i--) {
            TreeNode node = order.get(i);
            int leftGain = Math.max(gain.getOrDefault(node.left, 0), 0);
            int rightGain = Math.max(gain.getOrDefault(node.right, 0), 0);
            maxSum = Math.max(maxSum, node.val + leftGain + rightGain);
            gain.put(node, node.val + Math.max(leftGain, rightGain));
        }
        return maxSum;
    }
}
```

```rust
impl Solution {
    pub fn max_path_sum(root: Option<Box<TreeNode>>) -> i32 {
        // Pass 1: collect nodes so that every parent precedes its children
        let mut order: Vec<&TreeNode> = Vec::new();
        let mut stack: Vec<&TreeNode> = Vec::new();
        if let Some(node) = root.as_deref() {
            stack.push(node);
        }
        while let Some(node) = stack.pop() {
            order.push(node);
            if let Some(left) = node.left.as_deref() {
                stack.push(left);
            }
            if let Some(right) = node.right.as_deref() {
                stack.push(right);
            }
        }

        // Pass 2: process children before parents, keyed by node address
        let mut gain: HashMap<*const TreeNode, i32> = HashMap::new();
        let mut max_sum = i32::MIN;
        for &node in order.iter().rev() {
            let left_gain = node
                .left
                .as_deref()
                .map_or(0, |child| max(gain[&(child as *const TreeNode)], 0));
            let right_gain = node
                .right
                .as_deref()

            max_sum = max(max_sum, node.val + left_gain + right_gain);
            gain.insert(node as *const TreeNode, node.val + max(left_gain, right_gain));
        }
        max_sum
    }
```


> - **Time Complexity:** O(n). Pass 1 pushes and pops each node once. Pass 2 processes each node once with O(1) average-cost map operations.
> - **Space Complexity:** O(n). The order list and the gain map each hold all n nodes, and the explicit stack can hold up to O(n) nodes. Approach 2 uses only O(h) space, so this version trades memory for immunity to call-stack limits.
