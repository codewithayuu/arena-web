<LessonCard>

You are given two **0-indexed** integer arrays `nums1` and `nums2`, each of size `n`, and an integer `diff`. Find the number of **pairs** `(i, j)` such that:

- `0 <= i < j <= n - 1`, and
- `nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff`

Return the **number of pairs** that satisfy the conditions.

**Example 1:**

**Input:** `nums1 = [3,2,5]`, `nums2 = [2,2,1]`, `diff = 1`

**Output:** `3`

**Explanation:** There are 3 pairs that satisfy the conditions: (0, 1) since `3 - 2 <= 2 - 2 + 1`, (0, 2) since `3 - 5 <= 2 - 1 + 1`, and (1, 2) since `2 - 5 <= 2 - 1 + 1`.

**Example 2:**

**Input:** `nums1 = [3,-1]`, `nums2 = [-2,2]`, `diff = -1`

**Output:** `0`

**Explanation:** Since there are no pairs that satisfy the conditions, we return 0.

**Constraints:**

- `n == nums1.length == nums2.length`
- `2 <= n <= 10^5`
- `-10^4 <= nums1[i], nums2[i] <= 10^4`
- `-10^4 <= diff <= 10^4`

The inequality `nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff` has four array accesses and a constant, but it simplifies once we group the terms by index.

Rearranging the inequality:

`nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff`

`nums1[i] - nums2[i] <= nums1[j] - nums2[j] + diff`

If we define a new array `arr` where `arr[k] = nums1[k] - nums2[k]`, the inequality becomes:

`arr[i] <= arr[j] + diff`

Or equivalently: `arr[i] - arr[j] <= diff`

So the problem reduces to: given an array `arr`, count all pairs `(i, j)` with `i < j` such that `arr[i] - arr[j] <= diff`. This is a variant of counting inversions. The `i < j` index constraint combined with a value comparison is what merge sort-based counting and order-statistic structures like a Binary Indexed Tree are built to handle efficiently.

<h3 id="key-constraints">Key Constraints:</h3>

- `2 <= n <= 10^5`. With n up to 100,000, an O(n^2) brute force performs about 5 billion comparisons, too slow for typical limits. We need O(n log n) or better.
- `-10^4 <= nums1[i], nums2[i] <= 10^4`. The difference `arr[k] = nums1[k] - nums2[k]` ranges from -20,000 to 20,000. This bounded range lets a BIT index directly into a fixed-size array without coordinate compression.
- The answer can reach `n*(n-1)/2`, roughly 5 billion when n = 100,000. That overflows a 32-bit signed integer, so the count must use a 64-bit type.

<h1 id="approach-1-brute-force">Approach 1: Brute Force</h1>

<h3 id="intuition">Intuition</h3>

Build the array `arr` where `arr[k] = nums1[k] - nums2[k]`, then check every pair `(i, j)` with `i < j` against the simplified condition `arr[i] - arr[j] <= diff`. Two nested loops cover all pairs. This is the baseline before optimizing.

<h3 id="algorithm">Algorithm</h3>

1. Build the array `arr` where `arr[k] = nums1[k] - nums2[k]` for each index `k`.
2. Initialize a counter `count = 0`.
3. For each `i` from `0` to `n - 2`, for each `j` from `i + 1` to `n - 1`, check if `arr[i] - arr[j] <= diff`.
4. If the condition holds, increment `count`.
5. Return `count`.

<h3 id="example-walkthrough">Example Walkthrough</h3>

**Input:** `nums1 = [3, 2, 5], nums2 = [2, 2, 1], diff = 1`

First, build `arr = [1, 0, 4]`.

- Pair (0, 1): `arr[0] - arr[1] = 1 - 0 = 1 <= 1`. Valid.
- Pair (0, 2): `arr[0] - arr[2] = 1 - 4 = -3 <= 1`. Valid.
- Pair (1, 2): `arr[1] - arr[2] = 0 - 4 = -4 <= 1`. Valid.

Result: 3 pairs.

> - **Time Complexity:** O(n^2). We check all pairs (i, j) with i < j. There are n\*(n-1)/2 such pairs, and each check is O(1).
> - **Space Complexity:** O(n). We build the arr array of size n.

The quadratic scan is wasteful: for a fixed `j`, it recompares against every earlier element one at a time. Sorting the values lets us count matching elements in bulk, and merge sort can do this sorting while still respecting the `i < j` ordering.

<h1 id="approach-2-merge-sort">Approach 2: Merge Sort</h1>

<h3 id="intuition">Intuition</h3>

Merge sort splits the array into a left half (smaller indices) and a right half (larger indices), sorts each, then merges them. The counting happens just before each merge. At that point every element in the left half had a smaller original index than every element in the right half, so the cross-boundary pairs are precisely the `i < j` pairs where `i` is in the left half and `j` is in the right half. Pairs that lie entirely inside one half are counted by the recursive calls on that half.

Both halves are sorted just before the merge. So for each element `arr[j]` in the right half, we count how many elements `arr[i]` in the left half satisfy `arr[i] <= arr[j] + diff`. Because the left half is sorted ascending, those matching elements form a prefix, and a single forward-moving pointer finds the prefix length.

The right half is also sorted ascending, so as `j` advances, `arr[j]` and the threshold `arr[j] + diff` only increase. The pointer therefore never moves backward: it advances across all of the right half once per merge, making the counting step O(n) per merge level and O(n log n) overall.

<h3 id="algorithm">Algorithm</h3>

1. Build the array `arr` where `arr[k] = nums1[k] - nums2[k]`.
2. Run a modified merge sort on `arr`.
3. In each merge step, before the standard merge, count valid pairs:
4. After counting, perform the standard merge to sort the subarray.
5. Return the total count.

```java
class Solution {
    private long count = 0;
    private int diff;

    public long numberOfPairs(int[] nums1, int[] nums2, int diff) {
        int n = nums1.length;
        this.diff = diff;
        int[] arr = new int[n];

        for (int i = 0; i < n; i++) {
            arr[i] = nums1[i] - nums2[i];
        }

        mergeSort(arr, 0, n - 1);
        return count;
    }

    private void mergeSort(int[] arr, int left, int right) {
        if (left >= right) return;

        int mid = left + (right - left) / 2;
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);

        // Count valid pairs: left half has smaller indices, right half has larger
        int p = left;
        for (int j = mid + 1; j <= right; j++) {
            // Count elements in left half where arr[i] <= arr[j] + diff
            while (p <= mid && arr[p] <= arr[j] + diff) {
                p++;
            }
            count += (p - left);
        }

        // Standard merge step
        int[] temp = new int[right - left + 1];
        int i = left, j = mid + 1, k = 0;
        while (i <= mid && j <= right) {
            if (arr[i] <= arr[j]) {
                temp[k++] = arr[i++];
            } else {
                temp[k++] = arr[j++];
            }
        }
        while (i <= mid) temp[k++] = arr[i++];
        while (j <= right) temp[k++] = arr[j++];

        for (int idx = 0; idx < temp.length; idx++) {
            arr[left + idx] = temp[idx];
        }
    }
}
```

```python
class Solution:
    def numberOfPairs(self, nums1: list[int], nums2: list[int], diff: int) -> int:
        n = len(nums1)
        arr = [nums1[i] - nums2[i] for i in range(n)]
        self.count = 0

        def merge_sort(left, right):
            if left >= right:
                return

            mid = left + (right - left) // 2
            merge_sort(left, mid)
            merge_sort(mid + 1, right)

            # Count valid pairs across the two halves
            p = left
            for j in range(mid + 1, right + 1):
                while p <= mid and arr[p] <= arr[j] + diff:
                    p += 1
                self.count += (p - left)

            # Standard merge step
            temp = []
            i, j = left, mid + 1
            while i <= mid and j <= right:
                if arr[i] <= arr[j]:
                    temp.append(arr[i])
                    i += 1
                else:
                    temp.append(arr[j])
                    j += 1
            while i <= mid:
                temp.append(arr[i])
                i += 1
            while j <= right:
                temp.append(arr[j])
                j += 1

            for idx in range(len(temp)):
                arr[left + idx] = temp[idx]

        merge_sort(0, n - 1)
        return self.count
```

```rust
pub struct Solution;

impl Solution {
    pub fn number_of_pairs(nums1: Vec<i32>, nums2: Vec<i32>, diff: i32) -> i64 {
        let n = nums1.len();
        let mut arr = vec![0i32; n];
        for i in 0..n {
            arr[i] = nums1[i] - nums2[i];
        }

        let mut count: i64 = 0;
        Self::merge_sort(&mut arr, 0, n as i32 - 1, diff, &mut count);
        count
    }

    fn merge_sort(arr: &mut Vec<i32>, left: i32, right: i32, diff: i32, count: &mut i64) {
        if left >= right {
            return;
        }

        let mid = left + (right - left) / 2;
        Self::merge_sort(arr, left, mid, diff, count);
        Self::merge_sort(arr, mid + 1, right, diff, count);

        // Count valid pairs across the two halves
        let mut p = left as usize;
        let left_u = left as usize;
        let mid_u = mid as usize;
        let right_u = right as usize;
        for j in (mid_u + 1)..=right_u {
            while p <= mid_u && (arr[p] as i64) <= (arr[j] as i64 + diff as i64) {
                p += 1;
            }
            *count += (p - left_u) as i64;
        }

        // Standard merge step
        let mut temp = vec![0i32; right_u - left_u + 1];
        let mut i = left_u;
        let mut j = mid_u + 1;
        let mut k = 0usize;
        while i <= mid_u && j <= right_u {
            if arr[i] <= arr[j] {
                temp[k] = arr[i];
                i += 1;
            } else {
                temp[k] = arr[j];
                j += 1;
            }
            k += 1;
        }
        while i <= mid_u {
            temp[k] = arr[i];
            i += 1;
            k += 1;
        }
        while j <= right_u {
            temp[k] = arr[j];
            j += 1;
            k += 1;
        }

        for idx in 0..temp.len() {
            arr[left_u + idx] = temp[idx];
        }
    }
}
```

> - **Time Complexity:** O(n log n). Merge sort has O(log n) levels. At each level, the counting step and the merge step each take O(n) time.
> - **Space Complexity:** O(n). The temporary array used during the merge step requires O(n) space. The recursion stack uses O(log n) space.

Merge sort reaches O(n log n) but needs a custom recursive merge. The next approach reaches the same bound with a single left-to-right pass, delegating the counting to a Binary Indexed Tree.

<h1 id="approach-3-binary-indexed-tree-bit">
  Approach 3: Binary Indexed Tree (BIT)
</h1>

<h3 id="intuition">Intuition</h3>

Instead of using merge sort's divide-and-conquer structure to enforce the `i < j` ordering, process elements from left to right. By the time we reach index `j`, all elements at indices `0` through `j - 1` have already been processed, so we need an efficient way to count how many of those earlier values satisfy `arr[i] <= arr[j] + diff`.

A Binary Indexed Tree (also called a Fenwick Tree) supports two operations in O(log n) time: update a position (add 1 to record that a value has been seen) and query a prefix sum (count how many recorded values fall at or below a threshold). Counting earlier values at or below `arr[j] + diff` is a prefix-sum query.

The values of `arr[k]` range from -20,000 to 20,000, so adding a fixed offset of 20,001 maps them to positive indices. For each index `j`, query the BIT for the count of recorded values at most `arr[j] + diff`, add that to the result, then record `arr[j]`. Querying before recording enforces `i < j`: only values from earlier indices are in the tree when index `j` is counted.

<h3 id="algorithm">Algorithm</h3>

1. Build the array `arr` where `arr[k] = nums1[k] - nums2[k]`.
2. Initialize a BIT of size large enough to cover all possible values (offset by a constant to handle negatives).
3. For each index `j` from `0` to `n - 1`:
4. Return the total count.

```java
class Solution {
    private int[] bit;

    public long numberOfPairs(int[] nums1, int[] nums2, int diff) {
        int n = nums1.length;
        int[] arr = new int[n];
        for (int i = 0; i < n; i++) {
            arr[i] = nums1[i] - nums2[i];
        }

        // Values range from -20000 to 20000, offset to make non-negative
        int offset = 20001;
        int size = 40003;
        bit = new int[size + 1];

        long count = 0;
        for (int j = 0; j < n; j++) {
            // Query: how many previous values are <= arr[j] + diff
            int threshold = arr[j] + diff + offset;
            threshold = Math.min(threshold, size);
            if (threshold >= 1) {
                count += query(threshold);
            }
            // Insert arr[j] into the BIT
            update(arr[j] + offset, size);
        }

        return count;
    }

    private void update(int idx, int size) {
        for (; idx <= size; idx += idx & (-idx)) {
            bit[idx]++;
        }
    }

    private long query(int idx) {
        long sum = 0;
        for (; idx > 0; idx -= idx & (-idx)) {
            sum += bit[idx];
        }
        return sum;
    }
}
```

> - **Time Complexity:** O(n log M). For each of the n elements, we perform one query and one update on the BIT. Each BIT operation takes O(log M) time, where M is the value range (about 40,000).
> - **Space Complexity:** O(M). The BIT array uses O(M) space where M is the value range. The arr array uses O(n) additional space.
