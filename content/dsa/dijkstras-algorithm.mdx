<LessonCard>

Dijkstra's algorithm finds the shortest path in a weighted graph from a single source vertex to every other vertex. It solves shortest-path problems when edge weights are non-negative, and it is used in applications ranging from network routing to map navigation.

BFS only solves the shortest-path problem on unweighted graphs, where every edge counts the same. Once edges have distinct weights, a path with fewer edges is not necessarily shorter than a path with more edges, and BFS gives the wrong answer.

Dijkstra's algorithm handles weighted graphs by always extending the lowest-cost known path next, using a greedy strategy backed by a priority queue.

<h2 id="what-is-dijkstras-algorithm">What Is Dijkstra's Algorithm?</h2>

Dijkstra's algorithm, invented by Edsger Dijkstra in 1956, is a **greedy single-source shortest path algorithm** for graphs with **non-negative edge weights**. Given a source vertex, it finds the shortest path from that source to every other vertex in the graph.

Breaking that down:

- **Single-source:** You pick one starting vertex, and the algorithm computes shortest paths from that vertex to all others.
- **Greedy:** At each step, it picks the unvisited vertex with the smallest known distance and commits to it. It never backtracks.
- **Non-negative weights:** All edge weights must be zero or positive. The "Why It Works" section explains the reason for this restriction.

Running Dijkstra's from vertex A finds the shortest distance from A to every other vertex. The algorithm arrives at A->C->B->D->E with a total cost of 7, and the following sections walk through exactly how.

<h2 id="how-dijkstras-works">How Dijkstra's Works</h2>

The algorithm relies on two key ideas: a **priority queue** (min-heap) and **edge relaxation**.

<h3 id="priority-queue">Priority Queue</h3>

Instead of processing vertices in arbitrary order, Dijkstra's uses a min-heap to always process the vertex with the smallest tentative distance next. This is what makes it greedy: it always commits to the closest unvisited vertex.

The min-heap replaces a linear scan over all vertices to find the one with the smallest tentative distance. Each extract-min runs in O(log V) instead of O(V).

<h3 id="edge-relaxation">Edge Relaxation</h3>

When the algorithm visits a vertex `u` and looks at its neighbor `v`, it checks whether the path through `u` is shorter than the best path found to `v` so far. If yes, `v`'s distance is updated. This process is called **relaxation**.

```text
if dist[u] + weight(u, v) < dist[v]:
    dist[v] = dist[u] + weight(u, v)
```

The name comes from the idea of "relaxing" the constraint on how short the path to `v` can be, bringing it closer to the true shortest distance.

<h3 id="the-algorithm">The Algorithm</h3>

1. Initialize a distance array `dist[]` with infinity for all vertices except the source, which gets distance 0.
2. Add the source to a min-heap with distance 0.
3. While the min-heap is not empty:
4. When the heap is empty, `dist[]` contains the shortest distances from the source to all reachable vertices.

<h2 id="why-it-works">Why It Works</h2>

The correctness of Dijkstra's algorithm rests on one key insight: **once a vertex is extracted from the priority queue, its distance is finalized, and no shorter path to it can ever be found.**

Why is this true? Consider the moment vertex `u` is extracted from the min-heap with distance `d`. Could there be some other, undiscovered path to `u` with a shorter distance? That path would have to go through at least one unvisited vertex `w`. But `w` is still in the heap, and its distance is greater than or equal to `d` (because `u` was extracted first, meaning `u` had the smallest distance).

Since all edge weights are non-negative, any path through `w` to `u` would have a total distance of at least `dist[w]`, which is already >= `d`. There is no shorter path.

This is the greedy choice: `u`'s distance can be committed because no future discovery can improve it.

<h3 id="why-non-negative-weights-are-required">
  Why Non-Negative Weights Are Required
</h3>

The argument above falls apart if edges can have negative weights. If there is a negative-weight edge from `w` to `u`, then a path through `w` could be shorter than `d`, even though `dist[w] > d`. The greedy assumption, that extracting the smallest distance from the heap gives a finalized answer, no longer holds.

The "Why Dijkstra Fails with Negative Weights" section works through a concrete example of this failure. Dijkstra's algorithm requires all edge weights to be non-negative. For graphs with negative weights, use the Bellman-Ford algorithm instead.

<h2 id="implementation">Implementation</h2>

The implementation uses an adjacency list and a min-heap (priority queue):

```java
import java.util.*;

public class Dijkstra {

    // Run Dijkstra's algorithm from the source vertex.
    // Returns an array where dist[i] = shortest distance from source to vertex i.
    public int[] dijkstra(int n, List<int[]>[] graph, int source) {
        // dist[i] holds the shortest known distance from source to i
        int[] dist = new int[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[source] = 0;

        // visited[i] is true once vertex i's shortest distance is finalized
        boolean[] visited = new boolean[n];

        // Min-heap storing {distance, vertex}
        // We compare by distance so the closest vertex is dequeued first
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
        pq.offer(new int[]{0, source});

        while (!pq.isEmpty()) {
            int[] curr = pq.poll();
            int d = curr[0];
            int u = curr[1];

            // If we already finalized this vertex, skip it.
            // This handles duplicate entries in the priority queue.
            if (visited[u]) continue;
            visited[u] = true;

            // Relax all edges from u
            for (int[] edge : graph[u]) {
                int v = edge[0];
                int weight = edge[1];

                if (!visited[v] && d + weight < dist[v]) {
                    dist[v] = d + weight;
                    pq.offer(new int[]{dist[v], v});
                }
            }
        }

        return dist;
    }

    // Helper to build an adjacency list for a directed graph
    public static List<int[]>[] buildGraph(int n, int[][] edges) {
        List<int[]>[] graph = new ArrayList[n];
        for (int i = 0; i < n; i++) {
            graph[i] = new ArrayList<>();
        }
        for (int[] edge : edges) {
            int from = edge[0], to = edge[1], weight = edge[2];
            graph[from].add(new int[]{to, weight});
        }
        return graph;
    }
}
```

```python
import heapq
from typing import List, Tuple

def dijkstra(n: int, graph: List[List[Tuple[int, int]]], source: int) -> List[int]:
    """Run Dijkstra's algorithm from the source vertex.
    Returns a list where dist[i] = shortest distance from source to vertex i.
    """
    # dist[i] holds the shortest known distance from source to i
    dist = [float('inf')] * n
    dist[source] = 0

    # visited[i] is True once vertex i's shortest distance is finalized
    visited = [False] * n

    # Min-heap storing (distance, vertex)
    pq = [(0, source)]

    while pq:
        d, u = heapq.heappop(pq)

        # If we already finalized this vertex, skip it.
        # This handles duplicate entries in the priority queue.
        if visited[u]:
            continue
        visited[u] = True

        # Relax all edges from u
        for v, weight in graph[u]:
            if not visited[v] and d + weight < dist[v]:
                dist[v] = d + weight
                heapq.heappush(pq, (dist[v], v))

    return dist

def build_graph(n: int, edges: List[List[int]]) -> List[List[Tuple[int, int]]]:
    """Helper to build an adjacency list for a directed graph."""
    graph: List[List[Tuple[int, int]]] = [[] for _ in range(n)]
    for frm, to, weight in edges:
        graph[frm].append((to, weight))
    return graph
```

```csharp
using System;
using System.Collections.Generic;

public class Dijkstra {

    // Run Dijkstra's algorithm from the source vertex.
    // Returns an array where dist[i] = shortest distance from source to vertex i.
    public int[] Run(int n, List<(int to, int weight)>[] graph, int source) {
        // dist[i] holds the shortest known distance from source to i
        int[] dist = new int[n];
        Array.Fill(dist, int.MaxValue);
        dist[source] = 0;

        // visited[i] is true once vertex i's shortest distance is finalized
        bool[] visited = new bool[n];

        // Min-heap storing (distance, vertex)
        var pq = new PriorityQueue<int, int>();
        pq.Enqueue(source, 0);

        while (pq.Count > 0) {
            pq.TryDequeue(out int u, out int d);

            // If we already finalized this vertex, skip it.
            if (visited[u]) continue;
            visited[u] = true;

            // Relax all edges from u
            foreach (var (v, weight) in graph[u]) {
                if (!visited[v] && d + weight < dist[v]) {
                    dist[v] = d + weight;
                    pq.Enqueue(v, dist[v]);
                }
            }
        }

        return dist;
    }

    // Helper to build an adjacency list for a directed graph
    public static List<(int to, int weight)>[] BuildGraph(int n, int[][] edges) {
        var graph = new List<(int to, int weight)>[n];
        for (int i = 0; i < n; i++) {
            graph[i] = new List<(int to, int weight)>();
        }
        foreach (var edge in edges) {
            int from = edge[0], to = edge[1], weight = edge[2];
            graph[from].Add((to, weight));
        }
        return graph;
    }
}
```

```go
package main

import "container/heap"

// MinHeap implements heap.Interface for (distance, vertex) pairs
type Item struct {
	dist, vertex int
}
type MinHeap []Item

func (h MinHeap) Len() int            { return len(h) }
func (h MinHeap) Less(i, j int) bool   { return h[i].dist < h[j].dist }
func (h MinHeap) Swap(i, j int)        { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x interface{})  { *h = append(*h, x.(Item)) }
func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// Edge represents a directed edge with a destination and weight.
type Edge struct {
	to, weight int
}

// Dijkstra runs Dijkstra's algorithm from the source vertex.
// Returns a slice where dist[i] = shortest distance from source to vertex i.
func Dijkstra(n int, graph [][]Edge, source int) []int {
	const inf = int(1e18)
	dist := make([]int, n)
	for i := range dist {
		dist[i] = inf
	}
	dist[source] = 0

	visited := make([]bool, n)

	pq := &MinHeap{{0, source}}
	heap.Init(pq)

	for pq.Len() > 0 {
		curr := heap.Pop(pq).(Item)
		d, u := curr.dist, curr.vertex

		// If we already finalized this vertex, skip it.
		if visited[u] {
			continue
		}
		visited[u] = true

		// Relax all edges from u
		for _, e := range graph[u] {
			if !visited[e.to] && d+e.weight < dist[e.to] {
				dist[e.to] = d + e.weight
				heap.Push(pq, Item{dist[e.to], e.to})
			}
		}
	}

	return dist
}

// BuildGraph builds an adjacency list for a directed graph.
func BuildGraph(n int, edges [][]int) [][]Edge {
	graph := make([][]Edge, n)
	for _, e := range edges {
		from, to, weight := e[0], e[1], e[2]
		graph[from] = append(graph[from], Edge{to, weight})
	}
	return graph
}
```

```rust
pub struct Solution;

impl Solution {
    // Run Dijkstra's algorithm from the source vertex.
    // Returns a vector where dist[i] = shortest distance from source to vertex i.
    pub fn dijkstra(n: usize, graph: &Vec<Vec<(usize, i64)>>, source: usize) -> Vec<i64> {
        const INF: i64 = i64::MAX;

        // dist[i] holds the shortest known distance from source to i
        let mut dist = vec![INF; n];
        dist[source] = 0;

        // visited[i] is true once vertex i's shortest distance is finalized
        let mut visited = vec![false; n];

        // Min-heap storing (distance, vertex). Reverse turns the max-heap into a min-heap
        // so the closest vertex is dequeued first.
        let mut pq: BinaryHeap<Reverse<(i64, usize)>> = BinaryHeap::new();
        pq.push(Reverse((0, source)));

        while let Some(Reverse((d, u))) = pq.pop() {
            // If we already finalized this vertex, skip it.
            // This handles duplicate entries in the priority queue.
            if visited[u] {
                continue;
            }
            visited[u] = true;

            // Relax all edges from u
            for &(v, weight) in &graph[u] {
                if !visited[v] && d + weight < dist[v] {
                    dist[v] = d + weight;
                    pq.push(Reverse((dist[v], v)));
                }
            }
        }

        dist
    }

    // Helper to build an adjacency list for a directed graph
    pub fn build_graph(n: usize, edges: &Vec<(usize, usize, i64)>) -> Vec<Vec<(usize, i64)>> {
        let mut graph = vec![Vec::new(); n];
        for &(from, to, weight) in edges {
            graph[from].push((to, weight));
        }
        graph
    }
}
```

```javascript
/**
 * Run Dijkstra's algorithm from the source vertex.
 * @param {number} n - Number of vertices
 * @param {number[][][]} graph - Adjacency list where graph[u] = [[v, weight], ...]
 * @param {number} source - Source vertex
 * @returns {number[]} dist where dist[i] = shortest distance from source to i
 */
function dijkstra(n, graph, source) {
  // dist[i] holds the shortest known distance from source to i
  const dist = new Array(n).fill(Infinity);
  dist[source] = 0;

  // visited[i] is true once vertex i's shortest distance is finalized
  const visited = new Array(n).fill(false);

  // Min-heap storing [distance, vertex]
  const pq = new MinPriorityQueue();
  pq.enqueue([0, source]);

  while (!pq.isEmpty()) {
    const [d, u] = pq.dequeue();

    // If we already finalized this vertex, skip it.
    if (visited[u]) continue;
    visited[u] = true;

    // Relax all edges from u
    for (const [v, weight] of graph[u]) {
      if (!visited[v] && d + weight < dist[v]) {
        dist[v] = d + weight;
        pq.enqueue([dist[v], v]);
      }
    }
  }

  return dist;
}

// Simple min-priority queue (use a library like @datastructures-js/priority-queue in practice)
class MinPriorityQueue {
  constructor() {
    this.data = [];
  }
  enqueue(val) {
    this.data.push(val);
    this._bubbleUp(this.data.length - 1);
  }
  dequeue() {
    const top = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      this._sinkDown(0);
    }
    return top;
  }
  isEmpty() {
    return this.data.length === 0;
  }
  _bubbleUp(i) {
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.data[i][0] < this.data[parent][0]) {
        [this.data[i], this.data[parent]] = [this.data[parent], this.data[i]];
        i = parent;
      } else break;
    }
  }
  _sinkDown(i) {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1,
        right = 2 * i + 2;
      if (left < n && this.data[left][0] < this.data[smallest][0])
        smallest = left;
      if (right < n && this.data[right][0] < this.data[smallest][0])
        smallest = right;
      if (smallest !== i) {
        [this.data[i], this.data[smallest]] = [
          this.data[smallest],
          this.data[i],
        ];
        i = smallest;
      } else break;
    }
  }
}

 * Helper to build an adjacency list for a directed graph.

function buildGraph(n, edges) {
  const graph = Array.from({ length: n }, () => []);
  for (const [from, to, weight] of edges) {

  return graph;
```

```typescript
 * Run Dijkstra's algorithm from the source vertex.
 * Returns an array where dist[i] = shortest distance from source to vertex i.
 */
function dijkstra(n: number, graph: Edge[][], source: number): number[] {

  dist[source] = 0;

  const visited: boolean[] = new Array(n).fill(false);

  const pq = new MinPriorityQueue();
  pq.enqueue([0, source]);

  while (!pq.isEmpty()) {
    const [d, u] = pq.dequeue()!;

      if (!visited[v] && d + weight < dist[v]) {
        dist[v] = d + weight;
        pq.enqueue([dist[v], v]);
      }
    }
  }

  return dist;

class MinPriorityQueue {
  private data: [number, number][] = [];

  enqueue(val: [number, number]): void {
    this.data.push(val);
    this.bubbleUp(this.data.length - 1);
  }

  dequeue(): [number, number] | undefined {
    if (this.data.length === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop()!;
    if (this.data.length > 0) {
      this.data[0] = last;
      this.sinkDown(0);
    }
    return top;
  }

  isEmpty(): boolean {
    return this.data.length === 0;
  }

  private bubbleUp(i: number): void {
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.data[i][0] < this.data[parent][0]) {
        [this.data[i], this.data[parent]] = [this.data[parent], this.data[i]];
        i = parent;
      } else break;
    }
  }

  private sinkDown(i: number): void {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1,
        right = 2 * i + 2;
      if (left < n && this.data[left][0] < this.data[smallest][0])
        smallest = left;
      if (right < n && this.data[right][0] < this.data[smallest][0])
        smallest = right;
      if (smallest !== i) {
        [this.data[i], this.data[smallest]] = [
          this.data[smallest],
          this.data[i],
        ];
        i = smallest;
      } else break;
    }
  }
}
```

- **Duplicate entries in the priority queue:** When relaxing an edge produces a shorter path to vertex `v`, a new entry is added to the heap. The old, stale entry for `v` might still be in the heap. The `if visited[u]` check handles this by skipping vertices already finalized.
- **Why not decrease-key?** Most standard library priority queues do not support efficient decrease-key. Instead, the algorithm adds duplicates and skips stale entries. This is called the "lazy deletion" approach.
- **Integer overflow:** A large sentinel value serves as infinity. The expression `d + weight` must not overflow. The `!visited[v]` check helps because relaxation only happens from finalized vertices, but in edge cases a larger integer type may be needed.

<h2 id="why-dijkstra-fails-with-negative-weights">
  Why Dijkstra Fails with Negative Weights
</h2>

Consider this graph:

Running Dijkstra from A:

1. Extract A (dist=0). Relax: dist[B]=1, dist[C]=3.
2. Extract B (dist=1). B is finalized with distance 1.
3. Extract C (dist=3). Relax edge C->B: 3 + (-5) = -2 < 1. But B is already finalized.

Dijkstra reports dist[B] = 1, but the true shortest path is A->C->B with cost 3 + (-5) = -2. The algorithm fails because it finalized B too early. The greedy assumption, that the smallest distance in the heap is the true shortest, breaks down when negative edges exist.

<h3 id="dijkstra-with-path-reconstruction">
  Dijkstra with Path Reconstruction
</h3>

Many problems require the actual path, not just the shortest distance. To reconstruct the path, maintain a `parent[]` array that records which vertex each vertex was relaxed from.

```java
public List<Integer> shortestPath(int n, List<int[]>[] graph, int source, int target) {
    int[] dist = new int[n];
    int[] parent = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    Arrays.fill(parent, -1);
    dist[source] = 0;
    boolean[] visited = new boolean[n];

    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    pq.offer(new int[]{0, source});

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];

        if (visited[u]) continue;
        visited[u] = true;

        for (int[] edge : graph[u]) {
            int v = edge[0], w = edge[1];
            if (!visited[v] && d + w < dist[v]) {
                dist[v] = d + w;
                parent[v] = u;  // Record where we came from
                pq.offer(new int[]{dist[v], v});
            }
        }
    }

    // Reconstruct path from target to source
    if (dist[target] == Integer.MAX_VALUE) return Collections.emptyList();

    List<Integer> path = new ArrayList<>();
    for (int v = target; v != -1; v = parent[v]) {
        path.add(v);
    }
    Collections.reverse(path);
    return path;
}
```

```python
import heapq
from typing import List, Tuple

def shortest_path(n: int, graph: List[List[Tuple[int, int]]], source: int, target: int) -> List[int]:
    dist = [float('inf')] * n
    parent = [-1] * n
    dist[source] = 0
    visited = [False] * n

    pq = [(0, source)]

    while pq:
        d, u = heapq.heappop(pq)

        if visited[u]:
            continue
        visited[u] = True

        for v, w in graph[u]:
            if not visited[v] and d + w < dist[v]:
                dist[v] = d + w
                parent[v] = u  # Record where we came from
                heapq.heappush(pq, (dist[v], v))

    # Reconstruct path from target to source
    if dist[target] == float('inf'):
        return []

    path = []
    v = target
    while v != -1:
        path.append(v)
        v = parent[v]
    path.reverse()
    return path
```

```go
func ShortestPath(n int, graph [][]Edge, source, target int) []int {
    const inf = int(1e18)
    dist := make([]int, n)
    parent := make([]int, n)
    for i := range dist {
        dist[i] = inf
        parent[i] = -1
    }
    dist[source] = 0
    visited := make([]bool, n)

    pq := &MinHeap{{0, source}}
    heap.Init(pq)

    for pq.Len() > 0 {
        curr := heap.Pop(pq).(Item)
        d, u := curr.dist, curr.vertex

        if visited[u] {
            continue
        }
        visited[u] = true

        for _, e := range graph[u] {
            if !visited[e.to] && d+e.weight < dist[e.to] {
                dist[e.to] = d + e.weight
                parent[e.to] = u // Record where we came from
                heap.Push(pq, Item{dist[e.to], e.to})
            }
        }
    }

    // Reconstruct path from target to source
    if dist[target] == inf {
        return nil
    }

    var path []int
    for v := target; v != -1; v = parent[v] {
        path = append(path, v)
    }
    // Reverse
    for i, j := 0, len(path)-1; i < j; i, j = i+1, j-1 {
        path[i], path[j] = path[j], path[i]
    }
    return path
}
```

```rust
use std::cmp::Reverse;
use std::collections::BinaryHeap;

pub struct Solution;

impl Solution {
    pub fn shortest_path(
        n: usize,
        graph: &Vec<Vec<(usize, i64)>>,
        source: usize,
        target: usize,
    ) -> Vec<usize> {
        const INF: i64 = i64::MAX;
        let mut dist = vec![INF; n];
        let mut parent: Vec<i64> = vec![-1; n];
        dist[source] = 0;
        let mut visited = vec![false; n];

        let mut pq: BinaryHeap<Reverse<(i64, usize)>> = BinaryHeap::new();
        pq.push(Reverse((0, source)));

        while let Some(Reverse((d, u))) = pq.pop() {
            if visited[u] {
                continue;
            }
            visited[u] = true;

            for &(v, w) in &graph[u] {
                if !visited[v] && d + w < dist[v] {
                    dist[v] = d + w;
                    parent[v] = u as i64; // Record where we came from
                    pq.push(Reverse((dist[v], v)));
                }
            }
        }

        // Reconstruct path from target to source
        if dist[target] == INF {
            return Vec::new();
        }

        let mut path = Vec::new();
        let mut v: i64 = target as i64;
        while v != -1 {
            path.push(v as usize);
            v = parent[v as usize];
        }
        path.reverse();
        path
    }

        let mut graph = vec![Vec::new(); n];
        for &(from, to, weight) in edges {
            graph[from].push((to, weight));
        }
        graph
    }
}
```

The only addition to the standard algorithm is the `parent[]` array and the backtracking loop at the end. Path reconstruction is a common follow-up.

<h3 id="bidirectional-dijkstra">Bidirectional Dijkstra</h3>

For point-to-point shortest path queries (source to a specific target), Dijkstra can run from both the source and the target simultaneously, stopping when the two searches meet. This often reduces the number of vertices explored, though the worst-case complexity stays the same.

Bidirectional Dijkstra is used in road-network and large-graph applications. Map services typically layer additional preprocessing techniques like Contraction Hierarchies on top of the basic algorithm.

<h3 id="0-1-bfs">0-1 BFS</h3>

When all edge weights are either 0 or 1, a deque (double-ended queue) can replace the priority queue. Add 0-weight edges to the front of the deque and 1-weight edges to the back. This gives O(V + E) time instead of O((V + E) log V), since the heap overhead is removed.

<h2 id="complexity-analysis">Complexity Analysis</h2>

<h3 id="time-complexity">Time Complexity</h3>

The time complexity depends on the priority queue implementation:

| Implementation         | Extract-Min        | Decrease-Key   | Total Complexity     |
| ---------------------- | ------------------ | -------------- | -------------------- |
| Binary Heap (standard) | O(log V)           | O(log V)       | **O((V + E) log V)** |
| Array (no heap)        | O(V)               | O(1)           | **O(V^2)**           |
| Fibonacci Heap         | O(log V) amortized | O(1) amortized | **O(V log V + E)**   |

Breaking down O((V + E) log V) for the binary heap approach:

- Each vertex is extracted from the heap at most once: O(V log V)
- Each edge is examined at most once, potentially causing a heap insertion: O(E log V)
- Total: O((V + E) log V)

For **dense graphs** (E is close to V^2), the array-based approach with O(V^2) can be faster because it avoids heap overhead. For **sparse graphs** (E is much less than V^2), the binary heap approach wins.

<h3 id="space-complexity">Space Complexity</h3>

- Distance array: O(V)
- Visited array: O(V)
- Priority queue: O(V) in the worst case (though with lazy deletion, it can temporarily hold up to O(E) entries)
- Adjacency list: O(V + E)
- **Total: O(V + E)**

<h2 id="key-takeaways">Key Takeaways</h2>

- Dijkstra's algorithm computes the shortest path from a single source vertex to every other vertex in a weighted graph, and it works only when all edge weights are non-negative.
- The algorithm is greedy. It uses a min-priority-queue to repeatedly extract the unvisited vertex with the smallest tentative distance, finalizes that vertex, and relaxes its outgoing edges to update neighbor distances.
- Finalization is safe because once a vertex is extracted with distance d, every other vertex still in the heap has distance at least d, so non-negative edges cannot produce a shorter path.
- Dijkstra's algorithm fails on graphs with negative edge weights, since a later negative edge can create a shorter path to a vertex that was already finalized. Use the Bellman-Ford algorithm when negative weights are present.
- With a binary heap, the running time is O((V + E) log V), while an array-based version runs in O(V^2) and can be faster on dense graphs. Space usage is O(V + E).
- To recover the actual path rather than only distances, store a parent pointer for each vertex during relaxation and walk the pointers back from the target to the source.
