<LessonCard>

Design a time-based key-value data structure that can store multiple values for the same key at different time stamps and retrieve the key's value at a certain timestamp.

Implement the `TimeMap` class:

- `TimeMap()` Initializes the object of the data structure.
- `void set(String key, String value, int timestamp)` Stores the key `key` with the value `value` at the given time `timestamp`.
- `String get(String key, int timestamp)` Returns a value such that `set` was called previously, with `timestamp_prev <= timestamp`. If there are multiple such values, it returns the value associated with the largest `timestamp_prev`. If there are no values, it returns the empty string `""`.

**Example 1:**

- **Input:** `operations = ["TimeMap", "set", "get", "get", "set", "get"]`

- **Input:** `arguments = [[], ["foo", "bar", 1], ["foo", 1], ["foo", 3], ["foo", "bar2", 4], ["foo", 4]]`

- **Output:** `[null, null, "bar", "bar", null, "bar2"]`

**Example 2:**

- **Input:** `operations = ["TimeMap", "set", "set", "get", "get", "get"]`

- **Input:** `arguments = [[], ["love", "high", 10], ["love", "low", 20], ["love", 5], ["love", 10], ["love", 15]]`

- **Output:** `[null, null, null, "", "high", "high"]`

**Constraints:**

- `1 <= key.length, value.length <= 100`
- `key` and `value` consist of lowercase English letters and digits.
- `1 <= timestamp <= 10^7`
- All the timestamps `timestamp` of `set` are strictly increasing.
- At most `2 * 10^5` calls will be made to `set` and `get`.

We need to build a data structure that associates keys with values, but each key can hold multiple values stored at different points in time. A `get` does not return the latest value. It returns the value that was current at a specific timestamp, meaning the value set at the largest timestamp that does not exceed the query timestamp.

This behaves like version control for a key-value store. Each `set` call creates a new version, and each `get` call asks what the value was at a given point in time. When no exact match exists, the answer is the most recent version before that time.

The timestamps for `set` calls arrive strictly increasing. The timestamps stored for each key are therefore already sorted, which makes binary search possible instead of scanning every entry.

- `1 <= timestamp <= 10^7` and timestamps are strictly increasing. The timestamps stored per key are guaranteed sorted, so we never sort anything ourselves.
- At most `2 * 10^5` calls to `set` and `get`. If every `set` targets one key and every `get` scans that key's full history, the total cost approaches 10^5 \* 10^5 = 10^10 operations, too slow for the time limit. The `get` path needs to be sublinear.
- `key.length, value.length <= 100`. String comparisons and copies are bounded by a small constant, so the running time depends on the lookup strategy rather than on string handling.

<h1 id="approach-1-hash-map-with-linear-scan">
  Approach 1: Hash Map with Linear Scan
</h1>

<h3 id="intuition">Intuition</h3>

Store each key's history as a list of (timestamp, value) pairs inside a hash map. For `set`, append to the list. For `get`, scan backward through the list and return the first entry whose timestamp does not exceed the query timestamp.

Because timestamps arrive in strictly increasing order, each list is already sorted ascending. Scanning from the end reaches the largest timestamps first, so the first entry that satisfies `timestamp <= query` is also the largest such timestamp. That makes it the correct answer, and we can stop immediately.

<h3 id="algorithm">Algorithm</h3>

1. Initialize a hash map where each key maps to a list of (timestamp, value) pairs.
2. For `set(key, value, timestamp)`: append `(timestamp, value)` to the list for `key`.
3. For `get(key, timestamp)`: look up the list for `key`. Iterate backward through the list. Return the value of the first entry whose timestamp is less than or equal to `timestamp`. If no such entry exists, return `""`.

```java
class TimeMap {
    // Map each key to a list of timestamps and corresponding values
    Map<String, List<int[]>> timeMap;
    Map<String, List<String>> valMap;

    public TimeMap() {
        timeMap = new HashMap<>();
        valMap = new HashMap<>();
    }

    public void set(String key, String value, int timestamp) {
        timeMap.computeIfAbsent(key, k -> new ArrayList<>()).add(new int[]{timestamp});
        valMap.computeIfAbsent(key, k -> new ArrayList<>()).add(value);
    }

    public String get(String key, int timestamp) {
        if (!timeMap.containsKey(key)) return "";
        List<int[]> times = timeMap.get(key);
        List<String> vals = valMap.get(key);
        // Scan backward to find the largest timestamp <= query timestamp
        for (int i = times.size() - 1; i >= 0; i--) {
            if (times.get(i)[0] <= timestamp) {
                return vals.get(i);
            }
        }
        return "";
    }
}
```

```rust
        Self {
            store: HashMap::new(),

        if !self.store.contains_key(&key) {

        for i in (0..pairs.len()).rev() {
            if pairs[i].0 <= timestamp {
                return pairs[i].1.clone();

    }
```

> - **Time Complexity:** O(1) for `set`, O(n) for `get` where n is the number of entries for that key. `set` appends to a list in O(1) amortized. `get` may scan all entries in the worst case.
> - **Space Complexity:** O(m) where m is the total number of `set` calls. We store every (timestamp, value) pair.

The linear scan ignores the sorted order of the timestamps. The next approach exploits that order with binary search, cutting `get` from O(n) to O(log n).

<h1 id="approach-2-hash-map-with-binary-search-optimal">
  Approach 2: Hash Map with Binary Search (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

The list of timestamps for each key is sorted ascending, so binary search replaces the backward scan. Instead of walking through thousands of entries, the search narrows to the right index in O(log n) time.

The query is a "floor" search: find the largest timestamp less than or equal to the target. We maintain a range `[left, right]` and check the middle element. If `timestamps[mid] <= target`, that timestamp is a valid candidate, but a larger valid one may sit to its right, so we record `mid` and move `left = mid + 1`. If `timestamps[mid] > target`, the middle timestamp is too new, so we move `right = mid - 1`. When `left` passes `right`, the last recorded candidate is the answer.

<h3 id="algorithm">Algorithm</h3>

1. Initialize a hash map where each key maps to a list of (timestamp, value) pairs.
2. For `set(key, value, timestamp)`: append `(timestamp, value)` to the list for `key`.
3. For `get(key, timestamp)`:

<h3 id="code">Code</h3>

```java
class TimeMap {
    // Map each key to parallel lists of timestamps and values
    Map<String, List<Integer>> timeMap;
    Map<String, List<String>> valMap;

    public TimeMap() {
        timeMap = new HashMap<>();
        valMap = new HashMap<>();
    }

    public void set(String key, String value, int timestamp) {
        timeMap.computeIfAbsent(key, k -> new ArrayList<>()).add(timestamp);
        valMap.computeIfAbsent(key, k -> new ArrayList<>()).add(value);
    }

    public String get(String key, int timestamp) {
        if (!timeMap.containsKey(key)) return "";
        List<Integer> times = timeMap.get(key);
        List<String> vals = valMap.get(key);

        // Binary search for largest timestamp <= query timestamp
        int left = 0, right = times.size() - 1, result = -1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (times.get(mid) <= timestamp) {
                result = mid;    // This timestamp is valid, but there might be a larger one
                left = mid + 1;
            } else {
                right = mid - 1; // This timestamp is too large
            }
        }
        return result == -1 ? "" : vals.get(result);
    }
}
```

```rust
use std::collections::HashMap;

struct TimeMap {
    // Map each key to parallel vectors of timestamps and values
    times: HashMap<String, Vec<i32>>,
    vals: HashMap<String, Vec<String>>,
}

impl TimeMap {
    fn new() -> Self {
        Self {
            times: HashMap::new(),
            vals: HashMap::new(),
        }
    }

    fn set(&mut self, key: String, value: String, timestamp: i32) {
        self.times.entry(key.clone()).or_insert_with(Vec::new).push(timestamp);
        self.vals.entry(key).or_insert_with(Vec::new).push(value);
    }

    fn get(&self, key: String, timestamp: i32) -> String {
        let ts = match self.times.get(&key) {
            Some(v) => v,
            None => return String::new(),
        };
        let vs = self.vals.get(&key).unwrap();

        // Binary search for largest timestamp <= query timestamp
        let mut left: i32 = 0;
        let mut right: i32 = ts.len() as i32 - 1;
        let mut result: i32 = -1;
        while left <= right {
            let mid = left + (right - left) / 2;
            if ts[mid as usize] <= timestamp {
                result = mid; // Valid candidate, look for a larger one
                left = mid + 1;
            } else {
                right = mid - 1; // Too large, search left half
            }
        }
        if result == -1 {
            String::new()
        } else {
            vs[result as usize].clone()
        }
    }
}
```
