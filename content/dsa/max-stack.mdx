<LessonCard>

Design a max stack data structure that supports the stack operations and supports finding the stack's maximum element.

Implement the `MaxStack` class:

- `MaxStack()` Initializes the stack object.
- `void push(int x)` Pushes element `x` onto the stack.
- `int pop()` Removes the element on top of the stack and returns it.
- `int top()` Gets the element on the top of the stack without removing it.
- `int peekMax()` Retrieves the maximum element in the stack without removing it.
- `int popMax()` Retrieves the maximum element in the stack and removes it. If there is more than one maximum element, only remove the **top-most** one.

\***\*Example 1:\*\***

- **Input:** `actions = ["MaxStack","push","push","push","top","popMax","top","peekMax","pop","top"]`

- **Input:** `args = [[],[5],[1],[5],[],[],[],[],[],[]]`

- **Output:** `[null,null,null,null,5,5,1,5,1,5]`

**Explanation:**

- `MaxStack stk = new MaxStack();`
- `stk.push(5);` // [5] the top of the stack and the maximum number is 5.
- `stk.push(1);` // [5, 1] the top of the stack is 1, but the maximum is 5.
- `stk.push(5);` // [5, 1, 5] the top of the stack is 5, and the maximum is 5.
- `stk.top();` // return 5, [5, 1, 5] the stack did not change.
- `stk.popMax();` // return 5, [5, 1] the stack is changed now, and the top is 1.
- `stk.top();` // return 1, [5, 1] the stack did not change.
- `stk.peekMax();` // return 5, [5, 1] the stack did not change.
- `stk.pop();` // return 1, [5] the stack is changed now, and the top is 5.
- `stk.top();` // return 5, [5] the stack did not change.

\***\*Constraints:\*\***

- `-10^7 <= x <= 10^7`
- At most `10^5` calls will be made to `push`, `pop`, `top`, `peekMax`, and `popMax`.
- There will be at least one element in the stack when `pop`, `top`, `peekMax`, or `popMax` is called.

<h1 id="understanding-the-problem">Understanding the Problem</h1>

We need a stack that supports the usual operations (push, pop, top) plus two extra ones: finding the maximum element and removing it. The hard operation is `popMax`. A regular stack only removes from the top, but `popMax` removes the maximum, which can sit anywhere in the stack. If several elements share the maximum value, it removes the one closest to the top.

A normal stack gives O(1) push, pop, and top. Supporting `peekMax` on top of that is straightforward: track the running maximum with a second stack, the same idea used in the Min Stack problem. `popMax` is the difficult part. The maximum can be deep in the stack, the elements above it must keep their order after removal, and the new maximum can be a different value. The conflict between stack ordering and fast max-tracking is the core of this problem.

The question is whether we can support all five operations efficiently, or whether some operation has to be slow.

<h3 id="key-constraints">Key Constraints:</h3>

- `-10^7 <= x <= 10^7`. Values can be negative and span a wide range, so we handle the full signed integer range rather than assuming positive or small values.
- At most `10^5` calls. An O(n) per `popMax` solution with O(1) for the other operations is fast enough to pass, since `popMax` itself amortizes well over a sequence of calls. The optimal solution drives every operation down to O(log n).

<h1 id="approach-1-two-stacks-brute-force-popmax">
  Approach 1: Two Stacks (Brute Force popMax)
</h1>

<h3 id="intuition">Intuition</h3>

Use two stacks. The main stack holds all elements in order. The second stack (the "max stack") tracks the running maximum at each level, the same idea used in the Min Stack problem.

This gives O(1) for `push`, `pop`, `top`, and `peekMax`. The max stack always has the current maximum at its top, because every time we push a value we also push `max(value, currentMax)` onto the max stack. Popping both together keeps them aligned.

`popMax` is harder. The maximum is not always at the top of the main stack, so we pop elements off the top one at a time until we reach the maximum, remove it, then push the popped elements back. The push-back step rebuilds the max stack at the same time, so it stays correct.

The implementation is short and correct. When the stack stays small, the linear `popMax` cost is acceptable.

<h3 id="algorithm">Algorithm</h3>

1. Maintain two stacks: `stack` (the main stack) and `maxStack` (tracks the running maximum).
2. `push(x)`: Push `x` onto `stack`. Push `max(x, maxStack.peek())` onto `maxStack` (or just `x` if `maxStack` is empty).
3. `pop()`: Pop from both `stack` and `maxStack`. Return the value from `stack`.
4. `top()`: Return `stack.peek()`.
5. `peekMax()`: Return `maxStack.peek()`.
6. `popMax()`: Get the maximum from `maxStack.peek()`. Pop elements into a temp stack until you find the max. Remove it. Push everything back using `push()`$Lcb

7. Maintain two stacks: `stack` (the main stack) and `maxStack` (tracks the running maximum).
8. `push(x)`: Push `x` onto `stack`. Push `max(x, maxStack.peek())` onto `maxStack` (or just `x` if `maxStack` is empty).
9. `pop()`: Pop from both `stack` and `maxStack`. Return the value from `stack`.
10. `top()`: Return `stack.peek()`.
11. `peekMax()`: Return `maxStack.peek()`.
12. `popMax()`: Get the maximum from `maxStack.peek()`. Pop elements into a temp stack until you find the max. Remove it. Push everything back using `push()`$L7a

```java
class MaxStack {
    Stack<Integer> stack;
    Stack<Integer> maxStack;

    public MaxStack() {
        stack = new Stack<>();
        maxStack = new Stack<>();
    }

    public void push(int x) {
        stack.push(x);
        if (maxStack.isEmpty()) {
            maxStack.push(x);
        } else {
            maxStack.push(Math.max(x, maxStack.peek()));
        }
    }

    public int pop() {
        maxStack.pop();
        return stack.pop();
    }

    public int top() {
        return stack.peek();
    }

    public int peekMax() {
        return maxStack.peek();
    }

    public int popMax() {
        int max = maxStack.peek();
        Stack<Integer> temp = new Stack<>();
        while (stack.peek() != max) {
            temp.push(stack.pop());
            maxStack.pop();
        }
        stack.pop();
        maxStack.pop();
        while (!temp.isEmpty()) {
            push(temp.pop());
        }
        return max;
    }
}
```

> - **Time Complexity:** O(1) for push, pop, top, peekMax. O(n) for popMax, where n is the number of elements in the stack. In the worst case, we pop all elements to find the maximum buried at the bottom.
> - **Space Complexity:** O(n). We store each element twice (once in each stack).

The bottleneck is `popMax`, which can pop the entire stack to reach a maximum buried at the bottom. The next approach replaces that linear scan with a heap that finds the maximum in O(log n).

<h1 id="approach-2-heap-lazy-deletion">Approach 2: Heap + Lazy Deletion</h1>

<h3 id="intuition">Intuition</h3>

A max-heap finds the maximum in O(log n), and a list maintains stack order. The difficulty is keeping the two structures consistent when `popMax` removes an element from one of them but not the other.

Lazy deletion resolves this. Instead of removing an element from both structures at once, we mark it deleted and skip it later when it surfaces. Each element carries a unique ID, a counter that increments on every push, so we can identify the exact element to delete even when two elements share the same value.

`popMax` pops the maximum from the heap, records its ID in a deleted set, and leaves the stack untouched. `pop` and `top` first discard any top-of-stack entries whose IDs are in the deleted set, then operate on the first surviving entry. Because each element is added to the deleted set at most once and skipped at most once, the cleanup cost amortizes across operations.

<h3 id="algorithm">Algorithm</h3>

1. Maintain a stack (list of `(value, id)` pairs), a max-heap of `(value, id)` pairs, a set of deleted IDs, and a counter for generating unique IDs.
2. `push(x)`: Assign a new unique ID. Push `(x, id)` onto the stack and the heap. Increment the counter.
3. `pop()`: Skip any top-of-stack entries whose IDs are in the deleted set. Pop the top entry, add its ID to the deleted set, and return the value.
4. `top()`: Skip any top-of-stack entries whose IDs are in the deleted set. Return the top value.
5. `peekMax()`: Skip any top-of-heap entries whose IDs are in the deleted set. Return the top value.
6. `popMax()`: Skip any top-of-heap entries whose IDs are in the deleted set. Pop the top entry, add its ID to the deleted set, and return the value.

```java
class MaxStack {
    List<int[]> stack;
    PriorityQueue<int[]> heap;
    Set<Integer> deleted;
    int counter;

    public MaxStack() {
        stack = new ArrayList<>();
        heap = new PriorityQueue<>((a, b) -> a[0] == b[0] ? b[1] - a[1] : b[0] - a[0]);
        deleted = new HashSet<>();
        counter = 0;
    }

    public void push(int x) {
        stack.add(new int[]{x, counter});
        heap.offer(new int[]{x, counter});
        counter++;
    }

    public int pop() {
        while (deleted.contains(stack.get(stack.size() - 1)[1])) {
            stack.remove(stack.size() - 1);
        }
        int[] top = stack.remove(stack.size() - 1);
        deleted.add(top[1]);
        return top[0];
    }

    public int top() {
        while (deleted.contains(stack.get(stack.size() - 1)[1])) {
            stack.remove(stack.size() - 1);
        }
        return stack.get(stack.size() - 1)[0];
    }

    public int peekMax() {
        while (deleted.contains(heap.peek()[1])) {
            heap.poll();
        }
        return heap.peek()[0];
    }

    public int popMax() {
        while (deleted.contains(heap.peek()[1])) {
            heap.poll();
        }
        int[] top = heap.poll();
        deleted.add(top[1]);
        return top[0];
    }
}
```

```cpp
class MaxStack {
    vector<pair<int, int>> stk;
    priority_queue<pair<int, int>> heap;
    unordered_set<int> deleted;
    int counter;

public:
    MaxStack() : counter(0) {}

    void push(int x) {
        stk.push_back({x, counter});
        heap.push({x, counter});
        counter++;
    }

    int pop() {
        while (deleted.count(stk.back().second)) {
            stk.pop_back();
        }
        auto [val, id] = stk.back();
        stk.pop_back();
        deleted.insert(id);
        return val;
    }

    int top() {
        while (deleted.count(stk.back().second)) {
            stk.pop_back();
        }
        return stk.back().first;
    }

    int peekMax() {
        while (deleted.count(heap.top().second)) {
            heap.pop();
        }
        return heap.top().first;
    }

    int popMax() {
        while (deleted.count(heap.top().second)) {
            heap.pop();
        }
        auto [val, id] = heap.top();
        heap.pop();
        deleted.insert(id);
        return val;
    }
};
```

```csharp
public class MaxStack {
    List<int[]> stack;
    SortedSet<int[]> sortedSet;
    HashSet<int> deleted;
    int counter;

    public MaxStack() {
        stack = new List<int[]>();
        sortedSet = new SortedSet<int[]>(Comparer<int[]>.Create((a, b) => {
            if (a[0] != b[0]) return a[0].CompareTo(b[0]);
            return a[1].CompareTo(b[1]);
        }));
        deleted = new HashSet<int>();
        counter = 0;
    }

    public void Push(int x) {
        stack.Add(new int[]{x, counter});
        sortedSet.Add(new int[]{x, counter});
        counter++;
    }

    public int Pop() {
        while (deleted.Contains(stack[stack.Count - 1][1])) {
            stack.RemoveAt(stack.Count - 1);
        }
        int[] top = stack[stack.Count - 1];
        stack.RemoveAt(stack.Count - 1);
        deleted.Add(top[1]);
        sortedSet.Remove(top);
        return top[0];
    }

    public int Top() {
        while (deleted.Contains(stack[stack.Count - 1][1])) {
            stack.RemoveAt(stack.Count - 1);
        }
        return stack[stack.Count - 1][0];
    }

    public int PeekMax() {
        return sortedSet.Max[0];
    }

    public int PopMax() {
        int[] max = sortedSet.Max;
        sortedSet.Remove(max);
        deleted.Add(max[1]);
        return max[0];
    }
}
```

```go
type MaxHeap []entry

func (h MaxHeap) Len() int { return len(h) }
func (h MaxHeap) Less(i, j int) bool {
    if h[i].val == h[j].val {
        return h[i].id > h[j].id
    }
    return h[i].val > h[j].val
}

    n := len(old)
    x := old[n-1]

    return x
}
```

```rust
struct MaxStack {
    stack: Vec<Entry>,
    heap: BinaryHeap<Entry>,

            deleted: HashSet::new(),

        self.stack.push(e);
        self.heap.push(e);
        self.counter += 1;
    }

    fn pop(&mut self) -> i32 {
        while self.deleted.contains(&self.stack[self.stack.len() - 1].id) {
            self.stack.pop();
        }
        let top = self.stack.pop().unwrap();
        self.deleted.insert(top.id);
        top.val
    }

        while self.deleted.contains(&self.stack[self.stack.len() - 1].id) {
            self.stack.pop();
        }
        self.stack[self.stack.len() - 1].val

        while self.deleted.contains(&self.heap.peek().unwrap().id) {
            self.heap.pop();
        }
        self.heap.peek().unwrap().val
```

> - **Time Complexity:** O(log n) amortized for all operations. Push is O(log n) due to heap insertion. Pop, top, peekMax, and popMax are amortized O(log n) because each element is lazily cleaned up at most once.
> - **Space Complexity:** O(n). Each element is stored in both the stack and the heap, plus the deleted set can grow up to n entries.

The heap with lazy deletion gives good amortized performance, but a single `pop` or `popMax` can be slow when it has to skip a long run of deleted entries. The next approach removes each element from both structures immediately, so no entry is ever skipped.

<h1 id="approach-3-treemap-doubly-linked-list-optimal">
  Approach 3: TreeMap + Doubly Linked List (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

Let's think about what each operation truly needs. Push and pop need stack ordering (know what's on top). PeekMax and popMax need fast access to the maximum. PopMax needs to remove an element from the MIDDLE of the stack without disturbing the order.

No single data structure gives us all of this. But two data structures working together can. A doubly linked list maintains stack order and lets us remove any node in O(1) if we have a pointer to it. A balanced BST (TreeMap/SortedDict) lets us find and access the maximum in O(log n).

The bridge between them: the TreeMap maps each value to a list of linked list node references. When we push a value, we add a node to the tail of the linked list and also record a reference to that node in the TreeMap. When we call popMax, we look up the maximum key in the TreeMap, grab the most recently pushed node with that value, remove it from the linked list in O(1), and remove the reference from the TreeMap. No lazy deletion needed.

<h3 id="algorithm">Algorithm</h3>

1. Maintain a doubly linked list where the tail represents the top of the stack.
2. Maintain a TreeMap where each key is a value, and the associated data is a list of node references (in push order).
3. `push(x)`: Create a new node, append it to the tail of the linked list. In the TreeMap, add this node reference to the list under key `x`.
4. `pop()`: Remove the tail node from the linked list. Remove the last node reference from the TreeMap under the node's value. If that list is empty, remove the key.
5. `top()`: Return the tail node's value.
6. `peekMax()`: Return the last key in the TreeMap (the maximum).
7. `popMax()`: Get the last key from the TreeMap. Get the last node reference from that key's list. Remove that node from the doubly linked list. Remove the reference from the TreeMap.

```python
class MaxStack:

    def __init__(self):
        self.head = Node(0)
        self.tail = Node(0)
        self.head.next = self.tail
        self.tail.prev = self.head

        self.map = {}              # val -> list of nodes
        self.max_heap = []         # max heap using negative values

    def push(self, x: int) -> None:
        node = Node(x)

        # insert into DLL
        node.prev = self.tail.prev
        node.next = self.tail
        self.tail.prev.next = node
        self.tail.prev = node

        # map
        if x not in self.map:
            self.map[x] = []
        self.map[x].append(node)

        # heap
        heapq.heappush(self.max_heap, -x)

    def pop(self) -> int:
        node = self.tail.prev
        self._remove_node(node)

        val = node.val
        nodes = self.map[val]
        nodes.pop()
        if not nodes:
            del self.map[val]

        node.alive = False
        return val

    def top(self) -> int:
        return self.tail.prev.val

    def peekMax(self) -> int:
        self._clean_heap()
        return -self.max_heap[0]

    def popMax(self) -> int:
        self._clean_heap()
        max_val = -heapq.heappop(self.max_heap)

        node = self.map[max_val].pop()
        if not self.map[max_val]:
            del self.map[max_val]

        self._remove_node(node)
        node.alive = False

        return max_val

    def _remove_node(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _clean_heap(self):
        # remove stale elements
        while self.max_heap:
            val = -self.max_heap[0]
            if val in self.map and self.map[val]:
                break
            heapq.heappop(self.max_heap)
```

```rust
                val: 0,
                prev: 0,
                next: 1,
            },
            Node {
                val: 0,
                prev: 0,
                next: 1,
            },

        // insert into DLL
        let prev = self.nodes[self.tail].prev;
        self.nodes[node_idx].prev = prev;
        self.nodes[node_idx].next = self.tail;
        self.nodes[prev].next = node_idx;
        self.nodes[self.tail].prev = node_idx;

        // map
        self.map.entry(x).or_default().push(node_idx);

        let node_idx = self.nodes[self.tail].prev;
        let val = self.nodes[node_idx].val;
        self.remove_node(node_idx);

        let nodes = self.map.get_mut(&val).unwrap();
        nodes.pop();
        if nodes.is_empty() {
            self.map.remove(&val);
        }

        self.free.push(node_idx);
        val
    }

        *self.map.keys().next_back().unwrap()
    }

        let max_val = *self.map.keys().next_back().unwrap();
        let node_idx = self.map.get_mut(&max_val).unwrap().pop().unwrap();
        if self.map.get(&max_val).unwrap().is_empty() {
            self.map.remove(&max_val);
        }

        self.remove_node(node_idx);
        self.free.push(node_idx);
        max_val
    }

        if let Some(idx) = self.free.pop() {
            self.nodes[idx].val = val;
            self.nodes[idx].prev = self.head;
            self.nodes[idx].next = self.tail;
            idx
        } else {
            let idx = self.nodes.len();
            self.nodes.push(Node {
                val,
                prev: self.head,
                next: self.tail,
            });
            idx
        }
    }

    fn remove_node(&mut self, node_idx: usize) {
        let prev = self.nodes[node_idx].prev;
        let next = self.nodes[node_idx].next;
        self.nodes[prev].next = next;
        self.nodes[next].prev = prev;
```

```typescript
      else hi = mid;
    }
    this.sortedKeys.splice(lo, 1);
  }

  private removeNode(node: DLLNode): void {
    node.prev!.next = node.next;
    node.next!.prev = node.prev;
  }

  push(x: number): void {
    const node: DLLNode = { val: x, prev: this.tail.prev, next: this.tail };
    this.tail.prev!.next = node;
    this.tail.prev = node;
    this.addKey(x);
    if (!this.nodeMap.has(x)) this.nodeMap.set(x, []);
    this.nodeMap.get(x)!.push(node);
  }

  pop(): number {
    const node = this.tail.prev!;
    this.removeNode(node);
    const nodes = this.nodeMap.get(node.val)!;
    nodes.pop();
    this.removeKey(node.val);
    return node.val;
  }

  top(): number {
    return this.tail.prev!.val;
  }

  peekMax(): number {
    return this.sortedKeys[this.sortedKeys.length - 1];
  }

  popMax(): number {
    const maxVal = this.sortedKeys[this.sortedKeys.length - 1];
    const nodes = this.nodeMap.get(maxVal)!;
    const node = nodes.pop()!;
    this.removeKey(maxVal);
    this.removeNode(node);
    return maxVal;
  }
}
```

> - **Time Complexity:** O(log n) for push, pop, peekMax, and popMax. O(1) for top. The TreeMap operations (insert, delete, lastKey) are O(log n). The doubly linked list operations (append, remove node) are O(1).
> - **Space Complexity:** O(n). The linked list holds n nodes, and the TreeMap holds n node references distributed across its keys.
