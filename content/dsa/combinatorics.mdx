<LessonCard>

A direct approach quickly becomes infeasible as input sizes grow. Combinatorics provides closed-form tools that count without enumeration. The rest of this chapter covers permutations and combinations, Pascal's triangle, the standard identities, `nCr` under a modulus, and the stars-and-bars technique.

<h1 id="permutations-vs-combinations">Permutations vs Combinations</h1>

The two fundamental building blocks of combinatorics are permutations and combinations. The difference comes down to one question: does order matter?

- **Permutation (nPr):** The number of ways to arrange r items from n items where order matters.
- **Combination (nCr):** The number of ways to choose r items from n items where order does not matter.

**Formula for Permutations:**

```text
P(n, r) = n! / (n - r)!
```

**Formula for Combinations:**

```text
C(n, r) = n! / (r! * (n - r)!)
```

Notice that C(n, r) = P(n, r) / r!, because combinations remove the r! orderings that permutations count separately.

**Quick example:** From a group of 5 people `{A, B, C, D, E}`, suppose we want to pick 3.

- **Permutations** (order matters): ABC, ACB, BAC, BCA, CAB, CBA are all different. P(5,3) = 5! / 2! = 60.
- **Combinations** (order does not matter): `{A, B, C}` is the same regardless of order. C(5,3) = 5! / (3! \* 2!) = 10.

<h1 id="factorials-and-their-properties">Factorials and Their Properties</h1>

The factorial function is the foundation of all combinatorial formulas. For a non-negative integer n:

```text
n! = n * (n-1) * (n-2) * ... * 2 * 1
0! = 1 (by definition)
```

Key properties you should know:

- **Recursive definition:** n! = n \* (n-1)!
- **Growth rate:** Factorials grow fast. 20! ≈ 2.43 × 10^18 is the largest factorial that fits in a 64-bit signed integer. 21! (about 5.1 × 10^19) overflows.
- **Cancellation trick:** When computing C(n, r), you do not need to compute the full factorials. For example, C(10, 3) = (10 _ 9 _ 8) / (3 _ 2 _ 1) = 120. The (n-r)! in the denominator cancels most of the numerator.

<h1 id="pascals-triangle">Pascal's Triangle</h1>

Pascal's Triangle is one of the most elegant structures in mathematics, and it gives us a way to compute C(n, r) without ever computing a factorial.

The idea is simple. Each entry in the triangle is the sum of the two entries directly above it:

```text
C(n, r) = C(n-1, r-1) + C(n-1, r)
```

This is called Pascal's identity. It works because choosing r items from n items can be split into two cases: either a specific item is included (leaving C(n-1, r-1) choices) or it is not (leaving C(n-1, r) choices).

Here is what the first six rows look like:

```text
Row 0:                1
Row 1:              1   1
Row 2:            1   2   1
Row 3:          1   3   3   1
Row 4:        1   4   6   4   1
Row 5:      1   5  10  10   5   1
```

<h1 id="common-combinatorial-identities">Common Combinatorial Identities</h1>

Before we move to implementation, here are identities you should know.

| Identity               | Formula                                        | Meaning                                         |
| ---------------------- | ---------------------------------------------- | ----------------------------------------------- |
| Symmetry               | C(n, r) = C(n, n-r)                            | Choosing r to include = choosing n-r to exclude |
| Row sum                | C(n,0) + C(n,1) + ... + C(n,n) = 2^n           | Total subsets of an n-element set               |
| Pascal's identity      | C(n, r) = C(n-1, r-1) + C(n-1, r)              | Include or exclude one element                  |
| Vandermonde's identity | C(m+n, r) = sum of C(m,k)\*C(n,r-k)            | Choosing from two groups                        |
| Hockey stick           | C(r,r) + C(r+1,r) + ... + C(n,r) = C(n+1, r+1) | Sum along a diagonal                            |

The symmetry identity is especially useful for optimization. If you need C(100, 97), compute C(100, 3) instead, which requires far fewer multiplications.

<h1 id="ncr-with-modular-arithmetic">nCr with Modular Arithmetic</h1>

When n is large (say, up to 10^6), the values of C(n, r) become astronomically large. Interview problems typically ask you to return the answer modulo 10^9 + 7 (a prime number). This is where modular arithmetic becomes essential.

The approach has three parts:

1. **Precompute factorials** mod p: fact[i] = i! mod p
2. **Precompute inverse factorials** mod p: inv_fact[i] = (i!)^(-1) mod p
3. **Compute nCr** as: fact[n] _ inv_fact[r] _ inv_fact[n-r] mod p

To compute modular inverse, we use Fermat's little theorem. For a prime p:

```text
a^(-1) mod p = a^(p-2) mod p
```

This works because a^(p-1) = 1 (mod p) for any a not divisible by p, so a^(p-2) \* a = 1 (mod p).

The key optimization is computing `inv_fact` backwards. Instead of calling modular exponentiation `n` times, we compute `inv_fact[n]` once using fast exponentiation, then derive the rest with `inv_fact[i] = inv_fact[i+1] · (i+1) mod p` going downward. This brings the total precomputation to O(n) time.

The recurrence falls out of one identity. By definition, `(i+1)! = (i+1) · i!`. Divide both sides by `(i+1)! · i!`:

`1/i! = (i+1) · 1/(i+1)!`

That is exactly `inv_fact[i] = (i+1) · inv_fact[i+1]`, reduced modulo `p`. So one expensive `modPow` call seeds `inv_fact[n]`, and the rest is a single multiplication per step.

<h1 id="stars-and-bars-technique">Stars and Bars Technique</h1>

The stars and bars technique answers a classic question: how many ways can you distribute n identical items into k distinct bins?

The answer is C(n + k - 1, k - 1).

The intuition is beautiful. Imagine n stars in a row representing the items. You need k-1 bars to separate them into k groups. The total number of symbols is n + k - 1, and you are choosing where to place the k - 1 bars.

**Example:** Distribute 5 identical balls into 3 bins.

We need C(5 + 3 - 1, 3 - 1) = C(7, 2) = 21 ways.

One such distribution: `**|*|**` means 2 balls in bin 1, 1 in bin 2, 2 in bin 3.

This technique is the foundation for many interview problems involving distributing resources, partitioning numbers, or counting solutions to equations like x1 + x2 + x3 = n where xi >= 0.

<h3 id="example-1-building-pascals-triangle">
  Example 1: Building Pascal's Triangle
</h3>

Let us build the first 5 rows step by step.

```text
Start:    dp[0] = [1]

Row 1:    dp[1][0] = 1,  dp[1][1] = 1
          Result: [1, 1]

Row 2:    dp[2][0] = 1
          dp[2][1] = dp[1][0] + dp[1][1] = 1 + 1 = 2
          dp[2][2] = 1
          Result: [1, 2, 1]

Row 3:    dp[3][0] = 1
          dp[3][1] = dp[2][0] + dp[2][1] = 1 + 2 = 3
          dp[3][2] = dp[2][1] + dp[2][2] = 2 + 1 = 3
          dp[3][3] = 1
          Result: [1, 3, 3, 1]

Row 4:    dp[4][0] = 1
          dp[4][1] = dp[3][0] + dp[3][1] = 1 + 3 = 4
          dp[4][2] = dp[3][1] + dp[3][2] = 3 + 3 = 6
          dp[4][3] = dp[3][2] + dp[3][3] = 3 + 1 = 4
          dp[4][4] = 1
          Result: [1, 4, 6, 4, 1]
```

<h3 id="example-2-computing-c10-3">Example 2: Computing C(10, 3)</h3>

Using the cancellation trick:

```text
C(10, 3) = 10! / (3! * 7!)
         = (10 * 9 * 8) / (3 * 2 * 1)
         = 720 / 6
         = 120
```

There are 120 ways to choose 3 items from 10.

<h3 id="example-3-grid-paths">Example 3: Grid Paths</h3>

How many unique paths are there from the top-left to the bottom-right of a 4x3 grid, moving only right or down?

To go from (0,0) to (3,2), we must make exactly 3 right moves and 2 down moves, for a total of 5 moves. The number of paths is the number of ways to choose which 2 of the 5 moves are "down" (or equivalently, which 3 are "right"):

```text
C(5, 2) = 5! / (2! * 3!) = (5 * 4) / (2 * 1) = 10
```

More generally, for an m x n grid: paths = C(m + n - 2, m - 1).

<h1 id="implementation">Implementation</h1>

Below are three implementations: factorial-based nCr (for small values), Pascal's Triangle via DP, and nCr with modular arithmetic using precomputed factorials and inverse factorials.

<h3 id="approach-1-factorial-based-ncr-small-values">
  Approach 1: Factorial-Based nCr (Small Values)
</h3>

This approach computes nCr directly using the cancellation trick. It works well for small n (roughly n < 20 to avoid overflow without modular arithmetic).

```java
public class Combinatorics {
    // Computes C(n, r) using the multiplicative formula
    // Works for small n without overflow concerns
    public static long nCr(int n, int r) {
        if (r > n) return 0;
        if (r == 0 || r == n) return 1;
        // Use symmetry: C(n, r) = C(n, n-r)
        if (r > n - r) r = n - r;

        long result = 1;
        for (int i = 0; i < r; i++) {
            result = result * (n - i) / (i + 1);
        }
        return result;
    }
}
```

<h3 id="approach-2-pascals-triangle-dp">Approach 2: Pascal's Triangle (DP)</h3>

This approach builds the entire triangle up to row n. It is useful when you need multiple nCr values for the same n, or when you want to avoid division entirely.

```java
public class PascalTriangle {
    public static long[][] buildPascal(int n) {
        long[][] dp = new long[n + 1][];
        for (int i = 0; i <= n; i++) {
            dp[i] = new long[i + 1];
            dp[i][0] = 1;
            dp[i][i] = 1;
            for (int j = 1; j < i; j++) {
                dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j];
            }
        }
        return dp;
    }

    // Usage: dp[n][r] gives C(n, r)
}
```

<h3 id="approach-3-ncr-with-modular-arithmetic-large-values">
  Approach 3: nCr with Modular Arithmetic (Large Values)
</h3>

This is the approach you need for competitive programming and most interview problems involving large n. It precomputes factorials and inverse factorials modulo a prime (10^9 + 7), allowing O(1) nCr queries after O(n) preprocessing.

```java
public class ModCombinatorics {
    static final long MOD = 1_000_000_007;
    static long[] fact;
    static long[] invFact;

    // Call this once before any nCr queries
    public static void precompute(int n) {
        fact = new long[n + 1];
        invFact = new long[n + 1];
        fact[0] = 1;
        for (int i = 1; i <= n; i++) {
            fact[i] = fact[i - 1] * i % MOD;
        }
        invFact[n] = modPow(fact[n], MOD - 2, MOD);
        for (int i = n - 1; i >= 0; i--) {
            invFact[i] = invFact[i + 1] * (i + 1) % MOD;
        }
    }

    public static long nCr(int n, int r) {
        if (r < 0 || r > n) return 0;
        return fact[n] % MOD * invFact[r] % MOD * invFact[n - r] % MOD;
    }

    private static long modPow(long base, long exp, long mod) {
        long result = 1;
        base %= mod;
        while (exp > 0) {
            if ((exp & 1) == 1) {
                result = result * base % mod;
            }
            exp >>= 1;
            base = base * base % mod;
        }
        return result;
    }
}
```

```rust
const MOD: i64 = 1_000_000_007;
static mut FACT: Vec<i64> = Vec::new();
static mut INV_FACT: Vec<i64> = Vec::new();

// Call this once before any nCr queries
pub fn precompute(n: usize) {
    let mut fact = vec![0i64; n + 1];
    let mut inv_fact = vec![0i64; n + 1];
    fact[0] = 1;
    for i in 1..=n {
        fact[i] = fact[i - 1] * i as i64 % MOD;
    }
    inv_fact[n] = mod_pow(fact[n], MOD - 2, MOD);
    for i in (0..n).rev() {
        inv_fact[i] = inv_fact[i + 1] * (i as i64 + 1) % MOD;
    }
    unsafe {
        FACT = fact;
        INV_FACT = inv_fact;
    }
}

pub fn n_cr(n: usize, r: i32) -> i64 {
    if r < 0 || r as usize > n {
        return 0;
    }
    let r = r as usize;
    unsafe {
        FACT[n] % MOD * INV_FACT[r] % MOD * INV_FACT[n - r] % MOD
    }
}
```

```javascript
  }
  return { fact, invFact };
}

function nCr(n, r, fact, invFact) {
  if (r < 0 || r > n) return 0n;
  return (((fact[n] * invFact[r]) % MOD) * invFact[n - r]) % MOD;
}
```

```typescript
const MOD = 1_000_000_007n;

function modPow(base: bigint, exp: bigint, mod: bigint): bigint {
  let result = 1n;
  base %= mod;
  while (exp > 0n) {
    if (exp & 1n) result = (result * base) % mod;
    exp >>= 1n;
    base = (base * base) % mod;
  }
  return result;
}

function precompute(n: number): { fact: bigint[]; invFact: bigint[] } {
  const fact: bigint[] = new Array(n + 1);
  const invFact: bigint[] = new Array(n + 1);
  fact[0] = 1n;
  for (let i = 1; i <= n; i++) {
    fact[i] = (fact[i - 1] * BigInt(i)) % MOD;
  }
  invFact[n] = modPow(fact[n], MOD - 2n, MOD);
  for (let i = n - 1; i >= 0; i--) {
    invFact[i] = (invFact[i + 1] * BigInt(i + 1)) % MOD;
  }
  return { fact, invFact };
}

function nCr(n: number, r: number, fact: bigint[], invFact: bigint[]): bigint {
  if (r < 0 || r > n) return 0n;
  return (((fact[n] * invFact[r]) % MOD) * invFact[n - r]) % MOD;
}
```

<h1 id="complexity-analysis">Complexity Analysis</h1>

| Approach                  | Time                                          | Space  | Best For                  |
| ------------------------- | --------------------------------------------- | ------ | ------------------------- |
| Factorial-based nCr       | O(r) per query                                | O(1)   | Small n, single query     |
| Pascal's Triangle         | O(n^2) build, O(1) query                      | O(n^2) | Multiple queries, small n |
| Modular nCr (precomputed) | O(n) build + O(log p) for inverse, O(1) query | O(n)   | Large n, mod arithmetic   |

For most interview problems, the modular approach is what you need. Precompute once, query in O(1). The Pascal's Triangle approach is great when n is small (say, under 1000) and you want to avoid dealing with modular inverse.
