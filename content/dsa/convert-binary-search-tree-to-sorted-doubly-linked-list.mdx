Convert a **Binary Search Tree** to a sorted **Circular Doubly-Linked List** in place.

Think of the left and right pointers as synonymous to the predecessor and successor pointers in a doubly-linked list. For a circular doubly linked list, the predecessor of the first element is the last element, and the successor of the last element is the first element.

We want to do the transformation **in place**. After the transformation, the left pointer of the tree node should point to its predecessor, and the right pointer should point to its successor. You should return the pointer to the smallest element of the linked list.

**Example 1:**

- **Input:** `root = [4,2,5,1,3]`

- **Output:** `[1,2,3,4,5]`

**Example 2:**

- **Input:** `root = [2,1,3]`

- **Output:** `[1,2,3]`

**Example 3:**

- **Input:** `root = []`

- **Output:** `[]`

**Example 4:**

- **Input:** `root = [1]`

- **Output:** `[1]`

**Constraints:**

- `The number of nodes in the tree is in the range [0, 2000]`
- `-1000 <= Node.val <= 1000`
- `All the values of the tree are unique`

We're given a BST and need to rearrange its pointers so it becomes a sorted circular doubly linked list. No new nodes are created. We reuse the existing tree nodes and change what `left` and `right` point to: `left` becomes the `prev` pointer of the doubly linked list, and `right` becomes the `next` pointer.

Since it's a BST, an in-order traversal visits nodes in sorted order. The problem reduces to: visit the nodes in that order, link each one to the node visited before it, and finally connect the head and tail to make the list circular.

- `0 <= number of nodes <= 2000` → The tree can be empty, so every approach must return null for a null root before touching any pointers.
- `-1000 <= Node.val <= 1000` → Values are never added or multiplied, only linked, so the range has no overflow implications.
- `All values are unique` → Each node has a distinct position in the sorted order, so no tie-breaking logic is needed.

<h3 id="intuition">Intuition</h3>

An in-order traversal of the BST visits nodes in sorted order. Collect them into a list, then rewire the pointers in a second pass: walk through the list, set each node's `right` to the next node and each node's `left` to the previous node, and connect the first and last nodes to make the list circular.

Separating "get the sorted order" from "link the nodes" keeps each step simple. No pointers change during the traversal itself, so the rewiring cannot interfere with how we walk the tree.

<h3 id="algorithm">Algorithm</h3>

1. Handle the edge case: if the root is null, return null.
2. Perform an in-order traversal of the BST, collecting all nodes into a list.
3. Iterate through the list and link consecutive nodes:
4. Close the circular connection: set `head.left = tail` and `tail.right = head`.
5. Return the head (first element in the sorted list).

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n). We visit every node exactly once during the in-order traversal, then iterate through the collected list once to rewire pointers. Both passes are O(n).
> - **Space Complexity:** O(n). The list storing all n nodes takes O(n) space. The recursion stack adds O(h) where h is the height of the tree (O(n) worst case for a skewed tree), but the list dominates.

The list of collected nodes is the only reason this approach needs O(n) extra space. The next approach links nodes during the traversal itself and drops that list.

<h1 id="approach-2-recursive-in-order-with-in-place-linking-optimal">
  Approach 2: Recursive In-Order with In-Place Linking (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

Instead of collecting all nodes and linking them afterward, we can link nodes together during the in-order traversal itself. During in-order traversal, the previously visited node is exactly the predecessor of the current node in sorted order, so a single pointer to the last processed node is all the state needed to wire up the doubly linked list.

Maintain two pointers: `first` (the head of the list, the smallest node) and `last` (the most recently processed node). As we visit each node during in-order traversal:

- Set `last.right = current` (the previous node's next pointer)
- Set `current.left = last` (the current node's prev pointer)
- Update `last = current`

When the traversal is done, `first` holds the smallest node and `last` holds the largest. Connect them to close the circle: `first.left = last` and `last.right = first`.

> Overwriting pointers in the middle of the traversal is safe because of the order in which they are touched. When the traversal processes a node, its left subtree is already fully visited, so reassigning `current.left` affects nothing the traversal still needs. Reassigning `last.right` is also safe: a node's `right` pointer is only overwritten after the traversal has already descended into its right subtree, and the recursive call `inOrder(node.right)` received the original child reference before the reassignment. The traversal keeps walking the original tree structure even as the list pointers are written over it.

<h3 id="algorithm">Algorithm</h3>

1. Handle the edge case: if the root is null, return null.
2. Initialize two pointers: `first = null` (will track the smallest node) and `last = null` (will track the most recently visited node).
3. Perform in-order traversal. At each node:
4. After traversal completes, close the circular link: `first.left = last` and `last.right = first`.
5. Return `first`.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n). We visit every node exactly once during the in-order traversal. Each visit does O(1) work (pointer reassignment). The final circular connection is O(1).
> - **Space Complexity:** O(h) where h is the height of the tree. The only extra space is the recursion stack. For a balanced BST, h = O(log n). For a skewed tree, h = O(n) in the worst case.

The recursive approach puts the O(h) space on the call stack, which has a fixed limit. The same traversal can run iteratively with an explicit stack on the heap.

<h1 id="approach-3-iterative-in-order-with-explicit-stack">
  Approach 3: Iterative In-Order with Explicit Stack
</h1>

<h3 id="intuition">Intuition</h3>

The logic is identical to the recursive approach: traverse in order and link each node to the previously visited one. The difference is that we drive the traversal with our own stack instead of the call stack, using the standard iterative in-order pattern: push nodes while walking left, pop and process, then move to the right child.

The rewiring stays safe here for the same ordering reason as in the recursive version: after processing a node we read `current.right` to continue the traversal, and that pointer is not overwritten until the next node is popped, which happens after the read. A deeply skewed tree no longer risks overflowing the call stack, since the explicit stack grows on the heap.

<h3 id="algorithm">Algorithm</h3>

1. Handle the edge case: if the root is null, return null.
2. Initialize a stack, and set `first = null`, `last = null`.
3. Push nodes: start from root, keep pushing `node.left` until we reach null.
4. Pop a node from the stack. This is the next node in sorted order.
5. Link it with `last` (same logic as the recursive approach).
6. Move to `node.right` and repeat step 3.
7. When the stack is empty and there's no node to process, close the circular connection and return `first`.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n). Every node is pushed onto the stack exactly once and popped exactly once. Processing each node is O(1).
> - **Space Complexity:** O(h) where h is the height of the tree (O(n) worst case for a skewed tree). The explicit stack holds at most h nodes at any time. Same asymptotic bound as the recursive approach, but now the space is on the heap rather than the call stack.
