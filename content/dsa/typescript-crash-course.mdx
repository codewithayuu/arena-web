<h1 id="built-in-data-structures">Built-in Data Structures</h1>

TypeScript on LeetCode works like JavaScript with types bolted on. You do not need to import anything for the core data structures and utilities. Everything is globally available:

| Built-in                 | What It Provides                                     | DSA Use Case                          |
| ------------------------ | ---------------------------------------------------- | ------------------------------------- |
| `Array`                  | Dynamic array with rich methods                      | Primary data structure for everything |
| `Map`                    | Hash map with any key type                           | Frequency counting, O(1) lookups      |
| `Set`                    | Hash set with any value type                         | Visited tracking, deduplication       |
| `Math`                   | `max`, `min`, `floor`, `ceil`, `abs`, `sqrt`, `log2` | Utility calculations                  |
| `JSON`                   | `stringify`, `parse`                                 | Deep copy, composite keys             |
| `Infinity` / `-Infinity` | Global sentinel values                               | Min/max initialization                |

But TypeScript also has notable gaps. These are data structures needed in DSA with no built-in equivalent:

| Not Built-in      | What You Must Do                         |
| ----------------- | ---------------------------------------- |
| Queue             | Use object with pointers, or linked list |
| Deque             | Use array (limited), or custom class     |
| PriorityQueue     | Implement a min-heap yourself            |
| TreeMap / TreeSet | Sorted array + binary search (limited)   |

We will cover typed implementations for each of these missing structures later in this chapter. What TypeScript does give you is clean, type-safe, and fast to write.

<h1 id="variables-types-and-the-number-type">
  Variables, Types, and the Number Type
</h1>

TypeScript is a statically typed superset of JavaScript. You declare types explicitly, or let the compiler infer them:

```typescript
let count: number = 0; // explicit type annotation
const ratio = 3.14; // inferred as number
const name: string = "hello"; // string
let found: boolean = true; // boolean
const nothing: null = null; // null
let missing: undefined; // undefined
```

For variable declarations, follow one rule: **use **`**const**`** by default, **`**let**`** when you need to reassign, never **`**var**`**.** The `var` keyword has function scope (not block scope), which leads to subtle bugs in loops and conditionals. Both `let` and `const` are block-scoped, which is what you expect.

```typescript
// var leaks out of blocks
for (var i = 0; i < 5; i++) {}
console.log(i); // 5 (still accessible!)

// let stays in its block
for (let j = 0; j < 5; j++) {}
// console.log(j); // Error: j is not defined
```

For DSA, a small set of types is enough:

| Type        | Example                  | DSA Use Case                                       |
| ----------- | ------------------------ | -------------------------------------------------- |
| `number`    | `42`, `3.14`, `Infinity` | Everything numeric (no separate int/float!)        |
| `string`    | `"hello"`                | Immutable character sequences                      |
| `boolean`   | `true`, `false`          | Visited arrays, flags                              |
| `null`      | `null`                   | Intentional absence (tree/linked list terminators) |
| `undefined` | `undefined`              | Uninitialized variables, missing properties        |
| `bigint`    | `42n`                    | Values exceeding 2^53 - 1 (rare in DSA)            |

TypeScript has no integer type. Every number is an IEEE 754 64-bit floating-point double, exactly like JavaScript. The number `42` and the number `42.0` are the same value, the same type, stored the same way.

This has three implications for DSA:

**1. Division always produces a float.** In TypeScript, `7 / 2` gives `3.5`, not `3`. You must explicitly truncate when you need an integer:

```typescript
// Integer division in TypeScript
Math.floor(7 / 2); // 3 (rounds toward negative infinity)
Math.trunc(7 / 2); // 3 (rounds toward zero)
Math.ceil(7 / 2); // 4 (rounds toward positive infinity)

// For positive numbers, floor and trunc are the same
// For negative numbers, they differ:
Math.floor(-7 / 2); // -4 (rounds down)
Math.trunc(-7 / 2); // -3 (rounds toward zero)
```

**2. Integer precision is limited to 2^53 - 1.** The `Number.MAX_SAFE_INTEGER` is 9,007,199,254,740,991. Beyond this, integer arithmetic loses precision without warning:

```typescript
console.log(9007199254740992 === 9007199254740993); // true! Both round to the same float
```

For most DSA problems where constraints are up to 10^9, this is not an issue. If you truly need arbitrary precision, use `BigInt`:

```typescript
const big: bigint = 9007199254740993n; // note the 'n' suffix
const result: bigint = big * 2n; // BigInt arithmetic
// Cannot mix: big + 1 throws TypeError. Must use big + 1n
```

**3. Binary search midpoint does not overflow, but needs floor.** TypeScript numbers safely hold sums up to 2^53, so `(left + right)` will not overflow for typical DSA inputs. But you need `Math.floor` because division produces a float:

```typescript
// WRONG: produces a float when left + right is odd
const mid = (left + right) / 2;

// CORRECT: floor to get integer index
const mid = Math.floor((left + right) / 2);
```

The **ternary operator** works exactly as in other languages:

```typescript
const result = a > b ? a : b; // Same as Math.max(a, b)
const label = count === 1 ? "item" : "items";
```

<h1 id="type-annotations-and-inference">Type Annotations and Inference</h1>

TypeScript's type system catches bugs before you run your code, which matters in DSA where one off-by-one or null-handling mistake can fail a submission. Here is what you need to know.

**When to annotate vs. let TypeScript infer:**

```typescript
// Inference works great for simple assignments
const count = 0; // inferred as number
const names = ["a", "b"]; // inferred as string[]

// Annotate when the type is not obvious from the value
let result: number[] = []; // empty array needs annotation
let node: ListNode | null = head; // union type
const freq: Map<string, number> = new Map(); // generic types
```

**Function signatures** should always be annotated. This is where type safety pays off most:

```typescript
function twoSum(nums: number[], target: number): number[] {
  const map = new Map<number, number>();
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (map.has(complement)) {
      return [map.get(complement)!, i];
    }
    map.set(nums[i], i);
  }
  return [];
}
```

The `!` after `map.get(complement)` is the **non-null assertion operator**. We already checked `map.has(complement)`, so we know the value exists, but TypeScript does not know that. The `!` tells the compiler "trust me, this is not undefined." We will cover this in detail in the Null Handling section.

**Array types** have two equivalent syntaxes:

```typescript
const nums: number[] = [1, 2, 3]; // Preferred for simple types
const grid: number[][] = [
  [1, 2],
  [3, 4],
]; // 2D array
const words: Array<string> = ["hello"]; // Generic syntax (same thing)
```

Use `number[]` for simple types and `Array<T>` when the element type is complex (like `Array<[number, number]>`).

**Tuple types** are useful for DSA. Unlike plain arrays, tuples have fixed length and typed positions:

```typescript
// A tuple representing [row, col]
const cell: [number, number] = [3, 5];

// Tuple with named elements (TypeScript 4.0+)
type Coordinate = [row: number, col: number];
const pos: Coordinate = [1, 2];

// Tuple for BFS queue entries: [row, col, distance]
type BFSEntry = [number, number, number];
const entry: BFSEntry = [0, 0, 0];
```

**Union types** handle cases where a value can be one of several types:

```typescript
// Tree node can be a TreeNode or null
let current: TreeNode | null = root;

// Function that returns a number or -1 for "not found"
function indexOf(nums: number[], target: number): number {
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] === target) return i;
  }
  return -1;
}
```

**Type narrowing** is how TypeScript automatically refines a union type based on control flow:

```typescript
function process(node: TreeNode | null): number {
  if (node === null) return 0; // After this line, node is TreeNode (not null)
  return node.val + process(node.left) + process(node.right);
}
```

The compiler tracks which branches have already handled `null`, so you get full type safety without extra casts.

<h1 id="operators-and-control-flow">Operators and Control Flow</h1>

Most operators work exactly like JavaScript, but a few deserve special attention for DSA.

<h3 id="strict-equality">Strict Equality</h3>

**Always use **`**===**`** and **`**!==**`** in TypeScript.** The `==` operator performs type coercion, which creates surprising results:

```typescript
0 == ""; // true (empty string coerces to 0)
0 == false; // true (false coerces to 0)
null == undefined; // true (special coercion rule)
"5" == 5; // true (string coerces to number; TypeScript may warn about this)

// With ===, none of these are true
0 === ""; // false
0 === false; // false
null === undefined; // false
```

TypeScript's type system helps here. It will flag many invalid `==` comparisons as errors. But `===` is still the right habit.

<h3 id="modular-arithmetic">Modular Arithmetic</h3>

The `%` operator appears in hashing, cyclic array problems, and math-heavy questions. Like JavaScript, TypeScript's `%` can return negative values for negative operands: `-7 % 3` gives `-1`, not `2`. To guarantee a positive result:

```typescript
((n % m) + m) % m; // Always non-negative
```

Many problems ask you to return the result "modulo 10^9 + 7":

```typescript
const MOD = 1_000_000_007; // Underscores for readability

let result = 0;
for (let i = 0; i < n; i++) {
  result = (result + values[i]) % MOD;
}
return result;
```

<h3 id="bitwise-operators">Bitwise Operators</h3>

Bitwise operators convert their operands to 32-bit signed integers. This means they work correctly for values up to about 2 billion, but produce wrong results for larger numbers without warning:

```typescript
// Works fine for normal DSA values
const isSet = (mask & (1 << i)) !== 0; // Check if bit i is set
const setBit = mask | (1 << i); // Set bit i
const clearBit = mask & ~(1 << i); // Clear bit i
const toggleBit = mask ^ (1 << i); // Toggle bit i

// XOR trick: find the number that appears once
let single = 0;
for (const num of nums) {
  single ^= num; // XOR cancels out duplicates
}
```

The key bitwise operators:

| Operator             | Symbol | DSA Use                                      |
| -------------------- | ------ | -------------------------------------------- |
| AND                  | `&`    | Masking, checking if bit is set              |
| OR                   | `\|`   | Setting bits                                 |
| XOR                  | `^`    | Finding unique elements, toggling            |
| NOT                  | `~`    | Bit inversion                                |
| Left shift           | `<<`   | Multiply by powers of 2: `1 << n` equals 2^n |
| Right shift          | `>>`   | Signed right shift (preserves sign)          |
| Unsigned right shift | `>>>`  | Unsigned right shift (fills with 0)          |

**Warning:** `1 << 31` gives `-2147483648` (negative!) because it sets the sign bit of a 32-bit integer. For bitmask problems with up to 20-25 elements, this is not a concern. For problems using all 32 bits, be careful.

<h3 id="control-flow">Control Flow</h3>

TypeScript offers three loop forms. Use each where it fits:

```typescript
// Index-based for: when you need the index
for (let i = 0; i < nums.length; i++) { ... }

// Backward traversal (used in some DP and stack problems)
for (let i = n - 1; i >= 0; i--) { ... }

// for-of: when you only need values
for (const num of nums) { ... }

// While: when the termination condition is not index-based
while (left < right) { ... }
```

One limitation: the `for-of` loop does not give you the index. If you need both index and value, use `for` with an index or `nums.forEach((val, idx) => ...)`.

<h3 id="nullish-coalescing-and-optional-chaining">
  Nullish Coalescing and Optional Chaining
</h3>

These two operators handle safe access in TypeScript:

```typescript
// Nullish coalescing: returns right side if left is null or undefined
const count = map.get(key) ?? 0; // 0 if key not found (get returns undefined)

// Optional chaining: short-circuits to undefined if left is null/undefined
const leftVal = node?.left?.val; // undefined if node or node.left is null

// Combining both: safe access with default
const val = node?.left?.val ?? 0;
```

The `??` operator is different from `||`. The `||` operator treats `0`, `""`, and `false` as falsy and returns the right side. The `??` operator only triggers on `null` and `undefined`. For frequency counting where 0 is a valid count, always use `??`.

<h1 id="functions-scope-and-generics">Functions, Scope, and Generics</h1>

In DSA problems on LeetCode, your solution is typically a function or a class method. TypeScript supports both regular functions and arrow functions:

```typescript
// Regular function with type annotations
function maxDepth(root: TreeNode | null): number {
  if (!root) return 0;
  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}

// Arrow function (common for helpers and callbacks)
const swap = (arr: number[], i: number, j: number): void => {
  [arr[i], arr[j]] = [arr[j], arr[i]];
};
```

<h3 id="pass-by-value-with-reference-types">
  Pass-by-Value with Reference Types
</h3>

TypeScript, like JavaScript, is always **pass-by-value**. But for objects (including arrays, Maps, Sets), the "value" is a reference. This means:

- **Primitive parameters** are copies. Changing them inside a function does not affect the caller.
- **Object/array parameters** pass a copy of the reference. You can modify the contents (like `arr[i] = 5`), but reassigning the reference itself does not affect the caller.

This is why backtracking works. You modify a shared array and undo the modification after recursion:

```typescript
function backtrack(path: number[], results: number[][]): void {
  if (isComplete(path)) {
    results.push([...path]); // MUST spread-copy, not push reference
    return;
  }
  for (const choice of choices) {
    path.push(choice); // Modify shared array
    backtrack(path, results); // Recurse
    path.pop(); // Undo modification
  }
}
```

The `[...path]` spread when saving results creates a copy. If you wrote `results.push(path)` instead, every entry in `results` would be a reference to the same array, and they would all end up empty after backtracking unwinds.

<h3 id="generics">Generics</h3>

Generics let you write type-safe, reusable code:

```typescript
// Generic function: works with any array type
function swap<T>(arr: T[], i: number, j: number): void {
  [arr[i], arr[j]] = [arr[j], arr[i]];
}

swap([1, 2, 3], 0, 2); // T inferred as number
swap(["a", "b", "c"], 0, 2); // T inferred as string
```

Generics appear heavily in the Queue and MinHeap implementations later. For now, think of `<T>` as "this works for any type T."

<h3 id="closures">Closures</h3>

Closures capture variables from their enclosing scope. This is useful in DSA for creating comparators and memoization:

```typescript
// Closure capturing 'graph' from outer scope
function dfs(
  node: number,
  visited: Set<number>,
  graph: Map<number, number[]>,
): void {
  visited.add(node);
  for (const neighbor of graph.get(node) ?? []) {
    if (!visited.has(neighbor)) {
      dfs(neighbor, visited, graph);
    }
  }
}
```

<h1 id="arrays">Arrays</h1>

Arrays are the foundational data structure and the starting point for almost every DSA problem.

```typescript
// Declaration and initialization
const nums: number[] = [1, 2, 3, 4, 5];
const visited: boolean[] = new Array(n).fill(false);
const dp: number[] = new Array(n + 1).fill(0);
const grid: number[][] = Array.from({ length: rows }, () =>
  new Array(cols).fill(0),
);
```

**Array initialization matters.** There is a gotcha with 2D arrays:

```typescript
// WRONG: all rows share the same inner array reference!
const bad: number[][] = new Array(3).fill(new Array(3).fill(0));
bad[0][0] = 1; // Changes ALL rows because they are the same array!

// CORRECT: each row is a new array
const good: number[][] = Array.from({ length: 3 }, () => new Array(3).fill(0));
good[0][0] = 1; // Only changes row 0
```

This is a common bug in matrix problems. `fill()` does not clone objects. It fills every slot with the same reference.

**The **`**.length**`** property** gives the array size. TypeScript is consistent across arrays and strings:

```typescript
const arr = [1, 2, 3];
arr.length; // 3 (property)

const s = "hello";
s.length; // 5 (property)

// Map and Set use .size instead
const map = new Map();
map.size; // 0 (property)
```

<h3 id="2d-arrays">2D Arrays</h3>

2D arrays appear in every matrix problem (BFS on grid, dynamic programming tables):

```typescript
const matrix: number[][] = Array.from({ length: rows }, () =>
  new Array(cols).fill(0),
);

// Access: matrix[row][col]
// Row count: matrix.length
// Column count: matrix[0].length
```

For DP problems, you often need a table with one extra row and column for the base case:

```typescript
const dp: number[] = new Array(n + 1).fill(0);
const dp2d: number[][] = Array.from({ length: m + 1 }, () =>
  new Array(n + 1).fill(0),
);
```

The 4-directional neighbor pattern is one of the most common patterns in matrix problems:

```typescript
const directions: number[][] = [
  [-1, 0],
  [1, 0],
  [0, -1],
  [0, 1],
];

for (const [dr, dc] of directions) {
  const newRow = row + dr;
  const newCol = col + dc;
  if (newRow >= 0 && newRow < rows && newCol >= 0 && newCol < cols) {
    // Process neighbor
  }
}
```

For 8-directional movement (including diagonals), add the four diagonal pairs: `[-1,-1], [-1,1], [1,-1], [1,1]`.

<h3 id="essential-array-methods">Essential Array Methods</h3>

```typescript
const arr: number[] = [1, 2, 3];

// Adding and removing
arr.push(4); // Add to end: O(1) -> [1, 2, 3, 4]
arr.pop(); // Remove from end: O(1) -> [1, 2, 3]
arr.unshift(0); // Add to front: O(n) -> [0, 1, 2, 3]
arr.shift(); // Remove from front: O(n) -> [1, 2, 3]

// Slicing and splicing
arr.slice(1, 3); // Copy subarray [1, 3): [2, 3] (does NOT modify original)
arr.splice(1, 1); // Remove 1 element at index 1: O(n) (MODIFIES original)

// Searching
arr.indexOf(2); // First index of value, -1 if not found: O(n)
arr.includes(2); // Boolean membership check: O(n)

// Utility
arr.reverse(); // Reverse in place
arr.fill(0); // Fill all elements with 0
arr.join(","); // Join elements: "1,2,3"
```

**The spread operator** `...` is the standard way to copy and combine arrays:

```typescript
const copy = [...arr]; // Shallow copy
const combined = [...arr1, ...arr2]; // Concatenate
const max = Math.max(...arr); // Spread into function arguments
const min = Math.min(...arr);
```

`**Array.from()**` creates arrays from iterables or with initialization logic:

```typescript
// Create array of indices
const indices = Array.from({ length: n }, (_, i) => i); // [0, 1, 2, ..., n-1]

// Create 2D array
const grid = Array.from({ length: rows }, () => new Array(cols).fill(0));

// Convert Set to Array
const arr = Array.from(mySet);
// Or equivalently: const arr = [...mySet];
```

<h1 id="strings">Strings</h1>

Strings in TypeScript are **immutable**. Every time you "modify" a string, you create a new one. This has a performance implication:

```typescript
// BAD: O(n^2) because each += creates a new string
let result = "";
for (const c of chars) {
  result += c; // Creates a new string every iteration
}

// GOOD: O(n) with array join
const parts: string[] = [];
for (const c of chars) {
  parts.push(c);
}
const result = parts.join("");
```

TypeScript does not have a dedicated mutable string builder. The standard approach is to collect parts in an array and join at the end.

Common string methods:

| Method                  | Returns    | Example              | DSA Use                                      |
| ----------------------- | ---------- | -------------------- | -------------------------------------------- |
| `charAt(i)` or `[i]`    | `string`   | `s[0]`               | Access individual characters                 |
| `length`                | `number`   | `s.length`           | Loop bounds (property, no parentheses)       |
| `substring(start, end)` | `string`   | `s.substring(0, 3)`  | Extract portions (end exclusive)             |
| `slice(start, end)`     | `string`   | `s.slice(0, 3)`      | Same as substring, supports negative indices |
| `split(sep)`            | `string[]` | `s.split(" ")`       | Tokenize strings                             |
| `indexOf(str)`          | `number`   | `s.indexOf("ab")`    | Find substrings (-1 if not found)            |
| `includes(str)`         | `boolean`  | `s.includes("ab")`   | Substring check                              |
| `startsWith(prefix)`    | `boolean`  | `s.startsWith("ab")` | Prefix check                                 |
| `endsWith(suffix)`      | `boolean`  | `s.endsWith("ab")`   | Suffix check                                 |
| `trim()`                | `string`   | `s.trim()`           | Remove leading/trailing whitespace           |
| `toLowerCase()`         | `string`   | `s.toLowerCase()`    | Case conversion                              |
| `toUpperCase()`         | `string`   | `s.toUpperCase()`    | Case conversion                              |
| `repeat(n)`             | `string`   | `"ab".repeat(3)`     | `"ababab"`                                   |

**Template literals** let you embed expressions in strings, which is useful for creating composite Map keys:

```typescript
// Composite key for a grid cell
const key = `${row},${col}`;
visited.add(key);

// Composite key for a state in BFS
const state = `${row},${col},${direction}`;
```

<h3 id="character-utilities">Character Utilities</h3>

TypeScript does not have a separate `char` type. Characters are single-character strings. To work with character codes, use `charCodeAt` and `String.fromCharCode`:

```typescript
const code = "a".charCodeAt(0); // 97
const char = String.fromCharCode(97); // "a"

// Map 'a'-'z' to 0-25 (frequency arrays)
const index = s.charCodeAt(i) - "a".charCodeAt(0);

// Map 0-25 back to 'a'-'z'
const char = String.fromCharCode("a".charCodeAt(0) + index);

// Check if character is alphanumeric
const isAlphaNum = (c: string): boolean => /^[a-zA-Z0-9]$/.test(c);

// Check if character is a digit
const isDigit = (c: string): boolean => c >= "0" && c <= "9";

// Check if character is a letter
const isLetter = (c: string): boolean => /^[a-zA-Z]$/.test(c);
```

The frequency array pattern using character codes:

```typescript
// Frequency array for lowercase letters (26 slots)
const freq: number[] = new Array(26).fill(0);
const aCode = "a".charCodeAt(0);
for (const c of s) {
  freq[c.charCodeAt(0) - aCode]++;
}
// freq[0] = count of 'a', freq[1] = count of 'b', etc.
```

This is faster and more memory-efficient than `Map<string, number>` when you know the character set is limited to lowercase (or uppercase, or digits).

<h1 id="collections-map-set-and-record">Collections: Map, Set, and Record</h1>

Choosing the right collection is often the difference between an O(n) and an O(n^2) solution. TypeScript inherits JavaScript's collections but adds type safety through generics.

<h3 id="map-the-hashmap-equivalent">Map: The HashMap Equivalent</h3>

ES6 `Map` with TypeScript generics gives you a type-safe hash map with O(1) average-case operations:

```typescript
const freq = new Map<string, number>();

// Frequency counting (most common Map pattern)
for (const c of s) {
  freq.set(c, (freq.get(c) ?? 0) + 1);
}

// Key operations
freq.has("a"); // Check if key exists: O(1)
freq.get("a"); // Get value (returns undefined if missing): O(1)
freq.set("a", 5); // Set value: O(1)
freq.delete("a"); // Remove key: O(1)
freq.size; // Number of entries (property, not method!)
freq.clear(); // Remove all entries

// Iteration (insertion order is preserved)
for (const [key, value] of freq) {
  /* key-value pairs */
}
for (const key of freq.keys()) {
  /* keys only */
}
for (const value of freq.values()) {
  /* values only */
}
```

**A critical type safety point:** `map.get(key)` returns `V | undefined` in TypeScript. The compiler forces you to handle the missing-key case explicitly:

```typescript
// TypeScript error: Type 'number | undefined' is not assignable to 'number'
const count: number = freq.get("a");

// Fix 1: nullish coalescing
const count: number = freq.get("a") ?? 0;

// Fix 2: non-null assertion (only when you KNOW the key exists)
const count: number = freq.get("a")!;
```

<h3 id="set-the-hashset-equivalent">Set: The HashSet Equivalent</h3>

```typescript
const visited = new Set<number>();

visited.add(node); // Add element: O(1)
visited.has(node); // Check membership: O(1)
visited.delete(node); // Remove element: O(1)
visited.size; // Number of elements

// Create from array (deduplication!)
const unique = new Set(nums);
const uniqueArr = [...new Set(nums)]; // Back to array

// Iteration
for (const val of visited) {
  /* values */
}
```

**Important:** Sets use reference equality for objects and arrays. `new Set([[1,2], [1,2]])` has size 2, not 1, because the two `[1,2]` arrays are different objects. For composite keys, serialize to strings:

```typescript
const visited = new Set<string>();
visited.add(`${row},${col}`); // Use template literal as key
visited.has(`${newRow},${newCol}`); // Check membership
```

<h3 id="record-type">Record Type</h3>

TypeScript's `Record` type creates typed plain objects, useful as lightweight maps with string keys:

```typescript
// Record<string, number> is equivalent to { [key: string]: number }
const freq: Record<string, number> = {};
for (const c of s) {
  freq[c] = (freq[c] ?? 0) + 1;
}

// Check existence
if (c in freq) {
  /* exists */
}
if (freq[c] !== undefined) {
  /* exists */
}

// Iterate
for (const key of Object.keys(freq)) {
  /* keys */
}
for (const [key, value] of Object.entries(freq)) {
  /* key-value pairs */
}
```

Use `Map<K, V>` as your default. Use `Record` only when you need a quick string-keyed frequency map and want concise code.

<h3 id="queue-implementation-typed">Queue Implementation (Typed)</h3>

TypeScript has no built-in queue with O(1) dequeue. A typed implementation using an object as a sparse array with head/tail pointers:

```typescript
class Queue<T> {
  private items: Record<number, T> = {};
  private head = 0;
  private tail = 0;

  enqueue(val: T): void {
    this.items[this.tail++] = val;
  }

  dequeue(): T | undefined {
    if (this.isEmpty()) return undefined;
    const val = this.items[this.head];
    delete this.items[this.head++];
    return val;
  }

  peek(): T | undefined {
    return this.items[this.head];
  }

  get size(): number {
    return this.tail - this.head;
  }

  isEmpty(): boolean {
    return this.tail === this.head;
  }
}
```

BFS using this queue:

```typescript
function bfs(graph: Map<number, number[]>, start: number): void {
  const visited = new Set<number>([start]);
  const queue = new Queue<number>();
  queue.enqueue(start);

  while (!queue.isEmpty()) {
    const node = queue.dequeue()!;
    for (const neighbor of graph.get(node) ?? []) {
      if (!visited.has(neighbor)) {
        visited.add(neighbor);
        queue.enqueue(neighbor);
      }
    }
  }
}
```

For level-order traversal, capture the queue size at the start of each level:

```typescript
let level = 0;
while (!queue.isEmpty()) {
  const levelSize = queue.size; // Capture before processing
  for (let i = 0; i < levelSize; i++) {
    const node = queue.dequeue()!;
    // ... process node, enqueue children
  }
  level++;
}
```

<h3 id="priorityqueue-minheap-typed">PriorityQueue / MinHeap (Typed)</h3>

TypeScript has no built-in priority queue. For problems like top-K elements, Dijkstra's algorithm, or merge-K-sorted-lists, you need a min-heap. A generic typed implementation:

```typescript
class MinHeap<T> {
  private heap: T[] = [];
  private compare: (a: T, b: T) => number;

  constructor(compareFn: (a: T, b: T) => number = (a: any, b: any) => a - b) {
    this.compare = compareFn;
  }

  push(val: T): void {
    this.heap.push(val);
    this.siftUp(this.heap.length - 1);
  }

  pop(): T | undefined {
    if (this.heap.length === 0) return undefined;
    const top = this.heap[0];
    const last = this.heap.pop()!;
    if (this.heap.length > 0) {
      this.heap[0] = last;
      this.siftDown(0);
    }
    return top;
  }

  peek(): T | undefined {
    return this.heap[0];
  }

  get size(): number {
    return this.heap.length;
  }

  isEmpty(): boolean {
    return this.heap.length === 0;
  }

  private siftUp(i: number): void {
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.compare(this.heap[i], this.heap[parent]) >= 0) break;
      [this.heap[i], this.heap[parent]] = [this.heap[parent], this.heap[i]];
      i = parent;
    }
  }

  private siftDown(i: number): void {
    const n = this.heap.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1;
      const right = 2 * i + 2;
      if (left < n && this.compare(this.heap[left], this.heap[smallest]) < 0)
        smallest = left;
      if (right < n && this.compare(this.heap[right], this.heap[smallest]) < 0)
        smallest = right;
      if (smallest === i) break;
      [this.heap[i], this.heap[smallest]] = [this.heap[smallest], this.heap[i]];
      i = smallest;
    }
  }
}
```

Usage:

```typescript
// Min-heap of numbers (default)
const minHeap = new MinHeap<number>();
minHeap.push(5);
minHeap.push(2);
minHeap.push(8);
minHeap.pop(); // 2

// Max-heap (reverse comparator)
const maxHeap = new MinHeap<number>((a, b) => b - a);

// Custom objects: sort by distance, then by node ID
const heap = new MinHeap<[number, number]>((a, b) =>
  a[0] !== b[0] ? a[0] - b[0] : a[1] - b[1],
);
heap.push([5, 3]); // [distance, nodeId]
heap.push([2, 1]);
heap.pop(); // [2, 1]
```

<h3 id="no-treemap-treeset">No TreeMap / TreeSet</h3>

TypeScript has no sorted map or sorted set. This is a genuine disadvantage for problems that need:

- Finding the floor/ceiling of a key (nearest smaller/larger)
- Range queries on keys
- Maintaining elements in sorted order with O(log n) insertions

Workarounds:

1. **Sorted array + binary search:** Maintain a sorted array and use binary search for lookups. Insertion is O(n) due to shifting, but works for small datasets.
2. **Sort when needed:** If you only need sorted access at the end, collect elements and sort once.
3. **Accept the limitation:** In a TypeScript interview, mention the missing data structure and discuss the trade-off.

<h3 id="collections-quick-reference">Collections Quick Reference</h3>

| Collection            | Type           | Key Methods                                       | Time Complexity                        | DSA Use                     |
| --------------------- | -------------- | ------------------------------------------------- | -------------------------------------- | --------------------------- |
| `Array<T>`            | Dynamic array  | `push`, `pop`, `shift`, `splice`, `slice`, `sort` | push/pop O(1), shift O(n), access O(1) | Stacks, results, DP tables  |
| `Map<K,V>`            | Hash map       | `set`, `get`, `has`, `delete`, `size`             | O(1) average                           | Frequency counting, two-sum |
| `Set<T>`              | Hash set       | `add`, `has`, `delete`, `size`                    | O(1) average                           | Visited tracking, dedup     |
| `Record<K,V>`         | Typed object   | bracket access, `in`, `Object.keys`               | O(1) average                           | Simple frequency maps       |

<h1 id="sorting-and-comparators">Sorting and Comparators</h1>

Sorting is a prerequisite for many algorithms: binary search, two pointers on sorted arrays, merge intervals, and greedy approaches.

**JavaScript and TypeScript's default sort behavior:** `Array.sort()` converts elements to strings and sorts lexicographically by default:

```typescript
const nums = [10, 9, 2, 21, 3];
nums.sort(); // [10, 2, 21, 3, 9] (WRONG! Lexicographic order)
nums.sort((a, b) => a - b); // [2, 3, 9, 10, 21] (correct numeric sort)
```

```typescript
// Sort ascending
nums.sort((a, b) => a - b);

// Sort descending
nums.sort((a, b) => b - a);

// Sort intervals by start time (merge intervals pattern)
const intervals: number[][] = [
  [1, 3],
  [2, 6],
  [8, 10],
];
intervals.sort((a, b) => a[0] - b[0]);

// Sort strings by length, then alphabetically for ties
words.sort((a, b) => {
  if (a.length !== b.length) return a.length - b.length;
  return a.localeCompare(b);
});

// Sort by multiple keys: sort people by height desc, then name asc
const people: [string, number][] = [
  ["Alice", 170],
  ["Bob", 180],
  ["Carol", 170],
];
people.sort((a, b) => (b[1] !== a[1] ? b[1] - a[1] : a[0].localeCompare(b[0])));
```

Note that `Array.sort()` modifies the array in place and returns the same array. If you need to preserve the original, spread first:

```typescript
const sorted = [...nums].sort((a, b) => a - b); // Original unchanged
```

**Important:** Since ES2019, `Array.sort()` is required by spec to be stable, and all modern engines (V8, SpiderMonkey, JavaScriptCore) comply. You can rely on stability on LeetCode and in any current Node version.

<h1 id="functional-patterns-for-dsa">Functional Patterns for DSA</h1>

TypeScript inherits JavaScript's functional array methods. These make DSA code concise, but use them with awareness of their performance characteristics:

```typescript
const nums = [1, 2, 3, 4, 5];

// map: transform each element
const doubled = nums.map((x) => x * 2); // [2, 4, 6, 8, 10]

// filter: keep elements matching condition
const evens = nums.filter((x) => x % 2 === 0); // [2, 4]

// reduce: accumulate a single value
const sum = nums.reduce((acc, x) => acc + x, 0); // 15

// find: first element matching condition (undefined if not found)
const firstEven = nums.find((x) => x % 2 === 0); // 2

// some: true if ANY element matches
const hasNegative = nums.some((x) => x < 0); // false

// every: true if ALL elements match
const allPositive = nums.every((x) => x > 0); // true

// forEach: iterate with side effects (no return value)
nums.forEach((val, idx) => {
  /* access both value and index */
});

// flat: flatten nested arrays
const nested = [
  [1, 2],
  [3, 4],
];
nested.flat(); // [1, 2, 3, 4]
```

**Performance note:** Each of these methods creates a new array (except `forEach`, `some`, `every`, and `find`). Chaining `.filter().map()` creates two intermediate arrays. In hot inner loops processing millions of elements, a plain `for` loop is faster. For most DSA problems, the difference is negligible.

<h1 id="null-undefined-and-strict-null-checks">
  Null, Undefined, and Strict Null Checks
</h1>

TypeScript distinguishes between `null` and `undefined`, and its type system helps you handle both safely.

**The difference:**

- `undefined` means "not assigned." It is the default value for uninitialized variables, missing object properties, and `Map.get()` for missing keys.
- `null` means "intentionally absent." You use it explicitly to represent "no node" in trees and linked lists.

In DSA, you encounter null/undefined primarily in three situations: tree/linked list problems, map lookups, and optional function parameters.

**Rule 1: Use union types to express nullability.**

```typescript
// Tree traversal: node can be null
function inorder(node: TreeNode | null): number[] {
  if (node === null) return [];
  return [...inorder(node.left), node.val, ...inorder(node.right)];
}

// Linked list: head can be null
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let curr = head;
  while (curr !== null) {
    const next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
  }
  return prev;
}
```

**Rule 2: Use nullish coalescing (**`**??**`**) for safe defaults.**

```typescript
// Safe map access
const count = freq.get(key) ?? 0;

// Safe graph neighbor access
const neighbors = graph.get(node) ?? [];
```

**Rule 3: Use the non-null assertion (**`**!**`**) sparingly and only when you are certain.**

```typescript
// We just checked .has(), so .get() will not return undefined
if (map.has(key)) {
  const val = map.get(key)!;
}

// After dequeue, we know queue was not empty
while (!queue.isEmpty()) {
  const node = queue.dequeue()!;
}
```

**Rule 4: Use optional chaining (**`**?.**`**) for safe property access.**

```typescript
const leftVal = node?.left?.val; // undefined if node or left is null
const firstNeighbor = graph.get(node)?.[0]; // undefined if no neighbors
```

<h1 id="iterating-and-modifying-collections-safely">
  Iterating and Modifying Collections Safely
</h1>

TypeScript does not throw errors when you modify a collection during iteration. But that does not mean it is safe. The behavior is well-defined but easy to get wrong, and it produces bugs that are hard to track down.

```typescript
// DANGEROUS: modifying array while iterating with for-of
const arr = [1, 2, 3, 4, 5];
for (const num of arr) {
  if (num % 2 === 0) {
    arr.splice(arr.indexOf(num), 1); // Skips elements!
  }
}
// arr might be [1, 3, 5] or something unexpected
```

Safe alternatives:

```typescript
// Option 1: Filter into a new array (preferred)
const odds = arr.filter((num) => num % 2 !== 0);

// Option 2: Iterate backward with index-based loop
for (let i = arr.length - 1; i >= 0; i--) {
  if (arr[i] % 2 === 0) {
    arr.splice(i, 1);
  }
}

// Option 3: Collect indices to remove, then remove in reverse
const toRemove: number[] = [];
for (let i = 0; i < arr.length; i++) {
  if (arr[i] % 2 === 0) toRemove.push(i);
}
for (let i = toRemove.length - 1; i >= 0; i--) {
  arr.splice(toRemove[i], 1);
}
```

For Maps and Sets, deleting during `for-of` iteration is safe per the ES6 specification. But adding new elements during iteration may or may not be visited, so avoid it:

```typescript
// Safe: delete from Map during iteration
for (const [key, value] of map) {
  if (value === 0) map.delete(key); // Defined behavior
}

// Dangerous: adding to Map during iteration
for (const [key, value] of map) {
  map.set(key + "_copy", value); // May or may not iterate over new entry
}
```

In practice, most DSA problems do not require removing during iteration. You are far more likely to build a new collection with the desired elements.

<h1 id="recursion-and-the-call-stack">Recursion and the Call Stack</h1>

Recursion is the backbone of tree traversal, graph DFS, backtracking, and divide-and-conquer. Understanding how TypeScript handles recursion matters for these problems.

Every function call goes on the **call stack**, which has limited space. If your recursion goes too deep, you get a `RangeError: Maximum call stack size exceeded`:

```typescript
// This will crash for large n (V8's call-stack limit is around 10,000 to 15,000 frames)
function factorial(n: number): number {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
```

**When to worry about stack depth:**

| Scenario                            | Typical Depth | Risk                          |
| ----------------------------------- | ------------- | ----------------------------- |
| Balanced binary tree (n nodes)      | O(log n)      | Safe for n up to 10^6         |
| Linked list / skewed tree (n nodes) | O(n)          | Dangerous if n > 5,000-10,000 |
| Backtracking (k choices, depth d)   | O(d)          | Usually safe (d is small)     |
| DFS on graph (n nodes)              | O(n)          | Dangerous for large n         |

**The fix:** Convert deep recursion to an iterative approach using an explicit stack:

```typescript
// Recursive DFS (risks stack overflow for deep graphs)
function dfs(
  node: number,
  visited: Set<number>,
  graph: Map<number, number[]>,
): void {
  visited.add(node);
  for (const neighbor of graph.get(node) ?? []) {
    if (!visited.has(neighbor)) dfs(neighbor, visited, graph);
  }
}

// Iterative DFS (safe for any depth)
function dfsIterative(
  start: number,
  visited: Set<number>,
  graph: Map<number, number[]>,
): void {
  const stack: number[] = [start];
  while (stack.length > 0) {
    const node = stack.pop()!;
    if (visited.has(node)) continue;
    visited.add(node);
    for (const neighbor of graph.get(node) ?? []) {
      if (!visited.has(neighbor)) stack.push(neighbor);
    }
  }
}
```

Note that TypeScript (and JavaScript) does **not** optimize tail recursion in practice. While the ES2015 spec defines proper tail calls, only Safari (JavaScriptCore) implements them. Node.js and V8 do not. If your recursion depth is proportional to input size and the input can be large, convert to iteration.

<h1 id="graph-representation-patterns">Graph Representation Patterns</h1>

Graphs appear in a large portion of DSA problems. TypeScript does not have a built-in graph class, so you need to build representations yourself. There are two common approaches:

**Approach 1: Adjacency list with **`**Array<number[]>**`**.** Use this when nodes are numbered 0 to n-1.

```typescript
const n = 5;
const graph: number[][] = Array.from({ length: n }, () => []);

// Add edges
for (const [u, v] of edges) {
    graph[u].push(v);
    graph[v].push(u); // Omit for directed graphs
}

// Access neighbors
for (const neighbor of graph[node]) { ... }
```

**Approach 2: Adjacency list with **`**Map<number, number[]>**`**.** Use this when node IDs are not contiguous or are very large.

```typescript
const graph = new Map<number, number[]>();

for (const [u, v] of edges) {
    if (!graph.has(u)) graph.set(u, []);
    if (!graph.has(v)) graph.set(v, []);
    graph.get(u)!.push(v);
    graph.get(v)!.push(u);
}

// Access neighbors (with safety)
for (const neighbor of graph.get(node) ?? []) { ... }
```

**Weighted graphs** use tuples to store neighbor and weight:

```typescript
// Adjacency list for weighted graph
const graph: [number, number][][] = Array.from({ length: n }, () => []);

graph[from].push([to, weight]);

// Used in Dijkstra:
const heap = new MinHeap<[number, number]>((a, b) => a[0] - b[0]);
heap.push([0, startNode]); // [distance, node]
```

| Approach                | Pros                                   | Cons                                | Use When                                   |
| ----------------------- | -------------------------------------- | ----------------------------------- | ------------------------------------------ |
| `Array<number[]>`       | Fast index access, no hashing overhead | Wastes space if node IDs are sparse | Nodes are 0 to n-1                         |
| `Map<number, number[]>` | Handles any node IDs, no wasted space  | Slightly slower due to hashing      | Node IDs are large, sparse, or non-numeric |

<h1 id="tuple-and-pair-alternatives">Tuple and Pair Alternatives</h1>

TypeScript does not have a built-in `tuple` at runtime. But its type system lets you type arrays as tuples, which gives you fixed-length, typed positions:

**Option 1: TypeScript tuple types (preferred for typed code)**

```typescript
// BFS entry: [row, col]
const cell: [number, number] = [3, 5];

// BFS with distance: [row, col, distance]
const entry: [number, number, number] = [0, 0, 0];

// Queue of tuples
const queue = new Queue<[number, number]>();
queue.enqueue([startRow, startCol]);

// Destructuring
const [r, c] = queue.dequeue()!;
```

**Option 2: Plain arrays (when you want flexibility)**

```typescript
const cell = [row, col]; // Inferred as number[] (not tuple)
const r = cell[0];
const c = cell[1];
```

**Option 3: Interface (when clarity matters)**

```typescript
interface Cell {
  row: number;
  col: number;
  dist: number;
}
const entry: Cell = { row: 0, col: 0, dist: 0 };
```

In practice, typed tuples `[number, number]` are the standard approach in TypeScript DSA. They combine type safety with conciseness.

<h1 id="deduplication-patterns">Deduplication Patterns</h1>

Many DSA problems require avoiding duplicate results (e.g., 3Sum, 4Sum, permutations with duplicates). TypeScript offers two approaches:

**Approach 1: Sort and skip duplicates (preferred for sorted array problems)**

```typescript
nums.sort((a, b) => a - b);
for (let i = 0; i < nums.length; i++) {
  // Skip duplicates: if this value is the same as the previous, skip it
  if (i > 0 && nums[i] === nums[i - 1]) continue;
  // Process nums[i]
}
```

This is the standard approach for problems like 3Sum and 4Sum. It runs in O(1) extra space (beyond the sort) and produces results in sorted order.

**Approach 2: Use a Set to collect unique results**

```typescript
const resultSet = new Set<string>();
// ... generate candidates ...
resultSet.add(JSON.stringify([a, b, c])); // Serialize for uniqueness
const results = [...resultSet].map((s) => JSON.parse(s) as number[]);
```

Since Sets compare objects by reference, you must serialize (e.g., `JSON.stringify`) to detect duplicate arrays. This is slower than the sort-and-skip approach but simpler to implement.

<h1 id="common-dsa-idioms-in-typescript">Common DSA Idioms in TypeScript</h1>

Common small patterns and utility calls:

**Swapping elements** (TypeScript's destructuring makes this clean):

```typescript
[arr[i], arr[j]] = [arr[j], arr[i]];

// Or for variables:
[a, b] = [b, a];
```

**Sentinel values** for tracking min/max:

```typescript
let minVal = Infinity;
let maxVal = -Infinity;
for (const num of nums) {
  minVal = Math.min(minVal, num);
  maxVal = Math.max(maxVal, num);
}
```

`Infinity` and `-Infinity` are globally available. They compare correctly with any number: `Infinity > 1e18` is `true`.

**Math utilities:**

```typescript
Math.max(a, b); // Larger of two values
Math.min(a, b); // Smaller of two values
Math.abs(a); // Absolute value
Math.pow(2, 10); // Power (also: 2 ** 10)

Math.log2(n); // Log base 2
Math.floor(a / b); // Floor division
Math.ceil(a / b); // Ceiling division
```

**Ceiling division** without floating point:

```typescript

// Or equivalently:

```

**Type conversions:**

```typescript
// number <-> string
const num = Number("42"); // 42
const num2 = parseInt("42", 10); // 42 (always pass radix!)
const str = String(42); // "42"
const str2 = (42).toString(); // "42"
const str3 = (42).toString(2); // "101010" (binary representation)

// string <-> array of characters

// Array <-> Set

// Deep copy (for simple objects/arrays)

```

`**parseInt**`** always needs a radix.** Without one, `parseInt("0x10")` parses as hex (`16`), which can produce surprising results when the input comes from user data. Modern engines (ES5+) treat a leading `0` as decimal, but the explicit radix is still required by most lint rules:

```typescript

parseInt("08", 10); // 8
parseInt("0x10", 10); // 0 (without radix this would parse as 16)
```

**Deep copy vs shallow copy:**

```typescript
// Shallow copy (array)
const copy = [...arr]; // New array, same element references
const copy2 = arr.slice(); // Same thing

// Shallow copy (object)
const copy = { ...obj };

// Deep copy (when elements are objects)
const deepCopy = JSON.parse(JSON.stringify(arr)); // Handles nested structures
// Or for 2D arrays:

```

<h1 id="oop-basics-for-design-problems">OOP Basics for Design Problems</h1>

DSA problems often define custom node classes. TypeScript classes give you type-safe definitions with clean syntax:

```typescript
// Linked list node
class ListNode {
  val: number;
  next: ListNode | null;

  constructor(val: number = 0, next: ListNode | null = null) {
    this.val = val;
    this.next = next;
  }
}

// Binary tree node
class TreeNode {
  val: number;
  left: TreeNode | null;
  right: TreeNode | null;

  constructor(
    val: number = 0,
    left: TreeNode | null = null,
    right: TreeNode | null = null,
  ) {
    this.val = val;
    this.left = left;
    this.right = right;
  }
}

// Trie node
class TrieNode {
  children: Map<string, TrieNode>;
  isEndOfWord: boolean;

  constructor() {
    this.children = new Map();
    this.isEndOfWord = false;
  }
}

// Graph node with neighbors
class GraphNode {
  val: number;
  neighbors: GraphNode[];

  constructor(val: number = 0, neighbors: GraphNode[] = []) {
    this.val = val;
    this.neighbors = neighbors;
  }
}
```

TypeScript also supports a **shorthand constructor** syntax that reduces boilerplate:

```typescript
class ListNode {
  constructor(
    public val: number = 0,
    public next: ListNode | null = null,

}

// This is equivalent to the longer version above.
// The 'public' keyword automatically creates and assigns the property.
```

**Interfaces vs Classes:** TypeScript also lets you define types with interfaces. For DSA, classes are more common because LeetCode provides them, but interfaces are useful for typing function parameters:

```typescript
// Interface for generic tree operations
interface BinaryTree {
  val: number;
  left: BinaryTree | null;
  right: BinaryTree | null;

// Works with any class that has these properties
function height(node: BinaryTree | null): number {
  if (!node) return 0;

}
```

```typescript

```
