<LessonCard>

You are given an `n x n` grid representing a field of cherries, each cell is one of three possible integers.

- `0` means the cell is empty, so you can pass through,
- `1` means the cell contains a cherry that you can pick up and the cell becomes empty,
- `-1` means the cell contains a thorn that blocks your way.

Return the maximum number of cherries you can collect under the following rules:

- Starting at the position `(0, 0)` and reaching `(n - 1, n - 1)` by moving right or down through valid path cells (cells with value `0` or `1`).
- After reaching `(n - 1, n - 1)`, returning to `(0, 0)` by moving left or up through valid path cells.
- When passing through a path cell containing a cherry, you pick the cherry, and the cell becomes an empty cell `0`.
- If there is no valid path between `(0, 0)` and `(n - 1, n - 1)`, then no cherries can be collected.

\***\*Example 1:\*\***

- **Input:** `grid = [[0,1,-1],[1,0,-1],[1,1,1]]`

- **Output:** `5`

\***\*Example 2:\*\***

- **Input:** `grid = [[1,1,-1],[1,-1,1],[-1,1,1]]`

- **Output:** `0`

\***\*Constraints:\*\***

- `n == grid.length`
- `n == grid[i].length`
- `1 <= n <= 50`
- `grid[i][j]` is `-1`, `0`, or `1`
- `grid[0][0] != -1`
- `grid[n - 1][n - 1] != -1`

This reads like two separate path problems: go from top-left to bottom-right collecting cherries, then come back collecting more. The trips are not independent, though. Cherries picked on the first trip disappear, so the second trip sees a modified grid, and maximizing each trip on its own can lock in a suboptimal total.

Instead of one trip forward and one trip back, model the round trip as two people walking simultaneously from (0, 0) to (n-1, n-1). Person 1 represents the forward trip. Person 2 represents the return trip, reversed so it also runs top-left to bottom-right. Both move one step at a time, either right or down, and a cherry on a cell both occupy is counted once. This reformulation turns a sequential problem with interacting trips into a single DP over both walkers' positions.

- `1 <= n <= 50` -> The grid is at most 50x50 = 2,500 cells. We have room for O(n^3) or even O(n^4) solutions.
- `grid[i][j]` is `-1`, `0`, or `1` -> Thorns block paths entirely, not just increase cost. We must handle unreachable states.

Solve the two trips independently: find the path from (0,0) to (n-1,n-1) that collects the most cherries, remove those cherries from the grid, then find a second maximum-cherry path on the modified grid (a return trip is equivalent to another forward trip with the moves reversed).

Each trip on its own is a standard maximum-path-sum DP, so this is easy to implement. It is also wrong. The best single path can take cherries positioned so that whatever remains cannot be covered by one more right/down path, while two coordinated paths, each individually suboptimal, collect more in total. The walkthrough below shows a grid where this happens.

<h3 id="algorithm">Algorithm</h3>

1. Use DP to find the path from (0,0) to (n-1,n-1) that collects the maximum cherries.
2. Mark all cherries along that path as collected (set them to 0).
3. Use DP again on the modified grid to find a second maximum-cherry path.
4. Return the sum of cherries from both trips.

```java
class Solution {
    public int cherryPickup(int[][] grid) {
        int n = grid.length;
        // First trip: max cherries from (0,0) to (n-1,n-1)
        int[][] dp1 = new int[n][n];
        for (int[] row : dp1) Arrays.fill(row, -1);
        dp1[0][0] = grid[0][0];

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == -1) { dp1[i][j] = -1; continue; }
                if (i == 0 && j == 0) continue;
                int best = -1;
                if (i > 0 && dp1[i - 1][j] >= 0) best = Math.max(best, dp1[i - 1][j]);
                if (j > 0 && dp1[i][j - 1] >= 0) best = Math.max(best, dp1[i][j - 1]);
                if (best < 0) { dp1[i][j] = -1; continue; }
                dp1[i][j] = best + grid[i][j];
            }
        }

        if (dp1[n - 1][n - 1] < 0) return 0;
        int firstTrip = dp1[n - 1][n - 1];

        // Trace back path and remove cherries (greedy backtrack)
        int r = n - 1, c = n - 1;
        while (r > 0 || c > 0) {
            grid[r][c] = 0;
            if (r > 0 && c > 0) {
                if (dp1[r - 1][c] >= dp1[r][c - 1]) r--;
                else c--;
            } else if (r > 0) r--;
            else c--;
        }
        grid[0][0] = 0;

        // Second trip on modified grid
        int[][] dp2 = new int[n][n];
        for (int[] row : dp2) Arrays.fill(row, -1);
        dp2[0][0] = grid[0][0];

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == -1) { dp2[i][j] = -1; continue; }
                if (i == 0 && j == 0) continue;
                int best = -1;
                if (i > 0 && dp2[i - 1][j] >= 0) best = Math.max(best, dp2[i - 1][j]);
                if (j > 0 && dp2[i][j - 1] >= 0) best = Math.max(best, dp2[i][j - 1]);
                if (best < 0) { dp2[i][j] = -1; continue; }
                dp2[i][j] = best + grid[i][j];
            }
        }

        int secondTrip = dp2[n - 1][n - 1] < 0 ? 0 : dp2[n - 1][n - 1];
        return firstTrip + secondTrip;
    }
}
```

> - **Time Complexity:** O(n^2). Each trip requires a single pass through the n x n grid, so O(n^2) per trip and O(n^2) total.
> - **Space Complexity:** O(n^2). We use an n x n DP table for each trip.

On the walkthrough grid, the greedy split collects 4 cherries while the true maximum is 5. No fix to the first trip repairs this, because the two paths have to be chosen together. The next approach optimizes them as a single decision.

<h1 id="approach-2-3d-dp-two-simultaneous-walkers">
  Approach 2: 3D DP (Two Simultaneous Walkers)
</h1>

<h3 id="intuition">Intuition</h3>

Reversing the return trip makes the two-walker model exact: a path from (n-1,n-1) to (0,0) using left and up moves, read backwards, is a path from (0,0) to (n-1,n-1) using right and down moves, and it visits the same cells. The round trip is therefore two forward paths, chosen together.

Both walkers take exactly `2*(n-1)` steps total to reach the destination. At each step, each walker moves either right or down. The number of steps taken so far, call it `t`, determines a constraint: if a walker is at row `r`, their column must be `c = t - r`. So with `t` fixed, we only need to track `r1` (walker 1's row) and `r2` (walker 2's row) to know both positions completely.

Cherry collection follows one rule: if both walkers are on the same cell, the cherry is counted once; otherwise each walker collects its own cell. This single rule is enough to prevent any cherry from being counted twice across the whole round trip.

> The same-cell check catches every possible double count, not only collisions that happen to occur at the same moment. Any right/down path reaches cell (r, c) after exactly r + c moves. So if both walkers' paths pass through a cell, they occupy it at the same step `t = r + c`, never at different times. Checking `r1 == r2` at each step (with `t` fixed, equal rows mean equal columns) therefore detects every shared cell.
>
> The reformulation is also exact in the other direction: every pair of forward paths corresponds to a valid round trip and collects the cherries on the union of the two paths, which is precisely the quantity to maximize.

<h3 id="algorithm">Algorithm</h3>

1. Let `t` range from 0 to `2*(n-1)`. This is the step number (how many moves each walker has made).
2. For each step `t`, iterate over all valid (r1, r2) pairs where `0 <= r1, r2 <= min(t, n-1)` and `c1 = t - r1` and `c2 = t - r2` are valid column indices.
3. Both walkers arrived at their current position from the previous step. Each could have moved down (from row r-1) or right (from row r at previous step). This gives 4 predecessor combinations.
4. Take the max over all 4 predecessor states. Add the cherries at both current positions. If both walkers are on the same cell, add the cherry value only once.
5. After the final step `t = 2*(n-1)`, both walkers are at (n-1, n-1), so the answer is `dp[n-1][n-1]`. If it is still negative, no valid path pair exists; return 0. (Each step only reads the previous step's values, so the implementation keeps two 2D arrays instead of a full 3D table.)

```java
class Solution {
    public int cherryPickup(int[][] grid) {
        int n = grid.length;
        int maxSteps = 2 * (n - 1);
        int[][] dp = new int[n][n];
        int[][] prev = new int[n][n];

        for (int[] row : dp) Arrays.fill(row, Integer.MIN_VALUE);
        dp[0][0] = grid[0][0];

        for (int t = 1; t <= maxSteps; t++) {
            for (int[] row : prev) Arrays.fill(row, Integer.MIN_VALUE);
            int[][] temp = prev;
            prev = dp;
            dp = temp;

            for (int r1 = Math.max(0, t - (n - 1)); r1 <= Math.min(t, n - 1); r1++) {
                int c1 = t - r1;
                if (c1 < 0 || c1 >= n) continue;
                if (grid[r1][c1] == -1) continue;

                for (int r2 = Math.max(0, t - (n - 1)); r2 <= Math.min(t, n - 1); r2++) {
                    int c2 = t - r2;
                    if (c2 < 0 || c2 >= n) continue;
                    if (grid[r2][c2] == -1) continue;

                }
            }
        }
```

> - **Time Complexity:** O(n^3). We iterate over t from 0 to 2(n-1), which is O(n) steps. At each step, we consider all (r1, r2) pairs where both range over at most n values. So it is O(n) _ O(n) _ O(n) = O(n^3).
> - **Space Complexity:** O(n^2). We maintain two 2D arrays (dp and prev) of size n x n, swapping between them at each step.

The same recurrence can also be written top down. Recursion with memoization removes the manual loop bounds and buffer swapping, at the cost of an O(n^3) memo table instead of two O(n^2) arrays.

<h1 id="approach-3-top-down-memoization">Approach 3: Top-Down Memoization</h1>

<h3 id="intuition">Intuition</h3>

The top-down version asks, from a given pair of positions, what is the best both walkers can still collect on the way to (n-1, n-1). Define a function `solve(r1, c1, r2)` that returns that maximum. Both walkers have taken the same number of steps, so `c2 = r1 + c1 - r2` and does not need to be passed. Each call tries the 4 movement combinations (each walker goes right or down) and takes the maximum over the valid ones.

<h3 id="algorithm">Algorithm</h3>

1. Define `solve(r1, c1, r2)` where `c2 = r1 + c1 - r2`.
2. If any position is out of bounds or a thorn, return negative infinity.
3. Base case: if `r1 == n-1` and `c1 == n-1`, walker 1 is at the destination, and so is walker 2: the bounds check already passed, and `c2 = 2*(n-1) - r2 <= n-1` forces `r2 = n-1`. Return `grid[n-1][n-1]`, counted once.
4. Compute cherries at current positions (once if same cell, both if different).
5. Try all 4 movement combinations: (down,down), (down,right), (right,down), (right,right).
6. Return current cherries + max of all 4 recursive results.
7. Memoize using a 3D table indexed by (r1, c1, r2).

```java
class Solution {
    int[][][] memo;
    int n;

    public int cherryPickup(int[][] grid) {
        n = grid.length;
        memo = new int[n][n][n];
        for (int[][] layer : memo)
            for (int[] row : layer)
                Arrays.fill(row, Integer.MIN_VALUE);

        int result = solve(grid, 0, 0, 0);
        return Math.max(0, result);
    }

    private int solve(int[][] grid, int r1, int c1, int r2) {
        int c2 = r1 + c1 - r2;
        // Out of bounds or thorn check
        if (r1 >= n || c1 >= n || r2 >= n || c2 >= n) return -1 << 30;
        if (grid[r1][c1] == -1 || grid[r2][c2] == -1) return -1 << 30;

        // Both reached destination
        if (r1 == n - 1 && c1 == n - 1) return grid[r1][c1];

        if (memo[r1][c1][r2] != Integer.MIN_VALUE) return memo[r1][c1][r2];

        // Cherries at current positions
        int cherries = grid[r1][c1];
        if (r1 != r2 || c1 != c2) cherries += grid[r2][c2];

        // Try all 4 movement combinations
        int best = -1 << 30;
        best = Math.max(best, solve(grid, r1 + 1, c1, r2 + 1)); // both down
        best = Math.max(best, solve(grid, r1 + 1, c1, r2));     // W1 down, W2 right
        best = Math.max(best, solve(grid, r1, c1 + 1, r2 + 1)); // W1 right, W2 down
        best = Math.max(best, solve(grid, r1, c1 + 1, r2));     // both right

        memo[r1][c1][r2] = cherries + best;
        return memo[r1][c1][r2];
    }
```

```go
        }

        best := NEG_INF
        best = max(best, solve(r1+1, c1, r2+1))
        best = max(best, solve(r1+1, c1, r2))
        best = max(best, solve(r1, c1+1, r2+1))
        best = max(best, solve(r1, c1+1, r2))

        memo[r1][c1][r2] = cherries + best
        return memo[r1][c1][r2]
    }

    return max(0, solve(0, 0, 0))
}
```

```rust
impl Solution {
    pub fn cherry_pickup(grid: Vec<Vec<i32>>) -> i32 {
        let n = grid.len();
        let mut memo = vec![vec![vec![i32::MIN; n]; n]; n];
        let result = Self::solve(&grid, &mut memo, n, 0, 0, 0);
        result.max(0)
    }

    fn solve(
        grid: &[Vec<i32>],
        memo: &mut [Vec<Vec<i32>>],
        n: usize,
        r1: usize,
        c1: usize,
        r2: usize,
    ) -> i32 {
        const NEG_INF: i32 = -(1 << 30);
        // Out of bounds or thorn check (r1 + c1 < r2 would make c2 negative)
        if r1 >= n || c1 >= n || r2 >= n || r1 + c1 < r2 {
            return NEG_INF;
        }
        let c2 = r1 + c1 - r2;
        if c2 >= n {
            return NEG_INF;
        }
        if grid[r1][c1] == -1 || grid[r2][c2] == -1 {
            return NEG_INF;
        }

        // Both reached destination
        if r1 == n - 1 && c1 == n - 1 {
            return grid[r1][c1];
        }

        if memo[r1][c1][r2] != i32::MIN {
            return memo[r1][c1][r2];
        }

        // Cherries at current positions
        let mut cherries = grid[r1][c1];
        if r1 != r2 {
            cherries += grid[r2][c2];
        }

        // Try all 4 movement combinations
        let mut best = NEG_INF;
        best = best.max(Self::solve(grid, memo, n, r1 + 1, c1, r2 + 1)); // both down
        best = best.max(Self::solve(grid, memo, n, r1 + 1, c1, r2)); // W1 down, W2 right
        best = best.max(Self::solve(grid, memo, n, r1, c1 + 1, r2 + 1)); // W1 right, W2 down
        best = best.max(Self::solve(grid, memo, n, r1, c1 + 1, r2)); // both right

        memo[r1][c1][r2] = cherries + best;
        memo[r1][c1][r2]
    }
}
```

```javascript
var cherryPickup = function (grid) {
  const n = grid.length;
  const NEG_INF = -Infinity;
  const memo = new Map();

  function solve(r1, c1, r2) {
    const c2 = r1 + c1 - r2;
    if (r1 >= n || c1 >= n || r2 >= n || c2 >= n) return NEG_INF;
    if (grid[r1][c1] === -1 || grid[r2][c2] === -1) return NEG_INF;

    if (r1 === n - 1 && c1 === n - 1) return grid[r1][c1];

    const key = r1 * n * n + c1 * n + r2;
    if (memo.has(key)) return memo.get(key);

    let cherries = grid[r1][c1];
    if (r1 !== r2 || c1 !== c2) cherries += grid[r2][c2];

    let best = NEG_INF;
    best = Math.max(best, solve(r1 + 1, c1, r2 + 1));
    best = Math.max(best, solve(r1 + 1, c1, r2));
    best = Math.max(best, solve(r1, c1 + 1, r2 + 1));
    best = Math.max(best, solve(r1, c1 + 1, r2));

    const result = cherries + best;
    memo.set(key, result);
    return result;
  }

  return Math.max(0, solve(0, 0, 0));
};
```

> - **Time Complexity:** O(n^3). There are at most n _ n _ n = n^3 unique states (r1, c1, r2). Each state does O(1) work (4 recursive calls, each looked up in O(1) from the memo table).
> - **Space Complexity:** O(n^3). The memoization table stores up to n^3 entries. The recursion stack depth is at most 2(n-1), which is O(n), dominated by the memo table.
