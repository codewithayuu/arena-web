<LessonCard>

Given an integer array `nums` and a positive integer `k`, return the most competitive subsequence of `nums` of size `k`.

An array's subsequence is a resulting sequence obtained by erasing some (possibly zero) elements from the array.

We define that a subsequence `a` is more competitive than a subsequence `b` (of the same length) if in the first position where `a` and `b` differ, subsequence `a` has a number less than the corresponding number in `b`. For example, `[1,3,4]` is more competitive than `[1,3,5]` because the first position they differ is at the final number, and `4` is less than `5`.

\***\*Example 1:\*\***

- **Input:** `nums = [3,5,2,6]`

- **Input:** `k = 2`

- **Output:** `[2,6]`

\***\*Example 2:\*\***

- **Input:** `nums = [2,4,3,3,5,4,9,6]`

- **Input:** `k = 4`

- **Output:** `[2,3,3,4]`

\***\*Constraints:\*\***

- `1 <= nums.length <= 10^5`
- `0 <= nums[i] <= 10^9`
- `1 <= k <= nums.length`

We need to pick exactly `k` elements from `nums` while keeping their original relative order, and the resulting subsequence should be the lexicographically smallest possible. When two subsequences of the same length are compared, the more competitive one has the smaller value at the first position where they differ.

This is a greedy selection problem with a constraint. At each position in the result we want the smallest possible value, but we also have to leave enough elements remaining to fill the rest of the subsequence. Picking the smallest value now and keeping enough elements for later pull in opposite directions, and balancing the two is the core of the problem.

That balance maps onto building a stack that stays as small as possible at the front, subject to a capacity of `k`. When a smaller element arrives, we can remove larger elements already chosen, as long as enough elements remain in the array to complete the subsequence.

- `1 <= nums.length <= 10^5` means an O(n^2) approach will time out. The target is O(n).
- `0 <= nums[i] <= 10^9` means values fit in a 32-bit signed integer, and there are no negatives. The range is too wide for counting sort or a frequency array.
- `1 <= k <= nums.length` guarantees `k` is always valid, so there is no `k > n` case to handle.

<h1 id="approach-1-brute-force-generate-all-subsequences">
  Approach 1: Brute Force (Generate All Subsequences)
</h1>

<h3 id="intuition">Intuition</h3>

Generate every possible subsequence of size `k`, compare them lexicographically, and return the smallest one. This enumerates all candidates and picks the winner with no cleverness.

For an array of size n, the number of subsequences of size k is C(n, k), which grows exponentially. For small inputs it works and confirms what the answer should be, which is useful for checking the optimal approach against it.

<h3 id="algorithm">Algorithm</h3>

1. Use backtracking to generate all subsequences of size `k` from `nums`.
2. For each subsequence, compare it with the current best using lexicographic comparison.
3. Keep track of the lexicographically smallest subsequence found.
4. Return the result after checking all candidates.

**Input:**

All subsequences of size 2: [3,5], [3,2], [3,6], [5,2], [5,6], [2,6]

Comparing lexicographically: [2,6] is the smallest (2 < 3 < 5 at the first position).

<h3 id="code">Code</h3>

```java
class Solution {
    int[] best;

    public int[] mostCompetitive(int[] nums, int k) {
        best = null;
        backtrack(nums, k, 0, new int[k], 0);
        return best;
    }

    private void backtrack(int[] nums, int k, int start, int[] current, int idx) {
        if (idx == k) {
            if (best == null || compare(current, best) < 0) {
                best = current.clone();
            }
            return;
        }
        // Need (k - idx) more elements, so can only go up to nums.length - (k - idx)
        for (int i = start; i <= nums.length - (k - idx); i++) {
            current[idx] = nums[i];
            backtrack(nums, k, i + 1, current, idx + 1);
        }
    }

    private int compare(int[] a, int[] b) {
        for (int i = 0; i < a.length; i++) {
            if (a[i] != b[i]) return a[i] - b[i];
        }
        return 0;
    }
}
```

```python
class Solution:
    def mostCompetitive(self, nums: list[int], k: int) -> list[int]:
        best = None

        def backtrack(start, current):
            nonlocal best
            if len(current) == k:
                if best is None or current < best:
                    best = current[:]
                return
            # Need (k - len(current)) more elements
            remaining_needed = k - len(current)
            for i in range(start, len(nums) - remaining_needed + 1):
                current.append(nums[i])
                backtrack(i + 1, current)
                current.pop()

        backtrack(0, [])
        return best
```

```rust
        let mut best: Option<Vec<i32>> = None;
        let mut current = vec![0; k];
        Self::backtrack(&nums, k, 0, &mut current, 0, &mut best);
        best.unwrap()
    }

    fn backtrack(
        nums: &Vec<i32>,
        k: usize,
        start: usize,
        current: &mut Vec<i32>,
        idx: usize,
        best: &mut Option<Vec<i32>>,
    ) {
        if idx == k {
            if best.is_none() || Self::compare(current, best.as_ref().unwrap()) < 0 {
                *best = Some(current.clone());

            return;
        }

        for i in start..=nums.len() - (k - idx) {

            Self::backtrack(nums, k, i + 1, current, idx + 1, best);
        }

            if a[i] != b[i] {
```

> - **Time Complexity:** O(C(n, k) \* k). We generate all C(n, k) subsequences, and comparing each against the current best takes O(k) time. C(n, k) is exponential in the worst case, so this only runs on small inputs.
> - **Space Complexity:** O(k). The recursion depth is at most k, and we store the current subsequence of size k.

The brute force enumerates an exponential number of subsequences, most of which are far from optimal. The next approach builds the answer greedily in a single pass, always preferring a smaller value at an earlier position whenever there is still room to complete the subsequence.

<h1 id="approach-2-monotonic-stack-optimal">
  Approach 2: Monotonic Stack (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

Build the result left to right. While scanning `nums`, when a value is smaller than one already chosen, replacing the larger earlier pick with this smaller value produces a more competitive subsequence. The replacement is only allowed when enough elements remain in the array to still fill all `k` spots.

A monotonic stack implements this directly. The stack holds the current best subsequence so far. For each element in the array:

- If the current element is smaller than the top of the stack, and enough elements remain to still fill `k` positions, pop the top (it is a larger value at an earlier position, so removing it helps).
- Push the current element onto the stack, unless the stack already holds `k` elements.

The remaining-elements check is what keeps the answer valid. With `n - i` elements left in the array (including the current one) and `stack.size()` elements already chosen, a pop is allowed only when `stack.size() - 1 + (n - i) >= k`. After removing one element, the elements still on the stack plus the elements still ahead in the array must be enough to reach size `k`.

> Lexicographic comparison is decided by the first position where two subsequences differ, so a smaller value at an earlier position outweighs any difference later. Reducing the value at the earliest position we can therefore never makes the result worse. When a smaller element arrives and a larger earlier pick can still be replaced without making the subsequence impossible to complete, replacing it strictly improves that earliest differing position.
>
> The check `size - 1 + (n - i) >= k` enforces the size requirement: it allows a pop only when the elements left on the stack plus the elements still ahead can reach `k`. If a pop would make a size-`k` subsequence impossible, the larger value stays.
>
> Each element is pushed at most once and popped at most once, so the total push and pop work is O(n) even though a single iteration can pop several elements.

<h3 id="algorithm">Algorithm</h3>

1. Initialize an empty stack (or list used as a stack).
2. Iterate through each element `nums[i]`:
3. Return the stack as the result array.

<h3 id="example-walkthrough">Example Walkthrough</h3>

<h3 id="code">Code</h3>

```java
class Solution {
    public int[] mostCompetitive(int[] nums, int k) {
        int n = nums.length;
        // Stack stores our current best subsequence
        int[] stack = new int[k];
        int size = 0;

        for (int i = 0; i < n; i++) {
            // Pop elements that are larger than current, if we can afford to
            while (size > 0 && stack[size - 1] > nums[i] && size - 1 + (n - i) >= k) {
                size--;
            }
            // Push current element if stack isn't full
            if (size < k) {
                stack[size++] = nums[i];
            }
        }
        return stack;
    }
}
```

```rust
impl Solution {
    pub fn most_competitive(nums: Vec<i32>, k: i32) -> Vec<i32> {
        let n = nums.len();
        let k = k as usize;
        // Stack stores our current best subsequence
        let mut stack: Vec<i32> = Vec::with_capacity(k);

        for i in 0..n {
            // Pop elements that are larger than current, if we can afford to
            while !stack.is_empty()
                && *stack.last().unwrap() > nums[i]
                && stack.len() - 1 + (n - i) >= k
            {
                stack.pop();
            }
            // Push current element if stack isn't full
            if stack.len() < k {
                stack.push(nums[i]);
            }
        }
        stack
    }
```

> - **Time Complexity:** O(n). Each element is pushed onto the stack at most once and popped at most once. So across all iterations, the total number of push and pop operations is at most 2n. Every other operation inside the loop is O(1).
> - **Space Complexity:** O(k). The stack holds at most k elements. In the Java and C# implementations, we pre-allocate an array of size k. In other languages, the dynamic array or list grows up to size k.
