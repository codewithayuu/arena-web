<LessonCard>

Given the `root` of a binary search tree and an integer `k`, return `true` if there exist two elements in the BST such that their sum is equal to `k`, or `false` otherwise.

\***\*Example 1:\*\***

- **Input:** `root = [5,3,6,2,4,null,7]`

- **Input:** `k = 9`

- **Output:** `true`

**Explanation:** Nodes 2 and 7 sum to 9. (Or nodes 3 and 6, or nodes 4 and 5.)

\***\*Example 2:\*\***

- **Input:** `root = [5,3,6,2,4,null,7]`

- **Input:** `k = 28`

- **Output:** `false`

**Explanation:** No pair of node values sums to 28. The maximum possible sum is 5 + 7 = 12.

\***\*Example 3:\*\***

- **Input:** `root = [1]`

- **Input:** `k = 2`

- **Output:** `false`

**Explanation:** There is only one node, so no pair exists.

\***\*Constraints:\*\***

- `The number of nodes in the tree is in the range [1, 10^4].`
- `-10^4 <= Node.val <= 10^4`
- `root is guaranteed to be a valid binary search tree.`
- `-10^5 <= k <= 10^5`

This is the Two Sum problem, but the input is a BST instead of an array. We need to find whether any two distinct nodes in the tree have values that add up to `k`.

There are two angles to work with. This is a "find two numbers that sum to a target" problem, which a hash set solves directly. It is also a BST, so an inorder traversal produces the values in sorted order, and finding a pair that sums to a target in a sorted sequence is a two-pointer problem.

So we can either treat this as a generic tree problem and use a hash set, or exploit the BST's sorted order with two pointers. Both run in O(n) time and differ in their space use.

- `Node values in [-10^4, 10^4], k in [-10^5, 10^5]` -- Values and the target can be negative, so the complement `k - node.val` can be negative. Any solution must handle negative values, but the magnitudes are small enough that a 32-bit `int` holds every value and every pairwise sum without overflow.
- `Number of nodes in [1, 10^4]` -- A single-node tree must return false, since a valid answer needs two distinct nodes. There is no empty-tree case to handle.

The BST property is not needed for a correct solution. We can treat the input as an ordinary binary tree and apply the same hash-set logic that solves Two Sum on an array.

For each node we visit, we compute its complement `k - node.val`. If that complement is already in the set of values seen so far, the current node and the earlier one form a valid pair. Otherwise we add the current node's value to the set and continue traversing. The tree traversal (DFS or BFS, either order works) takes the place of the array iteration, and the hash set provides O(1) average lookups.

<h3 id="algorithm">Algorithm</h3>

1. Create an empty hash set to store node values we have visited.
2. Start a DFS traversal from the root.
3. At each node, compute the complement: `complement = k - node.val`.
4. If the complement exists in the set, return true.
5. Otherwise, add `node.val` to the set.
6. Recursively check the left and right subtrees. If either returns true, return true.
7. If we finish traversing the entire tree without finding a pair, return false.

> - **Time Complexity:** O(n). We visit each node exactly once. At each node, the hash set lookup and insertion are both O(1) on average. So the total work is O(n).
> - **Space Complexity:** O(n). The hash set stores up to n values. The recursion stack adds O(h), where h is the tree height (O(n) for a skewed tree), but the hash set dominates, so the total is O(n).

This solution runs in O(n) time but ignores the BST property entirely. An inorder traversal of a BST produces a sorted sequence, and a sorted sequence admits a two-pointer search. The next approach uses that.

<h1 id="approach-2-inorder-traversal-two-pointers">
  Approach 2: Inorder Traversal + Two Pointers
</h1>

<h3 id="intuition">Intuition</h3>

An inorder traversal of a BST visits nodes in ascending order, so collecting the values during inorder produces a sorted list. Finding two numbers in a sorted list that sum to a target is the two-pointer problem from Two Sum II.

The plan is to flatten the BST into a sorted list with an inorder traversal, then run two pointers from both ends. If the sum of the two values is smaller than `k`, move the left pointer right to increase it. If it is larger, move the right pointer left to decrease it. If it equals `k`, the pair is found.

<h3 id="algorithm">Algorithm</h3>

1. Perform an inorder traversal of the BST to collect all values into a sorted list.
2. Initialize two pointers: `left` at the start of the list, `right` at the end.
3. While `left < right`:
4. If the pointers meet without finding a pair, return false.

<h3 id="example-walkthrough">Example Walkthrough</h3>

<h3 id="code">Code</h3>

```java
class Solution {
    public boolean findTarget(TreeNode root, int k) {
        // Flatten BST into sorted list via inorder traversal
        List<Integer> sorted = new ArrayList<>();
        inorder(root, sorted);

        // Two-pointer search on the sorted list
        int left = 0, right = sorted.size() - 1;
        while (left < right) {
            int sum = sorted.get(left) + sorted.get(right);
            if (sum == k) return true;
            if (sum < k) left++;
            else right--;
        }
        return false;
    }

    private void inorder(TreeNode node, List<Integer> sorted) {
        if (node == null) return;
        inorder(node.left, sorted);
        sorted.add(node.val);
        inorder(node.right, sorted);
    }
}
```


> Each pointer move discards an element that cannot belong to any remaining pair. If `list[left] + list[right] < k`, then `list[left]` paired with the largest remaining value is already below `k`, so it is below `k` with every smaller value too. No valid pair uses `list[left]`, so moving `left` forward loses nothing. The symmetric argument holds when the sum exceeds `k`: `list[right]` is too large for every remaining value, so moving `right` backward is safe. Since every discarded element provably has no valid partner, the scan never skips a pair that exists.

> - **Time Complexity:** O(n). The inorder traversal visits every node once, taking O(n). The two-pointer scan over the sorted list is also O(n) in the worst case. Total is O(n).
> - **Space Complexity:** O(n). We store all n values in the sorted list. The recursion stack for inorder traversal adds O(h) (O(n) for a skewed tree), but the list dominates.

Both approaches so far use O(n) extra space. The next approach runs the same two-pointer scan directly on the tree, walking it from both ends at once, so it never materializes the full sorted list and uses only O(h) space.

<h1 id="approach-3-bst-iterator-two-pointers">
  Approach 3: BST Iterator Two Pointers
</h1>

<h3 id="intuition">Intuition</h3>

This approach runs the two-pointer idea from Approach 2 directly on the BST, without collecting values into a list. It uses two iterators: one that yields values in ascending order (inorder: left, root, right) and one that yields them in descending order (reverse inorder: right, root, left).

The ascending iterator plays the role of the left pointer, starting at the smallest value and stepping up. The descending iterator plays the right pointer, starting at the largest value and stepping down. At each step we compare their sum to `k` and advance whichever side the comparison calls for, exactly as the two-pointer scan does on a sorted array.

Each iterator is an explicit stack. The forward iterator pushes a node and all its left descendants, so the top of the stack is the next smallest value; after popping a node, it descends into that node's right subtree and again pushes all left descendants. The reverse iterator mirrors this: push all right descendants to reach the largest value, and after popping descend into the left subtree.

<h3 id="algorithm">Algorithm</h3>

1. Initialize a forward stack by pushing all left children starting from the root (this positions us at the smallest value).
2. Initialize a reverse stack by pushing all right children starting from the root (this positions us at the largest value).
3. Pop the top of each stack to get the current smallest (`leftVal`) and largest (`rightVal`).
4. While `leftVal < rightVal`:
5. If the pointers meet or cross, return false.

<h3 id="example-walkthrough">Example Walkthrough</h3>

<h3 id="code">Code</h3>

```java
class Solution {
    public boolean findTarget(TreeNode root, int k) {
        // Forward iterator stack (ascending order)
        Deque<TreeNode> leftStack = new ArrayDeque<>();
        // Reverse iterator stack (descending order)
        Deque<TreeNode> rightStack = new ArrayDeque<>();

        // Initialize forward iterator: push all left children
        pushAllLeft(root, leftStack);
        // Initialize reverse iterator: push all right children
        pushAllRight(root, rightStack);

        // Get starting values
        TreeNode leftNode = leftStack.pop();
        TreeNode rightNode = rightStack.pop();

        while (leftNode != rightNode) {
            int sum = leftNode.val + rightNode.val;
            if (sum == k) return true;

            if (sum < k) {
                // Advance forward iterator
                pushAllLeft(leftNode.right, leftStack);
                leftNode = leftStack.pop();
            } else {
                // Advance reverse iterator
                pushAllRight(rightNode.left, rightStack);
                rightNode = rightStack.pop();
            }
        }
        return false;
    }

    private void pushAllLeft(TreeNode node, Deque<TreeNode> stack) {
        while (node != null) {
            stack.push(node);
            node = node.left;
        }
    }

    private void pushAllRight(TreeNode node, Deque<TreeNode> stack) {
        while (node != null) {
            stack.push(node);
            node = node.right;
        }
    }
}
```

```go
func findTarget(root *TreeNode, k int) bool {
    // Forward iterator stack (ascending order)
    leftStack := []*TreeNode{}
    // Reverse iterator stack (descending order)
    rightStack := []*TreeNode{}

    // Initialize forward iterator: push all left children
    pushAllLeft := func(node *TreeNode) {
        for node != nil {
            leftStack = append(leftStack, node)
            node = node.Left
        }
    }
    // Initialize reverse iterator: push all right children
    pushAllRight := func(node *TreeNode) {
        for node != nil {
            rightStack = append(rightStack, node)
            node = node.Right
        }
    }

    pushAllLeft(root)
    pushAllRight(root)

    // Get starting values
    leftNode := leftStack[len(leftStack)-1]
    leftStack = leftStack[:len(leftStack)-1]
    rightNode := rightStack[len(rightStack)-1]
    rightStack = rightStack[:len(rightStack)-1]

    for leftNode != rightNode {
        sum := leftNode.Val + rightNode.Val
        if sum == k {
            return true
        }
        if sum < k {
            // Advance forward iterator
            pushAllLeft(leftNode.Right)
            leftNode = leftStack[len(leftStack)-1]
            leftStack = leftStack[:len(leftStack)-1]
        } else {
            // Advance reverse iterator
            pushAllRight(rightNode.Left)
            rightNode = rightStack[len(rightStack)-1]
            rightStack = rightStack[:len(rightStack)-1]
        }
    }
    return false
}
```

```rust
type Node = Rc<RefCell<TreeNode>>;

impl Solution {
    pub fn find_target(root: Option<Rc<RefCell<TreeNode>>>, k: i32) -> bool {
        // Forward iterator stack (ascending order)
        let mut left_stack: Vec<Node> = Vec::new();
        // Reverse iterator stack (descending order)
        let mut right_stack: Vec<Node> = Vec::new();

        // Initialize forward iterator: push all left children
        Self::push_all_left(root.clone(), &mut left_stack);
        // Initialize reverse iterator: push all right children
        Self::push_all_right(root, &mut right_stack);

        let mut left_node = match left_stack.pop() {
            Some(node) => node,
            None => return false,
        };
        let mut right_node = match right_stack.pop() {
            Some(node) => node,
            None => return false,
        };

        // The iterators converge on the same node when all pairs are exhausted
        while !Rc::ptr_eq(&left_node, &right_node) {
            let sum = left_node.borrow().val + right_node.borrow().val;
            if sum == k {
                return true;
            }

            if sum < k {
                // Advance forward iterator into the right subtree
                let right_child = left_node.borrow().right.clone();
                Self::push_all_left(right_child, &mut left_stack);
                match left_stack.pop() {
                    Some(node) => left_node = node,
                    None => return false,
                }
            } else {
                // Advance reverse iterator into the left subtree
                let left_child = right_node.borrow().left.clone();
                Self::push_all_right(left_child, &mut right_stack);
                match right_stack.pop() {
                    Some(node) => right_node = node,
                    None => return false,
                }
            }
        }
        false
    }

    fn push_all_left(mut node: Option<Node>, stack: &mut Vec<Node>) {
        while let Some(cur) = node {
            let next = cur.borrow().left.clone();
            stack.push(cur);
            node = next;
        }
    }

    fn push_all_right(mut node: Option<Node>, stack: &mut Vec<Node>) {
        while let Some(cur) = node {
            let next = cur.borrow().right.clone();
            stack.push(cur);
            node = next;
        }
    }
}
```

```javascript
var findTarget = function (root, k) {
  // Forward iterator stack (ascending order)
  var leftStack = [];
  // Reverse iterator stack (descending order)
  var rightStack = [];

  // Initialize forward iterator: push all left children
  function pushAllLeft(node) {
    while (node !== null) {
      leftStack.push(node);
      node = node.left;
    }
  }
  // Initialize reverse iterator: push all right children
  function pushAllRight(node) {
    while (node !== null) {
      rightStack.push(node);
      node = node.right;
    }
  }

  pushAllLeft(root);
  pushAllRight(root);

  // Get starting values
  var leftNode = leftStack.pop();
  var rightNode = rightStack.pop();

  while (leftNode !== rightNode) {
    var sum = leftNode.val + rightNode.val;
    if (sum === k) return true;

    if (sum < k) {
      // Advance forward iterator
      pushAllLeft(leftNode.right);
      leftNode = leftStack.pop();
    } else {
      // Advance reverse iterator
      pushAllRight(rightNode.left);
      rightNode = rightStack.pop();
    }
  }
  return false;
};
```

```typescript
function findTarget(root: TreeNode | null, k: number): boolean {
  // Forward iterator stack (ascending order)
  const leftStack: TreeNode[] = [];
  // Reverse iterator stack (descending order)
  const rightStack: TreeNode[] = [];

  // Initialize forward iterator: push all left children
  function pushAllLeft(node: TreeNode | null): void {
    while (node !== null) {
      leftStack.push(node);
      node = node.left;
    }
  }
  // Initialize reverse iterator: push all right children
  function pushAllRight(node: TreeNode | null): void {
    while (node !== null) {
      rightStack.push(node);
      node = node.right;
    }
  }

  pushAllLeft(root);
  pushAllRight(root);

  // Get starting values
  let leftNode = leftStack.pop()!;
  let rightNode = rightStack.pop()!;

  while (leftNode !== rightNode) {
    const sum = leftNode.val + rightNode.val;
    if (sum === k) return true;

    if (sum < k) {
      // Advance forward iterator
      pushAllLeft(leftNode.right);
      leftNode = leftStack.pop()!;
    } else {
      // Advance reverse iterator
      pushAllRight(rightNode.left);
      rightNode = rightStack.pop()!;
    }
  }
  return false;
}
```

> The two iterators produce the same ascending and descending sequences that Approach 2 reads off the sorted list, one value at a time, so the pointer logic is identical and the same discard argument applies. Termination relies on the two iterators meeting at the same node. The forward iterator walks values upward and the reverse iterator walks them downward through the same set of nodes, so they cross at one node. The check `leftNode != rightNode` stops the loop at that point, which means every distinct pair has been compared without a match.

> - **Time Complexity:** O(n). In the worst case, both iterators together visit every node once. Each node is pushed onto a stack and popped once, so the total work is O(n).
> - **Space Complexity:** O(h), where h is the height of the tree. Each stack holds at most one node per level along a root-to-leaf path, so O(h) nodes at a time. This is O(log n) for a balanced BST and O(n) for a skewed tree. Because we never store the full sorted list, this uses less space than Approach 2 on a balanced tree.
