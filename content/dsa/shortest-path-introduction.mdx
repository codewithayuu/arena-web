<LessonCard>

The shortest path problem is one of the most common patterns in graph algorithms. Given a graph with weighted edges, find the path between two nodes that minimizes the total weight.

It appears in many contexts: navigation apps computing driving directions, routing packets through the internet, planning delivery routes, and a large set of coding interview problems.

Several algorithms solve this problem, and each one is designed for a different scenario. The choice depends on whether the graph is weighted, whether the weights can be negative, and whether you need distances from one source or between all pairs of nodes.

This chapter introduces the shortest path pattern, covering the core algorithms used in coding interviews: BFS for unweighted graphs, Dijkstra's algorithm for non-negative weights, and Bellman-Ford for graphs that may have negative edges.

<h2 id="what-is-shortest-path">What Is Shortest Path?</h2>

A shortest path between two nodes in a graph is the path with the minimum total edge weight. In an unweighted graph, this means the path with the fewest edges. In a weighted graph, it means the path where the sum of edge weights is smallest.

In the unweighted graph, both paths from A to D have length 2 (A→B→D and A→C→D). In the weighted graph, A→B→D costs 4+3=7 while A→C→D costs 2+5=7. Both paths have the same total cost. If we changed C→D to weight 4, then A→C→D would become the shorter path at cost 6.

What counts as "shortest" depends on the metric. For unweighted graphs, count the edges. For weighted graphs, sum the weights.

<h2 id="types-of-shortest-path-problems">Types of Shortest Path Problems</h2>

Shortest path problems come in several flavors, and recognizing which type you are facing determines which algorithm to use.

<h4 id="single-source-shortest-path-sssp">
  Single-Source Shortest Path (SSSP)
</h4>

Find the shortest path from one starting node to all other nodes in the graph. This is the most common type in interviews. Phrases like "starting from node K" or "from source S" indicate SSSP.

<h4 id="single-pair-shortest-path">Single-Pair Shortest Path</h4>

Find the shortest path between exactly two nodes: a source and a destination. While this seems simpler than SSSP, the best known algorithms for this are the same as for SSSP. We solve the general problem and extract the specific answer.

<h4 id="all-pairs-shortest-path-apsp">All-Pairs Shortest Path (APSP)</h4>

Find the shortest path between every pair of nodes. This is useful when you need distances between all node pairs, like precomputing a distance matrix. Floyd-Warshall handles this case.

Most interview problems are single-source or single-pair. All-pairs is rare but appears in problems involving precomputation.

<h2 id="algorithm-overview">Algorithm Overview</h2>

Different graph characteristics call for different algorithms. Here is a brief look at each before the templates and walkthroughs.

**BFS (Breadth-First Search)** works when all edges have the same weight (typically 1). It explores nodes level by level, guaranteeing the first time you reach a node is via the shortest path.

**Dijkstra's Algorithm** extends BFS to handle different non-negative weights. It uses a priority queue to always process the node with the smallest known distance, ensuring correctness through a greedy approach.

**Bellman-Ford** handles negative edge weights by relaxing all edges V-1 times. It is slower but more general, and it can detect negative cycles.

**Floyd-Warshall** computes all-pairs shortest paths in O(V^3) time using dynamic programming. Useful when V is small and you need all distances.

<h2 id="bfs-template-for-unweighted-graphs">
  BFS Template for Unweighted Graphs
</h2>

When all edges have equal weight, BFS finds shortest paths naturally. The first time you reach a node, you have found the shortest path to it.

```java
public int[] bfsShortestPath(List<List<Integer>> graph, int source) {
    int n = graph.size();
    int[] distance = new int[n];
    Arrays.fill(distance, -1);  // -1 means unreachable

    Queue<Integer> queue = new LinkedList<>();
    queue.offer(source);
    distance[source] = 0;

    while (!queue.isEmpty()) {
        int current = queue.poll();

        for (int neighbor : graph.get(current)) {
            if (distance[neighbor] == -1) {  // Not visited
                distance[neighbor] = distance[current] + 1;
                queue.offer(neighbor);
            }
        }
    }

    return distance;  // distance[i] = shortest path from source to i
}
```

<h4 id="why-bfs-works-for-unweighted-graphs">
  Why BFS works for unweighted graphs:
</h4>

BFS explores nodes in order of their distance from the source. All nodes at distance 1 are processed before nodes at distance 2, which are processed before nodes at distance 3, and so on. This level-by-level expansion guarantees that when we first visit a node, we have arrived via a shortest path.

**Time Complexity:** O(V + E) where V is vertices and E is edges. Each vertex is enqueued and dequeued once. Each edge is examined once.

**Space Complexity:** O(V) for the queue and distance array.

<h2 id="dijkstras-algorithm-template">Dijkstra's Algorithm Template</h2>

Dijkstra's algorithm generalizes BFS to handle non-negative edge weights. Instead of a regular queue, it uses a priority queue to always process the node with the smallest known distance.

```java
public int[] dijkstra(List<List<int[]>> graph, int source) {
    int n = graph.size();
    int[] distance = new int[n];
    Arrays.fill(distance, Integer.MAX_VALUE);
    distance[source] = 0;

    // Priority queue: {distance, node}
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    pq.offer(new int[]{0, source});

    while (!pq.isEmpty()) {
        int[] current = pq.poll();
        int dist = current[0];
        int node = current[1];

        // Skip if we've already found a better path
        if (dist > distance[node]) {
            continue;
        }

        // Relax all neighbors
        for (int[] edge : graph.get(node)) {
            int neighbor = edge[0];
            int weight = edge[1];
            int newDist = dist + weight;

            if (newDist < distance[neighbor]) {
                distance[neighbor] = newDist;
                pq.offer(new int[]{newDist, neighbor});
            }
        }
    }

    return distance;
}
```

```rust
pub fn dijkstra(graph: Vec<Vec<(i32, i32)>>, source: usize) -> Vec<i32> {
    use std::cmp::Reverse;
    use std::collections::BinaryHeap;

    let n = graph.len();
    let mut distance = vec![i32::MAX; n];
    distance[source] = 0;

    // Priority queue: {distance, node}
    let mut pq = BinaryHeap::new();
    pq.push(Reverse((0, source)));

    while let Some(Reverse((dist, node))) = pq.pop() {
        // Skip if we've already found a better path
        if dist > distance[node] {
            continue;
        }

        // Relax all neighbors
        for &(neighbor, weight) in &graph[node] {
            let neighbor = neighbor as usize;
            let new_dist = dist + weight;

            if new_dist < distance[neighbor] {
                distance[neighbor] = new_dist;
                pq.push(Reverse((new_dist, neighbor)));
            }
        }
    }

    distance
}
```

```javascript
  const distance = Array(n).fill(Infinity);
  distance[source] = 0;

  // Priority queue: {distance, node}
  const pq = [[0, source]];
  let head = 0;

  while (head < pq.length) {
    let best = head;
    for (let i = head + 1; i < pq.length; i++) {
      if (pq[i][0] < pq[best][0]) best = i;
    }
    [pq[head], pq[best]] = [pq[best], pq[head]];

      continue;
    }

    // Relax all neighbors
    for (const edge of graph[node]) {
      const neighbor = edge[0];
      const weight = edge[1];
      const newDist = dist + weight;

      if (newDist < distance[neighbor]) {
        distance[neighbor] = newDist;
```

**The key operation is edge relaxation:**

```text
if distance[source] + weight < distance[destination]:
    distance[destination] = distance[source] + weight
```

We "relax" an edge by checking if going through the current node provides a shorter path to the neighbor than previously known.

**Why the priority queue matters:**

The priority queue ensures we process nodes in order of increasing distance. When we pop a node from the queue, we are guaranteed to have found the shortest path to it (assuming non-negative weights). This is because any alternative path would have to go through nodes with equal or greater distance.

**Time Complexity:** O((V + E) log V). Each vertex can be added to the priority queue multiple times, but at most E times (once per edge). Each priority queue operation is O(log V).

**Space Complexity:** O(V + E) for the graph representation and O(V) for the distance array and priority queue.

<h2 id="bellman-ford-algorithm-template">Bellman-Ford Algorithm Template</h2>

Bellman-Ford handles graphs with negative edge weights by taking a different approach: relax all edges V-1 times. This guarantees finding the shortest path because the longest possible shortest path has V-1 edges.

```java
public int[] bellmanFord(int n, int[][] edges, int source) {
    int[] distance = new int[n];
    Arrays.fill(distance, Integer.MAX_VALUE);
    distance[source] = 0;

    // Relax all edges V-1 times
    for (int i = 0; i < n - 1; i++) {
        boolean updated = false;

        for (int[] edge : edges) {
            int from = edge[0];
            int to = edge[1];
            int weight = edge[2];

            if (distance[from] != Integer.MAX_VALUE &&
                distance[from] + weight < distance[to]) {
                distance[to] = distance[from] + weight;
                updated = true;
            }
        }

        // Early termination if no updates
        if (!updated) break;
    }

    // Optional: detect negative cycles
    for (int[] edge : edges) {
        int from = edge[0];
        int to = edge[1];
        int weight = edge[2];

        if (distance[from] != Integer.MAX_VALUE &&
            distance[from] + weight < distance[to]) {
            // Negative cycle detected
            return null;
        }
    }

    return distance;
}
```

```javascript
    const weight = edge[2];

    if (
      distance[from] !== Number.POSITIVE_INFINITY &&
      distance[from] + weight < distance[to]
    ) {
      // Negative cycle detected
      return null;
    }
  }

  return distance;
}
```

```typescript
function bellmanFord(
  n: number,
  edges: number[][],
  source: number,
): number[] | null {
  const distance = new Array<number>(n).fill(Number.POSITIVE_INFINITY);
  distance[source] = 0;

  // Relax all edges V-1 times
  for (let i = 0; i < n - 1; i++) {
    let updated = false;

    for (const edge of edges) {
      const from = edge[0];
      const to = edge[1];
      const weight = edge[2];

      if (
        distance[from] !== Number.POSITIVE_INFINITY &&
        distance[from] + weight < distance[to]
      ) {
        distance[to] = distance[from] + weight;
        updated = true;
      }
    }

    // Early termination if no updates
    if (!updated) break;
  }

  // Optional: detect negative cycles
  for (const edge of edges) {
    const from = edge[0];
    const to = edge[1];
    const weight = edge[2];

    if (
      distance[from] !== Number.POSITIVE_INFINITY &&
      distance[from] + weight < distance[to]
    ) {
      // Negative cycle detected
      return null;
    }
  }

  return distance;
}
```

**Why V-1 iterations?**

A shortest path in a graph with V vertices can have at most V-1 edges (visiting each vertex once). In each iteration, Bellman-Ford guarantees that the shortest path using up to i edges is found. After V-1 iterations, all shortest paths are found.

**Negative cycle detection:**

If any edge can still be relaxed after V-1 iterations, a negative cycle exists. The cycle allows infinite reduction of path cost.

**Time Complexity:** O(V \* E). We iterate V-1 times and examine all E edges in each iteration.

**Space Complexity:** O(V) for the distance array.

<h2 id="complexity-comparison">Complexity Comparison</h2>

| Algorithm                 | Time             | Space    | Best For                           |
| ------------------------- | ---------------- | -------- | ---------------------------------- |
| BFS                       | O(V + E)         | O(V)     | Unweighted graphs, fewest edges    |
| Dijkstra (binary heap)    | O((V + E) log V) | O(V + E) | Non-negative weighted graphs       |
| Dijkstra (Fibonacci heap) | O(E + V log V)   | O(V + E) | Dense graphs, theoretical interest |
| Bellman-Ford              | O(V \* E)        | O(V)     | Negative weights, limited edges    |
| Floyd-Warshall            | O(V^3)           | O(V^2)   | All-pairs, small V                 |

<h4 id="practical-notes">Practical notes:</h4>

- For most interview problems with V, E up to 10^4 or 10^5, Dijkstra with a binary heap is fast enough
- Bellman-Ford becomes attractive when you need exactly K iterations or need to detect negative cycles
- Floyd-Warshall is practical only for small V (roughly V < 400)

<h2 id="key-takeaways">Key Takeaways</h2>

- Match the algorithm to the graph: use BFS when every edge has the same weight, Dijkstra when weights vary but stay non-negative, Bellman-Ford when edges can be negative or you need to detect a negative cycle, and Floyd-Warshall when you need shortest paths between all pairs of nodes on a small graph.
- BFS finds shortest paths in O(V + E) time and O(V) space because it explores nodes level by level, so the first time it reaches a node is along a path with the fewest edges.
- Dijkstra runs in O((V + E) log V) time with a binary heap and uses a priority queue to always process the node with the smallest known distance, which holds only when all edge weights are non-negative.
- Bellman-Ford runs in O(V \* E) time by relaxing every edge V-1 times, and one extra pass over the edges reveals a negative cycle when any distance can still be reduced.
- Floyd-Warshall computes all-pairs shortest paths in O(V^3) time and O(V^2) space, so it stays practical only when V is small.
- Identify the problem type first: single-source and single-pair questions use the same algorithms, while all-pairs questions point toward Floyd-Warshall.
