<LessonCard>

You want to schedule a list of jobs in `d` days. Jobs are dependent (i.e., to work on the `i`-th job, you have to finish all the jobs `j` where `0 <= j < i`).

You have to finish at least one job every day. The difficulty of a job schedule is the sum of difficulties of each day of the `d` days. The difficulty of a day is the maximum difficulty of a job done on that day.

You are given an integer array `jobDifficulty` and an integer `d`. The difficulty of the `i`-th job is `jobDifficulty[i]`.

Return the minimum difficulty of a job schedule. If you cannot find a schedule for the jobs, return `-1`.

**Example 1:**

- **Input:** `jobDifficulty = [6,5,4,3,2,1]`

- **Input:** `d = 2`

- **Output:** `7`

On day 1, you can finish the first 5 jobs with difficulty = max(6, 5, 4, 3, 2) = 6. On day 2, you finish the last job with difficulty = 1. Total difficulty = 6 + 1 = 7.

**Example 2:**

- **Input:** `jobDifficulty = [9,9,9]`

- **Input:** `d = 4`

- **Output:** `-1`

You cannot schedule 3 jobs in 4 days since each day must have at least one job.

**Example 3:**

- **Input:** `jobDifficulty = [1,1,1]`

- **Input:** `d = 3`

- **Output:** `3`

Each day gets exactly one job. Day difficulties are 1, 1, 1. Total = 3.

**Constraints:**

- `1 <= jobDifficulty.length <= 300`
- `0 <= jobDifficulty[i] <= 1000`
- `1 <= d <= 10`

We have n jobs that must be done in order (job 0 before job 1 before job 2, etc.), and we need to split them across exactly d days. Each day must have at least one job. The cost of a day is the maximum difficulty among all jobs assigned to that day, and we want to minimize the total cost across all days.

This is essentially a partition problem: split the array `jobDifficulty` into exactly `d` contiguous segments, where each segment has at least one element, and minimize the sum of the maximum value in each segment.

This has optimal substructure. The best way to schedule the first `i` jobs in `k` days can be built from the best way to schedule a prefix in `k-1` days, trying every possible split point for the last day. That structure points to dynamic programming.

- `1 <= jobDifficulty.length <= 300`. With n at most 300, an O(n^2 _ d) solution runs in roughly 300 _ 300 \* 10 = 900,000 operations, which is fast enough.
- `1 <= d <= 10`. Because d is bounded by 10, it works well as one of the DP dimensions.
- `0 <= jobDifficulty[i] <= 1000`. The largest possible total is 300 \* 1000 = 300,000, so the sum fits in a 32-bit integer with no overflow risk.

<h1 id="approach-1-top-down-dp-recursion-with-memoization">
  Approach 1: Top-Down DP (Recursion with Memoization)
</h1>

<h3 id="intuition">Intuition</h3>

On day 1, we decide how many jobs to do. We must do at least one, and we must leave enough jobs so that each remaining day still gets at least one. After fixing the jobs for today, the rest of the problem is the same kind of question over fewer jobs and fewer days, which we solve recursively.

Let `solve(i, k)` be the minimum difficulty to schedule jobs from index `i` onward using exactly `k` days. For the current day, we try assigning jobs `i`, `i+1`, ..., up to some endpoint `j`. The cost of this day is `max(jobDifficulty[i..j])`, and then we recursively solve `solve(j+1, k-1)` for the remaining jobs and days.

The base case: if `k == 1`, we must do all remaining jobs in one day, so the cost is `max(jobDifficulty[i..n-1])`.

<h3 id="algorithm">Algorithm</h3>

1. If n < d, return -1 (not enough jobs for each day to have at least one).
2. Define a recursive function `solve(i, k)` meaning: minimum cost to schedule jobs from index i through n-1 in exactly k days.
3. Base case: if k == 1, return the maximum of `jobDifficulty[i..n-1]`.
4. For the current day, try ending at every valid index j from i to n-k. Track the running maximum as we extend j.
5. For each choice, the cost is `currentMax + solve(j+1, k-1)`. Take the minimum over all choices.
6. Memoize results to avoid recomputation.

```java
class Solution {
    public int minDifficulty(int[] jobDifficulty, int d) {
        int n = jobDifficulty.length;
        if (n < d) return -1;

        int[][] memo = new int[n][d + 1];
        for (int[] row : memo) Arrays.fill(row, -1);

        return solve(jobDifficulty, 0, d, memo);
    }

    private int solve(int[] jobs, int i, int k, int[][] memo) {
        int n = jobs.length;
        // Base case: one day left, do all remaining jobs
        if (k == 1) {
            int maxVal = 0;
            for (int j = i; j < n; j++) {
                maxVal = Math.max(maxVal, jobs[j]);
            }
            return maxVal;
        }

        if (memo[i][k] != -1) return memo[i][k];

        int result = Integer.MAX_VALUE;
        int currentMax = 0;

        // Try ending the current day at index j
        for (int j = i; j <= n - k; j++) {
            currentMax = Math.max(currentMax, jobs[j]);
            int future = solve(jobs, j + 1, k - 1, memo);
            result = Math.min(result, currentMax + future);
        }

        memo[i][k] = result;
        return result;
    }
}
```

```go
    // Base case: one day left, do all remaining jobs
    if k == 1 {
        maxVal := 0
        for j := i; j < n; j++ {
            if jobs[j] > maxVal {
                maxVal = jobs[j]
            }

        return maxVal

    if memo[i][k] != -1 {
        return memo[i][k]

            currentMax = jobs[j]

        future := solve(jobs, j+1, k-1, memo)
        if currentMax+future < result {
            result = currentMax + future
        }
    }

    memo[i][k] = result
    return result
```

> - **Time Complexity:** O(n^2 _ d). There are O(n _ d) unique states, and for each state we iterate up to O(n) to try different split points.
> - **Space Complexity:** O(n _ d). The memoization table has n _ d entries. The recursion adds O(d) stack depth, since each call decreases the day count by one.

The same computation can be expressed bottom-up, filling the table iteratively instead of through recursion. The bottom-up form makes the inner loop easier to reason about and sets up the stack-based optimization that follows.

<h1 id="approach-2-bottom-up-dp">Approach 2: Bottom-Up DP</h1>

<h3 id="intuition">Intuition</h3>

Instead of thinking top-down, we build the solution iteratively. Let `dp[i][k]` represent the minimum difficulty to schedule the first `i` jobs in exactly `k` days.

The transition: for the k-th day, we assign some contiguous block of jobs ending at job i. If the k-th day covers jobs from index j to i-1, then `dp[i][k] = min over j of (dp[j][k-1] + max(jobDifficulty[j..i-1]))`.

We iterate j backward from i-1 down to k-1, tracking the running maximum. This avoids recomputing the maximum from scratch for each j.

<h3 id="algorithm">Algorithm</h3>

1. If n < d, return -1.
2. Create a 2D array `dp` of size (n+1) x (d+1), initialized to infinity. Set `dp[0][0] = 0`.
3. For each day k from 1 to d:
4. Return `dp[n][d]`.

```java
class Solution {
    public int minDifficulty(int[] jobDifficulty, int d) {
        int n = jobDifficulty.length;
        if (n < d) return -1;

        int[][] dp = new int[n + 1][d + 1];
        for (int[] row : dp) Arrays.fill(row, Integer.MAX_VALUE);
        dp[0][0] = 0;

        for (int k = 1; k <= d; k++) {
            for (int i = k; i <= n; i++) {
                int currentMax = 0;
                // Try all starting points for day k (iterate backward)
                for (int j = i; j >= k; j--) {
                    currentMax = Math.max(currentMax, jobDifficulty[j - 1]);
                    if (dp[j - 1][k - 1] != Integer.MAX_VALUE) {
                        dp[i][k] = Math.min(dp[i][k], dp[j - 1][k - 1] + currentMax);
                    }
                }
            }
        }

        return dp[n][d];
    }
}
```

> - **Time Complexity:** O(n^2 \* d). For each of the d days and each of the n positions, we iterate backward through up to n positions.
> - **Space Complexity:** O(n _ d). The 2D dp table has (n+1) _ (d+1) entries.

The inner loop rescans every split point from scratch for each position, which is where the second factor of n comes from. A monotonic stack removes that rescan by carrying the best split point forward as we move left to right, dropping the total to O(n \* d).

<h1 id="approach-3-dp-with-monotonic-stack-optimal">
  Approach 3: DP with Monotonic Stack (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

Fix a day k and compute dp[i][k] for all i from left to right. When job i is more difficult than some earlier job j (j < i), every last-day segment that previously had `jobDifficulty[j]` as its maximum now has `jobDifficulty[i]` as its maximum instead. Those earlier positions can be folded into the new one rather than recomputed.

A monotonic stack tracks this. The stack holds indices with strictly decreasing job difficulty. Before placing index i, pop every index whose difficulty is at most `jobDifficulty[i]`, and for each popped index update dp[i] to reflect the larger maximum. After the pops, the stack top (if any) is an index more difficult than i, so its stored dp value already accounts for that larger maximum, and we take it directly.

> The update during popping is `newDp[i] = min(newDp[i], popped.bestDp - popped.difficulty + jobDifficulty[i])`. The popped entry's `bestDp` is the cheapest cost for a last-day segment whose maximum was `popped.difficulty`. Subtracting that old maximum and adding `jobDifficulty[i]` reuses the same split point but charges the new, larger maximum, which is correct because extending the segment to include job i raises its maximum to `jobDifficulty[i]`.
>
> Each index is pushed once and popped at most once per day, so the stack work over all i is O(n) per day, giving O(n \* d) overall.

<h3 id="algorithm">Algorithm</h3>

1. If n < d, return -1.
2. Use a 1D dp array (space-optimized). Process day by day.
3. For each day k from 1 to d, iterate through jobs left to right:
4. Return dp[n-1] after processing all d days.

```java
class Solution {
    public int minDifficulty(int[] jobDifficulty, int d) {
        int n = jobDifficulty.length;
        if (n < d) return -1;

        int[] dp = new int[n];
        // Day 1: dp[i] = max(jobDifficulty[0..i])
        dp[0] = jobDifficulty[0];
        for (int i = 1; i < n; i++) {
            dp[i] = Math.max(dp[i - 1], jobDifficulty[i]);
        }

        for (int k = 2; k <= d; k++) {
            int[] newDp = new int[n];
            Arrays.fill(newDp, Integer.MAX_VALUE);
            // Stack stores [index, bestDp] with decreasing job difficulty
            Deque<int[]> stack = new ArrayDeque<>();

            for (int i = k - 1; i < n; i++) {
                // Start a new segment at i: previous day ends at i-1
                newDp[i] = dp[i - 1] + jobDifficulty[i];
```

```go
func minDifficulty(jobDifficulty []int, d int) int {
    n := len(jobDifficulty)
    if n < d {
        return -1
    }

    dp := make([]int, n)
    // Day 1: dp[i] = max(jobDifficulty[0..i])
    dp[0] = jobDifficulty[0]
    for i := 1; i < n; i++ {
        dp[i] = dp[i-1]
        if jobDifficulty[i] > dp[i] {
            dp[i] = jobDifficulty[i]
        }
    }

    for k := 2; k <= d; k++ {
        newDp := make([]int, n)
        for i := range newDp {
            newDp[i] = 1<<31 - 1
        }
        // Stack stores [index, bestDp] with decreasing job difficulty
        type entry struct{ index, bestDp int }
        stack := []entry{}

        for i := k - 1; i < n; i++ {
            // Start a new segment at i: previous day ends at i-1
            newDp[i] = dp[i-1] + jobDifficulty[i]

            // Pop entries with smaller or equal difficulty
            for len(stack) > 0 && jobDifficulty[stack[len(stack)-1].index] <= jobDifficulty[i] {
                popped := stack[len(stack)-1]
                stack = stack[:len(stack)-1]
                val := popped.bestDp - jobDifficulty[popped.index] + jobDifficulty[i]
                if val < newDp[i] {
                    newDp[i] = val
                }
            }

            // Check if stack top has a better dp value
            if len(stack) > 0 && stack[len(stack)-1].bestDp < newDp[i] {
                newDp[i] = stack[len(stack)-1].bestDp
            }

            stack = append(stack, entry{i, newDp[i]})
        }

        dp = newDp
    }

    return dp[n-1]
}
```

> - **Time Complexity:** O(n \* d). For each of the d days, we process all n jobs. The monotonic stack ensures each element is pushed and popped at most once per day.
> - **Space Complexity:** O(n). We use two 1D dp arrays of size n and a stack of at most n elements.
