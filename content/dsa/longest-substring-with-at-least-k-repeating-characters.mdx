Given a string `s` and an integer `k`, return the length of the longest substring of `s` such that the frequency of each character in this substring is greater than or equal to `k`.

If no such substring exists, return `0`.

\***\*Example 1:\*\***

- **Input:** `s = aaabb`

- **Input:** `k = 3`

- **Output:** `3`

**Explanation:** The longest substring is "aaa", as 'a' is repeated 3 times.

\***\*Example 2:\*\***

- **Input:** `s = ababbc`

- **Input:** `k = 2`

- **Output:** `5`

**Explanation:** The longest substring is "ababb", as 'a' is repeated 2 times and 'b' is repeated 3 times.

\***\*Constraints:\*\***

- `1 <= s.length <= 10^4`
- `s` consists of only lowercase English letters.
- `1 <= k <= 10^5`

We need to find the longest substring where every character that appears in it appears at least `k` times. This is not about finding a single character that repeats `k` times. Every character in the substring must meet the threshold. If even one character falls short, the entire substring is invalid.

The "at least k" constraint applies per-character within the substring, not globally. A character that appears 100 times in the full string might appear only once in a particular substring, disqualifying it. And unlike sliding window problems where the constraint can be checked incrementally as the window grows, here the validity of a window depends on all characters at once, so adding one character can invalidate a window that was previously valid.

One property drives most of the solutions: any character that appears fewer than `k` times in the entire string can never belong to any valid substring. Such characters act as splitting points that divide the string into segments. The answer must lie entirely within one of those segments. This property leads directly to a divide and conquer approach, and to a sliding window variant that fixes the number of distinct characters.

- `1 <= s.length <= 10^4` → With n up to 10,000, even O(n^2) approaches should work within time limits. But O(n) or O(n log n) is ideal.
- `s consists of only lowercase English letters` → At most 26 distinct characters. This bound lets us enumerate over the number of distinct characters allowed in a window (1 to 26), which is what makes the sliding window approach work.
- `1 <= k <= 10^5` → k can be larger than the string length, in which case the answer is always 0.

<h1 id="approach-1-brute-force">Approach 1: Brute Force</h1>

<h3 id="intuition">Intuition</h3>

Check every possible substring and test whether it satisfies the constraint. For each substring, count the frequency of every character and verify that all characters appear at least `k` times. Pick every starting index, extend to every ending index, count frequencies as you extend, and track the longest substring that passes.

<h3 id="algorithm">Algorithm</h3>

1. Iterate over all possible starting indices `i` from 0 to n-1.
2. For each starting index, iterate over all ending indices `j` from `i` to n-1.
3. Count the frequency of each character in the substring `s[i..j]`.
4. Check if every character in the substring has a frequency of at least `k`.
5. If valid, update the maximum length.
6. Return the maximum length found.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n^2). We have two nested loops iterating over all pairs of indices (O(n^2)), and for each pair we check all 26 characters to validate the substring. Since 26 is constant, this simplifies to O(n^2).
> - **Space Complexity:** O(1). We only use a fixed-size frequency array of 26 characters.

This checks every substring independently and ignores the structure of the problem. The next approach uses the low-frequency characters to split the string into smaller independent subproblems.

<h1 id="approach-2-divide-and-conquer">Approach 2: Divide and Conquer</h1>

<h3 id="intuition">Intuition</h3>

If a character appears in `s` fewer than `k` times total, it can never be part of any valid substring, so every valid substring must avoid it entirely. That character splits the string into segments, and the answer lies entirely within one of those segments.

This gives a recursive strategy. Count character frequencies for the current string. Find a character that appears fewer than `k` times. Split the string at every occurrence of that character, then recursively solve each segment. The answer is the maximum across all segments.

If every character in the current string already meets the threshold, the entire string is valid and we return its length. That is the base case.

> Each recursive call either returns the whole segment as valid (base case) or splits on a character whose count is below `k`. The character used to split is removed from every child segment, so each child works over a strictly smaller alphabet. With at most 26 distinct characters, the recursion depth is bounded by 26 regardless of string length.

<h3 id="algorithm">Algorithm</h3>

1. Count the frequency of each character in the current string.
2. If every character has frequency >= k, return the length of the string (the whole string is valid).
3. Otherwise, find a character with frequency < k.
4. Split the string at every occurrence of that character.
5. Recursively solve each segment.
6. Return the maximum result across all segments.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n). At each level of recursion, we scan the string once to count frequencies and find the split point. The recursion depth is at most 26 (one level per unique character eliminated), so the total work across all levels is O(26 \* n) = O(n).
> - **Space Complexity:** O(1). The recursion depth is at most 26, and each level uses a frequency array of size 26, so stack space is O(676), which is constant.

The divide and conquer approach is efficient but recursive. The next approach solves the problem iteratively with a sliding window. The obstacle is the shrink condition, which the approach removes by fixing the number of distinct characters allowed in the window.

<h1 id="approach-3-sliding-window-with-unique-character-count">
  Approach 3: Sliding Window with Unique Character Count
</h1>

<h3 id="intuition">Intuition</h3>

A standard sliding window fails here because there is no monotonic shrink condition. When the window expands and a new character enters with frequency below `k`, shrinking from the left could remove a character that was already valid, so the window length is not a function we can grow and shrink greedily.

Adding one constraint fixes this. Instead of asking for the longest valid substring directly, ask for the longest valid substring that contains exactly `t` distinct characters. Fixing `t` gives a clean shrink condition: whenever the window holds more than `t` distinct characters, shrink from the left until it holds exactly `t` again. When the window holds exactly `t` distinct characters and all `t` of them have frequency at least `k`, the window is valid.

A valid answer has some number of distinct characters between 1 and 26, so running this windowed scan once for each `t` from 1 to 26 covers every case. Each scan is O(n), so the total is O(26n) = O(n).

<h3 id="algorithm">Algorithm</h3>

1. For each target number of unique characters `t` from 1 to 26:
2. Return the overall maximum.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n). We run the sliding window at most 26 times (once per possible unique character count). Each sliding window pass is O(n) since every character is added and removed at most once. Total: O(26n) = O(n).
> - **Space Complexity:** O(1). We use a frequency array of 26 elements per sliding window pass. No recursion needed.
