This is essentially how the **Fast & Slow Pointers** pattern works.

It uses two pointers that traverse a sequence at different speeds. Typically:

- **Slow pointer**: Moves one step at a time
- **Fast pointer**: Moves two steps at a time

By the time the fast pointer reaches the end (or catches up to the slow pointer in a cycle), the slow pointer will be at a position of interest, like the middle of the list or the cycle entry point.

<h1 id="why-does-this-technique-work">Why Does This Technique Work?</h1>

The mathematical intuition behind fast and slow pointers is elegant:

<h4 id="for-finding-the-middle">For finding the middle</h4>

If the fast pointer moves at 2x speed and the slow pointer at 1x speed, when the fast pointer has covered the entire distance, the slow pointer has covered exactly half. This places the slow pointer at the middle.

<h4 id="for-cycle-detection">For cycle detection</h4>

If there is a cycle, the fast pointer will eventually "lap" the slow pointer. The key insight from Floyd's algorithm is that if they meet, there is definitely a cycle. And the mathematics of their meeting point reveals exactly where the cycle begins.

In a cycle, both pointers will eventually enter the cycle. Since the fast pointer moves twice as fast, it will catch up to the slow pointer within the cycle. The meeting is guaranteed because the relative speed difference is 1 step per iteration.

<h1 id="when-to-use-fast-and-slow-pointers">
  When to Use Fast and Slow Pointers
</h1>

This pattern is the right tool when you see these situations:

**1. Finding the middle of a linked list**

When you need to find the middle element without knowing the length in advance, fast and slow pointers give you a single-pass O(n) solution.

**2. Detecting cycles in a linked list or sequence**

If a sequence might contain a cycle (a node pointing back to an earlier node), fast and slow pointers can detect it in O(1) space.

**3. Finding the start of a cycle**

Not only can you detect a cycle, but with a clever technique you can also find exactly where the cycle begins.

**4. Checking for palindromes in linked lists**

Combined with list reversal, this pattern helps check if a linked list is a palindrome.

**5. Finding cycles in number sequences**

Some numerical problems (like Happy Number) involve sequences that might cycle. The same technique applies.

Here are common problem types where fast and slow pointers excel:

| Problem Type        | Examples                                |
| ------------------- | --------------------------------------- |
| Find middle element | Middle of the Linked List, Reorder List |
| Cycle detection     | Linked List Cycle, Linked List Cycle II |
| Cycle in sequences  | Happy Number, Find the Duplicate Number |
| Palindrome checking | Palindrome Linked List                  |
| List partitioning   | Split list into halves for merge sort   |

<h1 id="the-fast-and-slow-pointers-templates">
  The Fast and Slow Pointers Templates
</h1>

Most fast and slow pointer problems follow one of two templates. Let us establish them clearly.

<h3 id="template-1-finding-the-middle">Template 1: Finding the Middle</h3>

```java
public ListNode findMiddle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;

    // Move until fast reaches the end
    while (fast != null && fast.next != null) {
        slow = slow.next;          // Move slow by 1
        fast = fast.next.next;     // Move fast by 2
    }

    return slow;  // Slow is at the middle
}
```

    pub fn find_middle(head: Option<Box<ListNode>>) -> Option<Box<ListNode>> {
        let mut slow = head.as_ref();
        let mut fast = head.as_ref();

        // Move until fast reaches the end
        while fast.is_some() && fast.unwrap().next.is_some() {
            slow = slow.unwrap().next.as_ref(); // move slow by 1
            fast = fast.unwrap().next.as_ref().unwrap().next.as_ref(); // move fast by 2
        }

        slow.cloned() // slow is at the middle
    }
}

**Note on even-length lists**: When the list has an even number of nodes, this template returns the second middle node. For example, in `[1, 2, 3, 4]`, it returns node 3. If you need the first middle node, check `fast.next != null && fast.next.next != null` instead.

<h3 id="template-2-cycle-detection-floyds-algorithm">
  Template 2: Cycle Detection (Floyd's Algorithm)
</h3>

```java
public boolean hasCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;

    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;

        // If they meet, there's a cycle
        if (slow == fast) {
            return true;
        }
    }

    // Fast reached the end, no cycle
    return false;
}
```

pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}

impl ListNode {
    #[allow(dead_code)]
    pub fn new(val: i32) -> Self {
        ListNode { val, next: None }
    }
}

pub struct Solution;

impl Solution {
    pub fn has_cycle(head: Option<Box<ListNode>>) -> bool {
        let mut slow = head.as_deref();
        let mut fast = head.as_deref();

        while let Some(f) = fast {
            if f.next.is_none() {
                break;
            }

            slow = slow.and_then(|node| node.next.as_deref());
            fast = f.next.as_deref().and_then(|node| node.next.as_deref());

            // If they meet, there's a cycle
            if let (Some(s), Some(f)) = (slow, fast) {
                if core::ptr::eq(s, f) {
                    return true;
                }
            }
        }

        // Fast reached the end, no cycle
        false
    }
}

<h3 id="template-3-finding-cycle-start">Template 3: Finding Cycle Start</h3>

```java
public ListNode findCycleStart(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;

    // Phase 1: Detect cycle and find meeting point
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;

        if (slow == fast) {
            // Phase 2: Find cycle start
            ListNode pointer = head;
            while (pointer != slow) {
                pointer = pointer.next;
                slow = slow.next;
            }
            return slow;  // Cycle start
        }
    }

    return null;  // No cycle
}
```

```rust
pub struct Solution;

/**
 * Definition for singly-linked list.
 * #[derive(PartialEq, Eq, Clone, Debug)]
 * pub struct ListNode {
 *     pub val: i32,
 *     pub next: Option<Box<ListNode>>,
 * }
 */

impl Solution {
    pub fn find_cycle_start(head: Option<Box<ListNode>>) -> Option<Box<ListNode>> {
        let mut slow = head.as_ref();
        let mut fast = head.as_ref();

        // Phase 1: Detect cycle and find meeting point
        while let Some(f_node) = fast {
            if f_node.next.is_none() {
                break;
            }

            slow = slow.and_then(|node| node.next.as_ref());
            fast = f_node
                .next
                .as_ref()
                .and_then(|node| node.next.as_ref());

            if let (Some(s), Some(f)) = (slow, fast) {
                if std::ptr::eq(s, f) {
                    // Phase 2: Find cycle start
                    let mut pointer = head.as_ref();
                    while let (Some(p), Some(s2)) = (pointer, slow) {
                        if std::ptr::eq(p, s2) {
                            break;
                        }
                        pointer = p.next.as_ref();
                        slow = s2.next.as_ref();
                    }
                    return head;
                }
            } else {
                break;
            }
        }

        None // No cycle
    }
}
```
