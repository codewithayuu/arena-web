<LessonCard>

Given an integer array `nums` and an integer `k`, return the maximum sum of a non-empty subsequence of that array such that for every two consecutive integers in the subsequence, `nums[i]` and `nums[j]`, where `i < j`, the condition `j - i <= k` is satisfied.

A subsequence of an array is obtained by deleting some number of elements (can be zero) from the array, leaving the remaining elements in their original order.

\***\*Example 1:\*\***

- **Input:** `nums = [10,2,-10,5,20]`

- **Input:** `k = 2`

- **Output:** `37`

\***\*Example 2:\*\***

- **Input:** `nums = [-1,-2,-3]`

- **Input:** `k = 1`

- **Output:** `-1`

\***\*Example 3:\*\***

- **Input:** `nums = [10,-2,-10,-5,20]`

- **Input:** `k = 2`

- **Output:** `23`

\***\*Constraints:\*\***

- `1 <= k <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

This problem asks us to pick a non-empty subsequence from the array where consecutive elements in the subsequence are at most `k` positions apart. We want to maximize the sum of this subsequence.

This is not a contiguous subarray problem. We can skip elements, but we can't skip too many. If we pick `nums[i]`, the next element we pick must be at some index `j` where `j - i <= k`. So we have a "maximum gap" constraint between consecutive picks.

This structure fits dynamic programming. If `dp[i]` represents the maximum sum of a valid subsequence ending at index `i`, then `dp[i]` depends on the best `dp[j]` values for all `j` in the range `[i-k, i-1]`. The element `nums[i]` must always be included (since the subsequence ends at `i`), so `dp[i] = nums[i] + max(0, max(dp[j]) for j in [i-k, i-1])`. We take `max(0, ...)` because we might be better off starting a new subsequence at `i` rather than extending a negative-sum one.

The challenge is computing that "max over a sliding window of dp values" efficiently.

<h3 id="key-constraints">Key Constraints:</h3>

- `1 <= nums.length <= 10^5`: with n up to 100,000, we need O(n log n) or O(n). An O(n\*k) approach degrades to O(n^2) when k is close to n, which is too slow.
- `-10^4 <= nums[i] <= 10^4`: values can be negative, and we can't skip all of them. A negative element may be the only stepping stone within range to a large positive value further ahead. The maximum possible sum is 10^5 \* 10^4 = 10^9, which fits in a 32-bit signed integer, so no wider type is needed.
- `1 <= k <= nums.length`: k can be as large as n, in which case there is no gap constraint at all.

<h1 id="approach-1-dynamic-programming-brute-force">
  Approach 1: Dynamic Programming (Brute Force)
</h1>

<h3 id="intuition">Intuition</h3>

For every index `i`, look back at all indices in the range `[i-k, i-1]` and pick the one with the highest dp value. If that best value is positive, extend that subsequence. If it's negative, start fresh at `i`.

This computes the recurrence directly: `dp[i] = nums[i] + max(0, max(dp[j]) for j in [max(0, i-k), i-1])`.

<h3 id="algorithm">Algorithm</h3>

1. Create a `dp` array of size n, where `dp[i]` will store the maximum subsequence sum ending at index i.
2. Set `dp[0] = nums[0]`.
3. For each index `i` from 1 to n-1:
4. Return the maximum value in the `dp` array.

<h3 id="example-walkthrough">Example Walkthrough</h3>

**Input:**

The dp array fills in left to right. For each index, scan up to k = 2 previous dp values, take the best, and add `nums[i]`:

The answer is `max(dp) = 37`, produced by the subsequence `[10, 2, 5, 20]` (indices 0, 1, 3, 4; the gaps between consecutive picks are 1, 2, and 1, all within k = 2).

<h3 id="code">Code</h3>

```java
class Solution {
    public int constrainedSubsetSum(int[] nums, int k) {
        int n = nums.length;
        int[] dp = new int[n];
        dp[0] = nums[0];
        int result = dp[0];

        for (int i = 1; i < n; i++) {
            // Find the max dp value in the window [i-k, i-1]
            int bestPrev = 0;
            for (int j = Math.max(0, i - k); j < i; j++) {
                bestPrev = Math.max(bestPrev, dp[j]);
            }
            dp[i] = nums[i] + bestPrev;
            result = Math.max(result, dp[i]);
        }

        return result;
    }
}
```

> - **Time Complexity:** O(n \* k). For each of the n elements, we look back at up to k previous dp values. When k is close to n, this degrades to O(n^2).
> - **Space Complexity:** O(n). We store the dp array of size n.

Each iteration rescans up to k previous dp values, even though the window has shifted by only one position since the last scan. A data structure that maintains the window maximum as elements enter and leave removes that repeated work.

<h1 id="approach-2-dp-with-heap-priority-queue">
  Approach 2: DP with Heap (Priority Queue)
</h1>

<h3 id="intuition">Intuition</h3>

Instead of scanning the entire window each time, we can keep the window's dp values in a max-heap (priority queue). The heap gives us the maximum value in O(1) via a peek, and we insert new values in O(log n).

The complication is staleness: the heap's maximum might have fallen out of the window (its index could be more than `k` positions behind the current index). So each heap entry stores both the dp value and its index, and stale entries are removed lazily.

> Entries are not removed the moment their index leaves the window. A stale entry sitting below the top is harmless: dp values are only ever read from the top, and the top is checked against the window boundary before every read. If the top is stale, pop it and check the next one. Each element is pushed once and popped at most once across the whole run, so the total heap work is O(n log n) even though some iterations pop several entries.

<h3 id="algorithm">Algorithm</h3>

1. Create a max-heap. Push `(dp[0], 0)` into it, where `dp[0] = nums[0]`.
2. For each index `i` from 1 to n-1:
3. Return the maximum dp value.

<h3 id="example-walkthrough">Example Walkthrough</h3>

The trace uses the same input, `nums = [10, 2, -10, 5, 20]` with `k = 2`. Each step checks the index of the heap's top entry against the window boundary `i - k` before reading its value:

At i = 4 the entry (12, 1) is outside the window, but it never needs to be popped: the larger entry (17, 3) sits above it, so it never reaches the top. This is lazy deletion working as intended.

<h3 id="code">Code</h3>

```java
class Solution {
    public int constrainedSubsetSum(int[] nums, int k) {
        int n = nums.length;
        int[] dp = new int[n];
        dp[0] = nums[0];
        // Max-heap storing [dp value, index]
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> Integer.compare(b[0], a[0]));
        heap.offer(new int[]{dp[0], 0});
        int result = dp[0];

        for (int i = 1; i < n; i++) {
            // Remove entries that are outside the window
            while (heap.peek()[1] < i - k) {
                heap.poll();
            }
            dp[i] = nums[i] + Math.max(0, heap.peek()[0]);
            heap.offer(new int[]{dp[i], i});
            result = Math.max(result, dp[i]);
        }

        return result;
    }
}
```

```csharp
    public int ConstrainedSubsetSum(int[] nums, int k) {
        int n = nums.Length;
        int[] dp = new int[n];
        dp[0] = nums[0];
        // PriorityQueue is a min-heap; negate the priority so it behaves as a max-heap
        PriorityQueue<int[], int> heap = new PriorityQueue<int[], int>();
        heap.Enqueue(new int[]{dp[0], 0}, -dp[0]);
        int result = dp[0];

        for (int i = 1; i < n; i++) {
            // Remove entries that are outside the window
            while (heap.TryPeek(out int[] top, out _) && top[1] < i - k) {
                heap.Dequeue();
            }
            heap.TryPeek(out int[] current, out _);
            dp[i] = nums[i] + Math.Max(0, current[0]);
            heap.Enqueue(new int[]{dp[i], i}, -dp[i]);
            result = Math.Max(result, dp[i]);
        }

        return result;
    }
```

```go
func constrainedSubsetSum(nums []int, k int) int {
    n := len(nums)
    dp := make([]int, n)
    dp[0] = nums[0]
    result := dp[0]

    // Max-heap
    h := &maxHeap{{dp[0], 0}}
    heap.Init(h)

    for i := 1; i < n; i++ {
        // Remove entries outside the window
        for (*h)[0].index < i-k {
            heap.Pop(h)
        }
        bestPrev := (*h)[0].val
        if bestPrev < 0 {
            bestPrev = 0
        }
        dp[i] = nums[i] + bestPrev
        heap.Push(h, entry{dp[i], i})
        if dp[i] > result {
            result = dp[i]
        }
    }

    return result
}

    val, index int

type maxHeap []entry

func (h maxHeap) Len() int            { return len(h) }
func (h maxHeap) Less(i, j int) bool  { return h[i].val > h[j].val }
func (h maxHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *maxHeap) Push(x interface{}) { *h = append(*h, x.(entry)) }
func (h *maxHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
```

```rust
use std::collections::BinaryHeap;

pub struct Solution;

impl Solution {
    pub fn constrained_subset_sum(nums: Vec<i32>, k: i32) -> i32 {
        let n = nums.len();
        let k = k as usize;
        let mut dp = vec![0; n];
        dp[0] = nums[0];
        // Max-heap storing (dp value, index)
        let mut heap: BinaryHeap<(i32, usize)> = BinaryHeap::new();
        heap.push((dp[0], 0));
        let mut result = dp[0];

        for i in 1..n {
            // Remove entries that are outside the window
            // (saturating_sub avoids usize underflow when i < k)
            while let Some(&(_, idx)) = heap.peek() {
                if idx < i.saturating_sub(k) {
                    heap.pop();
                } else {
                    break;
                }
            }
            let best_prev = heap.peek().map(|&(v, _)| v).unwrap_or(0).max(0);
            dp[i] = nums[i] + best_prev;
            heap.push((dp[i], i));
            result = result.max(dp[i]);
        }

        result
    }
}
```

```javascript
var constrainedSubsetSum = function (nums, k) {
  const n = nums.length;
  const dp = new Array(n).fill(0);
  dp[0] = nums[0];
  let result = dp[0];

  // Max-heap with lazy deletion
  const heap = [[dp[0], 0]];

  const swap = (i, j) => {
    [heap[i], heap[j]] = [heap[j], heap[i]];
  };

  const siftUp = (i) => {
    while (i > 0) {
      const p = Math.floor((i - 1) / 2);
      if (heap[i][0] > heap[p][0]) {
        swap(i, p);
        i = p;
      } else break;
    }
  };

  const siftDown = (i) => {
    while (true) {
      let largest = i;
      const l = 2 * i + 1,
        r = 2 * i + 2;
      if (l < heap.length && heap[l][0] > heap[largest][0]) largest = l;
      if (r < heap.length && heap[r][0] > heap[largest][0]) largest = r;
      if (largest === i) break;
      swap(i, largest);
      i = largest;
    }
  };

  const push = (val, idx) => {
    heap.push([val, idx]);
    siftUp(heap.length - 1);
  };

  const pop = () => {
    const top = heap[0];
    const last = heap.pop();
    if (heap.length > 0) {
      heap[0] = last;
      siftDown(0);
    }
    return top;
  };

  for (let i = 1; i < n; i++) {
    // Remove entries outside the window
    while (heap[0][1] < i - k) pop();
    dp[i] = nums[i] + Math.max(0, heap[0][0]);
    push(dp[i], i);
    result = Math.max(result, dp[i]);
  }

  return result;
};
```

> - **Time Complexity:** O(n log n). Each element is pushed and popped from the heap at most once. Each push/pop is O(log n).
> - **Space Complexity:** O(n). The heap can hold up to n elements in the worst case, plus the dp array.

The heap orders every element in the window, but only the maximum is ever read. The final approach stores only the elements that could still become the maximum and discards everything else, which drops the log factor.

<h1 id="approach-3-dp-with-monotonic-deque-optimal">
  Approach 3: DP with Monotonic Deque (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

This is the "sliding window maximum" technique applied to the dp array. Instead of keeping every dp value in a heap, we maintain a deque of indices whose dp values decrease from front to back. The front of the deque then always holds the maximum dp value in the current window.

A decreasing deque is safe because of a dominance argument. If `dp[j] >= dp[i]` and `j > i` (j is newer), then `dp[i]` will never be the answer for any future query: it expires from the window sooner than `j` and its value is no larger. So before inserting a new index at the back, we discard every index whose dp value is less than or equal to the new one. No potential window maximum is ever lost, and the deque stays decreasing without any sorting.

<h3 id="algorithm">Algorithm</h3>

1. Create a deque that stores indices. Initialize it with index 0, and set `dp[0] = nums[0]`.
2. For each index `i` from 1 to n-1:
3. Return the maximum dp value.

<h3 id="example-walkthrough">Example Walkthrough</h3>

Same input once more: `nums = [10, 2, -10, 5, 20]`, `k = 2`. The deque stores indices. Each step shows which indices get removed from the back so that dp values stay decreasing from front to back:

Over the whole run the deque held at most two indices at a time, while the heap in Approach 2 accumulated every entry it was ever given. Discarding dominated indices on insertion is what removes the log factor.

<h3 id="code">Code</h3>

```java
class Solution {
    public int constrainedSubsetSum(int[] nums, int k) {
        int n = nums.length;
        int[] dp = new int[n];
        dp[0] = nums[0];
        int result = dp[0];
        // Monotonic deque storing indices, dp values in decreasing order
        Deque<Integer> deque = new ArrayDeque<>();
        deque.offerLast(0);

        for (int i = 1; i < n; i++) {
            // Remove indices outside the window
            while (!deque.isEmpty() && deque.peekFirst() < i - k) {
                deque.pollFirst();
            }

            // The front has the max dp value in the window
            dp[i] = nums[i] + Math.max(0, dp[deque.peekFirst()]);

            // Maintain decreasing order: remove smaller dp values from back
            while (!deque.isEmpty() && dp[deque.peekLast()] <= dp[i]) {
                deque.pollLast();
            }
            deque.offerLast(i);
            result = Math.max(result, dp[i]);
        }

        return result;
    }
}
```

```cpp
class Solution {
public:
    int constrainedSubsetSum(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> dp(n);
        dp[0] = nums[0];
        int result = dp[0];
        // Monotonic deque storing indices, dp values in decreasing order
        deque<int> dq;
        dq.push_back(0);

        for (int i = 1; i < n; i++) {
            // Remove indices outside the window
            while (!dq.empty() && dq.front() < i - k) {
                dq.pop_front();
            }

            // The front has the max dp value in the window
            dp[i] = nums[i] + max(0, dp[dq.front()]);

            // Maintain decreasing order: remove smaller dp values from back
            while (!dq.empty() && dp[dq.back()] <= dp[i]) {
                dq.pop_back();
```

```go
    dp := make([]int, n)

    result := dp[0]

    deque := []int{0}

        // Remove indices outside the window
        for len(deque) > 0 && deque[0] < i-k {
            deque = deque[1:]
        }

        // The front has the max dp value in the window
        bestPrev := dp[deque[0]]
        if bestPrev < 0 {
            bestPrev = 0
        }
        dp[i] = nums[i] + bestPrev

        // Maintain decreasing order: remove smaller dp values from back
        for len(deque) > 0 && dp[deque[len(deque)-1]] <= dp[i] {
            deque = deque[:len(deque)-1]
        }
        deque = append(deque, i)
        if dp[i] > result {
            result = dp[i]
        }
    }
```

> - **Time Complexity:** O(n). Each index is pushed to the deque once and popped at most once. All deque operations are O(1), so the total work is O(n).
> - **Space Complexity:** O(n) for the dp array. The deque itself never holds more than k + 1 indices, since indices outside the window are removed from the front and dominated indices are removed from the back.
