<LessonCard>

Given an integer array `nums`, return the maximum possible sum of elements of the array such that it is divisible by three.

**Example 1:**

- **Input:** `nums = [3,6,5,1,8]`

- **Output:** `18`

**Explanation:** Pick numbers 3, 6, 1, and 8. Their sum is 18, which is divisible by 3.

**Example 2:**

- **Input:** `nums = [4]`

- **Output:** `0`

**Explanation:** 4 is not divisible by 3, so we cannot pick it. The best we can do is pick nothing, giving sum 0.

**Example 3:**

- **Input:** `nums = [1,2,3,4,4]`

- **Output:** `12`

**Explanation:** Pick 1, 3, 4, and 4. Their sum is 12, which is divisible by 3.

**Constraints:**

- `1 <= nums.length <= 4 * 10^4`
- `1 <= nums[i] <= 10^4`

Add up all the numbers. If the total is already divisible by 3, that total is the answer. Otherwise we remove the elements that subtract the least while fixing the remainder.

We want the largest subset sum that is divisible by 3. Adding every element gives the largest possible sum, but that total might not be divisible by 3. When it is not, we have to drop some elements to fix the remainder while sacrificing as little as possible.

This reduces to working with remainders mod 3. Every number leaves a remainder of 0, 1, or 2 when divided by 3, and so does the total sum. If the total has remainder 0, it is already the answer. If the total has remainder 1, we restore divisibility by removing either the smallest element with remainder 1, or the two smallest elements with remainder 2 (because 2 + 2 = 4 has remainder 1). If the total has remainder 2, we remove either the smallest remainder-2 element or the two smallest remainder-1 elements. That is the greedy approach.

A dynamic programming approach avoids the removal logic entirely by tracking the best achievable sum for each remainder (0, 1, 2) as it processes each number in one pass.

- `1 <= nums.length <= 4 * 10^4` → An O(n^2) scan would be about 1.6 billion operations, too slow. Both approaches below run in O(n log n) or O(n).
- `1 <= nums[i] <= 10^4` → All values are positive, so the empty subset (sum 0) is always a valid fallback. The maximum possible sum is 4 _ 10^4 _ 10^4 = 4 _ 10^8, which fits in a signed 32-bit integer (max ~2.1 _ 10^9).

Add up all the numbers. If the total is already divisible by 3, that total is the answer. Otherwise we remove the elements that subtract the least while fixing the remainder.

The remainder of the total is either 1 or 2. When it is 1, two removals restore divisibility: dropping the single smallest remainder-1 element, or dropping the two smallest remainder-2 elements (since 2 + 2 = 4 and 4 mod 3 = 1). We pick whichever subtracts less. When the remainder is 2, the symmetric options are the smallest remainder-2 element or the two smallest remainder-1 elements.

Why are only these two options worth checking for remainder 1? To lower a sum with remainder 1 down to remainder 0, the removed elements must themselves sum to a remainder of 1. The cheapest ways to reach remainder 1 are one remainder-1 element or two remainder-2 elements. Any other combination removes at least as much, so the minimum is one of these two. Sorting puts the smallest element of each remainder class at the front, so we read them directly.

<h3 id="algorithm">Algorithm</h3>

1. Compute the total sum of all elements.
2. If `totalSum % 3 == 0`, return `totalSum`.
3. Sort the array in ascending order.
4. Classify each element by its remainder when divided by 3.
5. If `totalSum % 3 == 1`: remove the smallest remainder-1 element, or two smallest remainder-2 elements (whichever subtracts less).
6. If `totalSum % 3 == 2`: remove the smallest remainder-2 element, or two smallest remainder-1 elements (whichever subtracts less).

<h3 id="example-walkthrough">Example Walkthrough</h3>

**Input:**

Total sum = 23, remainder = 23 % 3 = 2. We need to remove the minimum to fix this.

After sorting: `[1, 3, 5, 6, 8]`. Remainder-2 elements (sorted): `[5, 8]`. Remainder-1 elements (sorted): `[1]`.

Option A: Remove smallest remainder-2 element (5), sum = 23 - 5 = 18.

Option B: Remove two smallest remainder-1 elements, but only one exists. Not possible.

Best option: 18.

<h3 id="code">Code</h3>

```java
class Solution {
    public int maxSumDivThree(int[] nums) {
        int totalSum = 0;
        for (int num : nums) {
            totalSum += num;
        }

        if (totalSum % 3 == 0) {
            return totalSum;
        }

        Arrays.sort(nums);

        // Collect elements by remainder
        List<Integer> rem1 = new ArrayList<>();
        List<Integer> rem2 = new ArrayList<>();
        for (int num : nums) {
            if (num % 3 == 1) rem1.add(num);
            else if (num % 3 == 2) rem2.add(num);
        }

        int result = 0;
        if (totalSum % 3 == 1) {
            int optionA = (rem1.size() >= 1) ? totalSum - rem1.get(0) : 0;
            int optionB = (rem2.size() >= 2) ? totalSum - rem2.get(0) - rem2.get(1) : 0;
            result = Math.max(optionA, optionB);
        } else {
            int optionA = (rem2.size() >= 1) ? totalSum - rem2.get(0) : 0;
            int optionB = (rem1.size() >= 2) ? totalSum - rem1.get(0) - rem1.get(1) : 0;
            result = Math.max(optionA, optionB);
        }

        return result;
    }
}
```

> - **Time Complexity:** O(n log n). Sorting dominates. The sum computation, classification, and removal logic are all O(n).
> - **Space Complexity:** O(n). We store up to n elements in the remainder lists. Sorting may also use O(log n) auxiliary space.

The greedy approach needs a sort and extra lists for the remainder classes. The next approach removes both by tracking the best sum for each remainder in a single pass.

<h1 id="approach-2-dynamic-programming-optimal">
  Approach 2: Dynamic Programming (Optimal)
</h1>

<h3 id="intuition">Intuition</h3>

Instead of computing the total and then removing elements, we build the answer incrementally while keeping only three numbers: the maximum sum reachable so far with remainder 0, with remainder 1, and with remainder 2.

For each new number we choose to include it or skip it. Including it adds the number to one of the existing sums and shifts that sum into a new remainder class. If the best sum with remainder 1 is 10 and the new number has remainder 2, then 10 plus that number has remainder 0 (1 + 2 = 3). So a remainder-2 number can improve `dp[0]` by building on the current `dp[1]`.

We hold an array `dp` of size 3, where `dp[r]` is the maximum sum whose value mod 3 equals `r`. We start with `dp[0] = 0` (the empty subset has sum 0, remainder 0) and `dp[1] = dp[2] = -infinity`, marking those remainders as unreachable until some element produces them. Each number updates all three states from a snapshot of the previous values.

<h3 id="algorithm">Algorithm</h3>

1. Initialize `dp = [0, -infinity, -infinity]` where `dp[r]` represents the max sum with remainder `r`.
2. For each number `num` in the array:
3. Return `dp[0]` (the maximum sum with remainder 0).

<h3 id="example-walkthrough">Example Walkthrough</h3>

<h3 id="code">Code</h3>

```java
class Solution {
    public int maxSumDivThree(int[] nums) {
        // dp[r] = max sum with remainder r when divided by 3
        long[] dp = new long[]{0, Long.MIN_VALUE, Long.MIN_VALUE};

        for (int num : nums) {
            long[] temp = dp.clone();
            int r = num % 3;
            for (int i = 0; i < 3; i++) {
                int newRem = (i + r) % 3;
                dp[newRem] = Math.max(dp[newRem], temp[i] + num);
            }
        }

        return (int) dp[0];
    }
}
```

```go
func maxSumDivThree(nums []int) int {

    dp := [3]int{0, -1 << 31, -1 << 31}

    for _, num := range nums {
        temp := dp
        r := num % 3
        for i := 0; i < 3; i++ {
            newRem := (i + r) % 3
            if temp[i]+num > dp[newRem] {
                dp[newRem] = temp[i] + num
            }
        }
    }

    return dp[0]
```
