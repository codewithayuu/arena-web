<LessonCard>

There is a row of `n` houses, where each house can be painted one of three colors: red, blue, or green. The cost of painting each house with a certain color is different. You have to paint all the houses such that no two adjacent houses have the same color.

The cost of painting each house with a certain color is represented by an `n x 3` cost matrix `costs`.

For example, `costs[0][0]` is the cost of painting house 0 with the color red; `costs[1][2]` is the cost of painting house 1 with the color green, and so on...

Return the minimum cost to paint all houses.

**Example 1:**

- **Input:** `costs = [[17,2,17],[16,16,5],[14,3,19]]`

- **Output:** `10`

**Example 2:**

- **Input:** `costs = [[7,6,2]]`

- **Output:** `2`

**Constraints:**

- `costs.length == n`
- `costs[i].length == 3`
- `1 <= n <= 100`
- `1 <= costs[i][j] <= 20`

Try every valid coloring and pick the cheapest one. For house 0 we have 3 color choices. For every house after that we have 2 choices, anything except the color used for the house before it. Recursively explore all valid combinations and return the minimum total cost.

<h1 id="understanding-the-problem">Understanding the Problem</h1>

We have a row of houses, and each one needs to be painted either red, blue, or green. No two neighboring houses can share the same color. Each house has its own cost for each color, and we want the cheapest total.

This is a decision-at-each-step problem. At each house, we pick a color, but that choice constrains what the next house can pick. A greedy approach (always picking the cheapest color for the current house) does not work, because a locally cheap choice can force an expensive choice for the next house. We have to account for the downstream effect of each decision.

That downstream effect has a clean structure: the minimum cost to paint house `i` with color `c` depends only on the minimum costs of painting house `i-1` with the other two colors. This overlapping substructure is what makes dynamic programming a good fit.

<h3 id="key-constraints">Key Constraints:</h3>

- `1 <= n <= 100` → A small upper bound, so even an O(n^2) solution would run instantly. The structure of the problem gives us O(n) regardless.
- `costs[i].length == 3` → Exactly 3 colors. With a fixed, small color count, iterating over all colors at each step is O(1).
- `1 <= costs[i][j] <= 20` → All costs are positive. The maximum total is bounded by 100 \* 20 = 2000, which fits comfortably in a 32-bit integer, so there is no overflow concern.

<h1 id="approach-1-brute-force-recursion">
  Approach 1: Brute Force (Recursion)
</h1>

<h3 id="intuition">Intuition</h3>

Try every valid coloring and pick the cheapest one. For house 0 we have 3 color choices. For every house after that we have 2 choices, anything except the color used for the house before it. Recursively explore all valid combinations and return the minimum total cost.

This builds a decision tree. The root branches into 3 colors, and every node below it branches into 2. The total number of leaves is 3 \* 2^(n-1), which grows exponentially with the number of houses.

<h3 id="algorithm">Algorithm</h3>

1. Define `solve(house, color)` as the minimum cost to paint houses `house` through `n-1`, given that `house` is painted `color`.
2. Add `costs[house][color]` for painting the current house.
3. Base case: if `house` is the last house (`n-1`), return that cost.
4. Otherwise, recurse on the next house with each of the other two colors, and add the smaller of the two results.
5. Start by calling `solve(0, c)` for all three colors and return the minimum, since the first house has no previous-color constraint.

<h3 id="example-walkthrough">Example Walkthrough</h3>

**Input:**

The recursion explores all valid colorings and keeps the cheapest. The branch that starts with house 0 painted blue (cost 2) leads to the answer. From blue, house 1 can be red (16) or green (5); the cheaper continuation comes from green. From green at house 1, house 2 can be red (14) or blue (3); blue is cheaper. That path totals 2 + 5 + 3 = 10. Every other starting color produces a larger total: starting red gives at least 17 + 5 + 3 = 25, and starting green gives at least 17 + 16 + 3 = 36, so the minimum over all branches is 10.

```java
class Solution {
    public int minCost(int[][] costs) {
        int n = costs.length;
        // Try starting with each color and take the minimum
        return Math.min(
            solve(costs, 0, 0, n),
            Math.min(solve(costs, 0, 1, n), solve(costs, 0, 2, n))
        );
    }

    private int solve(int[][] costs, int house, int color, int n) {
        // Cost of painting current house with chosen color
        int total = costs[house][color];

        if (house == n - 1) {
            return total;
        }

        // Try the other two colors for the next house
        if (color == 0) {
            total += Math.min(solve(costs, house + 1, 1, n), solve(costs, house + 1, 2, n));
        } else if (color == 1) {
            total += Math.min(solve(costs, house + 1, 0, n), solve(costs, house + 1, 2, n));
        } else {
            total += Math.min(solve(costs, house + 1, 0, n), solve(costs, house + 1, 1, n));
        }

        return total;
    }
}
```

> - **Time Complexity:** O(2^n). At each house, we branch into 2 recursive calls (the two colors that differ from the current one), creating a binary tree of depth n.
> - **Space Complexity:** O(n). The recursion stack goes n levels deep, one for each house.

The cost of this approach is repeated work. The same `(house, color)` subproblem is recomputed many times across different recursion paths, since the best way to paint the houses from index `i` onward given a fixed color at `i` does not depend on how we reached `i`. Caching each subproblem result, or building the answers bottom-up, removes that repetition.

<h1 id="approach-2-dynamic-programming-2d-table">
  Approach 2: Dynamic Programming (2D Table)
</h1>

<h3 id="intuition">Intuition</h3>

The recursive solution recomputes the same `(house, color)` state many times. Building the answers bottom-up computes each state once. Define `dp[i][c]` as the minimum cost to paint houses 0 through `i` with house `i` painted color `c`.

To paint house `i` with color `c`, we pay `costs[i][c]` plus the cheapest way to have painted house `i-1` with either of the other two colors:

- `dp[i][0] = costs[i][0] + min(dp[i-1][1], dp[i-1][2])`
- `dp[i][1] = costs[i][1] + min(dp[i-1][0], dp[i-1][2])`
- `dp[i][2] = costs[i][2] + min(dp[i-1][0], dp[i-1][1])`

The answer is `min(dp[n-1][0], dp[n-1][1], dp[n-1][2])`.

> The adjacency constraint is the reason `dp[i][0]` (house `i` red) draws only from `dp[i-1][1]` and `dp[i-1][2]`, never from `dp[i-1][0]`. The two values it can draw from already represent optimal colorings of houses 0 through `i-1` that end in blue or green, so taking their minimum and adding `costs[i][0]` gives the optimal coloring through house `i` that ends in red. Computing all three colors at each step covers every legal coloring, and the final answer is the cheapest of the three options for the last house.

<h3 id="algorithm">Algorithm</h3>

1. Create a 2D array `dp` of size `n x 3`.
2. Initialize `dp[0][c] = costs[0][c]` for each color `c` (painting the first house has no constraints).
3. For each house from 1 to n-1, compute `dp[i][c]` using the recurrence above.
4. Return the minimum of `dp[n-1][0]`, `dp[n-1][1]`, `dp[n-1][2]`.

```java
class Solution {
    public int minCost(int[][] costs) {
        int n = costs.length;
        int[][] dp = new int[n][3];

        // Base case: first house has no constraints
        dp[0][0] = costs[0][0];
        dp[0][1] = costs[0][1];
        dp[0][2] = costs[0][2];

        // Fill DP table: each house depends on the previous one
        for (int i = 1; i < n; i++) {
            dp[i][0] = costs[i][0] + Math.min(dp[i - 1][1], dp[i - 1][2]);
            dp[i][1] = costs[i][1] + Math.min(dp[i - 1][0], dp[i - 1][2]);
            dp[i][2] = costs[i][2] + Math.min(dp[i - 1][0], dp[i - 1][1]);
        }

        // Answer is the minimum cost to paint the last house with any color
        return Math.min(dp[n - 1][0], Math.min(dp[n - 1][1], dp[n - 1][2]));
    }
}
```

> - **Time Complexity:** O(n). We iterate through n houses, doing a constant amount of work (3 color options, each needing a min of 2 values) per house.
> - **Space Complexity:** O(n). The 2D DP table has n rows and 3 columns.

The DP table uses O(n) space, but each row only depends on the row directly before it. Once we have computed row `i`, every earlier row is dead weight. Keeping only the previous row's three values reduces the space to O(1).

<h1 id="approach-3-space-optimized-dp">Approach 3: Space-Optimized DP</h1>

<h3 id="intuition">Intuition</h3>

Since each row of the DP table only depends on the previous row, we can replace the entire 2D table with three variables holding the previous house's costs. After processing each house, we overwrite these variables with the new house's costs for the next iteration.

This drops the space from O(n) to O(1) while keeping the O(n) time complexity. The recurrence is unchanged; only the storage shrinks.

<h3 id="algorithm">Algorithm</h3>

1. Initialize three variables `prevRed`, `prevBlue`, `prevGreen` with the costs of painting house 0.
2. For each house from 1 to n-1, compute the new costs using the previous values.
3. Be careful to use temporary variables so that updating one color doesn't corrupt the calculation of another.
4. Return the minimum of the three final values.

<h3 id="example-walkthrough">Example Walkthrough</h3>

<h3 id="code">Code</h3>

```java
class Solution {
    public int minCost(int[][] costs) {
        int n = costs.length;

        // Start with the first house's costs
        int prevRed = costs[0][0];
        int prevBlue = costs[0][1];
        int prevGreen = costs[0][2];

        for (int i = 1; i < n; i++) {
            // Compute new costs using previous values (use temps to avoid overwriting)
            int newRed = costs[i][0] + Math.min(prevBlue, prevGreen);
            int newBlue = costs[i][1] + Math.min(prevRed, prevGreen);
            int newGreen = costs[i][2] + Math.min(prevRed, prevBlue);

            prevRed = newRed;
            prevBlue = newBlue;
            prevGreen = newGreen;
        }

        return Math.min(prevRed, Math.min(prevBlue, prevGreen));
    }
}
```
