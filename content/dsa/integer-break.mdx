<LessonCard>

Given an integer `n`, break it into the sum of `k` positive integers, where `k >= 2`, and maximize the product of those integers.

Return the maximum product you can get.

\***\*Example 1:\*\***

- **Input:** `n = 2`

- **Output:** `1`

**Explanation:** 2 = 1 + 1, 1 x 1 = 1.

\***\*Example 2:\*\***

- **Input:** `n = 10`

- **Output:** `36`

**Explanation:** 10 = 3 + 3 + 4, 3 x 3 x 4 = 36.

\***\*Constraints:\*\***

- `2 <= n <= 58`

The question asks us to split a number into at least two positive parts and make the product of those parts as large as possible. For small numbers this is easy to verify by hand, but the real challenge is figuring out a general strategy for any n up to 58.

Consider n = 6. We could split it as 3 + 3 (product 9), 2 + 4 (product 8), 2 + 2 + 2 (product 8), or 1 + 5 (product 5). The best split is 3 + 3. The factor 3 recurs across the best splits because among all positive integers, 3 gives the best product per unit when used as a factor. The reason for that leads directly to the optimal solution.

- `2 <= n <= 58` -> With n at most 58, even an O(n^2) solution runs fast. The answer also stays within a 32-bit signed integer (the largest result is 3^19 = 1,162,261,467 for n = 57), so a plain `int` does not overflow.
- `k >= 2` -> We must split n into at least two parts. This matters for the small cases n = 2 and n = 3, where any split lowers the value below n itself.

Try every way to split off a first part `i`, leaving `n - i`. The left part `i` stays whole. The right part `n - i` is either kept whole or broken down further by solving the same problem on it. Taking the maximum over all split points `i` gives the answer for `n`.

<h3 id="algorithm">Algorithm</h3>

1. For each split point `i` from 1 to `n - 1`, consider breaking n into `i` and `n - i`.
2. For the second part `n - i`, we have two choices: keep it as `n - i` or recursively break it to get `integerBreak(n - i)`.
3. The product for this split is `i * max(n - i, integerBreak(n - i))`.
4. Return the maximum product across all split points.

<h3 id="example-walkthrough">Example Walkthrough</h3>

**Input:**

For n = 6, the recursion first needs the answers for the smaller values it depends on. The base cases give `integerBreak(2) = 1` and `integerBreak(3) = 2`. From those:

- `integerBreak(4)`: best split is i = 2, giving `2 * max(2, integerBreak(2)=1) = 2 * 2 = 4`.
- `integerBreak(5)`: best split is i = 2, giving `2 * max(3, integerBreak(3)=2) = 2 * 3 = 6`.

Now the top-level call for n = 6 tries each split point:

The maximum across all rows is 9, from the split 3 + 3.

<h3 id="code">Code</h3>

```java
class Solution {
    public int integerBreak(int n) {
        if (n <= 2) return 1;

        int maxProduct = 0;
        for (int i = 1; i < n; i++) {
            // Either keep (n - i) whole or break it further
            int product = i * Math.max(n - i, integerBreak(n - i));
            maxProduct = Math.max(maxProduct, product);
        }
        return maxProduct;
    }
}
```

> - **Time Complexity:** O(2^n). Each call branches into up to n - 1 recursive calls, and overlapping subproblems are recomputed many times.
> - **Space Complexity:** O(n). The recursion stack goes at most n levels deep.

Computing `integerBreak(6)` recomputed `integerBreak(4)`, `integerBreak(3)`, and `integerBreak(2)` many times across different branches. Storing each result the first time it is computed removes the repeated work.

<h1 id="approach-2-dynamic-programming-bottom-up">
  Approach 2: Dynamic Programming (Bottom-Up)
</h1>

<h3 id="intuition">Intuition</h3>

The recursive solution recomputes overlapping subproblems, so dynamic programming applies. Instead of recomputing `integerBreak(k)` every time it is needed, build the answers bottom-up from 2 to n and store each result in an array, so every later value reads its dependencies directly.

<h3 id="algorithm">Algorithm</h3>

1. Create an array `dp` of size `n + 1`, where `dp[j]` represents the maximum product for integer `j`.
2. Base case: `dp[2] = 1` (only split is 1 + 1).
3. For each `j` from 3 to `n`:
4. Return `dp[n]`.

<h3 id="example-walkthrough">Example Walkthrough</h3>

<h3 id="code">Code</h3>

```java
class Solution {
    public int integerBreak(int n) {
        int[] dp = new int[n + 1];
        dp[2] = 1;

        for (int j = 3; j <= n; j++) {
            for (int i = 1; i < j; i++) {
                // Either keep (j - i) whole or use its optimal break
                dp[j] = Math.max(dp[j], i * Math.max(j - i, dp[j - i]));
            }
        }
        return dp[n];
    }
}
```

<h1 id="approach-3-greedy-math">Approach 3: Greedy (Math)</h1>

<h3 id="intuition">Intuition</h3>

The optimal split uses as many 3s as possible. Three rules justify this:

- A factor of 1 never helps: removing a 1 and adding it to any other factor increases the product (`k > k * 1`), so the optimal split contains no 1s.
- No factor should be 5 or more: any `f >= 5` can be replaced by `3 + (f - 3)`, and `3 * (f - 3) > f` once `f >= 5` (for example 5 -> 3 _ 2 = 6, 6 -> 3 _ 3 = 9). So every factor in the optimal split is 2, 3, or 4. A 4 is left as-is because `2 * 2 = 4`, the same as keeping it whole.
- Prefer 3 over 2: three 2s sum to 6 and multiply to 8, while two 3s sum to 6 and multiply to 9. So whenever the remaining amount is 6 or more, splitting off a 3 beats splitting off a 2.

That leaves the leftover after taking out 3s, which is `n % 3`. If the remainder is 0, all 3s are used. If it is 2, that 2 is kept as its own factor. If it is 1, one 3 is combined with the leftover 1 into a 4 (used as 2 _ 2 = 4), because `2 _ 2 = 4`beats`3 \* 1 = 3`.

<h3 id="algorithm">Algorithm</h3>

1. If n == 2, return 1. If n == 3, return 2. (Must split, so 1 _ 1 and 1 _ 2.)
2. If n % 3 == 0, the answer is 3^(n/3).
3. If n % 3 == 1, give back one 3, use two 2s: answer is 3^(n/3 - 1) \* 4.
4. If n % 3 == 2, use one extra 2: answer is 3^(n/3) \* 2.

<h4 id="example-walkthrough">Example Walkthrough:</h4>

<h3 id="code">Code</h3>

```java
class Solution {
    public int integerBreak(int n) {
        if (n == 2) return 1;
        if (n == 3) return 2;

        int remainder = n % 3;
        if (remainder == 0) {
            return (int) Math.pow(3, n / 3);
        } else if (remainder == 1) {
            // Give back one 3 and use 2*2 instead of 3*1
            return (int) Math.pow(3, n / 3 - 1) * 4;
        } else {
            // remainder == 2, use one extra 2
            return (int) Math.pow(3, n / 3) * 2;
        }
    }
}
```
