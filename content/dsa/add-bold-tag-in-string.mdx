<LessonCard>

You are given a string `s` and an array of strings `words`.

You should add a closed pair of bold tag `<b>` and `</b>` to wrap the substrings in `s` that exist in any string in `words`.

If two such substrings overlap with each other, you should wrap them together with only one pair of bold tags. Also, if two substrings wrapped by bold tags are consecutive, you should combine them.

\***\*Example 1:\*\***

- **Input:** `s = abcxyz123`

- **Input:** `words = ["abc","123"]`

- **Output:** `<b>abc</b>xyz<b>123</b>`

\***\*Example 2:\*\***

- **Input:** `s = aaabbb`

- **Input:** `words = ["aa","b"]`

- **Output:** `<b>aaabbb</b>`

\***\*Constraints:\*\***

- `1 <= s.length <= 1000`
- `0 <= words.length <= 100`
- `1 <= words[i].length <= 1000`
- `s` and `words[i]` consist of English letters and digits.
- All values of `words` are unique.

**Note:** This question is the same as LeetCode 758: Bold Words in String.

<h1 id="approach-1-brute-force-interval-collection-and-merge">
  Approach 1: Brute Force (Interval Collection and Merge)
</h1>

<h3 id="intuition">Intuition</h3>

Find every occurrence of every word in `s`, record the interval `[start, end)` for each match, merge overlapping or adjacent intervals, and wrap each merged region in bold tags. This is the merge intervals pattern: sort the match intervals by start position, then sweep through them, extending the current region whenever the next interval starts at or before its end. Using start &lt;= end (rather than strict &lt;) is what folds adjacent matches into one region.

<h3 id="algorithm">Algorithm</h3>

1. For each word in `words`, find all starting positions where it appears in `s`. For each match at position `i`, record the interval `[i, i + word.length)`.
2. Sort all intervals by their start position.
3. Merge overlapping or adjacent intervals: if the current interval's start is less than or equal to the previous interval's end, extend the previous interval's end.
4. Build the result string: iterate through `s`, inserting `<b>` at the start of each merged interval and `</b>` at the end.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n _ m _ k + I log I), where I is the number of matches found (at most n _ m). Finding all occurrences takes O(n _ m \* k), sorting the intervals takes O(I log I), and merging plus building the result takes O(n + I).
> - **Space Complexity:** O(I) for the interval list, which is O(n \* m) in the worst case.

The sorting and merging steps can be removed entirely. The next approach marks each character position as bold directly, and a single scan over those marks produces the merged regions.

<h1 id="approach-2-boolean-bold-array">Approach 2: Boolean Bold Array</h1>

<h3 id="intuition">Intuition</h3>

Instead of collecting intervals and merging them, we use a boolean array `bold` of the same length as `s`. For each word in `words`, we find every occurrence in `s` and mark the covered positions as `true`. Once all words have been processed, we scan the `bold` array and insert `<b>` at every transition from false to true and `</b>` at every transition from true to false.

No sorting or merging is needed. Overlapping matches mark some positions twice, and setting an already-true entry to true changes nothing. Adjacent matches leave no false entry between them, so they form one contiguous run of true values, and the transition scan wraps that run in a single pair of tags.

<h3 id="algorithm">Algorithm</h3>

1. Create a boolean array `bold` of length `n` (same as `s`), initialized to false.
2. For each word in `words`, find every starting index where the word appears in `s`. For each match at index `i`, set `bold[i]` through `bold[i + word.length - 1]` to true.
3. Build the result string by scanning `s`:

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n _ m _ k). For each of the m words, we scan the string to find all occurrences. Each scan is O(n \* k) where k is the word length. The final scan to build the result is O(n).
> - **Space Complexity:** O(n). The boolean array is O(n). The result string is O(n) in the worst case.

The marking step still searches the string once per word. The final approach replaces those per-word scans with a single Trie walk from each starting position.

<h1 id="approach-3-trie-optimization">Approach 3: Trie Optimization</h1>

<h3 id="intuition">Intuition</h3>

Checking each word independently repeats work whenever words share prefixes: matching "abc" and "abd" at the same position compares "ab" twice. A Trie (prefix tree) built from the words checks all of them in one pass. Starting from position `i`, walk the Trie character by character; every node that marks the end of a word means that word matches at `i`. Track the farthest end among those matches and mark `bold[i..farthestEnd-1]` as true. Marking only up to the farthest end is enough because every shorter match starting at `i` covers a prefix of that same range.

This reduces the matching step from O(n _ m _ k) to O(n \* W), where W is the length of the longest word.

<h3 id="algorithm">Algorithm</h3>

1. Build a Trie from all words.
2. Create a boolean array `bold` of length n.
3. For each starting position `i` in `s`, walk the Trie from the root. At each step, if the current Trie node marks the end of a word, record the farthest end position. Continue until the Trie has no child for the next character or we reach the end of `s`. Mark `bold[i..farthestEnd-1]` as true.
4. Build the result string by scanning `bold` for transitions, same as Approach 2.

<h3 id="visualization-and-code">Visualization and Code</h3>

<InteractiveAnimation />

> - **Time Complexity:** O(n \* W + L). Building the Trie takes O(L), where L is the total length of all words. From each of the n starting positions, the Trie walk and the bold marking each take at most W steps (W = length of the longest word). Building the result is O(n).
> - **Space Complexity:** O(L + n). The Trie has at most L nodes (array-based child tables add a constant factor for the 62-character alphabet). The boolean array and the result string are O(n).
