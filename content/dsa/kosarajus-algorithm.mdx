<LessonCard>

SCCs appear in social network analysis (groups of people who all follow each other), compiler optimization (cycles in function call graphs), and 2-SAT solvers. They are also a common topic in graph interview questions.

Kosaraju's algorithm finds all SCCs in a directed graph with two passes of DFS. It is conceptually simpler than Tarjan's algorithm and a good way to build intuition for how DFS finish times encode the structure of a directed graph.

<h2 id="what-are-strongly-connected-components">
  What Are Strongly Connected Components?
</h2>

In an undirected graph, a connected component is a group of vertices where every vertex can reach every other vertex. In a directed graph, edges have direction, so reaching B from A does not guarantee you can get from B back to A.

A **Strongly Connected Component (SCC)** is a maximal set of vertices such that for every pair of vertices u and v in the set, there is a directed path from u to v AND a directed path from v to u. "Maximal" means you cannot add any more vertices to the set and keep this property.

Consider the following example.

This graph has three SCCs:

- **SCC 1 (cyan):** `{A, B, C}`. A can reach B, B can reach C, C can reach A. Every vertex can reach every other vertex.
- **SCC 2 (orange):** `{D, E, F}`. D reaches E, E reaches F, F reaches D, so the three vertices form a cycle.
- **SCC 3 (teal):** `{G, H}`. G reaches H and H reaches G.

C can reach D (through the edge C to D), but D cannot reach C, so C and D belong to different SCCs. Edges between SCCs always go in one direction, which is a property we will exploit later.

<h2 id="what-is-kosarajus-algorithm">What Is Kosaraju's Algorithm?</h2>

Kosaraju's algorithm finds all SCCs in a directed graph in O(V + E) time using two passes of DFS. The algorithm was independently discovered by S. Rao Kosaraju in 1978 and later published by Micha Sharir in 1981.

The algorithm has three steps:

1. **First DFS pass:** Run DFS on the original graph. As each vertex finishes (all its descendants have been fully explored), push it onto a stack. This records the "finish order."
2. **Transpose the graph:** Reverse the direction of every edge in the graph. If there was an edge from u to v, now there is an edge from v to u.
3. **Second DFS pass:** Pop vertices from the stack one by one. For each unvisited vertex, run DFS on the transposed graph. Each DFS tree you get in this pass is one SCC.

<h2 id="how-kosarajus-works">How Kosaraju's Works</h2>

The following walkthrough covers each step using a concrete graph.

<h3 id="the-example-graph">The Example Graph</h3>

Consider this directed graph with 8 vertices:

The three SCCs are `{0, 1, 2}`, `{3, 4, 5}`, and `{6, 7}`. Here is how Kosaraju's algorithm discovers them.

<h3 id="step-1-dfs-on-the-original-graph-record-finish-order">
  Step 1: DFS on the Original Graph (Record Finish Order)
</h3>

Run DFS starting from any unvisited vertex. When a vertex has no more unvisited neighbors (or all recursive calls from it have returned), push it onto a stack.

Suppose we start DFS from vertex 0:

- Visit 0, go to 1
- Visit 1, go to 2
- Visit 2, go to 0 (already visited), go to 3
- Visit 3, go to 4
- Visit 4, go to 5
- Visit 5, go to 3 (already visited), go to 6
- Visit 6, go to 7
- Visit 7, go to 6 (already visited), 7 finishes. Push **7**.
- 6 finishes. Push **6**.
- 5 finishes. Push **5**.
- 4 finishes. Push **4**.
- 3 finishes. Push **3**.
- 2 finishes. Push **2**.
- 1 finishes. Push **1**.
- 0 finishes. Push **0**.

Stack (top to bottom): **0, 1, 2, 3, 4, 5, 6, 7**

The vertex that finishes last ends up on top. This is the key piece of information for step 3.

<h3 id="step-2-transpose-the-graph">Step 2: Transpose the Graph</h3>

Reverse every edge in the original graph. If the original had an edge from u to v, the transposed graph has an edge from v to u.

The edges within each SCC still form a cycle. If A could reach B and B could reach A in the original, the same is true in the transpose. But the edges between SCCs have flipped direction. In the original, SCC `{0,1,2}` could reach SCC `{3,4,5}`. In the transpose, SCC `{3,4,5}` can reach SCC `{0,1,2}`. This reversal is what makes the second pass work.

<h3 id="step-3-dfs-on-the-transposed-graph-in-stack-order">
  Step 3: DFS on the Transposed Graph (In Stack Order)
</h3>

Pop vertices from the stack and run DFS on the transposed graph, skipping already-visited vertices. Each DFS tree is one SCC.

**Pop 0:** DFS from 0 on the transposed graph visits 0 to 2 to 1. All three are in one DFS tree. **SCC found: `{0, 1, 2}`.**

**Pop 1:** Already visited. Skip.

**Pop 2:** Already visited. Skip.

**Pop 3:** DFS from 3 on the transposed graph visits 3 to 5 to 4. (3 cannot reach 2 because 2 is already visited.) **SCC found: `{3, 4, 5}`.**

**Pop 4, 5:** Already visited. Skip.

**Pop 6:** DFS from 6 on the transposed graph visits 6 to 7. (6 cannot reach 5 because 5 is already visited.) **SCC found: `{6, 7}`.**

**Pop 7:** Already visited. Skip.

Result: three SCCs, exactly as expected.

<h2 id="why-it-works">Why It Works</h2>

The three steps are easy to follow mechanically. The reason they work is that finish order plus the transpose together guarantee one SCC per DFS call in the second pass.

<h3 id="finish-order-encodes-scc-structure">
  Finish Order Encodes SCC Structure
</h3>

When DFS finishes exploring a vertex, it means all vertices reachable from that vertex have already been explored. This means a vertex in an "upstream" SCC (one that can reach other SCCs) will finish after vertices in "downstream" SCCs.

In our example, vertices in SCC `{0,1,2}` finish after vertices in SCC `{3,4,5}`, which finish after vertices in SCC `{6,7}`. So the stack has the "source" SCCs on top.

<h3 id="the-transpose-reverses-inter-scc-edges">
  The Transpose Reverses Inter-SCC Edges
</h3>

Within an SCC, reversing edges does not change reachability. If u can reach v and v can reach u, the same holds after reversal.

But between SCCs, the direction flips. In the original graph, SCC-A reaches SCC-B. In the transpose, SCC-B reaches SCC-A.

<h3 id="combining-the-two">Combining the Two</h3>

When we process the stack in step 3, we start with a vertex from a "source" SCC in the original graph. In the transposed graph, this SCC becomes a "sink" (no outgoing inter-SCC edges). So DFS from this vertex explores only vertices within its own SCC, because there are no outgoing edges to other SCCs in the transpose.

Once that SCC is fully marked as visited, we move to the next vertex in the stack. The same logic applies: the DFS can only reach vertices within its own SCC because (a) inter-SCC edges now point inward (not outward) and (b) any SCC that could be reached has already been visited.

This is why the algorithm works: the finish order plus the transpose together ensure that each DFS in step 3 is perfectly contained within one SCC.

```java
import java.util.*;

public class KosarajuSCC {

    // Step 1: DFS on original graph, fill the stack with finish order
    private static void dfs(int node, List<List<Integer>> graph, boolean[] visited, Stack<Integer> stack) {
        visited[node] = true;
        for (int neighbor : graph.get(node)) {
            if (!visited[neighbor]) {
                dfs(neighbor, graph, visited, stack);
            }
        }
        stack.push(node);
    }

    // Step 3: DFS on transposed graph to collect one SCC
    private static void dfsTranspose(int node, List<List<Integer>> transpose, boolean[] visited, List<Integer> component) {
        visited[node] = true;
        component.add(node);
        for (int neighbor : transpose.get(node)) {
            if (!visited[neighbor]) {
                dfsTranspose(neighbor, transpose, visited, component);
            }
        }
    }

    public static List<List<Integer>> findSCCs(int n, List<List<Integer>> graph) {
        // Step 1: Fill the stack with finish order
        boolean[] visited = new boolean[n];
        Stack<Integer> stack = new Stack<>();
        for (int i = 0; i < n; i++) {
            if (!visited[i]) {
                dfs(i, graph, visited, stack);
            }
        }

        // Step 2: Build the transposed graph
        List<List<Integer>> transpose = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            transpose.add(new ArrayList<>());
        }
        for (int u = 0; u < n; u++) {
            for (int v : graph.get(u)) {
                transpose.get(v).add(u);
            }
        }

        // Step 3: DFS on transposed graph in reverse finish order
        Arrays.fill(visited, false);
        List<List<Integer>> sccs = new ArrayList<>();
        while (!stack.isEmpty()) {
            int node = stack.pop();
            if (!visited[node]) {
                List<Integer> component = new ArrayList<>();
                dfsTranspose(node, transpose, visited, component);
                sccs.add(component);
            }
        }

        return sccs;
    }

    public static void main(String[] args) {
        int n = 8;
        List<List<Integer>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }

        // SCC 1: {0, 1, 2}
        graph.get(0).add(1);
        graph.get(1).add(2);
        graph.get(2).add(0);

        // Bridge: 2 -> 3
        graph.get(2).add(3);

        // SCC 2: {3, 4, 5}
        graph.get(3).add(4);
        graph.get(4).add(5);
        graph.get(5).add(3);

        // Bridge: 5 -> 6
        graph.get(5).add(6);

        // SCC 3: {6, 7}
        graph.get(6).add(7);
        graph.get(7).add(6);

        List<List<Integer>> sccs = findSCCs(n, graph);

        System.out.println("Strongly Connected Components:");
        for (List<Integer> scc : sccs) {
            System.out.println(scc);
        }
    }
}
```

```go
package main

import "fmt"

// Step 1: DFS on original graph, fill the stack with finish order
func dfs(node int, graph [][]int, visited []bool, stack *[]int) {
	visited[node] = true
	for _, neighbor := range graph[node] {
		if !visited[neighbor] {
			dfs(neighbor, graph, visited, stack)
		}
	}
	*stack = append(*stack, node)
}

// Step 3: DFS on transposed graph to collect one SCC
func dfsTranspose(node int, transpose [][]int, visited []bool, component *[]int) {
	visited[node] = true
	*component = append(*component, node)
	for _, neighbor := range transpose[node] {
		if !visited[neighbor] {
			dfsTranspose(neighbor, transpose, visited, component)
		}
	}
}

func FindSCCs(n int, graph [][]int) [][]int {
	// Step 1: Fill the stack with finish order
	visited := make([]bool, n)
	stack := []int{}
	for i := 0; i < n; i++ {
		if !visited[i] {
			dfs(i, graph, visited, &stack)
		}
	}

	// Step 2: Build the transposed graph
	transpose := make([][]int, n)
	for i := 0; i < n; i++ {
		transpose[i] = []int{}
	}
	for u := 0; u < n; u++ {
		for _, v := range graph[u] {
			transpose[v] = append(transpose[v], u)
		}
	}

	// Step 3: DFS on transposed graph in reverse finish order
	for i := range visited {
		visited[i] = false
	}
	sccs := [][]int{}
	for len(stack) > 0 {
		node := stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		if !visited[node] {
			component := []int{}
			dfsTranspose(node, transpose, visited, &component)
			sccs = append(sccs, component)
		}
	}

	return sccs
}
```

```rust
use std::fmt::Write;

pub struct Solution;

impl Solution {
    // Step 1: DFS on original graph, fill the stack with finish order
    fn dfs(node: usize, graph: &Vec<Vec<i32>>, visited: &mut Vec<bool>, stack: &mut Vec<usize>) {
        visited[node] = true;
        for &neighbor in &graph[node] {
            let neighbor = neighbor as usize;
            if !visited[neighbor] {
                Self::dfs(neighbor, graph, visited, stack);
            }
        }
        stack.push(node);
    }

    // Step 3: DFS on transposed graph to collect one SCC
    fn dfs_transpose(
        node: usize,
        transpose: &Vec<Vec<usize>>,
        visited: &mut Vec<bool>,
        component: &mut Vec<i32>,
    ) {
        visited[node] = true;
        component.push(node as i32);
        for &neighbor in &transpose[node] {
            if !visited[neighbor] {
                Self::dfs_transpose(neighbor, transpose, visited, component);
            }
        }
    }

    pub fn find_sccs(n: i32, graph: Vec<Vec<i32>>) -> Vec<Vec<i32>> {
        let n = n as usize;

        // Step 1: Fill the stack with finish order
        let mut visited = vec![false; n];
        let mut stack: Vec<usize> = Vec::new();
        for i in 0..n {
            if !visited[i] {
                Self::dfs(i, &graph, &mut visited, &mut stack);
            }
        }

        // Step 2: Build the transposed graph
        let mut transpose: Vec<Vec<usize>> = vec![Vec::new(); n];
        for u in 0..n {
            for &v in &graph[u] {
                transpose[v as usize].push(u);
            }
        }

        // Step 3: DFS on transposed graph in reverse finish order
        visited.fill(false);
        let mut sccs: Vec<Vec<i32>> = Vec::new();
        while let Some(node) = stack.pop() {
            if !visited[node] {
                let mut component: Vec<i32> = Vec::new();
                Self::dfs_transpose(node, &transpose, &mut visited, &mut component);
                sccs.push(component);
            }
        }

        sccs
    }
}
```

```javascript
      dfs(i, graph, visited, stack);
    }
  }

  // Step 2: Build the transposed graph
  const transpose = Array.from({ length: n }, () => []);
  for (let u = 0; u < n; u++) {
    for (const v of graph[u]) {
      transpose[v].push(u);
    }
  }

  // Step 3: DFS on transposed graph in reverse finish order
  visited.fill(false);
  const sccs = [];
  while (stack.length > 0) {
    const node = stack.pop();
    if (!visited[node]) {
      const component = [];
      dfsTranspose(node, transpose, visited, component);
      sccs.push(component);
    }
  }

  return sccs;
}
```

```typescript
function dfs(
  node: number,
  graph: number[][],
  visited: boolean[],
  stack: number[],
): void {
  visited[node] = true;
  for (const neighbor of graph[node]) {
    if (!visited[neighbor]) {
      dfs(neighbor, graph, visited, stack);
    }
  }
  stack.push(node);
}

// Step 3: DFS on transposed graph to collect one SCC
function dfsTranspose(
  node: number,
  transpose: number[][],
  visited: boolean[],
  component: number[],
): void {
  visited[node] = true;
  component.push(node);
  for (const neighbor of transpose[node]) {
    if (!visited[neighbor]) {
      dfsTranspose(neighbor, transpose, visited, component);
    }
  }
}

function findSCCs(n: number, graph: number[][]): number[][] {
  // Step 1: Fill the stack with finish order
  const visited: boolean[] = new Array(n).fill(false);
  const stack: number[] = [];
  for (let i = 0; i < n; i++) {
    if (!visited[i]) {
      dfs(i, graph, visited, stack);
    }
  }

  // Step 2: Build the transposed graph
  const transpose: number[][] = Array.from({ length: n }, () => []);
  for (let u = 0; u < n; u++) {
    for (const v of graph[u]) {
      transpose[v].push(u);
    }
  }

  // Step 3: DFS on transposed graph in reverse finish order
  visited.fill(false);
  const sccs: number[][] = [];
  while (stack.length > 0) {
    const node = stack.pop()!;
    if (!visited[node]) {
      const component: number[] = [];
      dfsTranspose(node, transpose, visited, component);
      sccs.push(component);
    }
  }

  return sccs;
}
```

<h2 id="applications-of-sccs">Applications of SCCs</h2>

SCCs show up in several practical problems and graph interview questions.

<h3 id="1-condensation-graph-dag-of-sccs">
  1. Condensation Graph (DAG of SCCs)
</h3>

Once you find all SCCs, you can collapse each SCC into a single vertex. The resulting graph is guaranteed to be a DAG. This condensation is useful for:

- **Reachability queries:** Instead of checking reachability on the original graph, check on the much smaller DAG.
- **Shortest path in terms of components:** How many SCC boundaries do you need to cross?
- **Topological ordering of components:** Process SCCs in dependency order.

<h3 id="2-2-sat-boolean-satisfiability">2. 2-SAT (Boolean Satisfiability)</h3>

The 2-SAT problem asks: given a boolean formula where each clause has exactly two literals, is there a satisfying assignment? This can be modeled as an implication graph, and the formula is satisfiable if and only if no variable and its negation are in the same SCC. Kosaraju's algorithm gives you an O(V + E) solution to 2-SAT.

<h3 id="3-social-network-analysis">3. Social Network Analysis</h3>

In a follow/friend graph, SCCs represent communities where every member can reach every other member through a chain of follows. Finding these communities helps with recommendation systems and influence analysis.

<h3 id="4-compiler-optimization">4. Compiler Optimization</h3>

In a function call graph, SCCs represent groups of mutually recursive functions. The compiler can optimize these groups differently from non-recursive functions, for example by applying special inlining or tail-call strategies.

<h2 id="complexity-analysis">Complexity Analysis</h2>

<h3 id="time-complexity">Time Complexity</h3>

The overall time complexity is O(V + E). The first DFS pass over the original graph visits every vertex and edge once, which costs O(V + E). Building the transposed graph reverses each edge exactly once, adding another O(V + E). The second DFS pass over the transpose again touches every vertex and edge once for O(V + E). These three phases run one after another rather than nested, so their costs add up to O(V + E).

<h3 id="space-complexity">Space Complexity</h3>

The space complexity is O(V + E). The transposed graph holds all V vertices and E edges, which dominates the usage. On top of that, the algorithm keeps a visited array and a finish-order stack, each holding at most V entries, for O(V) additional space.

<h2 id="key-takeaways">Key Takeaways</h2>

- A strongly connected component is a maximal set of vertices in a directed graph where every vertex can reach every other vertex through directed paths in both directions.
- Kosaraju's algorithm finds all SCCs using two DFS passes: the first pass runs DFS on the original graph and pushes each vertex onto a stack as it finishes, and the second pass runs DFS on the transposed graph by popping vertices in reverse finish order.
- Transposing the graph reverses every edge, which keeps reachability inside each SCC unchanged but flips the direction of edges between SCCs, and this flip is what confines each second-pass DFS to a single component.
- The finish-order stack places source SCCs on top, so starting the second pass from those vertices isolates one SCC per DFS call because the SCCs they could otherwise reach are already visited.
- Kosaraju's runs in O(V + E) time across both DFS passes and the transpose construction, and it uses O(V + E) space for the transposed graph, the visited array, and the stack.
- The SCCs you find support practical applications such as building a condensation graph that is always a DAG, solving 2-SAT by checking that no variable and its negation share an SCC, detecting communities in social networks, and grouping mutually recursive functions during compilation.
