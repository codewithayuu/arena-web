Knowing matplotlib's API is half the job; the other half is knowing what chart to draw, what colors to use, and what mistakes to avoid. This lesson is about visualization as a discipline: how to pick the right chart for the data, how to make charts readable for everyone (including colorblind viewers), how to annotate for storytelling, what other tools exist beyond matplotlib, and the common mistakes that turn a chart into a lie. The lesson ends with the standard workflow: explore freely, refine the most useful chart, present it cleanly.

<h1 id="choosing-the-right-chart">Choosing the Right Chart</h1>

Most data-visualization problems collapse into one of five questions, and each has a small set of correct chart types. Pick the question first, then the chart.

| Question                                     | Good charts                             | Avoid                                 |
| -------------------------------------------- | --------------------------------------- | ------------------------------------- |
| What's the **distribution** of one variable? | Histogram, KDE, box plot, violin plot   | Pie chart                             |
| How do groups **compare** on one measure?    | Bar chart, grouped bar, dot plot        | Stacked area, pie                     |
| Are two variables **related**?               | Scatter, line (if x is ordered), hexbin | Bar, pie                              |
| How is something **composed** of parts?      | Stacked bar (few categories), treemap   | Pie (more than 3 slices), 3D anything |
| How does a measure **trend** over time?      | Line, area, slope chart                 | Bar (loses continuity), pie           |

The wrong chart isn't just ugly; it actively misleads. A pie chart for ten categories asks the reader to compare angles, which humans are bad at. A bar chart of the same data uses lengths, which are easy to compare precisely. Same data, very different reader experience.

<h3 id="distribution-histogram-kde-box-violin">
  Distribution: Histogram, KDE, Box, Violin
</h3>

A histogram bins values and shows counts. It's the right starting point for one numeric variable. A **kernel density estimate** (KDE) smooths the histogram into a continuous curve, which works better with enough data to make the smoothing meaningful when comparing distributions on the same chart.

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
ratings_old = np.random.normal(3.5, 0.8, 500).clip(1, 5)
ratings_new = np.random.normal(4.3, 0.5, 500).clip(1, 5)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(11, 4))

ax1.hist(ratings_old, bins=20, alpha=0.6, label="Before", color="#ffa94d")
ax1.hist(ratings_new, bins=20, alpha=0.6, label="After", color="#00ceff")
ax1.set_title("Histogram")
ax1.set_xlabel("Rating")
ax1.legend()

ax2.boxplot([ratings_old, ratings_new], labels=["Before", "After"], patch_artist=True,
            boxprops=dict(facecolor="#00ceff"), medianprops=dict(color="black"))
ax2.set_title("Box Plot")
ax2.set_ylabel("Rating")

fig.tight_layout()
plt.show()
```

The histogram shows the full shape, including the lower mode in the "before" data. The box plot shows the summary: median (line), interquartile range (box), whiskers (typical extent), outliers (dots). For two groups, the box plot is more compact and makes the median shift visible. For more than two groups, box plots scale better than overlapping histograms.

A **violin plot** is a box plot crossed with a KDE: it shows both the summary statistics and the full shape of the distribution. Seaborn's `violinplot` is the standard way to draw one.

<h3 id="comparison-bar-grouped-bar-dot">Comparison: Bar, Grouped Bar, Dot</h3>

A bar chart compares one measure across discrete categories. This section is about when to escalate beyond the basic bar.

**Use a grouped bar** when each category has two or three sub-measures. Side by side bars, one color per sub-measure, one position per category.

**Use a dot plot** when many categories make the bar's full length more visual noise than information. A dot plot puts a single dot at each category's value, sometimes with a thin connector to a baseline. Cleaner than a tall stack of long bars.

```python
import matplotlib.pyplot as plt
import numpy as np

categories = ["Electronics", "Audio", "Cables", "Webcams", "Storage", "Networking",
              "Peripherals", "Power", "Tablets", "Wearables"]
revenue = [12500, 8700, 3200, 5400, 7800, 4900, 6300, 2800, 9500, 4100]

order = np.argsort(revenue)[::-1]
categories_sorted = [categories[i] for i in order]
revenue_sorted = [revenue[i] for i in order]

fig, ax = plt.subplots(figsize=(8, 6))
y = np.arange(len(categories_sorted))
ax.hlines(y, 0, revenue_sorted, color="#00ceff", linewidth=2)
ax.plot(revenue_sorted, y, "o", color="#00ceff", markersize=10)
ax.set_yticks(y)
ax.set_yticklabels(categories_sorted)
ax.invert_yaxis()
ax.set_title("Revenue by Category")
ax.set_xlabel("Revenue ($)")
ax.spines["top"].set_visible(False)
ax.spines["right"].set_visible(False)
plt.show()
```

The dot plot shows each category's revenue as a horizontal line with a dot at the end. Sorting by value makes the ranking readable at a glance. `invert_yaxis()` puts the highest-revenue category at the top, matching top-to-bottom scanning order. The result is far less ink than a full bar chart and reads faster.

Always sort categorical bars or dots by value (descending), not alphabetically. Alphabetical order conveys nothing about the data; value order makes the ranking the visual story.

<h3 id="relationship-scatter-line-hexbin">
  Relationship: Scatter, Line, Hexbin
</h3>

For two numeric variables, a scatter plot is the default. If the x-axis is ordered (time, distance), a line connecting the points implies the sequence.

**Hexbin** fits when a scatter would have so many points they overlap into one black smear. Each hexagon counts how many observations fall into it, and the color encodes the count.

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
n = 50000
x = np.random.normal(0, 1, n)
y = x * 0.5 + np.random.normal(0, 0.5, n)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 5))

ax1.scatter(x, y, alpha=0.1, color="#00ceff", s=5)
ax1.set_title("Scatter (50k points, even with alpha=0.1)")

hb = ax2.hexbin(x, y, gridsize=30, cmap="viridis")
ax2.set_title("Hexbin (same data)")
fig.colorbar(hb, ax=ax2, label="Count")

fig.tight_layout()
plt.show()
```

The scatter, even with `alpha=0.1` to soften overlap, still saturates in the dense center. The hexbin shows the density structure clearly: a dense ridge along the diagonal correlation, fading out at the edges. For dense scatters, switch.

<h3 id="composition-stacked-bar-treemap">Composition: Stacked Bar, Treemap</h3>

A stacked bar shows how each total is composed of parts. It works for a small number of parts (3-5) when the totals themselves are meaningful.

```python
import matplotlib.pyplot as plt
import numpy as np

months = ["Jan", "Feb", "Mar", "Apr"]
electronics = [5200, 5800, 6500, 6900]
audio = [3100, 3300, 3800, 4100]
cables = [1200, 1400, 1500, 1700]

fig, ax = plt.subplots(figsize=(8, 5))
ax.bar(months, electronics, label="Electronics", color="#00ceff")
ax.bar(months, audio, bottom=electronics, label="Audio", color="#ffa94d")
ax.bar(months, cables, bottom=np.array(electronics) + np.array(audio),
       label="Cables", color="#69db7c")
ax.set_title("Monthly Revenue by Category")
ax.set_ylabel("Revenue ($)")
ax.legend()
plt.show()
```

`bottom=` shifts each next layer to start where the previous one ended. The result shows total revenue per month (bar heights) and the contribution of each category (segment heights). Stacked bars work here; pie charts for the same data would force the reader to compare angles between months separately, which is much harder.

The limit is the number of categories. With more than 5-6 segments per bar, the smaller ones become unreadable. Switch to a treemap (seaborn or plotly have decent ones) or a small-multiples grid of separate bar charts.

<h3 id="trends-line-area-slope">Trends: Line, Area, Slope</h3>

A line chart for time series is the default. **Area charts** add a filled region between the line and the x-axis, useful when the magnitude (not just the trajectory) is the point.

**Slope charts** show the change between two points in time for several groups: one short line per group, two x positions ("before" and "after"), with the lines colored by direction. Compact, ranking-friendly, and effective when the changes are mixed (some up, some down).
