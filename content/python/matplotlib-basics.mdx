<h1 id="the-two-apis-and-why-one-is-better">
  The Two APIs and Why One Is Better
</h1>

Matplotlib exposes two ways to make a plot. The `pyplot` API is state-machine-based: calls like `plt.plot(...)`, `plt.title(...)`, `plt.legend()` operate on an internally tracked "current figure" and "current axes". It mimics MATLAB and reads compactly for tiny throwaway plots.

```python
import matplotlib.pyplot as plt

prices = [29.99, 89.99, 24.50, 59.99, 49.99]
products = ["Mouse", "Keyboard", "Hub", "Webcam", "Speaker"]

plt.bar(products, prices)
plt.title("Product Prices")
plt.ylabel("Price ($)")
plt.show()
```

The same plot with the **object-oriented API** is more explicit but scales:

```python
import matplotlib.pyplot as plt

prices = [29.99, 89.99, 24.50, 59.99, 49.99]
products = ["Mouse", "Keyboard", "Hub", "Webcam", "Speaker"]

fig, ax = plt.subplots()
ax.bar(products, prices)
ax.set_title("Product Prices")
ax.set_ylabel("Price ($)")
plt.show()
```

`fig` is the entire figure (the canvas). `ax` is one set of axes (one chart inside the canvas). All the customization happens through `ax.set_xxx(...)` methods. The advantages of the OO API:

- **Multiple subplots are clean.** `fig, (ax1, ax2) = plt.subplots(1, 2)` provides two axes objects to draw on. With pyplot's state machine, switching the "current axes" is a constant source of bugs.
- **The model matches the actual class hierarchy.** A figure contains one or more axes; each axes has a title, labels, legend, ticks, lines, bars, and so on. The OO API is just calling methods on those objects.
- **Code is reusable.** A plotting function can take an `ax` argument and draw on a caller-supplied axes. Pyplot's "current axes" makes this awkward.
- **Most documentation and production matplotlib code uses it.** Pyplot examples are for quickstart; production scripts use OO.

The rest of this lesson uses the OO API exclusively. `fig, ax = plt.subplots()` is the entry point.

The diagram shows the figure-axes-elements hierarchy. One figure holds one or more axes; each axes owns its title, labels, ticks, legend, and the actual plotted elements (lines, bars, points). Every customization is a method call on the relevant object.

<h1 id="line-plots">Line Plots</h1>

A line plot shows a continuous quantity changing across an ordered axis. Daily sales, sensor readings over time, prices across order dates.

```python
import matplotlib.pyplot as plt

days = list(range(1, 11))
sales = [120, 135, 98, 142, 155, 130, 145, 160, 138, 150]

fig, ax = plt.subplots(figsize=(8, 4))
ax.plot(days, sales, marker="o", color="#00ceff", linewidth=2)
ax.set_title("Daily Sales (May 1-10)")
ax.set_xlabel("Day")
ax.set_ylabel("Sales ($)")
ax.grid(True, alpha=0.3)
plt.show()
```

`ax.plot(x, y)` is the basic call. `marker="o"` puts a circle at each data point. `color="#00ceff"` picks the line color. `linewidth=2` thickens the line slightly. `ax.grid(True, alpha=0.3)` adds a faint grid in the background, which makes values easier to read off the chart.

`figsize=(8, 4)` sets the figure size in inches. The default is `(6.4, 4.8)`, which is usually too small for presentation. Wide-and-short (8 by 4) suits time series; nearly square (6 by 6) suits scatter plots.

Multiple lines on one axes means multiple `ax.plot(...)` calls. Each call adds another line:

```python
import matplotlib.pyplot as plt

days = list(range(1, 11))
sales_a = [120, 135, 98, 142, 155, 130, 145, 160, 138, 150]
sales_b = [80, 95, 110, 105, 120, 130, 125, 140, 135, 145]

fig, ax = plt.subplots(figsize=(8, 4))
ax.plot(days, sales_a, label="Store A", color="#00ceff", linewidth=2)
ax.plot(days, sales_b, label="Store B", color="#ffa94d", linewidth=2)
ax.set_title("Daily Sales by Store")
ax.set_xlabel("Day")
ax.set_ylabel("Sales ($)")
ax.legend()
ax.grid(True, alpha=0.3)
plt.show()
```

Each line gets a `label=`. `ax.legend()` picks up those labels and renders the legend box. The default placement is "best" (matplotlib picks a corner that doesn't overlap data); pass `loc="upper left"` or similar to control placement.

<h1 id="bar-charts">Bar Charts</h1>

A bar chart shows values across discrete categories. Sales by product, headcount by department, ratings per category.

```python
import matplotlib.pyplot as plt

categories = ["Electronics", "Audio", "Cables", "Webcams"]
revenue = [12500, 8700, 3200, 5400]

fig, ax = plt.subplots(figsize=(8, 5))
bars = ax.bar(categories, revenue, color=["#00ceff", "#ffa94d", "#69db7c", "#38d9a9"])
ax.set_title("Revenue by Category (Q1)")
ax.set_xlabel("Category")
ax.set_ylabel("Revenue ($)")

for bar, value in zip(bars, revenue):
    ax.text(bar.get_x() + bar.get_width() / 2, value + 100, f"${value:,}",
            ha="center", fontsize=9)
plt.show()
```

`ax.bar(categories, values)` draws the bars. A list of colors paints each bar a different color, which can highlight a top category without cluttering the chart. The `for` loop adds a value label above each bar; `ax.text(x, y, text)` places a string at the given data coordinates, and `ha="center"` centers it horizontally.

For horizontal bars (better for long category names), `ax.barh(...)` is the same call with `x` and `y` swapped semantically.

```python
fig, ax = plt.subplots(figsize=(8, 4))
ax.barh(categories, revenue, color="#00ceff")
ax.set_title("Revenue by Category (Q1)")
ax.set_xlabel("Revenue ($)")
plt.show()
```

Horizontal bars usually work better when the category names are long enough that vertical-bar labels would overlap or rotate. Reading "Audio" stacked vertically under a thin bar is harder than reading it across.

For grouped bars (comparing two metrics side by side per category), shift the x positions:

```python
import matplotlib.pyplot as plt
import numpy as np

categories = ["Electronics", "Audio", "Cables", "Webcams"]
q1 = [12500, 8700, 3200, 5400]
q2 = [14200, 9100, 3500, 6100]

x = np.arange(len(categories))
width = 0.35

fig, ax = plt.subplots(figsize=(8, 5))
ax.bar(x - width / 2, q1, width, label="Q1", color="#00ceff")
ax.bar(x + width / 2, q2, width, label="Q2", color="#ffa94d")
ax.set_xticks(x)
ax.set_xticklabels(categories)
ax.set_title("Revenue by Category, Q1 vs Q2")
ax.set_ylabel("Revenue ($)")
ax.legend()
plt.show()
```

Two `ax.bar(...)` calls with shifted x positions and reduced widths produce the side-by-side bars. `ax.set_xticks(x)` plus `ax.set_xticklabels(categories)` puts the category names back where they belong (in the middle of each pair of bars).

<h1 id="scatter-plots">Scatter Plots</h1>

A scatter plot shows the relationship between two numeric variables. Each point is one observation. It's useful for spotting correlation, clusters, and outliers.

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
n = 60
price = np.random.uniform(10, 100, n)
units_sold = (200 - 1.5 * price + np.random.normal(0, 20, n)).clip(0, None)

fig, ax = plt.subplots(figsize=(7, 5))
ax.scatter(price, units_sold, color="#00ceff", alpha=0.7, edgecolors="black")
ax.set_title("Price vs Units Sold")
ax.set_xlabel("Price ($)")
ax.set_ylabel("Units Sold")
ax.grid(True, alpha=0.3)
plt.show()
```

`ax.scatter(x, y)` plots one dot per observation. `alpha=0.7` makes the dots semi-transparent so overlapping points darken visibly. `edgecolors="black"` outlines each dot, which improves visibility against a light background.

The relationship visible here is roughly linear and negative: higher prices correlate with fewer units sold. A scatter plot is the first chart for two numeric columns whose relationship is in question.

A third variable can be encoded in the dot size or color:

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
n = 30
price = np.random.uniform(10, 100, n)
rating = np.random.uniform(3, 5, n)
revenue = np.random.uniform(100, 5000, n)

fig, ax = plt.subplots(figsize=(7, 5))
scatter = ax.scatter(price, rating, s=revenue / 20, c=revenue, cmap="viridis", alpha=0.7)
ax.set_title("Price vs Rating (size and color = revenue)")
ax.set_xlabel("Price ($)")
ax.set_ylabel("Rating")
plt.colorbar(scatter, ax=ax, label="Revenue ($)")
plt.show()
```

`s=revenue / 20` sizes each dot by revenue (divided by 20 to keep dots reasonable). `c=revenue` colors each dot by the same value; `cmap="viridis"` is a perceptually uniform color map, which means equal differences in data correspond to equal perceptual differences in color (and it's colorblind-friendly). `plt.colorbar(...)` adds the color legend on the right.

Encoding too many variables in one plot gets noisy fast. Two extra dimensions (size and color, or shape and color) is the practical limit for readability.

Scatter plots with millions of points get slow to render and visually saturate (everything overlaps). For very large datasets, switch to `ax.hexbin(...)` (which bins the plane into hexagons and colors them by count) or `ax.hist2d(...)` (a 2D histogram). Both summarize density instead of drawing every point.

<h1 id="histograms">Histograms</h1>

A histogram shows the distribution of a single numeric variable: how many observations fall into each bin.

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
ratings = np.concatenate([np.random.normal(4.2, 0.5, 200), np.random.normal(3.0, 0.7, 50)])
ratings = ratings.clip(1, 5)

fig, ax = plt.subplots(figsize=(8, 5))
ax.hist(ratings, bins=20, color="#00ceff", edgecolor="black", alpha=0.8)
ax.set_title("Product Rating Distribution")
ax.set_xlabel("Rating")
ax.set_ylabel("Number of Reviews")
ax.axvline(ratings.mean(), color="#ff8787", linestyle="--", linewidth=2, label=f"Mean: {ratings.mean():.2f}")
ax.legend()
plt.show()
```

`ax.hist(values, bins=20)` partitions the value range into 20 equal-width bins and counts how many observations fall into each. `edgecolor="black"` outlines each bar, which makes the bin boundaries visible. `ax.axvline(...)` draws a vertical line at the mean, with a label that goes into the legend.

The bin count is a real choice. Too few bins (5) hides the shape; too many (100) makes the chart noisy. A rule of thumb is `bins = int(np.sqrt(len(data)))`, but the best value depends on the data. Try 10, 20, 50 and pick the clearest.

For comparing two distributions on the same axes, plot both with `alpha`:

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
old_ratings = np.random.normal(3.5, 0.8, 300).clip(1, 5)
new_ratings = np.random.normal(4.3, 0.5, 300).clip(1, 5)

fig, ax = plt.subplots(figsize=(8, 5))
ax.hist(old_ratings, bins=20, color="#ffa94d", alpha=0.6, label="Before redesign")
ax.hist(new_ratings, bins=20, color="#00ceff", alpha=0.6, label="After redesign")
ax.set_title("Rating Distribution: Before vs After")
ax.set_xlabel("Rating")
ax.set_ylabel("Number of Reviews")
ax.legend()
plt.show()
```

Both histograms are drawn semi-transparent so they overlap visibly. The shift in the new distribution toward higher ratings becomes visible. For more than two distributions, a `density=True` parameter normalizes each histogram so the areas sum to 1, making them comparable when the sample sizes differ.

<h1 id="pie-charts-use-sparingly">Pie Charts: Use Sparingly</h1>

`ax.pie(...)` draws a pie chart: a circle divided into slices proportional to category values.

```python
import matplotlib.pyplot as plt

categories = ["Electronics", "Audio", "Cables", "Webcams"]
revenue = [12500, 8700, 3200, 5400]

fig, ax = plt.subplots(figsize=(6, 6))
ax.pie(revenue, labels=categories, autopct="%1.1f%%",
       colors=["#00ceff", "#ffa94d", "#69db7c", "#38d9a9"])
ax.set_title("Revenue Share by Category")
plt.show()
```

`labels=` is the category names. `autopct="%1.1f%%"` shows the percentage of each slice (the format string `"%1.1f%%"` means "one decimal place followed by a literal `%`"). `colors=` is the slice palette.

Pie charts have a real readability problem: humans are bad at comparing angles. A bar chart with the same data is faster to read and more precise. Two cases where a pie chart works better: very few slices (2 or 3) where the proportions are themselves the story, and "X is a majority" claims where the visual punch matters more than precision. For everything else, prefer a bar chart.

<h1 id="customization-labels-titles-colors-styles">
  Customization: Labels, Titles, Colors, Styles
</h1>

Every plot needs at least a title and axis labels. Most need a legend, sensible tick formatting, and grid lines. The OO API exposes all of this through methods on `ax`.

```python
import matplotlib.pyplot as plt
import numpy as np

months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]
revenue = [12500, 13200, 14500, 14800, 16200, 17800]

fig, ax = plt.subplots(figsize=(8, 5))
ax.plot(months, revenue, marker="s", color="#00ceff", linewidth=2.5, markersize=10)
ax.set_title("Monthly Revenue Growth", fontsize=14, fontweight="bold")
ax.set_xlabel("Month", fontsize=11)
ax.set_ylabel("Revenue ($)", fontsize=11)
ax.yaxis.set_major_formatter(plt.FuncFormatter(lambda x, _: f"${int(x):,}"))
ax.grid(True, axis="y", linestyle="--", alpha=0.5)
ax.spines["top"].set_visible(False)
ax.spines["right"].set_visible(False)
plt.show()
```

Common customizations:

- `marker="s"` is a square marker. Common values: `"o"` (circle), `"s"` (square), `"^"` (triangle), `"d"` (diamond), `"*"` (star), `"x"` (cross).
- `linewidth` controls line thickness; `markersize` controls marker size.
- `ax.yaxis.set_major_formatter(...)` reformats the tick labels (here, adding `$$` and commas to revenue).
- `ax.grid(True, axis="y", linestyle="--")` adds only the horizontal grid lines (along the y-axis), dashed for subtlety.
- `ax.spines["top"].set_visible(False)` hides the top border of the plot. Removing top and right spines is a common "tufte-style" cleanup that reduces visual clutter.

Color values can be hex codes (`"#00ceff"`), named colors (`"red"`, `"steelblue"`, `"orange"`), or RGB tuples (`(0.0, 0.8, 1.0)`). Matplotlib's full list of named colors covers most needs; the project's brand palette is the hex form from the diagram guidelines.

Line styles: `"-"` (solid, default), `"--"` (dashed), `":"` (dotted), `"-."` (dash-dot).

<h1 id="subplots-multiple-charts-in-one-figure">
  Subplots: Multiple Charts in One Figure
</h1>

`plt.subplots(rows, cols)` creates a figure with a grid of axes. The result is `(fig, axes)`, where `axes` is a 2D array of Axes objects when there's more than one row or column.

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
prices = np.random.uniform(10, 100, 50)
ratings = np.random.uniform(3, 5, 50)
revenue = np.random.uniform(100, 5000, 50)

fig, axes = plt.subplots(2, 2, figsize=(12, 8))

axes[0, 0].hist(prices, bins=15, color="#00ceff", edgecolor="black")
axes[0, 0].set_title("Price Distribution")
axes[0, 0].set_xlabel("Price ($)")

axes[0, 1].hist(ratings, bins=15, color="#ffa94d", edgecolor="black")
axes[0, 1].set_title("Rating Distribution")
axes[0, 1].set_xlabel("Rating")

axes[1, 0].scatter(prices, ratings, color="#69db7c", alpha=0.7)
axes[1, 0].set_title("Price vs Rating")
axes[1, 0].set_xlabel("Price ($)")
axes[1, 0].set_ylabel("Rating")

axes[1, 1].scatter(prices, revenue, color="#38d9a9", alpha=0.7)
axes[1, 1].set_title("Price vs Revenue")
axes[1, 1].set_xlabel("Price ($)")
axes[1, 1].set_ylabel("Revenue ($)")

fig.suptitle("Product Analysis Dashboard", fontsize=14, fontweight="bold")
fig.tight_layout()
plt.show()
```

`plt.subplots(2, 2)` returns a figure with four axes in a 2x2 grid. `axes[row, col]` indexes them. Each axes is independent: its own title, labels, ticks. `fig.suptitle(...)` adds a title for the entire figure. `fig.tight_layout()` adjusts spacing so titles and labels don't overlap; without it, the dense grid looks cramped.

For a single row or column of subplots, the result is a 1D array, which can be unpacked directly:

```python
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 4))
ax1.bar(["A", "B", "C"], [3, 7, 5], color="#00ceff")
ax1.set_title("Sales")
ax2.bar(["A", "B", "C"], [4.2, 3.8, 4.5], color="#ffa94d")
ax2.set_title("Ratings")
plt.show()
```

Two axes side by side, unpacked into `ax1` and `ax2` for clarity. This is the cleanest pattern for two related charts.

When the subplots share an x or y range, `sharex=True` or `sharey=True` aligns the axes:

```python
fig, (ax1, ax2) = plt.subplots(2, 1, figsize=(8, 6), sharex=True)
ax1.plot([1, 2, 3, 4, 5], [120, 135, 98, 142, 155], color="#00ceff")
ax1.set_title("Store A")
ax2.plot([1, 2, 3, 4, 5], [80, 95, 110, 105, 120], color="#ffa94d")
ax2.set_title("Store B")
ax2.set_xlabel("Day")
plt.show()
```

`sharex=True` means both axes use the same x range and only the bottom one shows tick labels. The vertical alignment makes day-to-day comparisons easy.

<h1 id="saving-figures">Saving Figures</h1>

`fig.savefig(path)` writes the figure to disk. The format is inferred from the file extension: `.png`, `.jpg`, `.pdf`, `.svg`. PNG is the standard raster format for web; SVG is vector for scaling without quality loss; PDF is vector and prints well.

```python
import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(8, 4))
ax.plot([1, 2, 3, 4], [10, 25, 15, 30], color="#00ceff", linewidth=2)
ax.set_title("Sample Plot")
fig.savefig("sample.png", dpi=150, bbox_inches="tight")
plt.close(fig)
```

`dpi=150` controls pixel density for raster formats. The default is 100, which works for screens; 150-300 is better for print or high-res displays. `bbox_inches="tight"` trims excess whitespace around the figure, which matters when embedding in documents or web pages.

`plt.close(fig)` releases the figure's memory. In notebooks, matplotlib usually displays and closes automatically; in long-running scripts that generate many figures, skipping the close call leaks memory.

Common parameters:

| Parameter             | Effect                                                        |
| --------------------- | ------------------------------------------------------------- |
| `dpi`                 | Resolution for raster formats (higher = sharper, larger file) |
| `bbox_inches="tight"` | Trim excess whitespace                                        |
| `transparent=True`    | PNG with transparent background                               |
| `facecolor=`          | Background color (default white)                              |
| `format=`             | Force a format ignoring the extension                         |

<h1 id="working-with-pandas">Working with Pandas</h1>

Pandas DataFrames and Series have a `.plot()` method that delegates to matplotlib. It's the quickest way to chart pandas data and produces a matplotlib Axes object that can be customized further.

```python
import pandas as pd
import matplotlib.pyplot as plt

orders = pd.DataFrame({
    "month": ["Jan", "Feb", "Mar", "Apr", "May", "Jun"],
    "revenue": [12500, 13200, 14500, 14800, 16200, 17800],
    "orders": [320, 345, 380, 395, 420, 460],
})

fig, ax = plt.subplots(figsize=(9, 5))
orders.plot(x="month", y="revenue", kind="line", marker="o", ax=ax, color="#00ceff", linewidth=2)
ax.set_title("Monthly Revenue")
ax.set_ylabel("Revenue ($)")
ax.grid(True, alpha=0.3)
plt.show()
```

`df.plot(x=, y=, kind=, ax=)` is the pandas entry point. `kind=` can be `"line"`, `"bar"`, `"barh"`, `"hist"`, `"scatter"`, `"box"`, `"area"`, `"pie"`, `"kde"`. Passing `ax=ax` makes the plot draw on a specific axes (the one from `plt.subplots()`), which keeps the OO API intact and allows further axes customization.

Without `ax=`, pandas calls `plt.subplots()` itself and returns the new axes:

```python
ax = orders.plot(x="month", y="revenue", kind="bar", color="#00ceff")
ax.set_title("Monthly Revenue")
plt.show()
```

For multi-series plots, pandas handles the layout:

```python
ax = orders.plot(x="month", y=["revenue", "orders"], kind="line", marker="o",
                 secondary_y="orders", figsize=(9, 5))
plt.show()
```

`secondary_y="orders"` puts the orders series on a second y-axis on the right side, which fits when two series have very different scales (revenue in thousands, orders in hundreds). Use it sparingly: dual-axis charts are easy to mislead with.

```python
import pandas as pd
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
products = pd.DataFrame({
    "name": ["Mouse", "Keyboard", "Hub", "Webcam", "Speaker", "Headphones"],
    "price": [29.99, 89.99, 24.50, 59.99, 49.99, 79.99],
    "revenue": [3500, 8200, 1900, 4700, 3800, 6100],
})

fig, ax = plt.subplots(figsize=(8, 5))
products.plot(x="name", y="revenue", kind="barh", ax=ax, color="#00ceff", legend=False)
ax.set_title("Revenue by Product")
ax.set_xlabel("Revenue ($)")
plt.show()
```

`kind="barh"` gives horizontal bars; `legend=False` hides the legend since there's only one series.

`df.plot()` is convenient but slightly slower than the direct matplotlib calls because of the wrapping. For one-off charts the difference is invisible; for tight loops generating thousands of small charts, going straight to matplotlib saves time.

<h1 id="when-matplotlib-when-something-else">
  When Matplotlib, When Something Else
</h1>

Matplotlib fits when the requirements include:

- **Fine control over every detail.** Tick formatters, custom legends, annotations, multi-panel layouts. Publication-quality figures for papers, reports, dashboards.
- **A specific look.** Brand colors, exact font sizes, precise positioning. Matplotlib supports specifying all of it.
- **Static output.** Saving to PNG, PDF, SVG. Embedding in PDFs or print materials.
- **Programmatic generation.** Scripts that produce hundreds of figures with varying inputs.

Other libraries handle other cases better:

**Seaborn** wraps matplotlib with statistical defaults: better automatic palettes, built-in support for distributions (`displot`, `kdeplot`), categorical comparisons (`boxplot`, `violinplot`, `swarmplot`), and faceted plots (`relplot`, `catplot`). Charts come out looking polished with one call. Internally it produces a matplotlib figure, so further customization is possible. Use seaborn when the plot is a statistical summary and sensible defaults are wanted; use raw matplotlib when precise control matters.

**Plotly** produces interactive charts: hover tooltips, zoom, pan, click-to-toggle. The output is HTML, which works in notebooks and web pages. Use plotly for exploratory analysis in notebooks and dashboards where interactivity matters. The downside is heavier JavaScript output and a different API to learn.

**Bokeh** is similar to plotly: interactive, web-targeted, large dataset support. Slightly more verbose for simple plots but powerful for custom interactive dashboards.

**Altair** is a declarative wrapper around Vega-Lite. The chart is described in terms of data columns and encodings (this column to x, that column to color), and Altair figures out the rest. Concise for standard statistical charts, less flexible for fine-grained custom layouts.

A rough decision tree: matplotlib for static and precise, seaborn for statistical with good defaults, plotly for interactive. Most data-science codebases end up using both matplotlib and seaborn, because seaborn handles the high-level "summarize this distribution" and matplotlib handles the low-level "make it look exactly like this."
