<h1 id="why-not-just-split-on-commas">Why Not Just Split on Commas</h1>

CSV looks like a one-liner problem. Open the file, read each line, split on `,`, done. That works on the friendliest possible file and breaks on every real one. Three things go wrong fast.

First, fields can contain commas. A product titled `Anker, Wireless Mouse` is one field, not two. To handle this, CSV writers wrap fields that contain commas in double quotes: `"Anker, Wireless Mouse",29.99,Electronics`. A naive split on `,` returns four tokens; the correct parse returns three.

Second, fields can contain the quote character itself. CSV escapes an embedded `"` by doubling it: a review body of `She said "great mouse"` is written as `"She said ""great mouse"""`. Splitting on `,` produces garbage. Even splitting smarter without honoring the escape rule mishandles the inner quotes.

Third, fields can contain newlines. A product description that spans two lines is one logical record but two physical lines in the file, with the embedded newline wrapped inside quotes. Reading line-by-line with `for line in file:` cuts that record in half.

Here is what goes wrong with a hand-rolled splitter:

```python
row = '"Anker, Wireless Mouse",29.99,"She said ""great mouse"""'
print(row.split(","))
```

Four fields instead of three, the title is split in half, and the quoted review still has its escape doubling visible. The `csv` module gets all of this right because it implements the actual CSV grammar (RFC 4180 plus the common variants).

```python
import csv
import io

raw = '"Anker, Wireless Mouse",29.99,"She said ""great mouse"""'
reader = csv.reader(io.StringIO(raw))
for row in reader:
    print(row)
```

Three fields, the title intact, the inner quotes un-escaped. That's the whole reason the module exists.

> **Cost:** A regex or a manual state-machine that mimics `csv.reader` is almost always slower and definitely buggier. The `csv` module's parser is written in C and handles every edge in RFC 4180. Use it.

One more thing worth saying up front: the `csv` module is not pandas. `pandas.read_csv` is a heavier dependency that returns a `DataFrame` with type inference, missing-value handling, and column slicing. For the streaming, row-by-row reading and writing this lesson covers, the standard library is plenty.

<h1 id="reading-csvs-with-csvreader">Reading CSVs with csv.reader</h1>

`csv.reader` is the simplest interface. You give it any iterable of lines (a file, a list of strings, a `StringIO`), and it yields each record as a list of string fields.

Imagine a small product catalog file at `products.csv`:

```text
product_id,name,price,stock
P001,Wireless Mouse,29.99,42
P002,Mechanical Keyboard,89.99,15
P003,USB-C Hub,24.50,7
```

Reading it row by row:

```python
import csv

with open("products.csv", newline="") as f:
    reader = csv.reader(f)
    header = next(reader)
    print("columns:", header)
    for row in reader:
        product_id, name, price, stock = row
        print(f"{product_id}: {name} (${price}, {stock} in stock)")
```

Three things to notice. The `open()` call uses `newline=""`, which we'll cover in detail below. `next(reader)` pulls the first row, which is the header. The rest of the rows come out of the `for` loop as plain lists of strings. Every field is a string, even `price` and `stock`; CSV doesn't carry types, so converting to `float` or `int` is the caller's job.

Type conversion looks like this:

```python
import csv

with open("products.csv", newline="") as f:
    reader = csv.reader(f)
    next(reader)
    total_value = 0.0
    for row in reader:
        product_id, name, price, stock = row
        total_value += float(price) * int(stock)
    print(f"inventory value: ${total_value:.2f}")
```

`float(price)` and `int(stock)` happen per row. If the field is missing or malformed, the conversion raises `ValueError`, which you'd usually catch and log as a bad-row problem rather than crashing the import.

> **Cost:** `csv.reader` streams. It reads one row at a time and never holds the whole file in memory, which matters for a 5 GB order export. If you write `list(reader)` you suddenly hold every row in memory, so only do that when the file is small enough to fit.

<h1 id="writing-csvs-with-csvwriter">Writing CSVs with csv.writer</h1>

`csv.writer` is the mirror image. You hand it a file open for writing, then call `writerow(row)` or `writerows(rows)` with lists of values. The writer handles the quoting and escaping for you.

```python
import csv

orders = [
    ["order_id", "customer", "product", "quantity", "total"],
    [1001, "Alice", "Wireless Mouse", 1, 29.99],
    [1002, "Bob", "Mechanical Keyboard", 2, 179.98],
    [1003, "Carol", 'USB-C "Pro" Hub', 1, 24.50],
]

with open("orders.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerows(orders)

with open("orders.csv") as f:
    print(f.read())
```

Notice what the writer did with `'USB-C "Pro" Hub'`: it wrapped the whole field in double quotes (because the value itself contained a `"`) and doubled the inner quotes to escape them. That's the CSV escape rule, applied automatically. Numeric values were converted to their string forms using `str()`; `29.99` came out as `29.99`, and `24.5` came out as `24.5` (Python collapses the trailing zero, which is something to know if you care about pretty currency output).
