<h1 id="element-wise-arithmetic">Element-Wise Arithmetic</h1>

Arithmetic on a NumPy array applies to every element, in parallel. There's no loop in the code, and no loop in NumPy's Python layer either; the work happens in compiled C.

```python
import numpy as np

prices = np.array([29.99, 14.99, 9.99, 49.99, 19.99])

doubled = prices * 2
shifted = prices + 5
discounted = prices * 0.9

print("doubled:    ", doubled)
print("shifted:    ", shifted)
print("discounted: ", discounted)
```

Each operation produced a new array of the same shape. The original `prices` is untouched. `prices * 2` is shorthand for "multiply every element by 2", and `prices * 0.9` applied a 10% discount to every price. The operator on the right is a scalar (a single number), and NumPy broadcast it across the array.

Two arrays of the same shape combine element by element:

```python
import numpy as np

prices = np.array([29.99, 14.99, 9.99, 49.99])
quantities = np.array([2, 1, 3, 1])

line_totals = prices * quantities
print(line_totals)

cart_total = line_totals.sum()
print(f"Cart total: ${cart_total:.2f}")
```

`prices * quantities` multiplied corresponding elements: index 0 with index 0, index 1 with index 1, and so on. The result is a new array of per-row totals. Calling `.sum()` then collapses it to a single scalar. The whole thing is three lines, one mental step per line, and runs at C speed for a million items.

The four basic arithmetic operators (`+`, `-`, `*`, `/`) all work this way, as do the rest: `**` for exponentiation, `//` for floor division, `%` for modulo. Comparison operators (`==`, `!=`, `<`, `>`, `<=`, `>=`) produce a boolean array of the same shape, which can be used as a mask.

```python
import numpy as np

stock = np.array([42, 0, 15, 7, 0])

needs_restock = stock < 10
print(needs_restock)
```

The boolean array can drive the next operation: filter, replace, count, or anything else. This composability ("compute a mask, use the mask, compute the next thing") is the rhythm of NumPy code.

Every arithmetic operation on an array allocates a new array for the result. For long chains of operations on huge data, this can be the dominant cost. The in-place forms (`arr *= 2`, `arr += 5`) skip the allocation when the original isn't needed.

<h1 id="in-place-operations">In-Place Operations</h1>

The augmented operators (`+=`, `-=`, `*=`, `/=`) modify the array in place instead of allocating a new one. Same semantics, less memory pressure.

```python
import numpy as np

prices = np.array([29.99, 14.99, 9.99, 49.99])

prices *= 0.9
print(prices)
```

`prices *= 0.9` rewrote every cell of `prices` in place. No new array was allocated. For a 1-billion-element array, the difference between in-place and not is the difference between using 8 GB and 16 GB of memory.

In-place arithmetic also enforces dtype compatibility more strictly. `prices *= 0.9` works because `prices` is `float64`, which can hold the result. If `prices` were `int64`, the same expression would raise `TypeError` because the result needs floats. Out-of-place (`prices = prices * 0.9`) changes the result's dtype to `float64` automatically, which is sometimes desired and sometimes a memory surprise.

<h1 id="universal-functions-ufuncs">Universal Functions (ufuncs)</h1>

NumPy ships with a large library of element-wise functions called **universal functions**, or ufuncs. `np.sin`, `np.exp`, `np.log`, `np.sqrt`, `np.abs`, and many more. They take an array, apply the function to every element, and return a new array of the same shape.

```python
import numpy as np

prices = np.array([29.99, 14.99, 9.99, 49.99])

# Square root and natural log of every price
print(np.sqrt(prices))
print(np.log(prices))
```

Ufuncs apply a math function to every element, and they are also the foundation for more elaborate operations. The full list is long; the subset that comes up most often:

| Ufunc                | What it does                                  |
| -------------------- | --------------------------------------------- |
| `np.sqrt(x)`         | Square root of every element                  |
| `np.exp(x)`          | `e**x` for every element                      |
| `np.log(x)`          | Natural log of every element                  |
| `np.log10(x)`        | Base-10 log of every element                  |
| `np.abs(x)`          | Absolute value                                |
| `np.sin(x)`          | Sine, in radians                              |
| `np.cos(x)`          | Cosine, in radians                            |
| `np.floor(x)`        | Round down to the nearest integer (as float)  |
| `np.ceil(x)`         | Round up                                      |
| `np.round(x)`        | Round to the nearest, ties go to even         |
| `np.clip(x, lo, hi)` | Clamp every element into the range `[lo, hi]` |

`np.clip` handles "cap values between a min and a max" without a loop:

```python
import numpy as np

review_scores = np.array([4.5, 6.2, -0.5, 3.8, 9.9])

# Clamp every score into [0, 5]
clamped = np.clip(review_scores, 0, 5)
print(clamped)
```

Two-argument ufuncs combine two arrays element-wise. `np.maximum(a, b)` returns the elementwise maximum, `np.minimum` the minimum, `np.power(a, b)` raises `a` to `b`. Same shape rules as ordinary arithmetic.

```python
import numpy as np

list_price = np.array([29.99, 14.99, 9.99, 49.99])
sale_price = np.array([24.99, 19.99, 9.99, 39.99])

# For each item, pick the lower of the two
best_price = np.minimum(list_price, sale_price)
print(best_price)
```

This replaces a Python `for` loop with `min()` on each pair, and it runs about 50x faster for arrays large enough to matter.

<h1 id="aggregations">Aggregations</h1>

Aggregations collapse an array down to a smaller one (often a scalar) by combining values. The common ones live as both methods on the array and functions in the top-level `np` namespace.

```python
import numpy as np

prices = np.array([29.99, 14.99, 9.99, 49.99, 19.99])

print("sum:   ", prices.sum())
print("mean:  ", prices.mean())
print("std:   ", prices.std())
print("min:   ", prices.min())
print("max:   ", prices.max())
print("argmin:", prices.argmin())
print("argmax:", prices.argmax())
```

`sum`, `mean`, `std` (standard deviation), `min`, and `max` are all "reductions" that collapse the whole array into a single number. `argmin` and `argmax` return the **index** of the smallest and largest values, which is often more useful than the values themselves. Knowing that the cheapest product is at index 2 enables a lookup in a parallel array of names.

| Aggregation | Returns                                                      |
| ----------- | ------------------------------------------------------------ |
| `sum()`     | Total of all elements                                        |
| `mean()`    | Arithmetic mean (average)                                    |
| `std()`     | Standard deviation                                           |
| `var()`     | Variance                                                     |
| `min()`     | Smallest value                                               |
| `max()`     | Largest value                                                |
| `argmin()`  | Index of the smallest value (flattened if multi-dimensional) |
| `argmax()`  | Index of the largest value                                   |
| `prod()`    | Product of all elements                                      |
| `cumsum()`  | Running cumulative sum (returns an array, not a scalar)      |
| `cumprod()` | Running cumulative product                                   |

`cumsum` is interesting because it doesn't reduce to a scalar. It returns an array of the same length, where each element is the running total up to that point:

```python
import numpy as np

daily_sales = np.array([120, 95, 110, 130, 105, 140, 200])
running = daily_sales.cumsum()
print(running)
```

After day 0, the running total is 120. After day 1, it's 215. After day 6, it's 900. This is the building block for running revenue dashboards, time-series visualizations, and any report that needs "where am I now" rather than "what did I do today".

<h1 id="aggregating-along-an-axis">Aggregating Along an Axis</h1>

The aggregations become more powerful when applied to a multi-dimensional array along a specific axis. Without an `axis`, they reduce the whole array to a scalar. With `axis=0`, they collapse the rows, leaving one value per column. With `axis=1`, they collapse the columns, leaving one value per row.

```python
import numpy as np

# Rows are days (Mon-Sun), columns are categories (electronics, books, clothing)
revenue = np.array([
    [4520, 1200, 880],
    [3980, 1450, 720],
    [4100, 1380, 910],
    [5240, 1610, 1040],
    [6890, 1820, 1330],
    [9120, 2150, 1880],
    [7460, 1980, 1540],
])

# Total per category (sum down each column)
per_category = revenue.sum(axis=0)
print("per_category:", per_category)

# Total per day (sum across each row)
per_day = revenue.sum(axis=1)
print("per_day:     ", per_day)

# Grand total
print("grand total: ", revenue.sum())
```

The rule for axes: `axis=k` is the axis being collapsed. The remaining axes form the shape of the result. A `(7, 3)` array collapsed along `axis=0` (the rows) leaves a length-3 result (one value per column). Collapsed along `axis=1` (the columns) leaves a length-7 result (one value per row).

The same rule scales to higher dimensions. A `(4, 7, 3)` array (stores by days by categories) summed along `axis=0` gives a `(7, 3)` result (one value per day-and-category, summed across stores). Summed along `axis=1` it gives a `(4, 3)` result. Summed along axes `(0, 1)` it gives a `(3,)` result. The shape of the result is whatever was left after removing the collapsed axes.

`argmax` and `argmin` follow the same pattern: with no axis, they return a single index into the flattened array. With an axis, they return an array of indices, one per surviving axis position.

```python
import numpy as np

revenue = np.array([
    [4520, 1200, 880],
    [3980, 1450, 720],
    [4100, 1380, 910],
    [5240, 1610, 1040],
    [6890, 1820, 1330],
    [9120, 2150, 1880],
    [7460, 1980, 1540],
])

# Best day overall, per category
best_day_per_category = revenue.argmax(axis=0)
print("best day per category:", best_day_per_category)

# Best category, per day
best_category_per_day = revenue.argmax(axis=1)
print("best category per day:", best_category_per_day)
```

The best day for every category is day 5 (Saturday, index 5). The best category every day is category 0 (electronics). The first result has length 3 (one per category), the second has length 7 (one per day). Same rule: the collapsed axis disappears from the result.

<h1 id="broadcasting">Broadcasting</h1>

Broadcasting is the rule NumPy uses when an operation applies to two arrays of different shapes. Instead of failing or copying data, NumPy stretches the smaller array along the missing dimensions to match the larger one, virtually. The actual memory isn't duplicated; the smaller array is reused at every position along the stretched axis.

The simplest case is scalar broadcasting. `prices * 2` doesn't materialize a length-N array of `[2, 2, 2, ...]`. NumPy multiplies each price by the scalar `2`. That's broadcasting in its most basic form.

Broadcasting gets interesting with multi-dimensional arrays. The rule: two arrays are broadcast-compatible if, when their shapes are lined up from the right, every pair of corresponding dimensions is either equal or one of them is 1.

A concrete example. Subtract the per-category average from every cell in a `(7, 3)` revenue grid:

```python
import numpy as np

revenue = np.array([
    [4520, 1200, 880],
    [3980, 1450, 720],
    [4100, 1380, 910],
    [5240, 1610, 1040],
    [6890, 1820, 1330],
    [9120, 2150, 1880],
    [7460, 1980, 1540],
])

# Average per category, shape (3,)
category_avg = revenue.mean(axis=0)
print("category_avg:", category_avg)

# Subtract the average from every row of the original grid
delta = revenue - category_avg
print(delta)
```

`revenue` has shape `(7, 3)`. `category_avg` has shape `(3,)`. NumPy lines them up from the right: 3 matches 3. There's no second dimension on `category_avg`, so NumPy treats it as if it were `(1, 3)`, and broadcasts it down all 7 rows. The result is a `(7, 3)` array where each row has had the category averages subtracted. No loops, no `for` over the seven days.

The same trick works for "subtract the per-day average from every column". The average needs an extra dimension first, because the shape mismatch must align correctly:

```python
import numpy as np

revenue = np.array([
    [4520, 1200, 880],
    [3980, 1450, 720],
    [4100, 1380, 910],
    [5240, 1610, 1040],
    [6890, 1820, 1330],
    [9120, 2150, 1880],
    [7460, 1980, 1540],
])

# Average per day, shape (7,). Reshape to (7, 1) so it broadcasts across columns.
day_avg = revenue.mean(axis=1).reshape(7, 1)
print("day_avg shape:", day_avg.shape)

delta = revenue - day_avg
print(delta)
```

The `(7, 1)` shape lines up with `(7, 3)` because both have 7 on the left and the column on the right is 1, which broadcasts. Without the reshape, aligning `(7,)` against `(7, 3)` puts the 7 in the wrong slot (the column slot) and fails with a `ValueError`.

The rule visualized:

The whole rule: line shapes up from the right, walk each pair, accept if they're equal or one is 1, fail otherwise. Missing dimensions on the left of a shape are treated as 1. A `(3,)` array is equivalent to `(1, 3)` for broadcasting purposes, which is why it lined up with `(7, 3)` on the right.

When broadcasting fails, the error is explicit:

```python
import numpy as np

a = np.array([[1, 2, 3], [4, 5, 6]])  # shape (2, 3)
b = np.array([1, 2])                   # shape (2,)

try:
    result = a + b
except ValueError as e:
    print("error:", e)
```

`b` has shape `(2,)`, which aligns to the right of `a`'s shape: `(2, 3)` and `(2,)` become `(2, 3)` and `(_, 2)`. The 3 and the 2 don't match, neither is 1, so broadcasting fails. To make it work, `b` would need shape `(3,)` (broadcast across rows) or `(2, 1)` (broadcast across columns).

<h1 id="why-vectorized-beats-loops">Why Vectorized Beats Loops</h1>

The main reason to learn NumPy is the speedup over loops. Concrete numbers help. Compute the sum of squares of a million numbers:

```python
import numpy as np
import time

n = 1_000_000
data_list = list(range(n))
data_array = np.arange(n)

# Python loop
start = time.perf_counter()
total = 0
for x in data_list:
    total += x * x
list_time = time.perf_counter() - start

# Vectorized
start = time.perf_counter()
total_vec = (data_array ** 2).sum()
array_time = time.perf_counter() - start

print(f"Loop:       {list_time * 1000:.2f} ms")
print(f"Vectorized: {array_time * 1000:.2f} ms")
print(f"Speedup:    {list_time / array_time:.0f}x")
```

The exact ratio depends on the CPU and Python version, but 30x-100x is typical for arithmetic-heavy work. Two factors drive the speedup. First, the inner loop runs in compiled C instead of the Python interpreter, which strips out per-iteration overhead (no bytecode dispatch, no reference counting, no boxed object lookup). Second, the data is laid out contiguously, so the CPU's cache and prefetcher work efficiently.

A NumPy loop of the form `for x in arr: do_something(x)` is usually no faster than a list loop and sometimes slower, because of the overhead of extracting each element from the array. Look for a vectorized equivalent before writing such a loop.

Not every operation vectorizes neatly. When per-element logic needs branches, exception handling, or external state, a loop is the right answer. The goal isn't to eliminate loops everywhere, it's to use vectorized ops when the work is "do the same arithmetic to every element".

<h1 id="sorting">Sorting</h1>

`np.sort` returns a sorted copy of an array. `arr.sort()` sorts in place and returns `None` (same pattern as Python's `sorted` and `list.sort`).

```python
import numpy as np

prices = np.array([29.99, 14.99, 9.99, 49.99, 19.99])

sorted_prices = np.sort(prices)
print("sorted:  ", sorted_prices)
print("original:", prices)
```

For a 2D array, `np.sort` sorts along the last axis by default. Passing `axis=0` sorts each column independently, and `axis=None` flattens then sorts.

```python
import numpy as np

revenue = np.array([
    [4520, 1200, 880],
    [3980, 1450, 720],
    [4100, 1380, 910],
])

# Sort each row independently
print(np.sort(revenue, axis=1))

# Sort each column independently
print(np.sort(revenue, axis=0))
```

The first call sorts each row from low to high. The second sorts each column from low to high. Both keep the array's shape.
