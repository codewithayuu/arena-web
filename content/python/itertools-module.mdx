<h1 id="why-a-standard-library-of-iterator-operators">
  Why a Standard Library of Iterator Operators
</h1>

Generator expressions let you transform and filter streams lazily. `yield from` lets you flatten one generator into another by hand. `itertools` is the library that names the common shapes of those pipelines so you don't have to rewrite them every time. Every function in this module returns an iterator, holds no more than a handful of items in memory, and works on any iterable, lists, tuples, file objects, generator expressions, or other itertools chains.

The mental model worth holding: each `itertools` function is a small generator that knows one trick. You wire them together with the chain operator (function call composition) the same way you'd build a Unix pipeline. The trick is knowing which one to reach for.

```python
from itertools import islice, chain

warehouse_a = ["mug", "notebook", "pen"]
warehouse_b = ["bottle", "cap", "shirt"]

combined = chain(warehouse_a, warehouse_b)
first_four = list(islice(combined, 4))
print(first_four)
```

`chain` glues two product lists into one stream without building a third list, and `islice` peels off the first four items. Neither function builds the full combined list in memory. That's the pattern we'll see again and again.

<h1 id="combining-and-filtering-iterators">
  Combining and Filtering Iterators
</h1>

This first group of tools rearranges or filters items from one or more input streams. None of them produce new items out of thin air; they just rewire what's coming in.

<h3 id="chainiterables-and-chainfrom_iterableiterable_of_iterables">
  chain(*iterables) and chain.from_iterable(iterable_of_iterables)
</h3>

`chain` concatenates iterables. It yields every item from the first iterable, then every item from the second, and so on. `chain.from_iterable` does the same thing when the iterables are themselves wrapped in another iterable (often a generator that produces lists).

```python
from itertools import chain

warehouse_a = ["mug", "notebook"]
warehouse_b = ["bottle"]
warehouse_c = ["cap", "shirt"]

for product in chain(warehouse_a, warehouse_b, warehouse_c):
    print(product)
```

`chain.from_iterable` is the version you reach for when the inputs are produced lazily, for example by a generator that yields one warehouse's inventory at a time.

```python
from itertools import chain

def warehouses():
    yield ["mug", "notebook"]
    yield ["bottle"]
    yield ["cap", "shirt"]

for product in chain.from_iterable(warehouses()):
    print(product)
```

**Use when:** you have several iterables and want to walk them as one stream without copying everything into a new list. It's the iterator equivalent of `list_a + list_b + list_c`, but without the allocation. `yield from` inside a generator function does the same flattening; `chain` is the non-generator alternative when you don't need to write your own generator.

<h3 id="compressdata-selectors">compress(data, selectors)</h3>

`compress` walks two iterables side by side. For each pair, it yields the item from `data` only if the matching selector is truthy. It stops as soon as either iterable runs out.

```python
from itertools import compress

products = ["mug", "notebook", "pen", "bottle", "cap"]
in_stock = [1, 0, 1, 1, 0]

available = list(compress(products, in_stock))
print(available)
```

The selector doesn't have to be exactly `0` or `1`. Any truthy value (non-zero number, non-empty string, `True`) keeps the item; any falsy value (`0`, `""`, `None`, `False`) drops it. This is handy when the in-stock flag comes from a separate sensor or database column.

**Use when:** you've already computed a parallel list of booleans somewhere else (a database query, a separate calculation), and you want to filter without re-running the predicate.

<h3 id="dropwhilepred-iterable">dropwhile(pred, iterable)</h3>

`dropwhile` skips items while the predicate returns true, then yields every remaining item, including the first one that flipped the predicate to false. Once it starts yielding, it never looks at the predicate again.

```python
from itertools import dropwhile

cart_prices = [0.0, 0.0, 12.99, 7.49, 0.0, 1.99]

# Skip leading free items, then keep the rest including any later zeros.
priced = list(dropwhile(lambda p: p == 0.0, cart_prices))
print(priced)
```

Notice the `0.0` at index 4 stayed in the output. `dropwhile` only skips a leading run; once the predicate fails, the rest passes through untouched.

**Use when:** the input has a leading prefix you want to discard (warm-up data, header rows, free trial entries before the first real purchase), and the rest of the stream is "the real data."

<h3 id="takewhilepred-iterable">takewhile(pred, iterable)</h3>

`takewhile` is the mirror image. It yields items while the predicate is true and stops the moment the predicate fails, even if more matching items appear later.

```python
from itertools import takewhile

cart_prices = [12.99, 7.49, 1.99, 0.0, 49.99]

# Keep priced items until we hit the first free one.
priced = list(takewhile(lambda p: p > 0.0, cart_prices))
print(priced)
```

The `49.99` at the end never appears because `takewhile` had already stopped at the `0.0`. That's the key difference from `filter`, which would have kept both `49.99` and dropped only the zero.

**Use when:** you want to consume a sorted or otherwise structured stream up to a boundary. For example, reading reviews until the first one below 4 stars on a list already sorted by rating.

<h3 id="filterfalsepred-iterable">filterfalse(pred, iterable)</h3>

`filterfalse` is the inverse of the built-in `filter`. It yields items where the predicate is false. It's there for cases where the negative phrasing reads more naturally than wrapping a `lambda` in `not`.

```python
from itertools import filterfalse

cart_prices = [12.99, 0.0, 7.49, 0.0, 1.99]

# Items that aren't free.
non_free = list(filterfalse(lambda p: p == 0.0, cart_prices))
print(non_free)
```

You could write the same thing as `filter(lambda p: p != 0.0, cart_prices)`. `filterfalse` exists so you can keep the predicate phrased positively when that reads better, especially with named helper functions like `is_out_of_stock` or `is_refunded`.

**Use when:** the predicate has a clear positive name and you want the negative half of the split. Pair it with `filter` over the same iterable when you need both halves (but see the note on `tee` below before doing that).

<h3 id="isliceiterable-start-stop-step">
  islice(iterable, [start,] stop[, step])
</h3>

`islice` is the iterator-friendly version of regular slicing. Plain slicing (`some_iter[2:10]`) doesn't work on generators or other lazy iterators because they don't support indexing. `islice` walks the iterator forward, skipping and yielding the right items, without ever building the full list.

```python
from itertools import islice

def order_stream():
    for i in range(1, 1_000_000):
        yield f"order-{i}"

# Pretend we want orders 100 through 104.
preview = list(islice(order_stream(), 100, 105))
print(preview)
```

The generator could be billions of items long; `islice` only reads as far as `stop` and then stops. The signature mirrors Python's built-in `slice`, so `islice(it, 5)` means "first five," `islice(it, 5, 10)` means "items 5 through 9," and `islice(it, 0, None, 2)` means "every other item from the start."

> **Cost:** `islice` is O(stop) because it has to read and discard everything up to `start`. There's no way around this for a one-pass iterator. If you need true random access, materialize to a list first (and pay the memory cost).

**Use when:** you want to limit, page, or step through a lazy stream. Common patterns: `islice(stream, 10)` to peek at the first ten, `islice(stream, 1, None)` to skip a header row.

<h3 id="starmapfunc-iterable_of_tuples">starmap(func, iterable_of_tuples)</h3>

`starmap` is like the built-in `map`, but it expects each item in the iterable to be a tuple of arguments, and it unpacks that tuple when calling the function. It pairs naturally with `zip`, which produces tuples.

```python
from itertools import starmap

def line_total(price, quantity):
    return price * quantity

cart = [(12.99, 2), (7.49, 1), (1.99, 5)]
totals = list(starmap(line_total, cart))
print(totals)
```

Without `starmap`, you'd write `map(lambda pair: line_total(*pair), cart)`. `starmap` does that unpacking for you.

Combined with `zip`, it lets you apply a multi-argument function across parallel iterables:

```python
from itertools import starmap

products = ["mug", "notebook", "pen"]
prices = [12.99, 7.49, 1.99]

def describe(name, price):
    return f"{name}: ${price:.2f}"

for line in starmap(describe, zip(products, prices)):
    print(line)
```

**Use when:** you have a function that takes multiple arguments and a sequence of argument tuples, often the output of `zip`. It's cleaner than a generator expression that unpacks by hand.

<h1 id="grouping-and-accumulating">Grouping and Accumulating</h1>

The next set of tools builds derived streams from a single input: running totals, paired neighbours, grouped runs of equal items, fan-out copies. They're where `itertools` starts to feel like a tiny query engine.

<h3 id="groupbyiterable-key">groupby(iterable, key=...)</h3>

`groupby` yields `(key, group_iterator)` pairs as it walks the input. Each pair represents a run of consecutive items that share the same key. The group iterator is itself lazy; iterate it to get the items in that group, or wrap it in `list` to materialize them.

The critical thing to understand, and the source of the most common `groupby` bug, is that it only groups **consecutive** items. If the input isn't already sorted by the same key, you'll get many small groups instead of a few large ones.

Here's the right way: sort first, then group.

```python
from itertools import groupby

orders = [
    {"id": 1, "category": "kitchen", "total": 12.99},
    {"id": 2, "category": "office",  "total": 7.49},
    {"id": 3, "category": "kitchen", "total": 4.99},
    {"id": 4, "category": "office",  "total": 19.99},
    {"id": 5, "category": "kitchen", "total": 8.49},
]

def by_category(order):
    return order["category"]

# Sort by the same key first, otherwise groupby misses runs.
orders_sorted = sorted(orders, key=by_category)

for category, group in groupby(orders_sorted, key=by_category):
    items = list(group)
    print(f"{category}: {len(items)} orders, total ${sum(o['total'] for o in items):.2f}")
```
