<h1 id="strong-references-vs-weak-references">
  Strong References vs Weak References
</h1>

Every normal name in Python is a strong reference. As long as some strong reference exists, the object can't be garbage collected. That's why this works:

```python
class Product:
    def __init__(self, product_id: int, name: str, price: float):
        self.product_id = product_id
        self.name = name
        self.price = price

    def __repr__(self) -> str:
        return f"Product({self.product_id}, {self.name!r})"

headphones = Product(101, "Wireless Headphones", 79.99)
also_headphones = headphones
del headphones
print(also_headphones)
```

Even though we deleted `headphones`, the `Product` object is still alive because `also_headphones` is a strong reference to the same object.

A weak reference is different. It points at an object, but doesn't keep it alive. The moment the last strong reference goes away, the object is collected, and any weak reference to it quietly turns into `None`.

```python
import weakref

class Product:
    def __init__(self, product_id: int, name: str):
        self.product_id = product_id
        self.name = name

    def __repr__(self) -> str:
        return f"Product({self.product_id}, {self.name!r})"

headphones = Product(101, "Wireless Headphones")
ref = weakref.ref(headphones)

print(ref())
del headphones
print(ref())
```

`weakref.ref(obj)` returns a callable. Calling it with no arguments either gives you the original object or returns `None` if the object has been collected. That's the whole interface.

Here's the relationship visually. The dashed arrow is the weak reference: it knows about the object but doesn't count toward keeping it alive.

The strong reference `headphones` is what keeps the `Product` alive. The weak reference `ref` only watches. When the strong reference disappears, the object can be collected and the weak reference becomes a dead pointer that returns `None`.

<h1 id="which-objects-support-weak-references">
  Which Objects Support Weak References
</h1>

Not every Python object can have a weak reference taken to it. The object's type has to opt in. Most built-in containers and immutable types don't.

```python
import weakref

try:
    weakref.ref([1, 2, 3])
except TypeError as e:
    print(f"list: {e}")

try:
    weakref.ref({"a": 1})
except TypeError as e:
    print(f"dict: {e}")

try:
    weakref.ref("hello")
except TypeError as e:
    print(f"str: {e}")
```

The reason is implementation-driven. Weak references need a small extra slot on the object to hold the list of weak references that point at it. Built-in containers like `list`, `dict`, `tuple`, `int`, and `str` are tuned for size, so they skip that slot. User-defined classes get it by default.

| Type                                | Supports weak refs? |
| ----------------------------------- | ------------------- |
| User-defined class                  | Yes (by default)    |
| `list`, `dict`, `set`, `tuple`      | No                  |
| `int`, `float`, `str`, `bytes`      | No                  |
| Subclass of `list` or `dict`        | Yes                 |
| Slotted class without `__weakref__` | No                  |
